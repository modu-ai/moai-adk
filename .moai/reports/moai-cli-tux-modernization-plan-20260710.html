1. 현행 진단 (Discovery)

이미 좋은 뼈대가 있다. internal/tui(~1,824 LOC)는 lipgloss v1 기반 자체 디자인 시스템(테마 토큰·NO_COLOR/MOAI_THEME 감지·hex 리터럴 금지 계약)을 갖추고 있고, internal/cli/uikit이 배너·카드·에러 박스를 제공합니다. 문제는 세대(전부 v1 라이브러리)와 일관성(출력 채널 분산)입니다.

영역현재 상태문제점
스타일링lipgloss v1.1.0 + catppuccin 팔레트, internal/tui 토큰 SSOTv1 세대. 색 다운샘플링·배경 감지 정확도가 v2 대비 열세
인터랙션huh v1.0.0 폼 (init 위저드), bubbletea v1.3.10은 internal/merge/confirm.go 단 1곳huh v0.8 스크롤 버그 회피용 "질문 1개 = 폼 1개" 워크어라운드 (wizard.go:14) — 통합 화면 부재
진행 표시수제 stateless Spinner()/Progress()/ProgressLine (internal/tui/status.go, progress_line.go)비동기 애니메이션 스피너 없음. init은 정적 줄 출력만 — 긴 단계에서 무반응처럼 보임
도움말/에러cobra 기본 help, 에러는 RenderError와 cobra 기본 stderr 혼용help 페이지 무스타일. 경고가 stdout에 "Warning: %v"로 새어나감 (자체 컨벤션 위반)
출력 채널fmt.Printf 직접 호출 / cmd.OutOrStdout() / ConsoleReporter 혼재통합 Printer 추상화 부재 — 재설계의 1순위 대상
init 흐름internal/cli/init.go:218 runInit — 셀프업데이트 → wizard → PhaseExecutor사용자 인터랙션 전에 블로킹 네트워크 셀프업데이트(init.go:220); 진행 피드백 빈약
update 흐름update.go 117KB 단일 파일, 7단계 파이프라인 + namespace 보호 + 3-way merge파일 비대화; 변경 요약이 텍스트 나열 — diff 프리뷰/선택 UI 부재

2. 라이브러리 선정 (2026-07 기준 최신)

2026-02-23 Charm이 Bubble Tea · Lip Gloss · Bubbles v2 안정판을 동시 출시했습니다(6년 만의 첫 breaking change, import 경로가 charm.land/*/v2 vanity 도메인으로 이동). Crush(Charm의 AI 코딩 에이전트)에서 수개월 프로덕션 검증을 거친 스택입니다.

3. 디자인 방향 — "MoAI Terminal Design Language v3"

원칙

  • 토큰 SSOT 유지: internal/tui가 유일한 색·글리프 원천 (기존 AC-CLI-TUI-013 계약 승계)
  • 3계층 출력: 토큰(tui) → 컴포넌트(uikit) → 통합 Printer(신규) — 모든 커맨드는 Printer만 사용
  • stdout=데이터, stderr=상태/경고 규율 기계화 (+ --json/--plain 전역 플래그)
  • graceful degradation: TTY→풀 TUI, non-TTY/CI→plain 라인, NO_COLOR/MOAI_REDUCED_MOTION 존중 (기존 계약 유지)

비주얼

  • 브랜드 액센트: 코랄/테라코타 계열(claude warm 계열과 정합) + catppuccin 유지 검토
  • 배너 경량화: 대형 ASCII 로고 → 컴팩트 1–2행 아이덴티티 + pill 메타(버전/go/claude)
  • 상태 어휘 통일: ✓ ✗ ! ● ○ ◆ 글리프 화이트리스트 유지, 스피너는 bubbles v2
  • Fang 테마를 tui 토큰으로 주입 → help/에러/커맨드 출력 색 일치

4. 실행 계획 — 4 마일스톤

  • M1 — 기반 교체: Charm v2 마이그레이션 + 통합 Printer P0 Tier L 진입점
    • go.mod: charm.land/{lipgloss,bubbletea,bubbles}/v2 + charm.land/fang/v2 도입, v1 제거
    • internal/tui를 lipgloss v2 API로 포팅 (토큰 계약·테스트 보존, behavior-preserving DDD)
    • 신규 internal/cli/printer: Printer 인터페이스(Info/Warn/Error/Data/Step/Spinner) — stdout/stderr 규율 + TTY/plain/json 3모드 단일 구현. ConsoleReporter·직접 fmt.Printf 호출을 전량 흡수
    • fang.Execute로 root 진입 교체 → 전 서브커맨드 help/에러 즉시 현대화
  • M2 — moai init 재설계 P0
    • 순서 교정: 셀프업데이트 체크를 위저드 이후 비동기(또는 --check-update opt-in)로 이동 — 첫 인터랙션까지 네트워크 0회
    • huh v2 스파이크로 스크롤 버그 해소 확인 → 6개 개별 폼을 단일 멀티필드 위저드(그룹 2–3개 + 사이드 스텝퍼)로 통합; 실패 시 현행 구조 유지 + 스타일만 v2
    • PhaseExecutor 진행을 bubbles v2 spinner + 파일 카운트 라이브 진행률로 교체 (non-TTY는 기존 plain 라인)
    • 경고 수집기: 단계별 Warning: 산발 출력 → 종료 시 stderr 요약 패널 1회
    • 완료 카드에 "다음 액션"(cd → moai cc → /moai plan) 명시
  • M3 — moai update 재설계 P1
    • update.go(117KB) 서브패키지 분해: internal/cli/update/{plan,backup,deploy,merge,report} — namespace 보호·3-way merge 로직은 behavior-preserving 이동
    • 변경 프리뷰 TUI: 분석 단계 결과를 Bubble Tea 테이블(추가/갱신/보존/충돌 분류 + 파일별 diff 프리뷰)로 표시, --yes/non-TTY는 요약 텍스트
    • 기존 internal/merge/confirm.go 체크박스 UI를 bubbles v2 list로 승격해 update 충돌 해소에도 재사용
    • 버전 스킵/강제/드라이런 결과를 통일된 outcome 카드로 (Already up-to-date / Updated N files / Dry-run)
    • 백업 위치·복구 커맨드를 완료 화면에 항상 표기
  • M4 — 전면 폴리시: doctor/status/spec 표면 P2
    • moai doctor: 체크 항목 라이브 진행 + 섹션별 pass/fail 테이블 (bubbles table)
    • moai status/moai spec: glamour 마크다운 렌더 (SPEC 요약·핸드오프 열람)
    • 배너 경량화 + moai --help 그룹 재정리 (launch/project/tools 그룹 유지, 사용 빈도순 정렬)
    • 스크린리더·CI 회귀 검증: NO_COLOR, non-TTY, Windows Terminal 골든 테스트 갱신
