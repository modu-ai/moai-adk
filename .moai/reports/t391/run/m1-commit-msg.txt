feat(cli): bare `moai codex` launches; status keeps the readout (t391)

SPEC-CODEX-LAUNCH-VERB-001 M1-M5. Supersedes REQ-CL-002 of
SPEC-CODEX-LAUNCHER-001: the bare invocation launched nothing and printed the
readiness readout. It now launches the Codex CLI, and `status` is the explicit
readout alias.

The risk that argued for the old default -- an accidental invocation carrying
the session away -- does not apply here: since the 0.8.0 revision this launcher
starts an os/exec CHILD with verbatim exit-code propagation, not a process
replacement, so the shell is still there when codex exits.

Two tables, not one. Routing (codexVerbRouting) answers "what did the operator
ask for" and stays a closed set -- absence IS the rejection, no default branch.
Argv translation (codexChildSubcommand), strictly downstream and a strict
subset, answers "what does codex accept": only a verb naming a real codex
subcommand reaches the child.

-w/--worktree is consumed here and never forwarded: it points the child's
working directory at an EXISTING worktree. It RESOLVES and never CREATES -- an
absent name is a diagnostic with launch count 0 and the directory still absent
afterwards. This is deliberately asymmetric with `moai cc`, where the flag is
forwarded and claude creates the tree; the reason is recorded [HARD] in the SPEC
so a later "make it consistent" argument has to answer it.

CODEX_HOME now reaches the child as an explicit environment entry on both the
direct path (exec.Cmd.Env) and the new-window path (a command-scoped assignment
in the tmux command string), rather than by ambient inheritance. No file is
written on any verb -- the entry is process-local, so REQ-CL-013 holds.

2. TestCodexSpawn_RealAssemblyThroughStubTmux pinned the `cli` token in the

4. TestCodexSpawn_RejectedOnReadoutForms drops its bare row: `moai codex

5. TestCodexVerbRouting_HelpAfterDashDashIsNotHelp changes shape. The property
   is unchanged -- `--help` after `--` belongs to codex -- but the bare form is

6. TestCodexVerbRouting_ClosedSets is removed; the post-reversal set derivation

   Two copies of the literal sets would be two places to update in step.

7. codex_launcher_readout_test.go / codex_launcher_cross_test.go: readout cells
