MoAI-ADK는 Lilian Weng, Harness Engineering for Self-Improvement(2026-07-04)가 정립한 하네스 엔지니어링 프레임워크를 최대한 승계해 설계됐다 — 루프 엔지니어링·파일 영속 메모리·서브에이전트 3대 디자인 패턴과 Self-Harness 자기 개선 루프를 구현체로 옮겼다. (승계 매핑 보기 ↓)

이 문서는 v3.0.0-rc11 README 재설계 미리보기입니다. 확정 후 README.md에 반영됩니다.

핵심 — 세 가지 기둥

첫 단어 설명: 하네스(harness)는 모델을 둘러싼 실행·운영 계층으로, 에이전트가 안정적으로 일하게 만드는 "작업대"다. MoAI-ADK는 코드를 직접 짜는 대신 이 하네스를 설계합니다.

MoAI-ADK는 세 가지 핵심 원칙으로 AI 개발을 새롭게 정의합니다.

🪙

토크노믹스

더 저렴한 모델에 더 깊은 추론을 결합합니다. CG 모드로 60–70% 비용 절감, 3-tier 정책(max/medium/low), GLM glm-5.2[1m] 1M 컨텍스트.

🔁

재귀적 자가 학습

/goal·/loop가 에이전틱 루프를 돌며 관찰을 축적합니다. 하네스가 학습해 스킬·에이전트 지침을 진화시킵니다.

🤖

에이전틱 하네스

10개 retained 에이전트가 협력합니다. builder-harness가 하네스가 하네스를 만드는 재귀 구조를 제공합니다.

설계 철학 — Lilian Weng Harness Engineering 승계

MoAI-ADK는 Lilian Weng의 Harness Engineering for Self-Improvement(2026-07-04)가 정립한 하네스 엔지니어링 프레임워크를 최대한 승계해 설계됐다. 이 글이 제시한 디자인 패턴과 자기 개선 루프를 그대로 구현체로 옮겼다.

❝

하네스란 — "A harness is the system surrounding a base model that orchestrates execution and decides how the model thinks and plans, calls tools and acts, perceives and manages context, stores artifacts, and evaluates results."

— Lilian Weng, Harness Engineering for Self-Improvement (2026-07-04)

Weng은 RSI(재귀적 자기 개선)의 단기 경로가 "모델이 가중치를 직접 수정하는 것"이 아니라 "훈련 파이프라인과 배포 시스템(하네스)을 개선하는 것"이라고 예측했다. MoAI-ADK는 정확히 이 경로를 취한다 — 모델 가중치가 아니라 하네스(스킬·에이전트 지침)를 재귀적으로 개선합니다.

승계 매핑 — Weng 프레임워크 → MoAI-ADK 구현체

⚠

Weng의 경고를 성실히 반영: "평가자와 권한 컨트롤은 하네스를 진화시키는 루프 밖에 있어야 한다." MoAI-ADK는 하네스 진화(Tier-4 자동업데이트)를 사용자 승인 게이트(Layer 5)로 묶어, 자동 진화가 인간 감시 없이 닫힌 루프를 돌지 않도록 설계했습니다. Self-Harness 논문이 우려한 "reward hacking / 추상 경계 붕괴"에 대한 방어입니다.

참고: Weng은 또한 "재귀 구조만으로는 부족하고 기본 모델이 충분히 capable해야 한다"(STOP 실험 교훈)고 경고합니다. MoAI-ADK는 Claude Code라는 충분히 capable한 기반 위에 하네스를 얹습니다.

🪙 토크노믹스 (Token Economics)

토크노믹스(token-economics)는 토큰(모델이 읽고 쓰는 텍스트 단위)을 돈처럼 관리해, 비용 대비 품질을 극대화하는 설계 철학입니다.

더 저렴한 모델에 더 깊은 추론을 결합합니다. 고가 모델보다 우수한 결과를 약 1/10 가격으로 달성하는 것이 목표입니다.

🔁 재귀적 자가 학습 (에이전틱 루프 엔지니어링)

이것이 MoAI-ADK의 핵심 혁신입니다. 에이전틱 루프 엔지니어링이란, 루프를 돌며 관찰을 축적하고 그 관찰로 하네스가 스스로 진화하는 구조를 설계하는 것입니다.

두 가지 운동으로 구성됩니다: (4.1) 루프 엔지니어링이 관찰을 만들고, (4.2) 재귀적 하네스 진화가 그 관찰로 지침을 업그레이드합니다.

에이전틱 루프 (Agentic Loop) 상세

MoAI-ADK의 에이전틱 루프는 두 가지 핵심 명령어로 구동됩니다. 각각은 재귀적 자가 학습의 다른 측면을 담당합니다.

/goal — 완료 조건 자율 루프

/goal "<조건>"은 세션별 완료 조건을 설정합니다. 조건이 충족될 때까지 턴을 이어가며, status로 상태 확인, clear로 초기화, resume로 재개할 수 있습니다.

  • autonomous(기본): 조건 충족 시 자동으로 다음 턴 진행
  • semi-autonomous: 중요 단계마다 게이트(사용자 승인) 통과
  • 턴 상한: 기본 30턴, stop after N turns로 조정

stop-goal Stop-hook가 매 턴 끝에 조건을 평가합니다. 예시: /goal "모든 테스트가 통과하고 lint가 깨끗할 때까지"

구현: internal/goal/ — SPEC-GOAL-ENGINE-001

/loop — 진단형 자가 수정 루프 (Ralph Engine)

/moai loop는 internal/ralph/engine.go가 구동하는 진단 기반 자가 수정 루프입니다. 병렬 스캔으로 문제를 찾고, 자동 분류로 우선순위를 정하고, 수렴 감지로 완료를 판단합니다.

단계설명
병렬 스캔LSP 진단 + AST-grep + 린터 동시 실행
자동 분류Level 1(자동 수정) ~ Level 4(사용자 개입 필요)
수렴 감지동일 에러 반복 시 대체 전략 시도
완료 조건0 에러, 0 타입 에러, 85%+ 커버리지
 
/moai loop     # 완료 마커 감지까지 반복 (최대 100회)
/moai fix      # 단일 패스 비교

관계: goal vs loop

두 루프는 상호 보완적입니다. goal은 목표 수렴 루프(언제까지), loop는 진단 수정 루프(무엇을). 둘 다 에이전틱 루프 엔지니어링의 핵심이며, 재귀적 하네스 진화의 관찰 원료가 됩니다.

4.1 에이전틱 루프 엔지니어링 — 관찰 축적

루프가 돌며 관찰을 축적하고, 축적된 관찰이 학습의 원료가 됩니다.

/goal 엔진 (SPEC-GOAL-ENGINE-001)

internal/goal/ — 세션별 완료 조건 상태(.moai/state/goal/<session-id>.json), 하이브리드 2-tier Stop-hook 평가자: Tier 1 기계적(종료코드·grep 수·파일 존재·턴 상한), Tier 2 오케스트레이터 자기평가. 턴 상한 기본 30.

# 세션별 완료 조건 설정 — 조건 충족까지 턴을 이어감
/goal "모든 테스트가 통과하고 lint가 깨끗할 때까지"

/loop Ralph Engine

internal/ralph/engine.go — Decide()가 continue/converge/request_review/abort를 우선순위로 반환. 진단 기반 자가 수정 루프.

  1. 병렬 스캔: LSP 진단 + AST-grep + 린터
  2. 자동 분류: Level 1(자동 수정) ~ Level 4(사용자 개입)
  3. 수렴 감지: 동일 에러 반복 시 대체 전략
  4. 완료 조건: 0 에러, 0 타입 에러, 85%+ 커버리지
/moai loop     # 완료 마커 감지까지 반복 (최대 100회)
/moai fix      # 단일 패스

Analyze-First 라우팅 (SPEC-ANALYZE-FIRST-ROUTING-001)

언어 독립적 의도 분석이 /moai 기본 라우팅입니다. cue word는 영어 예시지만, semantic classification은 어떤 언어든 작동합니다.

  1. 의도 분석: 요청의 의도를 분류 (기술 언어 무관)
  2. 컨텍스트 충분성: 불충분 시 Socratic 인터뷰
  3. 실행 계획: 스킬/에이전트/동적 워크플로우 체인 선택
  4. 오케스트레이션 모드: solo-sequential / parallel-subagents / dynamic-workflow

4.2 재귀적 하네스 진화 — 스스로 업그레이드

축적된 관찰을 바탕으로 하네스가 스킬과 에이전트 지침을 스스로 업그레이드합니다. 이것이 "재귀적"의 핵심입니다.

4계층 학습 사다리 ● LIVE

internal/harness/learner.go — confidence floor 0.70. 관찰이 쌓일수록 학습이 자율성을 얻습니다.

왜 모든 Go 코드에 @MX 태그가 없나요?

이것이 정상입니다. @MX 태그는 "필요한 코드에만" 추가됩니다. 대부분의 코드는 충분히 단순·안전해서 태그가 필요 없습니다. 위 @MX 태그 시스템 섹션을 참조하세요.

statusline의 버전 표시는 무엇을 의미하나요?

🗿 v2.2.2 ⬆️ v2.2.5 — v2.2.2는 현재 설치 버전, ⬆️ v2.2.5는 업데이트 가능한 새 버전. 최신이면 버전 번호만 표시합니다. moai update로 갱신.

"하네스가 스스로 진화한다"는 게 이미 작동하나요?

부분적으로. 4-tier 학습 사다리(internal/harness/learner.go)는 이미 live로 관찰을 축적·학습합니다. 완전한 자가 진화를 담당할 Routing Observation Ledger(SPEC-HARNESS-EVOLVE-001)는 현재 구축 중(plan-phase)입니다. 과대 광고 없이 정확한 상태를 표시합니다.
