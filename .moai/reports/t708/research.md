### F1. The gateway mints one envelope per turn from upstream reasoning items and places it in the client-visible response (confidence: HIGH)

`outputEnvelopeWithRaw` (`/Users/goos/MoAI/moai-adk-go/.claude/worktrees/t708/internal/gateway/translate/reasoning.go:41-77`) collects every upstream `type:"reasoning"` item as `opaque.Item{OutputIndex, Raw}`, preserving the raw `output_item.done` payload byte-for-byte (capture at `/Users/goos/MoAI/moai-adk-go/.claude/worktrees/t708/internal/gateway/translate/stream.go:135-144` and `/Users/goos/MoAI/moai-adk-go/.claude/worktrees/t708/internal/gateway/translate/response.go:26-29`). The envelope is serialized as the first content block `{"type":"redacted_thinking","data":"moai_opaque_v1_|v2_<base64url>"}` (`response.go:56-58`), returned in the assistant message (`response.go:115`), and the same message — envelope included — is appended to history and published via `History.Publish` (`response.go:120-128`). Carrier format: `moai_opaque_v1_`/`moai_opaque_v2_` + base64url of the canonical raw envelope JSON (`/Users/goos/MoAI/moai-adk-go/.claude/worktrees/t708/internal/gateway/opaque/codec.go:16-25, 70-79`). ### F3. The four-way binding defines what a replay must carry; Prefix deliberately excludes thinking content (confidence: HIGH)

`Manifest.Check` (`/Users/goos/MoAI/moai-adk-go/.claude/worktrees/t708/internal/gateway/receipt/core.go:99-126`) requires every replayed assistant boundary to match a published candidate on (Prefix, Previous, Opaque, Items) (`Candidate` at core.go:40-48; `valid()` requires Required ⇔ Items>0 ∧ Opaque≠0 at core.go:75-77). The empty fallback (`o.Opaque == Digest{} && o.Items == 0`) is accepted ONLY when no Required candidate exists at that position (`found = empty && !required`, core.go:118-120), with mixed-domain anti-downgrade in `checkObserved` (`/Users/goos/MoAI/moai-adk-go/.claude/worktrees/t708/internal/gateway/translate/receipt_history.go:262-292`, domain separation at 184-195). Publish sets `Required: last.Items > 0` (`receipt_history.go:255`), so every envelope-bearing turn creates a Required candidate — an envelope-less replay at that boundary is structurally unanswerable.

Two structural facts are decisive for every repair design:

1. **Prefix does not cover the envelope.** `CanonicalPrefixes` skips `thinking`/`redacted_thinking` blocks when hashing (`/Users/goos/MoAI/moai-adk-go/.claude/worktrees/t708/internal/gateway/receipt/projection.go:92-93`; doc "It does not authenticate thinking blocks" at projection.go:18-22; public-content chain at 34-67; tool-id canonicalization via `decodeID` at 110-126). Re-injecting an envelope changes neither Prefix nor Previous — it only restores the Opaque/Items observation.
2. **The digest is content-addressed and canonical.** `Digest()` = SHA-256 of the canonical raw bytes (codec.go:80-86); `Decode` rejects any alternate spelling of the same envelope (`bytes.Equal(e.raw, raw)`, codec.go:169-222, equality check at 213-221). Exactly one byte sequence per envelope can ever pass. The surviving `toolu_moai_v1_*` markers self-attest the required digest: `BindToolID` embeds `{call_id, opaque_sha256}` (codec.go:292-304) and `RestoreToolID` refuses any marker whose embedded digest differs from the presented envelope's (codec.go:306-329) — which is precisely why the t703 stripped-but-marker-bearing replay is the observed failure shape.

### F7. Security determination: verbatim launcher-side re-injection of the gateway's OWN previously-issued envelopes SATISFIES the t672 binding rather than bypassing it (confidence: HIGH on the mechanism; two preconditions unmeasured, see gaps)

Why envelope-less acceptance is forbidden: accepting it would require either relaxing the empty fallback against Required candidates or item-level existence checks — t672 explicitly rejected both on security grounds ("item-level existence checks … would accept intra-session transplant and reordering — a real weakening", `/Users/goos/MoAI/moai-adk-go/.claude/worktrees/t708/.moai/reports/t672/investigation.md` §2 Candidate A; Candidate B rejected request-driven seeding; §2 Desync: "A safe gateway-side re-root does NOT exist: the client transcript is the authority for history content, so any gateway-initiated re-root would have to trust a client-declared truncation — the same loosening rejected above"). It would also be untranslatable — the forward path cannot restore tool ids or re-inject upstream reasoning without the envelope (`request.go:359-365`).

Why re-injection is different: because Prefix excludes thinking content (F3.1) and the digest is canonical (F3.2), re-injecting the exact issued `data` string at its original boundary reconstructs exactly the observation tuple the gateway already authorized (Opaque = digest of identical bytes, Items = identical count, Prefix/Previous untouched) and passes the UNCHANGED validator — no relaxation, no synthesis. The surviving tool markers make the repair provable before injection: each orphaned marker discloses the exact 64-hex digest required, so the repair can verify `sha256(candidate_raw) == marker.opaque_sha256 == published candidate.Opaque`. Worst-case abuse is bounded by the binding itself: a cross-boundary transplant fails Opaque equality, any reordering or public-content edit fails Prefix/Previous — verbatim re-injection's worst outcome is exact reconstruction of already-published boundaries. Conditions a compliant repair must meet: (1) byte-exact envelope; (2) position exactness (only where a Required candidate exists at that Prefix/Previous); (3) no public-content edit rides along; (4) launcher-driven, never request-driven ("NewReceiptHistory accepts only a launcher-authorized UUID and private store. Request metadata never selects a receipt root or authorizes a conversation", `receipt_history.go:84-95`). Residual risk on the preconditions: whether the client's switch-turn re-encode altered ONLY envelopes or also public content is unmeasured (t703 could not capture the failing request body, `verdict.md:94`); if public content changed, re-injection alone still fails at the Prefix site.
