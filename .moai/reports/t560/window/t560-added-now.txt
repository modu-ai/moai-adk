+- **Hook-layer git-environment leak sweep** ([#1691](https://github.com/modu-ai/moai-adk/issues/1691), card t560, follow-up to card t516) — git exports `GIT_DIR` and `GIT_INDEX_FILE` into every hook it runs, and **those outrank the working directory**, so neither `cmd.Dir` nor `git -C <dir>` confines a child process: it resolves through the caller's git context instead of the directory it was given. Card t516 closed this at `runStep` in `internal/hook/quality/gate.go`; it did not close **the sibling call one screen away in the same file and the same process**. `stagedFiles` read the *caller's* staged set, so under a pre-commit hook the quality gate chose which steps to run from another repository's state — silently, because neither branch errors. The scrub list has moved to the new `internal/gitenv` package precisely because a repair confined to one package could not reach its siblings; `internal/hook/quality` now delegates to it, and t516's existing tests bind unchanged, which is what makes the move readable as a move.
+  - **Scrubbed (6 sites)**: `quality/gate.go` `stagedFiles`, `agentmemory.go` `gitOutput`, `navigator_detect.go` `changedAtForProject`, `session_end.go` `getModifiedGoFiles`, `security/guardian.go` `runGit`, `worktree_create.go` `resolveWorktreeRepoRoot`. Scope stays narrow: only repository **location** is removed. Identity (`GIT_AUTHOR_*`, `GIT_COMMITTER_*`) and behaviour (`GIT_EDITOR`, `GIT_CONFIG_GLOBAL`, …) reach the child, because a child stripped of its identity fails for an unrelated reason and one stripped of its behaviour settings does something different rather than doing it somewhere different.
+  - **Reachability is stated, not implied**: only `stagedFiles` is confirmed reachable from a git-hook environment (the pre-commit hook shells out to `moai gate`). The other five have Claude Code as their parent, which does not export `GIT_DIR` — their change **closes a leak surface and does not repair an observed incident**, and is not claimed as one.
+  - **Deliberately NOT scrubbed (5 sites)**: `worktree_base_branch.go`. Its discriminant compares `git rev-parse --git-dir` against `--git-common-dir` to decide whether this is the primary checkout, so removing `GIT_DIR` would change its answer — scrubbing there would *be* the defect rather than fix one. The file is unchanged and pinned by `worktree_base_branch_ambient_env_test.go`, which asserts the two `GIT_DIR` cases must **differ**; under a mutation that adds the scrub they collapse to the same answer and the test fails, so the guard was shown to fail rather than merely to exist.
+  - **Reported, not repaired (1 site)**: `quality/tool_registry.go` `RunTool` is defect-shaped — arbitrary child, `cmd.Dir` set, `cmd.Env` nil — but its only callers are `Formatter` and `Linter`, which have no non-test constructor outside the package (control: `runStep` 8 hits vs those constructors 0 hits outside the package). Repairing dead code produces a change no test can verify.
+  - **Defect 1 of #1691 (`core.bare` flips to `true`) is now VERIFIED**, where t516 recorded it as unreproduced. That earlier non-reproduction was correct as an observation and too weak as a conclusion: its model used a host repository with **no linked worktree**, so `GIT_DIR` named a plain `.git`. Measured on git 2.50.1 (Apple Git-155), a child `git init` flips the host's `core.bare` **only** when `GIT_DIR` names a per-worktree gitdir (`<host>/.git/worktrees/<wt>`); the shared gitdir and `GIT_INDEX_FILE` alone do not. The key lands in `<host>/.git/config`, which every linked worktree shares, so one test fixture makes the whole repository fail with `fatal: this operation must be run in a work tree`. Reproduced through production code by mutating away the t516 scrub (`core.bare: "false" before, "true" after`), and the discriminator itself is pinned as a test so a future git that changes this fails loudly instead of hollowing the guard out. **"Did not reproduce" and "the firing shape has not been measured yet" produce the same output.**
