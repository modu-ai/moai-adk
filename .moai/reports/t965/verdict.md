## Evidence

### 복귀 지점 (관측 4건)

전량 `observations.md` 에. 요지: 단일 진입(대조군) → A · 연쇄 `A→B→C` → **A**(B 아님, 두 경로
문자열이 달라 판별력 있음) · 같은 Exit 응답이 C 를 「보존됨」으로 지목하면서 A 로 복귀 · **세션이
워크트리 안에서 시작한 경우에도** 출발 디렉터리가 아니라 primary 로 복귀.

네 번째가 제3의 답을 만든다 — 복귀 지점이 연쇄 깊이와도 세션 출발 디렉터리와도 무관하다.
그 결과 상위 설명의 "where it was before `EnterWorktree`" 는 **모호한 것이 아니라 거짓으로**
읽힌다.

### 소유권 (주장 4) — 부재를 측정으로

```
grep -rl "Restores the session's working directory" .   → 적중 1 (내가 방금 쓴 SPEC, 인용)
grep -rln 'Exit a worktree session created by EnterWorktree' .  → 0
```
문안이 런타임 소유이고 저장소에 없다. **고칠 수 없음이 결과**이고, 산출물은 이 저장소의 규칙
문서(`worktree-integration.md`, 그 무수식 문장을 직접 읽어 확인)로 돌렸다.

### SPEC 0.2.0 이 만족 불가였다 (주장 5)

대상 파일이 바이트 동일성 허용목록(`internal/template/rule_template_mirror_test.go`,
측정 시점 57행)에 등재돼 있고 SPEC 은 그 가드를 한 번도 이름 대지 않았다. 세 가드가 덫을 이룬다:

iter-1 의 D1 수리가 날짜를 피하려 비대칭을 택했고, 그 비대칭이 다른 가드에 걸렸다 — 결함이

### 경로 A 의 목표 상태가 실재한다 (주장 6) — 존재 증명

「없다」를 증명한 자리이므로 「있다」는 **보이는 것 말고 방법이 없다.** 목표 상태를 실제로 만들어
측정했다 — 두 사본에 **동일한** 버전 귀속 한 줄(날짜·내부 경로·SPEC ID 없음), `cmp -s` 로 바이트
동일 확인 후:

| 가드 | 결과 |
|---|---|
| `TestRuleTemplateMirrorDrift` | ok |
| 누출 가드 default 티어 | ok |
| 누출 가드 strict 티어 (`MOAI_TEMPLATE_LEAK_STRICT=1`) | ok |
| `TestTemplateNeutralityAudit` | ok |

**음성 대조** — 초록이 가드 고장이 아님을 가른다. 두 사본에 **동일하게** SPEC ID 를 심으니
`[1] templates/.claude/rules/moai/workflow/worktree-integration.md | class=C1-spec-id-prefix | match=SPEC-WORKTREE-EXIT-RETURN-001` → FAIL.

프로브 전량 제거 후 `git status --porcelain` 에 규칙·템플릿 파일 **0건**. 시뮬레이션은 트리에
남지 않았고, 커밋에 실린 것은 SPEC 산출물 4개뿐이다.

### 선례가 경로 A 를 정당화한다

`63ff0953…`), 미러 237행에 `Measured on Claude Code 2.1.276` 를 싣고 날짜 리터럴 0건으로 전 티어

논거: 이 주장은 달력이 아니라 **런타임 버전 축으로 늙는다.** 사용자 프로젝트 독자는
