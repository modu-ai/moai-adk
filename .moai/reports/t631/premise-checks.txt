170:## Background Agent Execution
171-
172-[ZONE:Evolvable] [HARD] Since Claude Code v2.1.198 subagents run in the background by **default**;
173-the runtime chooses foreground only when it needs the result. The default changes *where* a
174-subagent runs, not *what* it may do — a background subagent still surfaces every permission prompt
175-in the main session. MoAI aligns with the default and does not set the `background:` frontmatter
176-field.
177-
178-The retained safeguard is **concurrency, not backgrounding**, because the actual hazard is a
179-file-write race: never run two write-capable agents at once, and keep orchestrator work concurrent
180-with a write-capable agent read-only. Read-only tasks are safe in the background while the
181-orchestrator continues other read-only work; for write tasks, let the runtime choose the mode rather
182-than forcing it. Pre-approved write paths in settings.json `permissions.allow` reduce prompts.
183-Runtime-history rationale: `agent-common-protocol-reference.md` § Background Agent Execution
184-rationale.
185-
186-[ZONE:Evolvable] [HARD] **While a worktree is being actively audited, it has exactly one writer.**
