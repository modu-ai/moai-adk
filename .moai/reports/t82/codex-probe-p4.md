# t82 — P4 실측: `project_doc_max_bytes` 의 설정 스코프

리드의 측정 힌트에 따른 후속 실측. 같은 픽스처·같은 수단(`codex debug prompt-input`, 모델 호출 0회),
codex-cli 0.147.0. 사용자 실환경을 건드리지 않기 위해 `CODEX_HOME` 로 가짜 홈을 물려 측정했다
(`~/.codex/config.toml` 원본 미수정).

## 판정

**프로젝트 스코프 설정은 가능하다 — 단, 그 프로젝트가 사용자 config 에서 `trusted` 일 때만.**
신뢰되지 않은 프로젝트의 `.codex/config.toml` 은 **조용히 무시**된다.

## 4회 차동 측정

눈금 마커의 마지막 통과 오프셋으로 실효 한도를 읽는다.

| # | 사용자 config (`$CODEX_HOME/config.toml`) | 프로젝트 trust | 프로젝트 `<repo>/.codex/config.toml` | 마지막 마커 | 실효 한도 |
|---|---|---|---|---|---|
| 1 | 없음 | 미등록 | `4096` | `MARK32670` | **32,768 (기본값 — 프로젝트 파일 무시)** |
| 2 | `4096` | 미등록 | 없음 | `MARK04070` | 4,096 (사용자 config 반영) |
| 3 | `4096` | 미등록 | `8192` | `MARK04070` | 4,096 (**프로젝트 파일 무시**) |
| 4 | `4096` | `trust_level = "trusted"` | `8192` | `MARK08140` | **8,192 (프로젝트가 사용자 값을 이김)** |

3 → 4 는 프로젝트 config 파일을 그대로 둔 채 사용자 config 의 신뢰 항목만 넣고 뺀 차동이다.
따라서 판별자는 파일의 존재나 위치가 아니라 **신뢰 등록**이다.

신뢰 등록 형식(사용자 config):

```toml
[projects."/abs/path/to/repo"]
trust_level = "trusted"
```

네 번 모두 stderr 0 바이트. **무시도 무음이다** — §3(잘림 무음)과 같은 성질이며, 사용자는
"한도를 올렸는데 안 올라갔다"는 신호를 받지 못한다.

## 설계 귀결

카드·t91 이 모두 누락했던 P4 의 답은 **양자택일이 아니라 조건부**였다. 세 갈래로 갈린다.

1. **다이어트는 여전히 전량 부담을 진다 — 신뢰 이전 상태가 기본값이기 때문.**
   배포 사용자가 리포를 처음 받아 codex 를 띄우는 순간에는 프로젝트가 아직 신뢰되지 않았고,
   그때 실효 한도는 32,768 이다. 즉 **첫 세션에서 계약이 잘리면 안 된다**는 제약은 그대로다.
   한도 상향은 "이미 신뢰한 사용자에게만 사후적으로 주어지는 여유"이지 설계 전제가 될 수 없다.

2. **M4(t88 배선 생성기)에게는 실재하는 레버다 — 단 조건 고지 의무가 붙는다.**
   `moai init --agent codex` 가 `<repo>/.codex/config.toml` 에 한도를 배출하는 것은 유효하다.
   그러나 그 값은 신뢰 등록 전까지 작동하지 않으므로, 생성기는 **한도만 배출하고 끝내면 안 된다** —
   신뢰가 필요하다는 사실을 사용자에게 알리거나, `moai doctor` 가 "프로젝트 config 는 있는데
   신뢰 등록이 없어 한도가 미적용" 상태를 능동 점검해야 한다. 무음 무시라 그 점검이 유일한 탐지 수단이다.

3. **한도 상향을 다이어트의 대체재로 쓰는 설계는 금지된다.**
   1·2 를 합치면 상향은 조건부·사후적·무음실패 가능이다. SPEC 의 감축 목표는 32,768 기준으로 잡히고,
   상향은 그 위에 얹는 여유로만 취급한다.

## 미검증 / 잔여

- 신뢰 등록이 대화형 첫 실행에서 자동으로 제안·기록되는지는 확인하지 않았다
  (`codex debug prompt-input` 는 대화형 신뢰 프롬프트를 띄우지 않는다). 배포 사용자의 실제 신뢰 획득
  경로는 M4 설계 시 별도 확인이 필요하다.
- `trust_level` 의 다른 값(`untrusted` 등)에서의 동작은 측정하지 않았다. 측정한 것은
  "항목 있음(trusted)" 대 "항목 없음" 두 상태다.
- macOS + codex-cli 0.147.0 단일 환경. 다른 OS·버전에서 동일하다고 가정하지 않는다.
