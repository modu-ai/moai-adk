## Baseline-attribution

- 모든 gateway 시각은 위 debug file의 UTC timestamp에 귀속한다.
- 작업 트리 기준은 `WT-graph-stamp-freshness`의 `7097e6e21`이다.
- 오류 관측은 build `7a7a08f20` 확인 이후의 동일 lane 실행에 귀속한다.
- 첫 번째 실패 agent는 `ac2635d4a5498d714`, 새 대화 실패 agent는 `aa27311929d5450ae`이다.

## Gaps

- 이 기록만으로 receipt-chain 불일치의 하위 원인(모델 family 선택, gateway receipt 저장, 자동 요약 fork 중 어느 계층인지)은 판정하지 않았다.
- process registry 전체를 별도 수집해 외부 세션의 fork 겹침을 증명하지는 않았다. 이 lane의 orchestrator dispatch 기록과 gateway debug에서 확인되는 범위만 기록했다.
- 두 번째 시도의 `plan.md`와 `acceptance.md`는 생성되었지만 plan-auditor 검토, 전용 SPEC lint, commit, `progress.md §E.1` 완료는 아직 관측하지 않았다.
- 이 보고서는 두 번째 새 대화가 종료된 뒤 작성되었으므로, 새 대화 재시도 **이전**에 보고서를 남기라는 운영 순서를 시간상 충족하지 못했다. 동시 writer 충돌을 피하기 위해 종료 후 기록했다.

## Residual-risk

- 같은 gateway family에서 동일 400이 반복되었고, 새 대화 중 502도 연속 관측되었으므로 다음 manager-agent 호출도 계획 단계 중간 종료될 수 있다.
- 미커밋 SPEC artifact가 현재 worktree에만 존재한다. plan-auditor와 commit이 완료되기 전에는 이 카드의 plan-phase가 audit-ready라고 볼 수 없다.
- `AgentSummary` 내부 fork와 receipt-chain 오류의 인과관계는 확인되지 않았으므로, 이 기록은 상관관계를 원인으로 승격하지 않는다.
