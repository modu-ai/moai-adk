본 설계는 moai-adk-go 저장소에서 자가 진화 루프가 스스로 돌아가도록 만들면서, 배포되는 moai 자산에는 한 줄도 손대지 않는 것을 목표로 한다. 사전 감사가 증명했듯 관측 절반은 이미 대규모로 동작한다. usage-log 11만 이벤트, lessons-inbox 569건, tier-promotions 159행이 살아 있다. 그러나 자가 학습을 선언한 모든 루프는 같은 한 지점에서 끊긴다. 제안에서 적용으로 넘어가는 경계(PROPOSE→APPLY)다. Go로 짠 Applier.Apply는 한 번도 실행된 적 없고 manifest.jsonl은 존재하지 않는다. CuratorDispatch는 프로덕션 호출자가 0명이며, 드레인은 헌법(constitution) 문단으로만 존재하고 Go 코드는 0건이다. 결과적으로 실제 개선은 모델이 중개한다 — 에이전트가 SPEC 작업 중 doctrine을 읽고 feedback_*.md를 손으로 옮기는 식이다. 기계적 피드백 신호에서 나온 것이 아니다.

본 설계는 이 경계를 사용자 소유 영역 안에서만 닫는다. 핵심은 동결된 Go applier를 우회하는 병렬 사용자 소유 applier를 세우는 것이다. 동결된 applier를 켜면 @MX 주석이 배포용 에이전트 서피스로 주입되어 doctrine 훼손이 된다. 그래서 켜지 않고 우회한다. 루프는 여섯 진화 가능 영역에만 쓴다.

이 설계는 다섯 연구 렌즈에 근거한다. ExpeL·Voyager·Generative-Agents·Reflexion의 2단계 메모리, Constitutional AI와 MemGPT의 안전 자기 수정, Thompson sampling의 개인화가 그것이다. 두 차례 적대적 비평은 같은 치명적 결함을 찾아냈다 — 동결 영역 허용 목록(allowlist) 정규식이 진화 가능한 git 추적 스킬 파일 안에 들어 있어서, 루프가 자기 수갑을 스스로 풀 수 있었다는 점이다. 종합된 설계(본 제안)는 허용 목록을 동결 메타 파일로 옮기고, 강제 게이트 대상에 집행 메타 파일을 추가하며, 루프가 실제로 발화하도록 기계적 트리거를 단다. 그리고 이 설계가 닫는 것은 사용자 로컬 루프이지, 감사가 지적한 배포 서피스 경로가 아님을 솔직히 밝힌다.

02문제: 관측은 대규모로, 적용 경계는 죽어 있다

이 설계의 출발점은 앞선 감사의 증거 기반 발견이다. 모든 선언된 자가 학습 루프가 동일한 한 지점 — PROPOSE→APPLY seam —에서 끊긴다.

감사 핵심 발견 (관측 vs 적용)

  • Applier.Apply 한 번도 실행 안 됨 — manifest.jsonl 부재, snapshots/ 빔. 유일한 프로덕션 호출자는 opt-in moai harness execute인데 호출된 적 없음.
  • CuratorDispatch 프로덕션 호출자 0 — 72개 draft가 어디로도 가지 않음. 자기 헤더가 "INERT 상태를 구동하는 caller"라고 선언하지만 grep 하면 본인+테스트뿐.
  • drain = constitution 문단, Go 코드 0건 — moai-constitution.md:147이 언급하는 "drain-marking mechanism"은 전 리포 grep 0 hits.
  • lessons-inbox 554~569 stubs / 25일 / ZERO drained — 파일에 닿는 비테스트 Go 코드는 writer(failure_observer.go:129) 단 하나.
  • inbox 노이즈 과점 — 약 63%가 tool_failure:Bash:UnknownFailure (타임아웃·샌드박스 위반 노이즈).
  • delegation.yaml 재귀 분석 = 문장뿐 — CLAUDE.md §4가 선언하지만 이 파일을 쓰는 코드 0건. 매 변경이 사람 손편집.
  • 실제 개선은 model-mediated — 에이전트가 SPEC 작업 중 doctrine에서 feedback_*.md·@MX 태그를 손으로 옮김. 기계적 신호가 아님.
  • 근원 — observation-first 빌드; 적용 닫기는 명시적으로 연기됨(applier.go:22 enableTriggerInjectionWrites=false + @MX:TODO "Phase 4").

요약하면 관측 절반은 살아 있고, 적용 절반은 코드가 있어도 한 번도 실행된 적 없다. 본 설계의 임무는 이 끊긴 seam을, moai doctrine은 절대 수정하지 않으면서, 기계적으로 닫는 것이다.

03연구 근거 (논문·베스트 프랙티스 5개 렌즈)

웹 조사로 5개 렌즈에서 논문과 실무 베스트 프랙티스를 수집했다. 각 렌즈의 핵심 통찰과 MoAI 적용점을 아래에 정리한다.

Lens 1 · 학술 — 경험적 학습·자기 개선 LLM 에이전트

비모수적 루프 골격(ACT→OBSERVE→REFLECT→STORE→RETRIEVE)이 Reflexion·ExpeL·Voyager·Generative Agents에서 동일하다. 구조적 교훈 두 가지: (1) 2단계 저장 분리 — 원시 에피소드 추적(Tier 1, bounded, recency 가중) vs 정제된 교차-작업 통찰/스킬(Tier 2, 정제·재사용). 이것이 MoAI의 lessons-inbox(Tier 1) vs feedback_*.md(Tier 2)에 그대로 대응한다. (2) 검색(retrieval)이 모든 논문의 병목이며, 지배적 실패 양상도 공유된다 — 비정제 축적→노이즈→잘못된 교훈 검색→에이전트가 잘못된 자기 진단으로 재행동. Voyager는 실행 가능한 코드를 재사용 산출물로 저장하며 합성성(스킬이 스킬을 호출)을 갖는다 — 사용자 소유 hns-* 스킬 서피스로 가장 직접 이식 가능한 패턴. 모든 in-context 방식이 모수 갱신을 피한다(ExpeL이 명시). MoAI도 같은 제약 아래 있으므로 자가 개선은 반드시 프롬프트 시점/in-context여야 하며, 파인튜닝이 아니다.

Lens 2 · 실무 — 코딩 에이전트 자기 개선

모든 주요 코딩 에이전트가 같은 2단계 메모리 형태로 수렴한다: 손으로 저술된 항상 로드되는 짧은 지시 파일(CLAUDE.md / AGENTS.md / .cursorrules / .clinerules) + 학습·축적된 주제 파일 색인 저장(필요시 검색). MoAI의 쌍(CLAUDE.local.md + memory/MEMORY.md + feedback_*.md)은 이미 이 형태다 — 격차는 발화 규율이지 아키텍처가 아니다. 이식 가능한 규칙 3가지: (1) 캡처는 싸고 진짜 어려운 건 사람 게이트 + 위생(CodeRabbit의 명시적 영수증 + approval_delay + 분기별 "축적 대신 갱신" 스윕); (2) 결정적 훅(hook) > 자연어 규칙 — 고정된 생명주기 지점에서 일어나야 하는 행동은 규칙(무시 가능)이 아니라 훅(무조건 실행)으로; (3) 규칙 파일 자기편집은 위험한 방향 — 에이전트가 저술한 학습은 별도의 학습 저장소로, 사람 게이트 아래로, 결코 규칙 파일에 조용히 되돌려 쓰지 않는다.

Lens 3 · 메모리 아키텍처 — 장기 horizon 에이전트

메모리는 모든 진지한 설계에서 계층 시스템이다: 작은 용량 제한 hot tier(MemGPT core memory, MoAI ≤50 active feedback_*.md) 뒤에 큰 cold tier(MemGPT archival, MoAI memory/_archive/). 검색은 lookup이 아니라 점수 함수다 — Generative Agents의 recency×importance×relevance 공식이 정규 형태. 정제(consolidation)는 별도 정책 층(Vectorize의 4개 레버: importance-gate / merge / decay / evict)이지 부수작이 아니다. 성찰(reflection)은 시계가 아니라 임계치 발화(누적 중요도 ~150). 실패가 최고 신호 쓰기 트리거(Reflexion). 결정적으로: 중요도는 쓰기 시점에 게이트로 할당되며, 축출 ≠ 보관 — 보관은 성능용, 하드 삭제는 규정 준수용. MoAI의 "삭제 말고 보관" 규칙이 옳음이 입증된다; 50-파일 한도는 축출 대상이 아니라 계층화 임계값이다.

Lens 4 · 안전한 자기 수정 — 가드레일

보편적 안전 자기편집 형태는 단일 가드가 아니라 파이프라인이다: PROPOSE(격리된 shadow) → SELF-CRITIQUE(고정 헌법 대비) → MECHANICAL VERIFY(환경이 진리) → APPROVE(사람, tier-gated) → PROMOTE(명시적 병합, 불변 버전) → MONITOR → ROLLBACK. 단일 하중 구조 속성은 CAI의 것이다: 헌법은 쓰기 영역 밖에 있어야 한다 — 모델은 산출물을 수정하지 원칙을 수정하지 않는다; 루프가 자신을 검사하는 규칙을 편집할 수 있으면 비판은 공허해진다. 가역성이 감시 무게를 라우팅하는 마스터 축이다(비가역→동기 승인; 가역→비동기 감시/카나리). 따라서 모든 편집을 가역-by-구조로 만들면(git 버전 관리, 불변 ID, doctrine과 분리) 대부분의 자기편집이 동기 게이트에서 카나리로 강등된다. 능력/임계치 조건부 게이팅(CSA if-then)이 평면 신뢰도 임계값보다 낫다.

Lens 5 · 개인화 — 로컬 적응형 설정

세 피드백 채널을 가차별 가중해야 한다: 수동/비의도적 암시(도구 승인 클릭)는 풍부하지만 약하다; 의도적 암시(Ctrl+G 계획 편집, 'Other' 자유형 덮어쓰기, 추천 거부)는 드물지만 강하다 — posterior 가중 5~10배. 신뢰도는 호환되는 세 방식(Thompson sampling 베이지안 사후 분산; 선호별 LLM-판사 강도 점수; 기대-후회-감소 vs bother-cost 임계값)으로 추적되며, 견고한 시스템은 세 가지 모두 쓴다. 콜드 스타트는 보편적으로 동일하게 풀린다: 모집단/템플릿 기본값으로 폴백, 관측이 쌓일 때만 개인 모델로 이동 — 작은 관측 예산이 존재하기 전에는 개인화하지 않는다. 묻기-vs-추론 결정은 정보가치 문제이며, c는 컨텍스트 크기 + warm-cache 가치와 함께 올라야 한다(cache-aware-execution directive 1과 통합). 추천이 매 세션 뒤집히는 것("UI thrashing")은 신뢰를 갉아먹으므로 히스테리시스가 일급 요구사항이다.

04설계 원칙: 고정 헌법, 사용자 소유 닫기

루프는 일곱 단계로 된다. OBSERVE는 이미 돌아가는 훅을 그대로 쓰되 의도적 암시 신호를 signals.jsonl에 추가로 담는다. 의도적 암시란 Ctrl+G 계획 편집, AskUserQuestion 'Other' 덮어쓰기, 추천 거부 같은 사용자의 의도적 행위로, 수동 승인보다 5~10배 높은 가중치를 받는다. CLUSTER는 lessons-inbox를 동반 오프셋(companion offset) 방식으로 드레인해 25일치 백로그를 후보 주제 파일로 바꾼다. 단 드레인 전에 기계적 심각도 필터가 Bash 타임아웃과 샌드박스 위반 노이즈를 거른다. 그래야 569건 중 약 63%를 차지하는 노이즈가 교훈으로 둔갑하지 않는다.

PROPOSE는 동결 doctrine에 대한 Constitutional AI식 자기 비판을 동반한 그림자 제안을 만든다. 제안을 쓰기 전에 관련 feedback_*.md를 먼저 검색하는 것도 잊지 않는다. APPROVE는 기존 AskUserQuestion Tier-4 흐름에 영향 반경 기준 에스컬레이션을 더한다. INVARANTS 커널, 보안 검증 예외 구간, 고정산입(high-fan-in) 참조, Bash 위험 경로, 그리고 허용 목록·applier·curator 스킬 본문·훅 스크립트 같은 집행 메타 파일까지는 제안자 신뢰도와 무관하게 사람 승인을 강제한다. APPLY가 진짜 경계 닫기다. 사용자 소유 applier가 동결 영역 허용 목록으로 검증된 경로에만 쓴다. 허용 목록 자체는 진화 가능 영역 밖 동결 메타 파일에 둬서 루프가 스스로 고칠 수 없게 한다. 적용마다 lsel-<proposal-id> 태그가 붙은 git 커밋이므로 되돌리기는 git revert 한 줄이다. REMEMBER는 feedback_*.md를 자동 메모리에 써서 /clear 너머로 기억한다. VERIFY는 /moai gate 의무 상위 집합을 돌려 통과 못 하면 되돌린다. 단 타임아웃 같은 불안정 신호에는 한 번 재시도해서, 옳은 제안이 노이즈에 의해 잘못 뒤집히지 않게 한다.

핵심 불변량 — 허용 목록은 진화 가능 영역 밖에 존재한다

비평이 지적한 대로 허용 목록이 hns-lsel-applier/SKILL.md 안에 있으면, 제안 A가 정규식을 넓히고 제안 B가 doctrine을 쓰는 경로가 열린다. 그래서 허용 목록은 동결 메타 파일로 옮기고, 집행 메타 파일은 영향 반경 기준 강제 게이트 목록에 넣어 사람 승인 없이는 고칠 수 없게 한다. 루프가 발화하는 것도 기계적으로 만든다 — SessionStart 훅이 백로그 재고 임계치를 넘기면 시스템 알림을 띄우고, 예정된 /loop 레시피는 기본으로 켠다. 사람이 호출할 때만 도는 구조는 감사가 지적한 "기능은 있으나 호출되지 않는다"는 실패를 그대로 되풀이하기 때문이다.

도구

서피스

3

생존한 군집(또는 사후가 수축한 설정/개인화 신호)마다 PROPOSAL 페이로드를 초안한다: {proposal_id, target_surface ∈ 6 evolvable, diff.patch, rationale, WHY-not-just-WHAT, prediction(반증 가능 기대 효과), verify_command, blast_radius, memory_type: semantic|procedural|episodic}. 결정적으로 제안자는 초안 전에 관련 feedback_*.md를 먼저 검색하고(Reflexion), 동결 doctrine 대비 CAI식 자기 비판을 내보낸다. 자기 비판이 깨끗해질 때까지 제안은 막힌다. 이것이 CuratorDispatch.Prepare()가 비계만 짓고 연결하지 않은, 빠진 PROPOSE다.

서피스
.moai/state/lsel/proposals/<proposal-id>/{proposal.md, diff.patch, self-critique.md} — shadow 파일만, 라이브 config 절대 아님. LangWatch dev→staging→prod 격리 반영.
도구
hns-lsel-curator 스킬 + 초안용 Agent(general-purpose) + 검색된 메모리 컨텍스트. 동결 CuratorDispatch.Prepare()는 참조 전용, 절대 호출 안 함.

오케스트레이터가 대기 중 제안을 기존 AskUserQuestion Tier-4 harness-학습 흐름으로 표시. 능력 조건부 에스컬레이션(CSA if-then): CLAUDE.local.md INVARANTS 커널, 보안/검증 예외 구간, HIGH-fan-in 참조, Bash 위험 경로, 집행 메타 파일(allowlist·applier/curator 스킬 본문·훅 스크립트·settings.local.json 훅 등록 서브블록)을 건드리는 제안은 제안자 신뢰도와 무관하게 동기 AskUserQuestion 강제. 루틴 memory//feedback/permissions.allow 편집은 가벼운 카나리 경로. 각 승인 라운드는 사용자 응답에 CodeRabbit식 "Learnings Added" 영수증을 싣는다. bother-cost 정지 규칙: 기대 후회 감소 > 중단 비용일 때만 묻되, 강제 게이트는 bother-cost 면제.

서피스
AskUserQuestion(오케스트레이터 채널 독점) + .moai/state/lsel/proposals/<id>/decision.json(승인/거부/연기 + 사유의 내구성 기록).

기존 moai-harness-learner 스킬 + askuser-protocol별 ToolSearch preload. 새 승인 메커니즘 없음 — 기존 것 재사용.
5

PR 의무 체제(§23)에 맞춰 feature 브랜치 + PR(Tier S 셀프 머지).

서피스
오직 6 evolvable 서피스(allowlist 강제). manifest는 .moai/state/lsel/apply-ledger.jsonl에 기록 — 동결 applier가 만들지 못한 manifest가 마침내 실재(사용자 소유 영역에서).
도구
hns-lsel-applier 스킬(APPROVE 후 오케스트레이터 호출) + allowlist 가드. branch_guard.go의 경로-allowlist + 예외 패턴을 아키텍처 참조로(모양만 재사용, 코드 아님).
6

적용된 모든 제안은 feedback_*.md 주제 파일(category + 잘못된 패턴 + 올바른 접근 + WHY + surface 태그 + prediction + verified:pending)과 MEMORY.md 색인 한 줄을 쓴다 — Self-Refine에는 없고 ExpeL이 하중이라 증명한 교차-세션 저장. 거부/되돌려진 제안도 verified:false 교훈을 쓴다(제안자가 같은 편집 부류를 재시도하지 않게). memory_type 라벨(CoALA)이 절차적 교훈은 hns-* 스킬로, 의미론적 사실은 feedback_*.md로 라우팅. 무장된 제안은 (재사용하는) handoff/pending.json을 타서 /clear 도중에도 다음 세션에서 이어진다.

서피스
memory/feedback_*.md + MEMORY.md 색인 + memory/_archive/(cold tier, 삭제 불가) + .moai/state/handoff/pending.json(재사용).
도구
Claude Code 네이티브 auto-memory + hns-lsel-applier가 최종 apply 단계로 주제 파일 작성. MemGPT식 promote-on-retrieval-hit 페이징.
7

VERIFY — 검증

적용 후 제안의 verify_command + 의무 /moai gate 상위집합(lint+format+type+test)을 실행. 증거는 기존 verification-batch 계약대로 .moai/state/verify/<session>/에 지속(요약이 아니라 verbatim 출력 — verification-claim-integrity §2 귀속). 검증이 실패하면 git revert lsel-<proposal-id>로 자동 되돌리고, 제안의 feedback_*.md는 verified:false 표시되며 거부는 Reflexion 교훈이 된다. 타임아웃 같은 불안정 신호에는 한 번 재시도하고 두 번째 비-타임아웃 실패에서만 되돌린다. 느린 주기로 임계치가 쌓이면(시계 아님) 세부 주제 파일 여러 개에서 추상 원칙 주제 파일 하나를 합성하고 원본은 cold tier로 내리는 정기 REFLECTION 패스.

서피스
.moai/state/verify/<session>/(증거) + apply-ledger.jsonl(결과 행: applied→verified|reverted) + memory/(verified 태그 갱신 + reflection 합성 원칙 파일).
도구
/moai gate + verification-batch 단일 턴 패턴 + go test -run <pattern>. reflection 패스는 월간 /loop 레시피 또는 /moai:harness lsel reflect.

07가드레일 (강화된 불변량)

두 차례 적대적 비평이 v1 설계의 치명적 결함(self-amending allowlist 등)을 찾아낸 뒤 강화된 불변량 집합이다.

  • 동결 영역 허용 목록 (핵심 불변량, CAI 고정 헌법의 구조화) — applier는 모든 쓰기 대상을 6 evolvable 서피스 경로 패턴에만 매칭하는 positive allowlist 정규식으로 검증. 그 외 경로( .claude/rules/moai/**, CLAUDE.md, internal/template/templates/**, retained agents, moai-* skills, .moai/config/sections/** 전부)는 hard reject되고 .moai/logs/lsel-reject.log에 기록. "doctrine 절대 안 건드림"은 열망이 아니라 경로-메커니즘 보장. 허용 목록 자체는 6 evolvable 영역 밖 동결 메타 파일에 존재(루프가 자기 수갑을 못 풀게).
  • 네임스페이스 분리 (§24) — 모든 신규 산출물은 hns-* / .claude/agents/harness/ / .moai/state/lsel/ 아래. 로컬 CI 테스트(split_namespace_test.go + internal_content_leak_test.go 미러)가 internal/template/templates/로의 leak을 단언.
  • 동결 Go applier는 동결된 채로 — enableTriggerInjectionWrites는 false로 잔존. 루프는 병렬 사용자 소유 applier로 우회. 감사가 증명한 끊긴 seam은 unfreeze가 아니라 bypass로 닫는다.
  • 불변 버전 ID + 즉시 롤백 (LangWatch) — 적용마다 lsel-<proposal-id> 태그 git 커밋. 롤백은 git revert <tag>. PR 의무 체제에 맞춰 feature 브랜치 + PR(Tier S 셀프 머지).
  • 능력 조건부 에스컬레이션 (CSA if-then) — INVARANTS 커널, 보안/검증 예외, HIGH-fan-in 참조, Bash 위험 경로, 집행 메타 파일을 건드리면 제안자 신뢰도와 무관하게 AskUserQuestion 강제. permissions.allow 추가는 명시적으로 보안-예외 구간으로 분류(매 라인 동기 승인).
  • 강제 게이트는 bother-cost 면제 (명시 조항) — bother-cost 정지 규칙은 루틴 tier에만 적용. 그렇지 않으면 큰 컨텍스트 무인 루프가 INVARANTS 편집 게이트를 억제하고 커널이 조용히 편집 가능해진다.
  • 적용 전 자기 비판 (CAI) — PROPOSE는 동결 doctrine 대비 자기 비판을 내보내고 비판이 깨끗해질 때까지 제안을 막는다. 검사 대상 헌법은 쓰기 영역 밖(allowlist 보장)이라 비판이 공허해지지 않는다.
  • 승격 전 기계적 검증 (Voyager) — 제안자의 "그럴듯함"은 가설; /moai gate + 테스트 + LSP가 진리. 제안자 자작 verify만으로는 순환 논리이므로 /moai gate를 의무로 더한다. 증거는 verbatim으로 .moai/state/verify/<session>/에 지속.
  • 하드 거부 / 킬 스위치 — /moai:harness lsel veto가 대기 제안을 전부 버리고 최근 N개 lsel-* 커밋을 known-good baseline로 되돌린다(단 destructive-primitive이므로 확인 수반, 무조건 자동이 아님).
  • 거부 교훈이 루프를 닫는다 (Reflexion) — 비판·승인·검증이 거부한 제안마다 verified:false 교훈을 써서 제안자가 다음 제안 전에 검색. 쓰기 범위를 넓히지 않고 메모리에서 개선.
  • 정제가 공유 실패 양상을 막는다 (Generative-Agents + Vectorize) — drain의 중요도 게이트가 저가치 군집을 feedback_*.md가 되기 전에 거부. verified:true 교훈이 명시적 조정 없이 최신 미검증 것으로 조용히 대체되지 않음. 보관-삭제-말고 로 50-파일 한도를 축출이 아닌 계층화 임계값으로 유지.
  • 읽기 전용 목표 커널 (Datagrid) — CLAUDE.local.md 상단의 짧은 INVARANTS 블록이 학습이 절대 덮어쓰면 안 되는 사용자 하드 선호(template-first, PR 의용, settings.local.json 커밋 금지)를 닻. 자기편집-가드레일-제거에 대한 로컬 킬 스위치.

P4

VERIFY + reflection (공유 실패 양상에 대한 정제)

적용 후 verify_command 연결 + 실패 시 자동 되돌리기; 정기 reflection 패스(월간 /loop 레시피)가 세부 군집에서 원칙 feedback 파일 합성; memory_type 라벨링(CoALA); decay 가중 검색으로 오래된 교훈이 top-5에서 빠짐.

닫는 격차: "정제/decay/가지치기 없음 → 비정제 축적 → 잘못된 교훈 검색" — 모든 논문이 다르게 공격하는 지배적 실패 양상. 이 단계 없으면 루프는 부패하고, 있으면 저장은 썩지 않고 복리된다.

P5

개인화 + 신호 캡처 (일반화 층)

signals.jsonl 의도적 암시 캡처(PostToolUse 훅 연결); Thompson sampling 사후로 evolvable 서피스 설정(effort, model, harness level) auto-tune, 템플릿 기본값을 제약 있는 안전 fallback arm으로; UI-thrashing 방지 hysteresis margin; bother-cost 게이트된 ask 주기(cache-aware-execution directive 1 통합). 단, 정적 기본값 대비 override율을 이름 붙인 시뮬레이션 하네스에서 낮추지 못하면 배포하지 않는다.

닫는 격차: "추천 = 정적 템플릿 기본값, 관측이 대규모로 돌아도 개인화 안 됨". 이기해야 할 귀무가설은 정적 템플릿 기본값이다.

11적대적 비평과 mustFix

두 독립 렌즈가 v1 설계를 공격했다. 둘 다 같은 치명적 결함(self-amending allowlist)을 찾았고, 종합 설계는 이를 반영해 강화됐다. 아래는 원 비평의 요지와 잔존 mustFix.

렌즈 A — Doctrine 침해 & 안전

bypass-the-frozen-applier 본능은 옳고 동결 allowlist는 올바른 핵심 불변량이다 — 그러나 v1은 그 allowlist를 진화 가능·git 추적 스킬 파일 안에 뒀어서 가드가 자가-수정 가능했다. 모델 전용(비기계적) 자기 비판, 선택적 루프 트리거(감사 실패 재현), CI 가드 없는 CLAUDE.local.md leak 서피스와 합쳐져 침입 가능하고 기본 미발화. mustFix #1/#2/#5/#6 출하 전 차단.

mustFix (A) — 모두 종합 설계에 반영
  • 허용 목록을 쓰기 영역 밖으로: hns-lsel-applier/SKILL.md(진화 가능·git 추적)에 두지 말고, 6 evolvable 영역 밖 동결 메타 파일의 상수로. 가장 하중 큰 수정.
  • 집행 메타 파일을 CSA 강제 게이트 목록에 추가: allowlist, applier/curator 스킬 본문, 훅 스크립트, settings.local.json 훅 등록 서브블록. 어떤 tier·신뢰도든 동기 AskUserQuestion 강제.
  • 강제 게이트는 bother-cost 면제(명시 조항).
  • CLAUDE.local.md internal-marker CI 가드: internal_content_leak_test.go를 internal/template/templates/뿐 아니라 실제 repo CLAUDE.local.md로 확장. SPEC-ID/SHA/내부 경로 차단.
  • 훅 applier는 승인된 큐만 소비: lsel-apply.sh는 이미 기록된 decision.json을 재생만, 새 apply를 만들지 않음.
  • drain/propose 주기의 기계적 트리거: SessionStart 훅이 백로그 재고 > 임계치면 알림, 또는 기본 켜짐 예정 /loop. §28 넛지는 불충분(모델이 읽는 문장).
  • settings.local.json 훅 등록 서브블록 보호: applier가 lsel 훅 등록을 제거/무력화하는 편집 거부(INVARANTS와 동일 meta-보호).
  • §23 PR 의무 하에 APPLY git 위상 명확화: feature 브랜치 커밋 + PR(Tier S 셀프 머지), main-checked-out 트리 아님. rollback 리허설 AC 추가.

렌즈 B — 실제 실효

doctrine 격리 축은 강하(경로-allowlist가 실제로 doctrine 쓰기를 막음, bypass 추론 건전). 그러나 실제 실효 축에서 이전 실패의 형태를 되풀이한다: OBSERVE 이후 모든 단계가 "오케스트레이터가 불리면 한다"(doctrine, not mechanism), 복제하는 기존 moai harness execute 경로의 69 보류 제안을 무시, drain이 기계적 트리거·기계적 중요도 임계 없이 362개 Bash 노이즈를 승격. Stop/예정 훅이 CLUSTER를, lsel-apply.sh가 (선택 아닌) 주 APPLY 경로로 발화하지 않으면 inbox는 또 550 un-drained stub을 쌓고 루프는 advisory로 잔존.

mustFix (B) — 모두 종합 설계에 반영
  • CLUSTER를 기계적 트리거로: Stop 훅 또는 예정 /loop가 wc -l inbox > offset + N일 때 hns-lsel-curator drain 발화. 없으면 570-stub 백로그가 스스로 drain되지 않는다.
  • APPLY를 기계적 트리거로, 또는 반자율-전용 명시: lsel-apply.sh를 (선택이 아닌) 주 경로로(승인 decision.json 쓰기 시 PostToolUse, 또는 SessionEnd flush). 아니면 APPLY가 오케스트레이터 매개이고 루프는 닫힌 자가 진화가 아니라 "제안 표시 도우미"라고 솔직히 선언.
  • P1 drain 전에 노이즈 과점 inbox 수정: inbox-쓰기 시점에 기계적 심각도 힌트(또는 이벤트 allowlist·요약 길이 바닥·반복 PID 검출 같은 기계적 임계). 그렇지 않으면 첫 drain이 362 타임아웃을 교훈으로 바꾼다.
  • 기존 moai harness apply/execute/propose CLI와 69 보류 제안 조율: 기존 opt-in execute 경로를 구동하고 병렬 applier를 폐기하거나, 같은 SPEC에서 분산 dead verb를 명시 폐기. 69가 썩는 동안 병렬 경로를 짓는 건 CLI 서피스에서 감사 발견의 되풀이다.
  • "OBSERVE unchanged" vs "verified 결과 태그" 모순 해결: 결과 태그를 담는 side file 명시(또는 writer 훅 수정하고 "unchanged" 주장 삭제). ExpeL 성공/실패 페어링은 하중이므로 under-specified로 둘 수 없다.
  • 독립 verify 상위집합 의무: 제안자 자작 verify_command만으로는 순환. 모든 제안 verify는 고정 /moai gate를 포함.
  • lsel-leak neutrality 가드를 CI로, "로컬 테스트"가 아닌. 정확한 워크플로 파일명·트리거 명시.
  • permissions.allow 추가를 보안-예외로 명시 분류, 매 라인 AskUserQuestion 강제.
  • lsel-apply.sh git 작업의 primary-checkout vs worktree 명시: primary면 main-checkout-branch-guard 존중(HEAD 재판독·pathspec 스테이징), worktree면 제안 생명주기가 worktree 경로 휴대.

13솔직한 한계 — 이 설계가 풀지 않는 것

이 설계를 "감사가 지적한 자가 학습 루프를 닫았다"고 내세우는 것 자체가 관찰되지 않은 완료 주장이 된다. 설계가 풀지 않는 것을 명시한다.

  • 사용자 로컬 루프를 닫는다, 감사가 지적한 배포 서피스 경로가 아니다. 동결 Go applier는 동결 채로 남고, 배포 사용자 16언어 모두의 moai harness apply 버튼은 별도 SPEC이 폐기하거나 구동하지 않는 한 여전히 죽어 있다. 사용자 로컬 닫기를 감사 닫기인 양 내세우지 않는다.
  • doctrine을 진화시키지 않는다. doctrine은 루프가 검사하지만 고칠 수 없는 고정 헌법이다. 프로젝트 학습이 doctrine 수준 변경을 요구하면, 여전히 Template-First 주기를 거치는 정상 SPEC이 템플릿 원본을 고쳐야 한다.
  • PROPOSE의 자기 비판은 모델이 수행한다. 기계적 doctrine 검사기가 아니다. 모델은 합리화할 수 있으며, 고정 헌법은 규칙을 고치지 못하게 막을 뿐 잘못 읽는 것까지는 막지 않는다. 실제 안전성 무게는 동결 allowlist와 /moai gate 검증이라는 기계적 바닥이 지탱한다. 자기 비판은 가벼운 안쪽 문이다.
  • P5 개인화는 영원히 오지 않을 수 있다. 정적 기본값 대비 override율을 이름 붙인 시뮬레이션 하네스에서 낮추지 못하면 배포하지 않는다는 조건이 달려 있는데, 시뮬레이션 하네스가 아직 지정돼 있지 않다. 일반화 층은 조건부지 보장이 아니다.
  • 루프 개선은 컨텍스트 안에서만 일어난다. 오케스트레이터 모델을 파인튜닝하지 않는다(ExpeEl의 API 전용 모델 제약). 모든 자가 개선은 다음 턴 컨텍스트에 주입되는 검색된 텍스트이지, 모수 갱신이 아니다.
  • hns-* 스킬은 git 추적되어 공개 OSS 저장소로 push된다. 루프 학습이 hns-lsel-*에 닿으면 템플릿 사용자에게는 보이지 않지만(split_namespace_test.go) 저장소를 읽는 사람에게는 보인다.
  • apply-ledger·상태 파일은 gitignored 기계 로컬이다. 동결 applier가 만들지 못한 불변 감사 원장은 실재하지만, 내구성은 로컬 상태가 살아 있는 한에서 성립. moai clean이 상태를 지우는 동안 lsel-* 커밋은 브랜치 위에 남는다. 뒤섞인 이력에서 선택 되돌리기는 운용상 아프다.
  • 루프 자체의 콜드 스타트. 지금부터 P2 전까지 CLAUDE.local.md §28은 존재하지 않고 루프 발화는 0이다. P2 이후에도 루프를 실제로 돌리는 건 기계적 트리거(SessionStart 백로그 점검 + 기본 켜짐 /loop)이며, §28의 "같은 실수를 두 번 하면 feedback_*.md를 쓴다"는 알림은 모델이 읽는 문장이지 탐지기가 아니다.
  • 기존 moai harness apply/execute/propose CLI는 배포 사용자 전원에게 죽은 apply 버튼으로 배포된다. 본 설계는 GOOS의 기계를 우회로 고칠 뿐, 분산된 죽은 서피스는 동반 SPEC이 폐기하거나 구동하도록 남겨둔다. 죽은 버튼을 아는 채로 배포하는 것 자체가 느린 doctrine 침식이며, 본 설계가 해결하지 않는 것이다.

14참고문헌

웹 조사에서 확인된 논문·실무 자료. 설계 근거(groundedIn) 매핑의 원천.

  • Reflexion — Shinn et al., NeurIPS 2023. 언어적 강화: 실패에 대한 자기-성찰을 다음 시도를 위해 저장; bounded 에피소드 버퍼. → PROPOSE retrieval-before-propose, REMEMBER verified:false 교훈.
  • Voyager — Wang et al., NeurIPS 2023. 기계 실행 검증 후에만 스킬 라이브러리 진입; 합성적 스킬. → VERIFY(도구가 진리), hns-* 스킬 라이브러리.
  • Generative Agents — Park et al., UIST 2023. recency×importance×relevance 검색; 성찰은 임계치 발화(누적 중요도 ~150). → CLUSTER 중요도 게이트, 정기 REFLECTION, decay 가중 검색.
  • ExpeL — Zhao et al., AAAI 2024. 성공 vs 실패 궤적 대조로 교차-작업 통찰 추출; 2단계(원시 추적 vs 정제 통찰) 분리. → verified:true|false 결과 태그, Tier-1/Tier-2 분리.
  • Self-Refine — Madaan et al., NeurIPS 2023. 작업 내 반영+정제(지속 저장 없음). → 반패턴으로 명시 거부: 세션 내 전용 /moai-fix 재시도 루프 금지, REMEMBER 의무화.
  • MemGPT — Packer et al., 2023. 계층 가상 메모리, 고정 hot tier + cold tier 주문형 페이징. → ≤50 active feedback_*.md(hot) + memory/_archive/(cold), promote-on-retrieval-hit.
  • CoALA — 2023. 4개 메모리 유형(working/semantic/episodic/procedural)의 서로 다른 쓰기·검색 트리거. → memory_type 라벨 라우팅(절차적→hns-*, 의미론적→feedback).
  • Constitutional AI — Anthropic. 고정 헌법 대비 자기 비판-후-수정; 모델은 산출물을 수정, 원칙은 수정 안 함. → 동결 allowlist = 고정 헌법, PROPOSE 자기 비판.
  • LangWatch 프롬프트/설정 버전 관리 — 불변 버전 ID, dev→staging→prod 승격, 즉시 롤백. → shadow 제안 + lsel-<id> 불변 커밋 + git revert.
  • Galileo HITL 감시 — 가역성 축이 감시 무게 라우팅(비가역→동기, 가역→비동기 카나리). → 가역-by-구조가 대부분 편집을 동기 게이트에서 카나리로 강등.
  • CSA Recursive Self-Improvement Security — Zero-Trust 파이프라인, 최소 권한, 능력 조건부 if-then 게이트. → CSA 에스컬레이션(INVARANTS/보안/HIGH-fan-in/집행 메타).
  • CodeRabbit Learnings — "Learnings Added" 영수증, approval_delay, 사용 추적(Active/Never Used), 분기별 "축적 대신 갱신" 스윕. → 승인 영수증, CLAUDE.local.md §28 위생 주기.
  • Devin Knowledge — 검색-트리거 항목(트리거 설명+내용); 저장 전 편집. → feedback_*.md의 트리거 조건, progressive disclosure.
  • HumanLayer / Anthropic context engineering — CLAUDE.md는 최고 레버리지이고 짧아야; 포인터로 progressive disclosure; 훅 > 규칙(고정 생명주기 강제). → INVARANTS 커널 짧게, 결정적 보장은 settings.local.json 훅.
  • Vectorize / Hindsight 4-레버 정제 — importance / merge / decay / evict; 축출은 성능이 아닌 규정 준수 도구. → CLUSTER 4단계 패스, 보관-삭제-말고.
  • Thompson sampling contextual bandits — Agrawal & Goyal; Deb et al. RLJ 2025. 사후 분산 = 신뢰도; 제약 기본값 = 안전 fallback arm. → P5 auto-tune, 콜드 스타트 = 템플릿 기본값.
  • Bother-cost preference elicitation — Le et al., AAMAS 2018; Gajos 2005. 기대 후회 감소 > 중단 비용일 때만 묻기. → APPROVE ask 주기, cache-aware-execution directive 1 통합.
  • Intentional implicit feedback — arXiv:2502.09869. 의도적 행동(계획 편집, 'Other' 덮어쓰기)은 수동 암시와 별개 고가중 채널. → signals.jsonl 5~10배 posterior.
  • Claude Code / Cursor / Cline / Continue 등 코딩 에이전트 메모리 실무 — CLAUDE.md/AGENTS.md/.cursorrules + topic-file 색인 저장의 보편적 2단계 형태. → MoAI 쌍이 이미 이 형태임 확인(격차 = 발화 규율).
