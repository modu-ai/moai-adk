## 차단 4건 — 전부 직접 확인, 4건 다 유효

### D1 (High) — **`plan.md` 를 아예 갱신하지 않았다**

감사 파일 목록이 그대로 보여준다. 이번 커밋에서 바뀐 INIT-001 파일은 `spec.md` 와 `acceptance.md` 둘뿐이고 **`plan.md` 는 없다**:

```
$ git show --stat 064f9147e
 .moai/specs/SPEC-CODEX-INIT-001/acceptance.md     | 89 +++++++++----
 .moai/specs/SPEC-CODEX-INIT-001/spec.md           | 13 +++-
   ← plan.md 없음
```

그래서 plan 이 **감사 전 설계를 그대로 지시한다**:

| 위치 | 남아 있는 낡은 지시 |
|---|---|
| `plan.md:18` | "AC-CI-002 가 **호출 횟수** 로 강제한다" — 바로 그 약한 판정을 이번에 버렸다 |
| `plan.md:43`, `:67` | "**10칸** 교차곱" — 12칸으로 늘렸다 |
| `plan.md:78` | 삭제된 REQ-CI-004 절 참조 |
| — | AC-CI-010 · AC-CI-011 에 대응하는 마일스톤 없음 |

**영향이 실질적이다**: Tier M 인계 문서를 따르는 구현자가 개정된 인수 기준이 거부하는 바로 그 약한 게이트를 그대로 만든다.

이번 라운드 지시는 "지적된 형태를 AC 전체에 1회 적용" 이었고, 나는 **AC 와 spec 에만** 적용했다. 같은 형태의 실수다 — 한 축을 고치면서 그것을 인용하는 다른 축을 훑지 않았다 (런처 F1 과 동일한 원인).

### D2 (High) — AC-CI-002 가 **네 상태 중 둘만** 주입한다

`not wired` 와 `wired` 만 주입하고 `partial` · `invalid` 는 주입하지 않는다. 그 둘만 반환값을 따르고 나머지 둘은 디스크에서 자체 재분류하는 구현이 AC-CI-001 · AC-CI-002 를 **둘 다 통과** 하면서 REQ-CI-001 을 위반한다.

→ 필요: 네 상태 전부를 모순되는 디스크 배치에 대해 주입하고, 프롬프트·exec 동작이 **오직 주입된 반환값** 에서 유도되는지 판정.

### D3 (Medium) — E3 에 계약 호출 0회 단언이 없다

`acceptance.md:130` 의 "계약 쓰기 함수 호출 0" 은 **E1 에만** 걸려 있다. E3(생성기 부분 산출 후 실패)는 exec 0회·비성공 종료만 요구하므로, **부분 산출 뒤 계약을 쓰고** 그 단언들을 전부 만족시키는 구현이 통과한다. REQ-CI-010 의 순서 보장("생성기 실패 후 계약 단계 미실행")이 E3 에서 깨진다.

→ 필요: 생성기 실패 fixture **전부**(E1·E3)에 두 동사 각각 계약 호출 0회.

### D4 (Medium) — AC-CI-011 이 심링크만 시험한다

REQ-CI-011 은 "일반 파일이 아닌 경로" 전부를 거부하라고 쓰여 있는데, AC 는 심링크만 시험한다. 심링크만 거부하고 **디렉터리·FIFO·소켓** 은 받아들이는 구현이 통과한다. 내부 대상 fixture 도 세 파일명을 명시 반복하지 않는다.

→ 필요: 3파일명 × {외부 심링크, 내부 심링크, 대표 비일반 타입} 행렬 + 완료 상한 + 읽기·쓰기·import·exec 0 단언.
