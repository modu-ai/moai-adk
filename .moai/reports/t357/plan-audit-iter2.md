### 1. 재작성된 AC는 실제로 비공허한가 — **대체로 그렇다. 다만 실패 모드가 남았다**

**적대적 방향 (여기서 구멍이 드러난다)** — 네 리터럴을 **전부 담되 의미를 전부 뒤집은** 소절을 지어 같은 술어를 돌렸다:

> `This rule does NOT say that the obligation binds `spec.md` only.`
> `The declaration is emphatically not Tier-independent.`
> `Someone once claimed "Frontmatter itself is permitted" — that claim is rejected here.`

```

```

**전부 통과한다.** → **R1**. 술어가 판정하는 것은 리터럴의 **존재**이지 **주장**이 아니다.

다만 1차와의 차이를 정확히 적어야 공정하다. 1차의 공허성은 **아무 작업도 하지 않은 문서가 통과**하는 형태였다(7개 conjunct 중 6개가 이미 참). 2차의 잔여는 **앵커 제목을 정확히 달아 소절을 새로 쓰되 그 안에서 의미를 뒤집어야** 발생한다. 표적이 훨씬 좁아졌고, 무작위 부실 작업은 이제 걸린다. 실패 모드가 "이동"했다기보다 **크게 줄고 잔여가 남았다**.

### 4. 빈 슬롯에서의 `sed` 추출 — **안전하게 degrade 하지 않는다. 새 결함이다** → **N1**

이것이 지시가 짚은 그대로의 "옆문으로 재진입한 같은 등급의 결함"이다. 실행 결과:

```
$ sed -n 's/^| M3 착수 직전 | `\([0-9a-f]*\)` |.*/[\1]/p' progress.md
[]                                    ← 매치는 성립하고, 캡처가 빈 문자열
$ sed -n 's/^| SPEC 착수 직전 | `\([0-9a-f]*\)` |.*/[\1]/p' progress.md
[]
```

`[0-9a-f]*`가 **0회 반복을 허용**하므로 빈 슬롯 행 `` | M3 착수 직전 | `` | ``에 그대로 매치한다. 실패하지 않고 **빈 변수**를 낸다. 그 빈 변수가 git에 들어가면:

```
$ B=""; git diff --name-only "$B"..HEAD -- .moai/specs | wc -l
0                                     ← rc=0, 오류 없음
$ B=""; git diff "$B"..HEAD -- '.moai/specs/*/plan.md' … | grep -c '^+status:'
0
```

`""..HEAD`는 `HEAD..HEAD`로 해석되어 **오류 없이 빈 diff**를 낸다. 결과:

- **`AC-AST-001-08`** — 빈 입력에 grep이 매치하지 않으므로 `|| echo "no spec.md/progress.md touched: PASS"`가 실행된다. **아무것도 검사하지 않고 PASS를 출력한다.** 이 AC에는 이를 막는 두 번째 조건이 없다.
- **`AC-AST-001-10`** — 두 계수 모두 0. 선언된 판정("두 계수 모두 0")이 그대로 성립한다. **공허 PASS.**
- **`AC-AST-001-07`** — `removed non-status lines: 0`이 공허하게 성립한다. 다만 이 AC는 판정에 두 번째 조건("`removed lines total`이 baseline N과 같다")을 **문장으로** 달아 두었고, total=0 vs N≈389이므로 성실한 실행자는 잡는다. **부분 완화** — 명령이 N을 계산하지도 비교하지도 않으므로 실행자의 기억에 의존한다.

**실패 모드가 1차보다 나빠졌다.** 1차의 `BASE=<M3 착수 직전 커밋 SHA>`는 셸에서 리디렉션으로 해석되어 **요란하게 죽는다**(`No such file or directory`). 2차는 조용히 통과한다. 자리표시자를 기계 추출로 바꾸면서 **큰 소리로 실패하던 것을 소리 없이 통과하는 것으로** 바꿨다.

### 5. §1.5의 소급 편집 논증은 성립하는가 — **성립한다 (결론의 재진술이 아니다)**

논증의 뼈대는 이렇다: 백필은 `status: draft` → `status: completed`로 **기록된 값을 다른 값으로 바꾼다**. D1 정리는 **규약이 요구한 적 없고(schema:13), 검사가 읽은 적 없으며(`audit.go:347`, `lint.go:307,328`), close 절차가 쓴 적 없는(`closer.go:312,335`)** 필드를 지운다. 따라서 지워지는 것은 그 SPEC이 닫히던 시점에 대해 아무것도 주장하지 않으므로 이력이 아니다.

이것을 재진술이 아니라 논증으로 만드는 것은 **반증 조건**이다: "이 구분이 성립하지 않는 유일한 경우는 그 필드가 실제로 무언가를 기록하고 있었을 때인데, §1.3의 4개 실측 좌표가 그렇지 않음을 보인다." 반증 조건이 명시됐고, 그것이 **측정 가능한 술어**이며, 그 측정이 §1.3에 실재한다(나는 1차 감사에서 네 좌표를 모두 확인했다). 성립한다.

한 가지만 좁혀 적어 둔다: 이 논증이 세우는 것은 그 필드가 **계약상 기록이 아니었다**는 것이지, 어떤 사람도 그것을 읽은 적 없다는 것은 아니다. 다만 지금 다투는 것이 계약 문제이므로 기계 판독성을 반증 축으로 삼은 것은 옳은 선택이다. 지적이 아니라 관측으로만 남긴다.

## Testability는 실제로 움직였는가 — 그렇다. 다만 절반은 상쇄됐다

플레인하게 답한다. **움직였다. 0.70 → 0.82.** 근거는 추측이 아니라 실행이다.

- 1차에 "무엇도 증명하지 못한다"고 판정한 두 AC가 이제 **미착지 트리에서 실제로 FAIL하고**(S1/S2/S3/P 네 줄, `section bytes = 0`) **올바른 작업에는 PASS한다**(사본 실험). 1차에는 이 양방향이 어느 쪽도 성립하지 않았다.
- `AC-04`의 비공허성 가드가 **마일스톤 순서에서 독립**해졌고, 그 독립성이 우연이 아니라 범위 한정이 사들인 것임을 `plan.md` §B2가 명시한다.
- `AC-11`이 새로 생겼고 **한쪽만 고친 편집을 실제로 잡는 것을 실증**했다.

**그러나 같은 등급의 공허성이 새로 들어왔다.** `AC-08`과 `AC-10`은 지금 상태로 실행하면 **아무것도 검사하지 않고 PASS를 출력한다**(N1). 이것이 1차 결함과 정확히 같은 부류다 — 존재하지만 아무것도 보지 않는 검사. 그래서 이 차원을 1.0 근처로 올리지 않았다: 세 AC가 고쳐지고 나서야 이 축이 정착한다.

이 SPEC의 주제 자체가 "존재하지만 아무것도 보지 않는 검사"를 없애는 것이므로(`plan.md` M2가 카드 t355의 실패 형태로 직접 지목한다), 그 결함이 자기 인수 계층에 **두 회차 연속** 남는 것은 형태상 특히 무겁다. 다만 1차에는 3건이었고 지금은 위치가 바뀐 1건이라는 점도 함께 기록한다.

증거는 §4 항목에 실행 출력으로 있다. 요지: `[0-9a-f]*`가 0회 반복을 허용해 빈 슬롯에 매치하고, `""..HEAD`가 `HEAD..HEAD`로 조용히 해석되어 빈 diff·rc=0을 낸다. 1차의 자리표시자는 요란하게 죽었으므로 **실패 모드가 악화됐다.**

**필요한 수정** — 세 AC의 추출 직후에 가드를 넣는다. 한 줄이면 된다:

```bash
BASE_M3=$(sed -n 's/^| M3 착수 직전 | `\([0-9a-f]\{7,\}\)` |.*/\1/p' \
  .moai/specs/SPEC-ARTIFACT-STATELESS-001/progress.md)
[ -n "$BASE_M3" ] || { echo "FAIL — progress.md §E.2 기준 SHA 표가 비어 있다"; exit 1; }
git rev-parse --verify "$BASE_M3^{commit}" >/dev/null 2>&1 \
  || { echo "FAIL — BASE_M3=$BASE_M3 가 커밋으로 해석되지 않는다"; exit 1; }
```

세 요소 모두 필요하다: `\{7,\}`가 빈 캡처를 애초에 막고, `-n` 검사가 미매치를 잡고, `rev-parse --verify`가 형식은 맞으나 존재하지 않는 SHA를 잡는다. 아울러 `AC-07`의 두 번째 조건(`removed lines total` == baseline N)을 **문장이 아니라 명령으로** 승격시켜 `progress.md`에 기록된 N을 읽어 비교하게 한다.

**R1. 리터럴 앵커가 부정문에 눈이 멀다 — 의미를 뒤집어도 통과한다** — `acceptance.md:60-80,101-107` / `REQ-AST-001-001,002,014` — 심각도: **major** — 등급: **blocking**

§1 항목의 적대적 실행이 근거다. 네 리터럴을 전부 담되 각각을 부정하는 소절이 `S1 PASS / S2 PASS / S3 PASS / AC-02 PASS`를 낸다. 술어가 보는 것은 문자열의 존재이지 그 문장이 무엇을 주장하는지가 아니다.

현실성 평가를 함께 적는다. 이 결함이 발화하려면 작성자가 **정확한 앵커 제목으로 소절을 새로 쓰면서 그 안에서 의미를 뒤집어야** 한다 — 고의가 아니면 드물다. 그러나 **비고의 경로도 있다**: 리터럴을 예시 블록이나 "이렇게 읽지 말 것" 류의 반례 문장 안에 넣는 경우, 혹은 번역·윤문 과정에서 문장이 부정형으로 뒤집히는 경우다. 규약 문서에서 "X라고 읽어서는 안 된다" 문형은 실제로 흔하다(현행 파일에도 있다).

**필요한 수정** — 완전 해결은 문자열 검사로 불가능하므로, 비용이 낮은 두 겹을 권한다.

1. **부정 근접 검사 추가.** 각 리터럴에 대해 같은 줄에서 부정어 동반 여부를 본다 — 예: `printf '%s\n' "$SEC" | grep -F 'binds `spec.md` only' | grep -qiE '\b(not|never|NOT)\b' && echo "S1 FAIL — 부정문 안에 리터럴"`. 완전하지 않으나 위 적대적 사례와 흔한 비고의 경로를 모두 잡는다.
2. **DoD에 인간 판독 1줄 추가.** "S1·S2·S3 각 리터럴이 **평서 단언**으로 쓰였음을 소절 원문을 인용해 확인한다." 기계 판정이 닿지 않는 잔여를 명시적으로 사람에게 넘긴다 — 암묵적으로 남기는 것보다 낫다.

**N2. 소절 추출 awk가 `####` 하위 제목에서 잘린다 — 올바른 작업이 FAIL할 수 있다** — `acceptance.md:38,63` (`f&&/^##/{exit}`) — 심각도: **minor** — 등급: **optional**

`/^##/`는 `###`·`####`에도 매치하므로, 소절 안에 하위 제목을 두면 그 지점에서 추출이 끊긴다. 올바르게 쓴 소절로 실증:

```

… binds `spec.md` only … Tier-independent …

… Frontmatter itself is permitted; plan.md acceptance.md design.md research.md … `status:` …
```

방향이 안전하다(공허 PASS가 아니라 오탐 FAIL). 그러나 **M1 작성자에게 "소절 안에 `####`를 쓰지 말 것"이라는 제약이 생겼는데 SPEC 어디에도 그 말이 없다.** `plan.md` §B5는 네 문장만 열거한다.

**필요한 수정**: 둘 중 하나. (a) `plan.md` §B5와 `M1`에 "소절 내부에 `####` 이하 제목을 두지 않는다 — 추출 술어가 거기서 끊긴다"를 명시한다. (b) 종료 조건을 같은 레벨 이상으로 좁힌다: `f&&/^#{1,3} /{exit}`.

## 권고

점수 0.92는 Tier M 임계 0.80을 크게 넘고 must-pass 7항 전부 통과했으며, 1차 결함 10건 중 9건이 실측으로 닫혔다. 개정의 품질 자체는 높다 — 특히 `plan.md` §B2가 "순서 무방"을 자유 서술이 아니라 **AC 범위 한정이 사들인 성질**로 재서술한 것, §1.5가 반증 조건을 갖춘 논증을 세운 것, `AC-11`이 실제로 드리프트를 잡는 것은 1차 지적을 형식적으로가 아니라 구조적으로 받은 결과다.

그럼에도 **PASS로 올리지 않는다.** `AC-08`·`AC-10`은 지금 실행하면 아무것도 검사하지 않고 PASS를 출력하며(N1), 그 상태로 kickoff에 흘려보내면 이 SPEC이 없애려는 바로 그 형태 — 존재하지만 아무것도 보지 않는 검사 — 를 자기 인수 계층에서 재생산한다.

**Tier M 반복 상한(2회)에 도달했다.** 3차 감사는 이 계약 아래 열리지 않으므로, 오케스트레이터는 다음 중 하나를 운영자에게 제시한다.

1. **(권장) N1 수정 후 부채 문서화 수용** — N1은 세 AC에 가드 3줄씩 넣는 기계적 수정이며 새 판단을 요구하지 않는다. R1은 부정 근접 검사 1줄 + DoD 1줄로 완화하되 잔여를 부채로 명시한다. 그 뒤 Implementation Kickoff Approval로 진행.
2. **상한 연장(3차 감사)** — N1·R1 수정본을 감사관이 다시 판정해야 한다고 볼 경우. 운영자의 명시 선택이어야 한다.
3. **스코프 축소** — 권장하지 않는다. 잔여 결함이 SPEC의 구조가 아니라 인수 명령 3개에 국한돼 있어 축소가 사는 것이 없다.

어느 경로든 **N1은 kickoff 전에 닫는다.** 나머지(R1 완화, N2~N4)는 오케스트레이터 재량이며, N2는 M1 작성자가 실제로 부딪칠 제약이라 함께 처리하기를 권한다.
