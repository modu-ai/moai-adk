TL;DR

Weng의 논지 — 자가 개선의 현실적 경로는 모델 가중치가 아니라 하네스 엔지니어링 — 를 moai-adk에 적용한다. moai-adk는 이미 4-tier 학습 사다리, 5-layer 안전 파이프라인, usage-log 관찰자, v4 Builder 등 하네스 자산의 약 70%를 보유하고 있으나, 학습 루프가 스킬 frontmatter 2개 필드에서 끝난다. 재설계의 핵심은 Curator의 편집 가능 표면(editable surfaces)을 3계층으로 확장하는 것: ① 메모리(임시, 세션) → ② CLAUDE.local.md(영구, 사용자별) → ③ CLAUDE.md 관리 블록(정적 기본 워크플로우). /moai 라우터가 매 호출을 관찰하고(Loop 0), 세션 경계에서 반추하고(Loop 1), tier 승격으로 영구 기록·기본 워크플로우를 갱신한다(Loop 2). 모든 쓰기는 인간 승인 게이트 + 스냅샷/롤백 + 회귀 게이트 뒤에 둔다.

1Weng 하네스 논지 → moai-adk 매핑

Weng은 하네스를 "베이스 모델을 둘러싸고 실행을 오케스트레이션하는 시스템 — 어떻게 사고·계획하고, 도구를 호출하고, 컨텍스트를 인지·관리하고, 산출물을 저장하고, 결과를 평가하는지를 결정하는 층"으로 정의한다. 핵심 주장: 재귀적 자가 개선(RSI)의 근시일 경로는 가중치 수정이 아니라 하네스 엔지니어링이며, 최적화 대상은 프롬프트 → 구조화 컨텍스트 → 워크플로우 → 하네스 코드 → 옵티마이저 코드 순으로 진화한다.

3목표 아키텍처 — 3-Loop Self-Evolving Harness

ACE의 Generator/Reflector/Curator를 moai-adk의 실행 주기에 맞춰 3개 루프로 구체화한다. 각 루프는 시간 스케일이 다르다: Loop 0은 매 턴, Loop 1은 세션 경계, Loop 2는 tier 승격 시점.

그림 1 — 3-Loop 자가 진화 구조. Loop 2의 산출물(CLAUDE.md 관리 블록 + CLAUDE.local.md)이 다음 세션 라우터의 Phase −1 입력이 되어 루프가 닫힌다.

Loop 0 — 관찰 (Generator, 매 턴)

  • routing-ledger.jsonl 신규 : .moai/state/routing-ledger.jsonl. 매 /moai 호출마다 {ts, session_id, request_digest, matched_subcommand, mode_selected(Phase 0.95), tier, clarify_rounds, outcome(success|fail|abort|reroute), duration_class} 1행 append. 기존 observer.go(PostToolUse) 패턴 재사용 — Stop/SubagentStop 훅에서 결과 확정.
  • 기존 usage-log.jsonl(하네스 생성물 관찰)과 분리 유지 — 관찰 대상이 다름(생성된 harness-* vs /moai 본체 라우팅).

Loop 1 — 반추 (Reflector, 세션 경계)

  • 세션 핸드오프/종료 시 learner.go가 routing-ledger를 집계: 패턴 키 = request_class + subcommand + mode + outcome. 반복 패턴은 tier 카운트 증가.
  • 집계 결과를 auto-memory에 임시 저장 (사용자 요구의 "메모리 임시 저장") — 기존 Lessons Protocol의 메모리 taxonomy(feedback|project) 재사용. 세션 간 유지되지만 아직 지시문 표면에는 미반영.
  • 실패 패턴(재질문 과다, 잘못된 분기, abort)은 lessons-inbox 스텁으로도 적재 — Weng의 약점 채굴(Weakness Mining) 입력.

Loop 2 — 승격 (Curator, tier 임계 도달)

  • Tier 3 (rule) → CLAUDE.local.md 영구 기록: ## Learned Workflow Rules (auto-curated) append-only 섹션에 (identifier, rule, evidence-count, date) 불릿 추가. 기존 doctrine 섹션(§1~§26)과 충돌하지 않는 전용 관리 영역. AskUserQuestion 승인 필수.
  • Tier 4 (auto_update) → CLAUDE.md 관리 블록: <!-- MOAI:LEARNED-WORKFLOW:BEGIN --> … END --> 마커 블록 내부만 갱신 — 기본 워크플로우 편향(예: "이 프로젝트에서 'refactor' 요청은 ddd 모드 우선", "docs 변경은 minimal 하네스 레벨") 을 불릿 단위로 기록. layer3.go InjectMarker를 일반화한 typed section writer가 담당. mergeSectionBased가 moai update 시 이 블록을 보존.
  • 모든 승격: 스냅샷 → L2 Canary(shadow 적용 + doctor + 회귀 게이트) → L3 Contradiction(Frozen rules와 모순 grep) → L4 Rate Limit → L5 인간 승인 → 적용 → lineage 기록. 롤백은 기존 overlay 방식.

4편집 가능 표면 계층 (Editable Surfaces)

Weng의 Self-Harness가 강조하는 "경계 내 제안(bounded proposal)"을 3-Zone 표면 계약으로 명문화한다. 기존 [ZONE:Frozen]/[ZONE:Evolvable] 체계에 ZONE:Learned를 추가한다.

/moai harness 콘솔 확장

harness 서브커맨드는 진화 루프의 관리 콘솔로 승격된다. 기존 Branch A(학습 verb) / A.1(v4 라이프사이클) / B(NL Builder) 3분기는 유지하고 Branch A에 verb를 추가한다.

Verb상태동작
status확장기존 제안 목록 + tier 파이프라인 뷰(패턴별 현재 tier·증거 수·다음 임계까지 남은 횟수) + Learned 표면 현황(블록 크기/예산)

promote / demote <pattern>신규특정 패턴의 tier 수동 승격/강등 (사용자가 학습을 직접 조타)

① 약하고 모호한 평가자outcome을 기계 신호로 한정: audit PASS/FAIL·게이트 exit code·재질문 횟수·abort 여부. "느낌상 성공"은 ledger에 기록 불가 (verification-claim-integrity §1.1과 정합)
② 컨텍스트·메모리 수명주기tier별 표면 분리 + 만료 정책(90일 미갱신 pruning 제안) + 블록 예산 상한(≤3K자, token_budget_guard 집행) + 기존 retention.go 재사용
③ 부정적 결과의 소실실패 패턴도 동등하게 ledger 적재 — "X 요청을 Y로 분기하면 실패" 형태의 negative rule 승격 허용
④ 다양성 붕괴learned 편향은 참고 신호일 뿐 결정 규칙이 아님 — Phase 0.95 임계값·착수 승인 게이트는 학습과 독립. 편향 강도 상한(권장 라벨 1개까지, 옵션 제거 금지)
⑤ 보상 해킹평가자(plan/sync-auditor)·rules·게이트 전부 Frozen — 학습 루프가 자기 성적표를 고칠 수 없음. L3 Contradiction이 Frozen 규칙과 모순되는 승격을 기각
⑥ 장기적 건전성lineage.go로 모든 승격의 계보 추적, 회귀 게이트 + 스냅샷 롤백. doctor가 Learned 표면 부패를 상시 검진
⑦ 인간의 역할"스택 위로": 사용자는 불릿 하나하나가 아니라 승격 순간만 승인 (L5 AskUserQuestion). promote/demote/freeze로 조타권 유지. CLAUDE.md/local.md 쓰기의 자동 무승인 경로는 존재하지 않음
경계 조건 3가지 (HARD)
① GLM 세션은 관찰만 — Tier 3+ 승격 제안 생성은 Opus/Fable 세션 한정 (STOP 교훈: 베이스 모델 역량 미달 시 자가 개선이 성능을 되레 악화). ② 템플릿 중립성 — routing-ledger·Learned 블록·local.md 섹션은 프로젝트 로컬 산출물이며 internal/template/templates/에는 빈 관리 블록 마커와 메커니즘만 배포 (학습 데이터 누출 금지, §25 준수). ③ 병렬 세션 레이스 — ledger는 append-only jsonl(행 단위 원자성), CLAUDE.md/local.md 쓰기는 승격 시점 단발 + 기존 Pre-Spawn Sync Check 적용.
