참고 이미지 → MoAI 매핑 진단

핵심 통찰: 이미지 ①의 4-루프는 에이전트 종류가 아니라 오케스트레이션 메커니즘이다 (에이전트 카탈로그와 직교). MoAI는 4종 모두 기존 메커니즘으로 커버한다. 이미지 ②의 2-패턴 중 Orchestrator-Worker는 완비, Executor-Advisor의 Advisor 슬롯만 공백이다.

02

공식 문서 근거 (2026-07 조사)

code.claude.com 공식 문서 2건 전문 + 2026 실무 가이드를 조사한 핵심 근거 4가지.

“Define a custom subagent when you keep spawning the same kind of worker with the same instructions.” F1 · sub-agents 문서 — 정적 파일 vs 동적 스폰의 유일한 공식 판정 기준. “모든 상황을 같은 자문 지시로 반복 호출”하는 범용 Advisor는 이 기준을 통과한다.
“By a second opinion: a verification subagent … has a fresh model try to refute the result, so the agent doing the work isn’t the one grading it.” F2 · best-practices 문서 — Advisor 패턴은 공식 권장. 단 경고 동반: “reviewer는 시키면 항상 gap을 찾아내므로 correctness에 영향 있는 것만 보고하게 하라.”
“effort — Overrides the session effort level. Default: inherits from session.” + 모델 해석 우선순위(v2.1.196+): env → per-spawn model 인자 → frontmatter → inherit F3·F4 · sub-agents 문서 — 서브에이전트 effort를 xhigh로 고정할 유일한 지점은 frontmatter(스폰 인자에 effort 없음). 모델은 스폰 인자가 frontmatter보다 우선 → “frontmatter inherit + 스폰 시 opus 주입”이 [1m] 안전 + 공식 우선순위 정합.
“Four to eight specialized agents is usually enough … too many agents with overlapping descriptions creates routing ambiguity.” F6 · 2026 실무 가이드 컨센서스 — 제안 8+1은 권장 구간 상단. 신설은 1종으로 한정하고 description 상호배제를 강제한다.
03

재설계 아키텍처 (Target)

두 패턴을 하나의 위상으로 통합: Orchestrator(Opus)가 Turn-based 메인 루프를 돌며, 좌하단 Worker 군단에 분배(Orchestrator-Worker)하고, 우측 advisor에게 온디맨드 자문(Executor-Advisor)한다. 판정(게이트)과 자문(비구속)은 분리된다.

실선 = 지시·의뢰 흐름, 점선 = 응답·결과 흐름. advisor는 Executor-Advisor 패턴의 온디맨드 조언자 슬롯(이미지 ②의 Fable 5 위치 → Opus 치환), Worker 군단은 Orchestrator-Worker 패턴(Sonnet). 우측 하단 4-Loop은 에이전트 카탈로그와 직교하는 실행 메커니즘 축.

진입 조건 (오케스트레이터 에스컬레이션 독트린)

  • E1 버그 교착 — 동일 결함 수정 3회 실패 (loop_prevention.max_retries: 3과 정렬) 또는 /moai fix 파이프라인 교착
  • E2 설계 결정 — 아키텍처·트레이드오프에서 오케스트레이터 확신이 낮은 결정 직전
  • E3 세컨드 오피니언 — 비게이트 리뷰(작성자와 채점자 분리가 필요한 검토)
  • E4 루프 교착 — /goal·/moai loop이 수렴하지 않을 때 탈출 처방

반환 계약

  • 반박 우선(refute-first) — correctness에 영향 있는 것만 (F2 경고 반영)
  • 근본원인 가설 순위 목록 + 각 가설의 검증 커맨드
  • 수정은 직접 하지 않음 — manager-develop 재위임용 처방 반환 (read-only)
