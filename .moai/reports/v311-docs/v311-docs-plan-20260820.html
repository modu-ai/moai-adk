먼저 짚을 것 — 릴리즈가 아직 안 끝났습니다

"릴리즈 완료"는 코드 기준으로만 참입니다. 실측 결과:

  • PR #1585 (release/v3.1.1 → main) 머지됨 — 2026-08-20 08:50
  • pkg/version/version.go:8 = v3.1.1, CHANGELOG [3.1.1] - 2026-08-20 작성됨
  • 그런데 git tag -l 'v3.1*' → v3.1.0까지만. v3.1.1 태그가 없습니다
  • 그리고 GitHub 릴리즈 v3.1.1이 Draft 상태(08-15 생성 — PR 머지보다 5일 앞선 스테일 초안). Latest는 여전히 v3.1.0

문서 작업 자체는 이것과 무관하게 진행할 수 있습니다. 다만 문서를 머지하기 전에 태그·게시가 끝나야 합니다 — README가 v3.1.1을 소개하는데 릴리즈 페이지에 v3.1.1이 없으면 그 문서가 거짓말이 됩니다. 그래서 M0을 게이트로 세웁니다.

계획 — 7 마일스톤

정본은 README.ko.md입니다. ko를 먼저 완성하고 en/ja/zh를 파생합니다(hns-oss-docs-readme-sync 규약). 4개 파일이 현재 778줄·72헤딩·같은 줄번호로 완전 동형이므로, 이 동형성을 깨지 않는 것이 작업 내내 유일한 구조적 제약입니다.

  • M0 · 게이트 릴리즈 마감 — 태그 + 게시
    v3.1.1 태그 생성·푸시, Draft 릴리즈를 실제 머지 헤드 기준으로 재생성해 게시. M6 머지 전까지만 끝나면 됩니다 — M1~M5와 병행 가능. 안 끝나면 문서가 없는 릴리즈를 가리키게 됩니다.
  • M1 · ko 사실 정정 5건 + 모호성 해소 1건
    위 ②표 그대로. ref 10→11, domain 5·8→7, CLI 36→49, alt 텍스트 10→11, 설정 섹션 문장을 "자주 쓰는 6개"로 한정. 12 vs 11 에이전트는 "커스텀 11 + 내장 Explore 1" 한 문장 추가. 줄 수 증가 없음(치환 위주).
  • M2 · ko v3.1.1 소개 절 신설
    L40 ## v3.1 새 기능 — 칸반 모드 아래에 ### v3.1.1에서 더해진 것을 신설. 담을 것: 홈 정리 3종(MOAI_HOME·clean --home·doctor 디스크), 크로스세션 설정, 프롬프트 캐시 설정, forge 스테이터스라인, /loop 포먼. H2를 새로 파지 않습니다 — 12개 H2 구조가 4로케일 동형성의 뼈대라 건드리면 파생 비용이 커집니다.

범위에 대해 제가 내린 판단 3가지

1. CHANGELOG도 같이 고칩니다. [3.1.1] 절이 Summary + SPEC 3건만 담고 있고 Changed/Fixed 하위절이 아예 없습니다. 위에 나열한 33건 중 30건이 CHANGELOG에 없습니다. README가 CHANGELOG를 가리키는데(L703-706) 그쪽이 비어 있으면 링크가 헛돕니다. 릴리즈 노트의 원천이기도 하니 M0에 묶습니다.

2. 기존 숫자 오류(②)도 함께 고칩니다. 엄밀히는 "3.1 이후 업데이트 반영"이 아니라 그 전부터 있던 오류입니다. 다만 같은 줄·같은 문단을 어차피 건드리고, 4로케일 파생을 두 번 돌리는 게 훨씬 비쌉니다. 한 번에 처리하는 게 맞다고 봅니다.

3. 내부 변경은 넣지 않습니다. always-loaded 다이어트(295,044→288,975바이트), 룰 파일 신설, internal/paths 리팩터, 오케스트레이션 모드 카탈로그 개명, 테스트 하네스 수정 — CHANGELOG가 명시적으로 "사용자 노출 표면 없음"이라 적은 것들입니다. README에 들어가면 독자가 쓸 수 없는 정보로 분량만 늘립니다.
