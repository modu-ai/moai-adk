## 1. Claim

One new writer persists the three existing graph-producing layers as a
git-diffable JSONL artifact (`moai graph build` → `.moai/project/graph/edges.jsonl`;
one line = one edge, sorted, byte-stable). New code = the writer
(`internal/graph/`, `internal/cli/graph.go`). The three extractors are reused
existing code with minimal export/extension seams (documented below).

## 2. Decisions

### 2.1 CLI surface: (a) `moai graph build` — chosen

- **Scope exceeds MX.** `moai mx` is documented as the "@MX TAG management
  tool" for the sidecar index. The aggregate spans import adjacency (a
  codemaps artifact concern) and SPEC→SPEC depends_on (a spec-frontmatter
  concern); nesting it under `moai mx export --edges` would misname the
  artifact and overload the mx command group.
- **Sibling-disjoint registration.** The command registers from its own file
  (`internal/cli/graph.go`, per-file `init()`), so ZERO existing CLI files
  were edited — maximally disjoint from t106's `internal/cli/todo.go`.
- **Precedent.** `moai navigator sync` already writes a dedicated graph
  artifact (`nav-graph.json`) as its own command; `moai graph build` follows
  the same one-artifact-one-command shape.

### 2.2 Premise verification — "codemaps --format json"

The card described layer 1 as `codemaps --format json` "already emitting the
import adjacency list". Measured reality:

- `/moai codemaps` is a Claude Code SKILL (LLM workflow), not a Go CLI. Its
  `--format json` option ("JSON alongside markdown") has never been
  persisted in this repo — no JSON artifact exists.
- What DOES exist: `.moai/project/codemaps/dependencies.md` (markdown,
  mermaid-fenced edge list, generated by `/moai codemaps --force`) plus an
  existing Go parser for it: `parseDependenciesMarkdown`
  (internal/navigator/tiers/blueprint.go) — previously unexported and
  consumed only by the blueprint scaffold.

Judgment: the layer's substance (import adjacency, existing, never persisted
as a graph) holds; only the "json" shape was wrong. I treated this as a
shape correction, not a premise failure, and reused the markdown artifact +
existing parser. Consequences handled by the writer:

- **Fence scoping** — the parser fed the WHOLE file also ingests prose
  sections ("**Presentation → Business", "`hook` → config, lsp, session, mx")
  producing junk nodes (measured: 27 modules whole-file vs 21 fence-scoped).
  The writer scopes parsing to the ```mermaid fence.
- **Label canonicalization** — mermaid edges use short node ids (`cli`),
  while the fence's node labels carry full paths (`cli["internal/cli<br/>…"]`).
  The writer resolves ids → full package paths via the label table and drops
  tokens carrying internal whitespace (scaffold noise).
- **Dotted-arrow defect fixed in the reused parser** — `lsp -.-> astgrep`
  previously split mid-arrow producing a junk `lsp -.` node (parser probed
  `->` inside `-.->`). Added `-.->` to the separator list (probed first).
  This benefits the parser's native consumer (blueprint scaffold) too.

### 2.3 Extractor reuse seams (minimal, no new analyzers)

| Layer | Extractor reused | Seam added |
|---|---|---|
| import | `parseDependenciesMarkdown` (tiers) | exported wrapper `ParseDependenciesMarkdown` + `ModuleDependency` type; `-.->` separator fix |
| mx-spec | `mx.Scanner` (`SpecRef` sub-line capture) | none — consumed as-is |
| spec-depends | `mx.parseFrontmatter` / `LoadSpecModules` pattern | `LoadSpecDependencies` + `DependsOn` field on the existing `specFrontmatter` struct |

Deliberate scope cut: mx-spec edges use ONLY the `@MX:SPEC` sub-line source
(direct, author-intended). The SpecAssociator's path-based and body-based
inferred associations are NOT emitted — they are a different (inferred)
layer and would inflate the artifact with non-authored edges.

### 2.4 Artifact shape

`{"kind":"import"|"mx-spec"|"spec-depends","source":…,"target":…,"line":N}`
— one JSON object per line; sorted by (kind, source, target, line); no
timestamps; mx-spec sources are repo-relative paths (absolute paths would be
machine-specific and non-diffable); `line` is the 1-based line of the @MX tag
OWNING the SPEC sub-line (the scanner records the owning tag's line, not the
sub-line's own position). Atomic write (temp + rename, mirroring the mx
sidecar pattern). Default output `.moai/project/graph/edges.jsonl`
(parallels `.moai/project/codemaps/` and `.moai/project/navigator/`).

## 3. Remeasure — "@MX:SPEC covers 39 unique SPECs"

The card's figure was grep-derived. Both numbers measured on this worktree:

| Method | Unique SPECs | Command |
|---|---|---|
| grep (pre-change tree) | **39** | `grep -rhoE '@MX:SPEC: ?SPEC-[A-Z0-9-]+' --include='*.go' internal/ cmd/ pkg/` → `sort -u` |
| internal/mx parser (pre-change tree) | **33** | unique `target`s of `kind:"mx-spec"` edges from `moai graph build` (scanner SpecRef capture), minus the 1 SPEC added by this card's own test fixture |
| grep (post-change tree) | 41 | +2 SPEC IDs that appear inside this card's new test fixtures |
| parser (post-change tree) | 34 | includes SPEC-GRAPH-TEST-001 (fixture tag in `internal/graph/graph_test.go`) |

**Delta = 6 SPECs the parser does not capture** (files: `remeasure_*.txt`):
`SPEC-AGENCY-ABSORB-001`, `SPEC-AUDIT-MULTI-MODEL-001`,
`SPEC-AUTONOMY-TIERS-001`, `SPEC-CODEX-PHASE2-001`, `SPEC-FIXTURE-001`,
`SPEC-WT-DOC-001`. Root cause verified by reading each site: they are
**file-header `@MX:SPEC` sub-lines with no preceding standalone @MX tag**
(e.g. `internal/cli/init_workflow_flags.go:10`, `internal/cli/codex_jobs.go:34`)
— the scanner classifies these `DanglingSpecRef` (warning, not captured),
because the @MX sub-line protocol attaches a SPEC only to a preceding
standalone tag. One further grep-only class: `@MX:SPEC` inside a quoted Go
string on the same physical line as the tag body (extractTagContent consumes
it into the tag body; no sub-line fires).

**Verdict: the grep figure overstated parser-verifiable coverage by 6.**
The dangling file-header form is a pre-existing data-hygiene finding (either
the six files should carry a standalone tag, or the scanner should learn a
header form) — out of scope for this card; recorded as residual risk.

## 5. Gaps (미검증)

- **Full `internal/cli` suite not run locally** — only `-run 'TestGraph'`
  plus package compile (the package's full suite is known to hang locally
  under load; CI owns the full-matrix verdict — the card's release gate is
  v3.1.1 CI full-suite green).
- **Full-repo suite not run** — lane-local discipline: touched packages only.
- `moai graph build` not exercised against a NON-Go user project (16-language
  neutrality is inherited from the reused layers — codemaps markdown works
  for any language; the mx scanner is extension-aware — but no non-Go
  fixture was tested).
- No test for the `--root`-less path (`findProjectRootFn` auto-detection) —
  tests pass `--root` explicitly to avoid touching the real checkout.
- Scanner warnings (incl. DanglingSpecRef) are not surfaced by the writer —
  dangling refs are invisible in edges.jsonl (by design; see remeasure).

## 6. Residual risk (잔여 위험)

- The import layer reflects the codemaps artifact as authored (LLM-generated
  by `/moai codemaps --force`, last generated for this repo's layout). It is
  a curated 22-edge summary, NOT the complete `go list` import graph. If a
  truer adjacency is wanted later, swap layer 1's source — the writer's
  import seam is one function.
- Staleness: edges.jsonl is a point-in-time artifact; nothing regenerates it
  automatically (deliberate — on-demand command, no hooks, per the
  operational-cost framing).
- The `-.->` parser fix changes blueprint scaffold output for repositories
  whose dependencies.md uses dotted arrows (previously produced a junk
  `x -.` node; now a clean edge). Downstream blueprint consumers were not
  re-audited beyond the tiers test suite.
- The six dangling file-header `@MX:SPEC` sites remain unassociated in any
  parser-derived artifact until the data-hygiene call is made (fix files vs
  teach scanner).
