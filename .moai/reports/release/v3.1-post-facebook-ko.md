## 본문 (여기부터 복사)

🇰🇷 8월 15일 광복절에 MoAI-ADK v3.1을 내놓습니다.

이번 버전의 주인공은 **칸반 모드**예요. 이름을 붙이자면 "토큰 리밋으로부터의 해방"인데, 솔직하게 먼저 말씀드릴게요 — **토큰 한도가 없어지는 건 아닙니다.** 그런 걸 만들 수 있으면 좋겠지만요.

대신 이런 게 달라집니다.

세션 하나는 컨텍스트 창 하나를 씁니다. 긴 SPEC 하나 붙잡고 있으면 그 창이 금방 차요. 더 답답한 건, 뒤에 오는 작업이 앞의 것을 전부 지고 간다는 점입니다. 이미 끝난 계획이 리뷰하는 내내 창에 남아 있고, 그 리뷰가 문서 쓰는 내내 또 남아 있습니다. 흔한 탈출구인 `/clear`는 짐과 함께 맥락까지 버리고요.

칸반 모드는 작업 하나를 **터미널 다섯 개**로 나눕니다.

리드 세션이 전체를 몰고, 네 개의 동반 세션이 `plan` · `run` · `review` · `sync` 를 한 칸씩 맡습니다. 각 세션은 **자기 칸의 맥락만** 집니다. 한도는 그대로 있지만, 어느 세션도 네 단계치 이력을 짊어지지 않아요. 그래서 같은 예산이 훨씬 멀리 갑니다. 끝난 단계는 카드를 잃지 않고 비울 수 있고요.

재밌는 건 여기서부터입니다. 칸마다 **모델과 추론 강도를 따로** 둘 수 있어요.

첫 번째 사진이 실제로 돌아가던 화면인데, 이렇게 배치돼 있습니다.

· Plan — Opus 5 (high)
· Run — GLM 5.2 (xhigh, ultracode)
· Review — Opus 5 (medium)
· Sync — GLM 5.2 (high)

판단이 필요한 자리엔 비싼 모델을 두고, 구현 몫은 저렴한 백엔드로 보냅니다. 칸마다 필요한 추론의 깊이가 같지 않으니까요. 이 분배가 다중 세션 작업의 비용을 감당 가능하게 만드는 핵심입니다.

시작은 이렇게 합니다.

moai cc -k                          ← 리드
moai cc -k --name plan-<run-id>     ← 동반 세션, 각자 별도 터미널
moai cc -k --name run-<run-id>
moai cc -k --name review-<run-id>
moai cc -k --name sync-<run-id>

동반 세션은 터미널을 하나씩 새로 열어 직접 띄웁니다. 세션이 다른 세션을 대신 띄우진 않아요. `moai cc` 대신 `moai glm`을 쓰면 그 칸만 GLM 백엔드로 돕니다.

보드는 backlog → plan → run → review → sync → done 여섯 칸입니다. backlog엔 주인 세션을 **일부러** 두지 않았어요. 그래야 일감이 사람 손을 거쳐서만 보드에 들어옵니다. `/moai todo "..."` 로 카드를 넣습니다.

그리고 v3.1에서 가장 신경 쓴 규칙 하나 —

**리드는 동반 세션의 "다 했습니다"라는 답장으로 카드를 넘기지 않습니다.** 카드의 progress.md에서 직접 읽은 증거로만 넘깁니다. 답장은 관측이 아니라 주장이고, 세션 간 전달이 보장되지도 않으니까요. 에이전트가 "테스트 통과했습니다"라고 말하는 것과 실제로 통과한 것은 다른 일입니다. MoAI-ADK가 처음부터 붙잡고 있는 문제이기도 하고요.

두 번째 사진은 `moai web`입니다. 터미널 다섯 개를 눈으로 훑는 대신 브라우저에서 같은 상태를 봅니다. 칸반 화면에 5세션 체인과 SPEC 파이프라인이 함께 뜨고, Overview · Specs · Monitor · Settings 화면이 붙습니다. 로컬호스트에만 열립니다.

설치는 한 줄이에요. 의존성 없는 Go 단일 바이너리라 macOS · Linux · Windows에서 그대로 돕니다.

curl -fsSL https://raw.githubusercontent.com/modu-ai/moai-adk/main/install.sh | bash
