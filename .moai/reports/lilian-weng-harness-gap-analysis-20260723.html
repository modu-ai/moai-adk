2. 신규 적용 후보 5건

P1 권장 하네스 편집의 "결정 관측성"

근거: 원문 AHE(Agentic Harness Engineering) — decision observability

룰·에이전트·훅을 수정할 때마다 실패 증거 → 추정 원인 → 표적 수정 → 반증 가능한 예측을 기록하고, 예측이 빗나가면 롤백한다. 현행 Lessons Protocol은 "잘못된 패턴→올바른 접근"까지만 기록하며, 편집의 사전 예측·사후 검증 고리가 없다. 이 리포에서 반복된 "룰을 고쳤는데 같은 위반 재발" 패턴의 구조적 해법.

  • 경량 시작안: lessons 엔트리에 prediction: / verified: 필드 2개 추가

P2 권장 하네스 편집 회귀 검사 (held-in / held-out)

근거: 원문 Self-Harness — 무회귀 채택 조건

수정이 잡으려던 실패를 잡는지(held-in)와 다른 것을 깨뜨리지 않는지(held-out) 둘 다 통과해야 채택. 코드에는 TRUST 5 회귀 검사가 있으나 룰/템플릿/에이전트 본문 편집에는 정적 가드(spec-lint, neutrality-check)만 존재.

  • 시작안: 룰 편집 커밋/PR에 "이 편집이 해결하는 실패 사례 재현" 체크리스트 항목 요구

P3 검토 실패 클러스터링 기반 weakness mining

lessons-inbox.jsonl 스텁을 개별 드레인하는 대신, event_key 클러스터링으로 "반복 근본원인 → 하네스 편집 후보" 승격. harness learner Tier-ladder가 부분 수행 중이므로 신규 SPEC 대신 Epic HARNESS-EVOLVE의 EVOLVE-004 범위로 흡수 검토.

P4 검토 부정적 결과(기각 이력) 보존

"시도했으나 채택 안 함" 후보 기록 — 같은 시도 반복 방지. P1의 verified: false 기록으로 자연 흡수 가능 → 별도 작업 불필요할 수 있음.

P5 검토 컴포넌트 관측성 태깅

lessons 엔트리에 결함 표면 태그(rule / agent / skill / hook / config / template) 1개 필드 추가. P3 클러스터링의 전제이며 저비용. 원문 AHE의 7-컴포넌트 분류에 대응.

4. 부록 — 원문에서 새로 확인된 개념 (카드뉴스 요약에 없던 것)

  • AHE 3-관측성: component(7개 편집 표면) / experience(계층적 증거 요약) / decision(편집↔반증 가능 예측 쌍) — 평가기·트레이서·LLM 설정은 read-only로 격리해 reward hacking 차단
  • STOP의 핵심 발견: 자기개선 루프는 강한 모델(GPT-4)에서만 개선, 약한 모델에서는 오히려 악화 — MoAI 모델 티어 설계의 "약한 모델+높은 effort 경고"와 공명
  • Auto-research 실패 모드 6종 (Trehan & Chopra 2026): 학습데이터 기본값 편향 · 구현 드리프트 · 기억 열화 · 과잉 낙관("numerical duct tape") · 도메인 암묵지 부족 · 과학적 감각 부재 — verification-claim-integrity 독트린이 이미 방어하는 축과 상당 부분 일치
