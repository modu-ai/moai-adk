이 계획이 지금 가능해진 이유 — 2026-07-14 범용화 전략 문서는 훅·서브에이전트를 "Claude 전용, 이식 불가"로 판정했습니다. 그 판정은 더 이상 사실이 아닙니다. 현재 Codex 공식 문서는 훅 11종, 서브에이전트, 스킬, 플러그인을 모두 문서화하고 있고, 훅의 계약(stdin JSON · exit 2 차단 · stdout JSON)이 Claude Code와 사실상 동형입니다.

2. 대응 관계 지도

설계에 들어가기 전에, 두 하네스가 실제로 얼마나 닮았는지 항목별로 맞춰봤습니다. 아래 표들이 이 재설계 전체의 근거예요.

2.1 훅 — 11종 중 8종이 1:1

moai가 settings.json에 거는 훅 이벤트는 11개입니다 (moai hook <event> 디스패처가 받는 이름 기준). Codex도 11개예요.

3. 재설계 아키텍처 — 5층

핵심 원칙 하나: 하네스별 코드를 늘리지 않고, 경계를 한 곳에 모은다. moai 안에 if codex { ... } else { ... }가 흩어지면 유지가 불가능해집니다. 그래서 하네스 차이는 L1 어댑터 한 층에만 존재하게 설계합니다.

L0 — 중립 코어 (변경 최소)

SPEC 워크플로, 품질 게이트, git/worktree, LSP, MX, codemaps. 이미 하네스 중립적이고 이번 재설계에서 건드릴 이유가 거의 없습니다. 훅 로직도 여기에 남습니다 — 하네스에 묶여 있는 건 로직이 아니라 이벤트 이름과 페이로드 모양뿐이에요.

L1 — 하네스 어댑터 (신규, 이번 작업의 핵심)

moai hook <event> 디스패처 앞에 정규화 층을 하나 넣습니다. 기존 11개 서브커맨드는 그대로 두고, Codex 이벤트 이름을 받아 같은 자리로 보냅니다.

# Claude Code 쪽 (기존, 변경 없음)
moai hook pre-tool          # settings.json 이 호출

# Codex 쪽 (신규) — 같은 바이너리, 같은 로직
moai hook --harness codex PreToolUse

# 또는 이벤트 이름 자동 판별 (권장)
moai hook PreToolUse        # PascalCase → codex 방언으로 자동 인식

어댑터가 흡수해야 하는 차이는 딱 3가지입니다:

  1. 이벤트 이름 매핑 — pre-tool ↔ PreToolUse 등 8쌍 (§2.1 표)
  2. 출력 방언 — Claude의 decision ↔ Codex의 permissionDecision/continue
  3. 운영 제약 — SessionEnd 1초 예산, 출력 2,500토큰 한도에 맞춘 잘라내기

32 KiB 한도를 넘기지 않는 방법 — "계약은 위, 상세는 아래"

룰 71개를 AGENTS.md에 넣는 건 불가능합니다. 대신 세 갈래로 쪼갭니다:

내용 성격어디로예산

이건 임시방편이 아니라 Codex가 권장하는 패턴 그 자체입니다 — 문서가 "특화된 작업에 가까운 곳에 override를 두라"고 명시하고, 스킬은 애초에 "이름·설명만 상시 노출, 본문은 필요할 때"라는 점진적 공개 구조예요.

부수 효과: 이 압축은 Claude Code 쪽에도 이득입니다. 현재 always-loaded 룰이 약 210KB인데, 이 작업은 진행 중인 SPEC-ALWAYS-LOADED-DIET-001과 목표가 같습니다.

L3 — 배선 생성기

moai init --agent claude|codex|both가 각 하네스의 설정 파일을 써줍니다. 사용자는 하네스 차이를 몰라도 됩니다.

# Codex 쪽 생성물 예시 — .codex/hooks.json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command",
                  "command": "moai hook PreToolUse",
                  "timeout": 30 }]
    }],
    "SessionStart": [{
      "hooks": [{ "type": "command",
                  "command": "moai hook SessionStart" }]
    }]
  }
}

# .codex/config.toml — MCP 서버 등록 (현재 누락되어 있음)
[mcp_servers.moai]
command = "moai"
args = ["mcp-server"]

L4 — MCP (변경 없음)

양쪽 다 MCP 클라이언트이므로 moai mcp-server는 그대로 재사용됩니다. 현재 ~/.codex/config.toml에 moai가 등록조차 안 되어 있는데, L3가 이를 자동화합니다.

4. 주의해야 할 충돌 지점

두 하네스가 닮았다는 건 좋은 소식이지만, 닮았기 때문에 생기는 충돌도 있습니다. 설계 단계에서 정하고 가야 할 것들이에요.

충돌내용제안
/goal 이름 충돌 Codex에 내장 /goal이 이미 있습니다 (설정·편집·일시정지·재개·조회·해제). moai의 /moai goal과 개념이 겹칩니다. Codex에서는 내장 /goal을 쓰고, moai의 goal 평가자는 Stop 훅 계층으로만 남깁니다. 중복 구현 금지.
/review, /plan Codex 내장 커맨드와 moai 워크플로 이름이 겹칩니다. moai 쪽은 $moai-review / $moai-plan 스킬 이름으로 네임스페이스 분리.
훅 신뢰 승인 Codex는 비관리 훅을 해시 기준으로 명시 신뢰해야 실행합니다. moai update로 훅이 바뀌면 조용히 실행이 멈춥니다. moai update 후 "/hooks에서 재승인하세요" 안내 필수. L3가 이 안내를 출력하도록 배선.
SessionEnd 1초 Codex의 SessionEnd 타임아웃은 기본 1초, 최대 3초입니다. moai의 세션 종료 정리 작업이 넘칠 수 있습니다. 정리 작업을 SessionEnd 밖으로 옮기거나 async 훅으로 분리.
훅 병합 규칙 Codex는 상위 계층이 하위를 대체하지 않고 병합합니다 ("Higher-precedence config layers don't replace lower-precedence hooks"). 사용자 ~/.codex/hooks.json과 프로젝트 훅이 둘 다 실행됨을 전제로 moai 훅을 멱등하게 유지.
Rules ≠ rules Codex의 Rules는 Starlark .rules 파일로 샌드박스 밖 명령 실행을 통제합니다. moai의 .claude/rules/(지시문)와 전혀 다른 것입니다. 용어 혼동 방지 — 문서에서 "실행 정책(Codex Rules)"과 "지시문 룰(moai rules)"을 명확히 구분해 표기.
5. 마일스톤

순서는 위험이 낮고 즉시 이득이 나는 것부터입니다. M1·M2만 끝나도 Codex 사용자가 moai 자산을 쓸 수 있어요.

M1

자산 정본화 — 스킬 32개를 .agents/skills/로

스킬을 중립 경로로 옮기고 .claude/skills/는 링크로 대체합니다. Codex 쪽 코드 변경 0으로 즉시 소비 가능해집니다. Claude Code 동작은 그대로예요.

가장 싼 승리동작 변화 없음Template-First
M2
