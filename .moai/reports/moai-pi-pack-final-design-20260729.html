Goal

무엇을 하려는가 — moai-adk의 하네스 (harness — AI 코딩 도구를 감싸서 품질·비용을 통제하는 바깥 껍데기) 철학을 Claude Code·Codex·OMP 세 런타임에 똑같이 전달합니다. OMP에는 moai-pi-pack 이라는 네이티브 플러그인으로, CC/Codex에는 파일 배포로 전달합니다.

왜 지금 이 문서인가 — 이 세션에서 나온 설계·기획·감사 결과를 하나로 합친 정본(canonical)입니다. 재논의가 끝난 결정들이 §4에 정리돼 있고, 다음 세션이 바로 코드부터 칠 수 있게 §5에 복사 가능한 스파이크 코드를 넣어 뒀습니다.

01

구조 — 3층으로 나눈 이유

같은 기능을 런타임마다 세 번 만들면 세 배로 망가집니다. 그래서 철학과 콘텐츠는 가운데(코어)에 한 번만 두고, 런타임마다 다른 부분만 얇은 어댑터 (adapter — 서로 다른 규격을 이어주는 변환기)로 감쌌습니다. 아래 그림에서 세로로 내려가는 흐름이 그 구조입니다.

먼저 알아 둘 용어
런타임 (runtime)
실제로 AI가 돌아가는 프로그램. 여기서는 Claude Code · Codex · OMP 세 가지.
OMP
oh-my-pi. 플러그인을 공식으로 받아 주는 오픈소스 AI 코딩 도구(MIT).
ExtensionAPI
OMP가 플러그인에게 열어 준 확장 창구. 여기에 함수를 걸어 두면 특정 순간에 불립니다.
후크 (hook)
“이 순간이 오면 내 코드를 불러 줘”라고 미리 걸어 두는 갈고리.
SSOT
Single Source of Truth. 같은 정보를 딱 한 군데만 두는 원칙.

그림 1 — 3층 구조. 맨 아래 증거 저장소를 공유하는 것이 핵심입니다. 어느 런타임에서 작업하든 SPEC·TRUST5 결과는 한 곳에 쌓입니다.

한 프로젝트가 여러 런타임을 동시에

사용자 요구를 반영해, 하나의 프로젝트가 Claude Code와 OMP를 동시에 타깃할 수 있습니다. 어떤 런타임을 쓸지는 .moai/config/runtime.yaml 한 파일에만 적습니다(SSOT).

명령동작
moai init 대화형 다중 선택(☐ CC ☐ OMP ☐ Codex) 또는 --runtime claude-code,omp. 선택한 트리를 동시에 배포합니다.
moai update 선택 집합을 다시 확인하고 리싱크. --runtime +omp / -codex 로 증분 변경. 네임스페이스 보호는 그대로 유지.
moai cc / codex / omp 런처. 어떤 런처로 들어가든 .moai/state/ 의 SPEC·TRUST5 증거는 공유됩니다.
02

moai-pi-pack — 감사로 확정된 설계

플러그인 하나(TypeScript extension 1개)가 OMP의 확장 창구에 다섯 갈래로 걸립니다. 아래 표의 VERIFIED 는 “문서로 확인했다”는 뜻입니다 — 추측이 아니라 OMP 공식 문서에서 근거를 찾은 항목입니다.

기능 거는 후크 확인 상태 / 근거
TRUST5 게이트
히어로 경로		 tool_call → {block, reason} 또는 입력 수정 VERIFIED — 정규 경로, fail-closed(막히는 쪽이 기본)
모델 라우팅 before_provider_request + setModel / setThinkingLevel / setServiceTier VERIFIED — extensions L123 / L128 / L245
검증 경제 compact() + session.compacting + context 다이어트 VERIFIED
토큰 모니터 getContextUsage() VERIFIED
에이전트 · 스킬 · 명령 pack agents/(Explore→scout) · 21+ 스킬 · 16 슬래시명령(registerCommand) · @MX(registerTool+TTSR) · 러닝(memory + managed-skills + metaharness) VERIFIED — 11 에이전트 매핑 완료
이게 실제로 어떻게 동작하나 — TRUST5 게이트 예시
  1. AI가 git commit --no-verify 를 실행하려고 합니다. (--no-verify 는 커밋 전 품질 검사를 건너뛰라는 옵션입니다.)
  2. OMP가 실행 직전 tool_call 후크를 부릅니다 → moai-pi-pack의 함수가 깨어납니다.
  3. 명령 문자열에 --no-verify 가 있으므로 { block: true, reason: "[moai TRUST5] 정책 위반 명령 차단" } 을 돌려줍니다.
  4. 명령은 실행되지 않고, 사용자 화면에 차단 이유가 그대로 보입니다.

핵심: 품질 규칙이 “권고 문서”가 아니라 실행 시점에 실제로 막는 장치가 됩니다. 그래서 이 경로가 가장 위험이 낮고 가치가 높은 첫 구축 대상입니다.

배포 방법 (감사 지적 R-C 반영)

마켓플레이스 캐시만으로는 extension이 로드되지 않는다는 점이 감사에서 드러났습니다. 따라서 두 경로만 유효합니다 — omp plugin install moai-pi-pack (npm/git, omp.extensions 매니페스트 경유) 또는 .omp/extensions/ 에 직접 배치. 한국어 지시문은 pack의 APPEND_SYSTEM.md(KO canonical)에 둡니다.

03

가치 제안 — 히어로와 훅을 나눈 이유

똑같은 제품이라도 사용자층마다 아픈 곳이 다릅니다. 그래서 하나의 메시지로 밀지 않고 둘로 나눴습니다.

역할무엇누구에게 / 왜
히어로 품질 · 신뢰성
(SPEC · TRUST5)		 구독형 사용자 다수의 1순위 고통. 런타임과 무관하게 통합니다. 대문에 내세울 메시지.
훅 Tokenomics
(비용 통제)		 종량제 파워유저의 지갑을 직접 건드리는 이야기. 관심을 끌어오는 미끼 역할.

런타임별 강제 수단

런타임품질 강제비용 강제
Claude Code command 후크 exit-code + LSP 게이트 외부 회로차단기
Codex command 후크 exit-code + LSP 게이트 rollout_budget 에 위임
OMP tool_call block VERIFIED + lsp 툴 + advisor session_stop{block} (메인 세션 전용)

세 런타임 모두 결과 증거는 .moai/state/ 한 곳(SSOT)에 씁니다. 검증 경제는 compact + context 다이어트 + mnemopi 로 처리합니다.

04

감사가 잡아낸 함정 4개 (R-A ~ R-D)

감사(moai-pack-audit-20260729.md)에서 나온 지적 네 가지입니다. 네 개 모두 설계에 이미 반영되어 재논의 대상이 아닙니다. 여기 적힌 대응을 그대로 따라가면 같은 함정을 다시 밟지 않습니다.

함정
위험도
확정된 대응
R-A — session_stop 이 메인 세션에서만 발화. 서브에이전트에서는 안 불림
HIGH
예산 강제는 오케스트레이터(메인) 단에서 총괄. 서브에이전트는 task.isolation 한도 + turn_end 모니터 + context 주입 게이트로 대신합니다. moai 위임 패턴과 정합.
R-B — raw 타이머(setInterval 직접 호출)를 쓰면 세션이 크래시
HIGH
예산 모니터는 반드시 ctx.setInterval 사용. 예외 없음.
R-C — 마켓플레이스 캐시만으로는 extension 미로드
MED
omp plugin install(매니페스트 경유) 또는 .omp/extensions/ 직접 배치 — 두 경로만 지원.
R-D — 관측성. 화면이 없는 환경에서 상태를 볼 수 없음
LOW
statusline interactive 를 1순위로. CI/RPC/헤드리스는 로그(pi.logger / ~/.omp/logs/) + ctx.hasUI 가드로 보조.

moai-pi-pack/spike.ts  ·  원천: extensions.md / authoring-extensions.md
// P-1 확인 스파이크
import type { ExtensionAPI } from "@oh-my-pi/pi-coding-agent";

const BUDGET_TOKENS = 200_000; // 예시 예산

export default function (pi: ExtensionAPI) {
  // (1) TRUST5 게이트 — 금지 tool_call 차단 (fail-closed, VERIFIED)
  pi.on("tool_call", async (event) => {
    const cmd = String((event.input as { command?: unknown }).command ?? "");
    if (event.toolName === "bash" && /--no-verify|rm -rf \//.test(cmd)) {
      return { block: true, reason: "[moai TRUST5] 정책 위반 명령 차단" };
    }
  });

  // (2)+(3) 예산 모니터 — 반드시 ctx.setInterval (R-B: raw 타이머 = 세션 크래시)
  let over = false;
  pi.on("session_start", async (_e, ctx) => {
    ctx.setInterval(() => {
      const u = ctx.getContextUsage();
      if (u && (u.tokens ?? 0) > BUDGET_TOKENS) {
        over = true;
        if (ctx.hasUI) ctx.ui.setStatus("moai-budget", "⚠ 예산 초과");
      }
    }, 30_000);
  });

  // (2) 메인 세션 회로차단기 — stop_hook_active 가드 필수(없으면 무한 continue 루프)
  //     R-A: 서브에이전트 세션에서는 session_stop 자체가 미발화됨
  pi.on("session_stop", async (event) => {
    if (event.stop_hook_active) return;        // ← authoring-extensions L206 필수 가드
    return over ? { decision: "block", reason: "[moai Budget] 토큰 예산 초과" } : undefined;
  });

  // (4) 라우팅 타이밍 점검 — before_provider_request 페이로드 관찰
  pi.on("before_provider_request", async (_event, ctx) => {
    pi.logger?.debug?.("[moai] route probe", { model: ctx.model });
  });
}
이 코드에서 절대 빼면 안 되는 한 줄

if (event.stop_hook_active) return; — 이 가드가 없으면 세션이 “멈춰라 → 계속해라”를 무한 반복합니다. session_stop 에서 block을 돌려주면 세션이 다시 이어지는데, 그때 또 session_stop 이 불리기 때문입니다. 이 플래그는 “지금 이미 stop 후크 처리 중”이라는 표시라서, 그때는 그냥 빠져나와야 루프가 끊깁니다.

스파이크 수락 기준

tool_call block 의 reason 이 화면에 보인다
메인 세션의 session_stop block 이 발화한다
ctx.setInterval 이 크래시 없이 안정적으로 돈다
setModel 이 후속 요청에 실제로 영향을 준다
