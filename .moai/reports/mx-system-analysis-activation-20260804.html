1. MX 시스템 실체 — 인벤토리

MX는 단순한 주석 규칙이 아니라 프로토콜 계층 + 기계적 구현 계층의 이중 구조다. 아래는 전체 구성요소다.

2. 4축 종합 진단

프로토콜 · CLI·scanner · 태그 커버리지 · 문서·배포 네 축으로 나눠 현 상태와 개선점을 진단한다.

2.1 프로토콜 축 견고

mx-tag-protocol.md는 단일 SSOT로 타입·생명주기·제한·문법을 일관되게 정의한다. 특히 @MX:DEBT의 CEILING + UPGRADE 트리플릿과 "UPGRADE 없으면 rotRisk" 규칙은 단순 주석 규칙을 넘어 자체 정정 메커니즘이다.

  • 강점: DEBT는 TODO와 명확히 구분됨(완료된 코드의 의도적 단순화 vs 미완료 작업). 자동 승격(WARN) 규칙이 DEBT엔 적용되지 않아 거짓 위험 신호를 차단.
  • 갭: note_per_file: 10, todo_per_file: 5 한도가 mx.yaml엔 있으나 프로토콜 본문엔 누락 — 문서·설정 간 미세 드리프트.
  • 갭: broken SPEC link → @MX:LEGACY 전환 규칙(references/mx-tag.md)이 있으나, 실제 LEGACY 태그가 3개뿐이라 규칙이 실제 작동했는지 검증 부족.

2.2 CLI · scanner 축 구현 풍부 복잡도 주의

moai mx scan은 한 패스에 .moai/state/mx-index.json을 빌드하고, moai mx query가 이를 읽어 --kind, --danger, --fan-in-min, --spec, --since 필터로 조회한다.

  • 강점: DEBT rotRisk가 실제로 동작함을 검증(scanner_debt_test.go:57 → "rotRisk":"no-trigger" 출력). LSP 기반 fan-in + textual fallback 이중 경로로 환경 의존성 흡수.
  • 갭 (P0): index 신선도 — grep 전수 1,567태그 vs index 803태그 = 764개 누락. 마지막 scan이 2026-07-29로, 그 후 추가된 태그가 index에 반영되지 않았다. moai mx query가 stale index를 반환하면 rotRisk·fan-in 신호가 왜곡된다.
  • 갭 (P2): internal/mx/resolver.go가 "placeholder for full fan-in per SPC-004"로 표시 — 일부 해석 경로 미완료. CGO tree-sitter 의존성(complexity 측정)이 빌드 복잡도를 높임(measure_nocgo.go 폴백 존재).
  • 갭 (P2): internal/astgrep/ analyzer가 validator에 "currently unused"로 주석 표시 — 연동 미흡.

2.3 태그 커버리지 · 품질 축 과소태깅

가장 뚜렷한 개선 기회다. ANCHOR(343)·NOTE(385)는 풍부하지만 TODO(2)·DEBT(5)는 극단적으로 부족하다.

  • SATD 연구 대비 과소: 학계 연구(arXiv 2601.06266)는 LLM 생성 코드의 SATD(self-admitted technical debt) 빈도가 85→90%라고 보고한다. 419개 파일에 DEBT 1개(프로덕션 non-test)는 실제 부채 규모와 심하게 불일치 — 태깅이 현실을 반영하지 못함.
  • DEBT sub-line 불일치: @MX:UPGRADE 10개 vs @MX:CEILING 2개(grep). DEBT-CEILING-UPGRADE 트리플릿이 깨진 경우가 대부분 → rotRisk 후보 다수. 실측 index의 DEBT 5개 중 4개가 test fixture이므로 프로덕션 DEBT 사실상 1개(internal/config/cache_config.go, CEILING/UPGRADE 없음 → rot).
  • SPEC 연결 약함: spec_associations 85/803 = 10.6%. @MX:SPEC sub-line이 있어도 연결되지 않은 태그가 다수.
  • 긍정: @MX:REASON 464개 — WARN/ANCHOR 필수 필수 필드가 잘 준수됨(강제 메커니즘 작동).

2.4 문서 · 배포 축 품질 양호 배포 비대칭

docs-site 4개국어 페이지(advanced/mx-tags.md 개념 + utility-commands/moai-mx.md 명령)는 구조화·현지화가 잘 돼 있다.

  • 갭 (P1) — 배포 비대칭: MX 프로토콜(규칙·스킬·명령)은 template로 배포되지만 mx.yaml은 repo-local only(template tree에 없음). 외부 사용자는 16언어 warn_patterns·임계값·danger_categories 없이 MX를 사용하게 된다. Go scanner는 moai binary에 내장되어 배포되지만, config 없이는 기본값으로만 동작.
  • 갭 (P2) — 문서 미설명: scanner 고급 기능(rotRisk 산출 로직, LSP fan-in 작동 조건, CGO complexity 경로)이 docs-site에 설명되지 않음. README FAQ "왜 모든 함수에 @MX 태그가 없나요?"는 있으나, scan 자동화 시점·index 갱신 주기는 미기술.
  • 강점: CHANGELOG에 실제 @MX:ANCHOR → @MX:NOTE 강등 보정 사례(SPEC-HOOK-TRACE-FLUSH-001, 허위 fan_in=24 → 실측 0)가 기록되어 있어 프로토콜이 스스로에게 적용됨(self-dogfood)을 입증.

3. 외부 자료 — 코드 주석 설계 × 에이전트 코드 이해 교차점

MX가 두 영역(코드에 맥락을 새기는 접근 + 에이전트가 코드를 탐색하는 접경)의 교차점에 있다는 전제로, 4개 카테고리의 근거를 수집했다. 모든 URL은 2026-08-04에 접근을 검증했다.

3.1 In-context annotation 계열 — MX의 직접 동류

블로그 · 2026-01 · 표준 제안

AI Annotations: Embedding Context in Your Codebase — Brad Murry

@! 접두사로 semantic metadata를 코드에 직접 내장하는 Agent Annotation Standard 제안. Toon Format 속성(JSON/YAML보다 간결), inline + block(@!begin/@!end) 문법. 핵심 keys: readonly, link, todo, canon, metadata.

MX와의 관계: 거의 동일 철학("annotate once, every agent benefits" · git-versioned · in-source synchronization). MX가 타입화 + lifecycle rule + sidecar index로 더 정교함(§4 비교표).

블로그 · 산업

LLM Knowledge Base for Coding Agents: Beyond RAG — Verdent

전통적 RAG를 넘어 코딩 에이전트가 세션 간 맥락을 누적하는 knowledge base 패턴. MX sidecar index가 "코드에 내장된 knowledge base"로 기능하는 방식과 정합.

3.2 Context engineering — just-in-time retrieval × progressive disclosure

Anthropic Engineering · 권위 BP

Effective context engineering for AI agents — Anthropic

context engineering = "최소의 고신호 토큰 집합을 큐레이션". just-in-time retrieval(가벼운 식별자로 runtime에 동적 로드)과 progressive disclosure(탐색을 통한 점진적 발견)가 핵심. Claude Code는 CLAUDE.md를 up-front, glob/grep을 just-in-time으로 사용.

MX 정합: @MX 주석은 "synchronized in-source context", moai mx query는 "just-in-time retrieval"(파일 경로라는 가벼운 식별자로 sidecar에서 동적 로드) — Anthropic이 설명하는 하이브리드 모델 그 자체.

Martin Fowler · BP

Context Engineering for Coding Agents — Martin Fowler

코딩 에이전트에 API·도구 접근을 언제·어떻게 열어줄지, 맥락을 어떻게 구조화할지에 대한 심층 가이드.

참고: Context Engineering for Multi-Agent LLM Code Assistants (arXiv 2508.08322) · Navigation Notes – Agentic Coding · Sourcegraph — Context Retrieval & Evaluation

3.4 SATD — @MX:DEBT 태그의 학술 근거 핵심

MX의 DEBT 태그 설계는 self-admitted technical debt(SATD) 연구 라인과 정확히 정합한다. 이는 MX 설계의 가장 강력한 학술 뒷받침이다.

논문 · arXiv 2601.06266 · 학술

Self-Admitted Technical Debt in LLM Software (2025)

LLM 시대 SATD 최초 실증 연구. SATD 빈도가 ML/non-ML 코드 대비 LLM 코드에서 85→90%로 상승. MX DEBT 태깅 과소(1개)는 이 연구가 예측하는 실제 부채 규모와 불일치.

논문 · ACM 3756681.3756976 · 학술

Technical Debt Across LLM Systems — Aljohani et al. (2025)

LLM 특화 SATD의 기원·빈도·완화 전략 대규모 실증.

논문 · ScienceDirect · 학술

SALA — LLM-based SATD Classification (Fontana et al. 2025)

LLM 기반 binary·다중클래스 SATD 탐지. fine-tuned LLM이 전통 text-mining을 크게 상회 → MX scanner가 자동 DEBT 탐지를 강화할 근거.

논문 · TU Delft · 학술

Impact of SATD on LLM Code Completion

The Heap(Java 500만 파일) 기반 — SATD가 LLM 코드 생성 성능을 측정가능하게 저하시킴 → 부채 태깅·관리가 에이전트 품질에 직결됨.

추가: Sierra et al. — A Survey of SATD (JSS 2019) · Intention Is All You Need (arXiv 2502.08172) · The Theory of Layered Documentation

4. MX vs Agent Annotation Standard — 표준 비교

Brad Murry의 @! 표준(2026-01)은 MX와 가장 가까운 독립 제안이다. 두 접근을 비교해 MX의 설계 위치를 확인한다.

6. 추가 축 — 온톨로지(Ontology) 도입 검토

사용자 제안으로 탐색한 추가 방향. MX 태그 체계를 의미론적 온톨로지로 발전시키는 가능성을, 기회·위험·진화 경로로 검토했다.

6.1 MX의 현재 의미론적 위치

메타데이터 체계는 일반적으로 controlled vocabulary → taxonomy → ontology → knowledge graph 스펙트럼을 따라 성숙한다. MX의 현재 위치:

단계정의MX 해당 여부
Controlled vocabulary통제된 용어 집합해당 NOTE/WARN/ANCHOR/TODO/DEBT 5 타입
Taxonomy계층 분류 + 속성해당 sub-key(SPEC/REASON/CEILING/UPGRADE), lifecycle 단계, priority P1-P5
Ontology개체·관계·제약의 형식 모델부분 fan-in 관계·강등 규칙은 있으나, 태그 간 시맨틱 관계·계층 미형식화
Knowledge graph그래프 구조 + 추론미해당 sidecar index는 flat 태그 목록(JSON), 그래프·추론 없음

결론: MX는 taxonomy 상단 ~ ontology 하단에 위치. 온톨로지 도입은 "새 기능 추가"가 아니라 "이미 어렴풋이 있는 의미론을 형식화"하는 방향이다.

6.2 온톨로지 도입 스펙트럼 (3단계)

A. Lightweight relation layer 권장 후보

태그 간 시맨틱 관계와 계층만 sidecar index에 추가. RDF/OWL 스택 없이 기존 JSON 확장.

  • 관계 필드: implies(WARN→주의), demotes_to(ANCHOR→NOTE), relates(SPEC↔태그)
  • 계층: Risk 상위 타입 아래 WARN/DEBT, Intent 아래 NOTE/ANCHOR
  • 검증: "정의되지 않은 규칙" 탐지 (DLT Hub: taxonomy가 verification bar를 높임)

비용: 중간 · 영향: 높음 · MX 단순성 보존

B. Formal ontology (OWL 경량)

OWL/Turtle로 MX 타입·관계를 형식화. 추론 엔진(DLV, HermiT) 옵션.

  • MX 타입 → OWL class, sub-key → property
  • 추론: "UPGRADE 없는 DEBT → rotRisk"를 OWL 규칙으로 인코딩 (이미 scanner가 함 → 이중화)

비용: 높음 · 영향: 중간 · 이미 scanner가 추론을 수행 중이므로 중복 위험

C. Full knowledge graph + GraphRAG 장기

코드 엔티티(함수·클래스·모듈·SPEC)를 노드, 호출·의존·태깅을 엣지로 하는 코드 지식 그래프 구축. Neo4j 등 그래프 DB + GraphRAG로 에이전트 검색.

비용: 매우 높음(신규 스택) · 영향: 잠재 큼 · 현재 MX의 "in-source + grep/query" 단순성과 철학 충돌(Anthropic: smallest set of high-signal tokens). 별도 대규모 SPEC 필요.

6.3 외부 근거

논문 · arXiv 2505.14394 · 학술

Knowledge Graph Based Repository-Level Code Generation (2025)

코드베이스를 지식 그래프로 표현해 LLM이 컨벤션에 정합한 코드를 생성. MX sidecar → 코드 KG 진화의 직접 근거.

논문 · arXiv 2604.00555 · 학술

Neurosymbolic 3-Layer Ontology (Role/Domain/Interaction)

LLM 에이전트 grounding을 위한 3층 온톨로지. 패턴매칭과 도메인 정확 추론 사이 시맨틱 갭 해소.

Semantic Web Journal · 학술

Agentic AI for Ontology Grounding (Sadruddin et al. 2025)

LLM이 발견한 스키마를 형식 온톨로지에 grounding — taxonomy→ontology 진화 경로의 모델.

블로그 · BP

Ontology Engineering — DLT Hub

taxonomy가 verification bar를 높인다 — LLM이 미정의 규칙을 탐지·거부. MX가 이미 taxonomy로 이 역할을 부분 수행 중.

참고: Enterprise Knowledge — Ontology & KG in the Age of AI Agents · deepsense.ai — Ontology-Driven KG for GraphRAG · Neo4j Going Meta — Agent Skills for Ontologies · OWL — Wikipedia

균형 잡힌 평가 (push back 포함). 온톨로지 도입은 매력적이지만 세 가지 경고가 있다: (1) MX의 현재 가치는 "in-source 주석 + grep/query"라는 극단적 단순성에 있고, Anthropic context engineering 원칙("smallest set of high-signal tokens")과 정합한다 — 무거운 온톨로지 스택은 이를 훼손할 수 있다. (2) scanner가 이미 rotRisk·강등 등 "추론"을 수행 중이므로, OWL 추론 엔진은 중복이다. (3) RDF/OWL 도입은 새 의존성·학습곡선·유지비를 발생시킨다.

실용적 추천: 온톨로지로의 점프(C)보다 단계 A(lightweight relation layer) — sidecar index에 관계 필드·계층만 추가해 검증 능력을 높이되, MX의 단순성·grep 친화성은 보존. 형식 OWL(B)과 코드 KG(C)는 A의 가치가 입증된 후 별도 SPEC으로.

7. 결론 및 다음 단계

핵심 결론. MX는 과소평가된 시스템이다. 외부에서는 "주석 규칙 정도"로 보일 수 있으나, 실제로는 타입화된 annotation + 생명주기 엔진 + sidecar index + 자체 정정(강등/rotRisk) + 16언어 scanner를 갖춘 도구-지원 시스템이다. 설계 철학은 2026년 외부 표준(Brad Murry @!, Anthropic context engineering)과 학계 SATD·RACG 연구와 정합하며, 기능적 우위까지 보유한다. MX는 "활성화가 필요한 미완 프로토콜"이 아니라 "이미 선두에 있으나 운영 갭이 있는 성숙 시스템"이다.

활성화를 위한 3가지 즉시 실행점

  1. 신호 신뢰성 확보(P0): index 신선도 자동화 + DEBT rot 처리 — moai mx query가 항상 최신·정확한 신호를 반환하도록. 이것이 MX "활성화"의 전제 조건이다.
  2. 현실 반영(P1): TODO/DEBT 과소태깅 해소 + SPEC 연결 강화 — 태그 분포가 실제 부채·의존성 규모를 반영하도록. SATD 연구가 예측하는 빈도에 근접.
  3. 배포 완결성(P1): mx.yaml template 배포 — 외부 사용자가 16언어 설정 없이 MX를 쓰는 갭을 메움. 분산 일관성 확보.

다음 단계

본 보고서는 분석 + 외부 근거 + 우선순위 제안까지를 산출한다(사용자 선택: 보고서 후 선택 반영). 후속으로 AskUserQuestion 게이트에서 반영할 항목을 선택받은 뒤, 승인된 범위만 SPEC 주기(또는 직접 수정)로 반영한다. P0 두 건은 단일 커밋·단일 세션으로 즉시 해결 가능한 빠른 승리다.
