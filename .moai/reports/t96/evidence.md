## Design decisions

1. **Operator-act rule, mechanically.** The loop dispatches only items whose queue state is already `picked` (`moai todo next <n>` is the operator's mutation; the skill forbids running it and forbids `moai todo add`). "Pick the next card" in the loop = choose the next *dispatchable* admitted card (oldest `picked`, no live worker, no blocker). Empty queue = legitimate idle.
2. **No gate bypass, concretely.** A card whose next step needs an un-recorded human decision (kickoff approval, review severity, scope choice) is reported `blocked-for-operator` and left `picked`; the loop never decides. Complement: no push / PR / merge / branch deletion / worktree disposal from the loop at all — integration stays with the operator (the card branch is unpushed; its worktree is the work's only instance).
3. **disallowed-tools scoped to the skill, not globally.** loop.md is plain Markdown with no frontmatter surface; the unified `moai` skill's frontmatter would bind every `/moai` invocation. A standalone `moai-kanban-foreman` skill binds exactly the loop-iteration turn. `user-invocable: false` per house style for `moai-workflow-*`/`moai-foundation-*` skills.
4. **Monitor composition.** `backlog.json` is rewritten by temp-file + atomic rename on every mutation (verified in `internal/kanban/backlog_store.go` → `atomicfile.Replace`), so handle-following tools (`tail -F`) are the wrong shape. The persistent Monitor runs a POSIX `cksum` poll (5 s, one tiny read per tick) emitting one line per content change — event-streamed wakeups instead of per-iteration polling, matching the documented dynamic-`/loop` + Monitor composition. Re-arm after session resume (monitors never restore). Primitive behavior verified; see Gaps.
5. **Background persistence** is native: start session → bare `/loop` → background the session (tasks carry over, keep running without a terminal). Escalation/stop conditions documented in the skill.
6. **Worker contract**: Agent spawn, `isolation: "worktree"`, relative paths, fixed-field dispatch block (pointer, not a copy — aligned with the kanban dispatch rule on this branch), branch renamed `WT-<card-id>`, evidence at `.moai/reports/<card-id>/evidence.md` with verbatim tails + gaps + residual risk, lane-local verification only, commit by explicit pathspec, never push. One write-capable worker at a time.
7. **Factory seam (t85 boundary).** Single-worker dispatch is the only mode. A marked "Factory seam (reserved, not implemented)" section in the skill is where multi-lane factory routing lands; until then the loop reads no factory state and launches no lanes. The seam text references only the neutral multi-lane launcher surface (the factory launcher code ships on this branch via `internal/cli/factory.go`), no internal ids.
8. **Template neutrality**: English-only, no SPEC ids / REQ tokens / dates / SHAs / PR numbers / absolute home paths; verified by the strict leak + neutrality suites (green below).
