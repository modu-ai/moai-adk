# t520 — 승인 출처 기록

이 카드의 plan→run 경계에서 두 건의 운영자 결정을 받았다. **두 결정 모두 이 레인
세션(lane-4)에서 `AskUserQuestion` 으로 받은 것이며, 리드는 관측하지 않았다.**
리드가 이 기록을 요구한 이유는 「다른 채널의 판정을 관측 없이 인용」하는 형태를
막기 위해서다.

## 결정 1 — plan-audit 반복 상한 1회 초과

- 물은 것: Tier M 감사 반복 상한(2회) 도달 후, 최종 수리본(`spec.md` 0.4.0)이
  미감사 상태로 남았다. 상한을 넘겨 3라운드를 돌릴 것인가.
- 제시한 근거: 관측된 재발 패턴 — 1차 수리(0.81 대응)가 N1~N5 를 들여왔고,
  그중 N1 은 run 이 그대로 구현하면 손상(대상 없는 심링크 16개)을 만드는 결함.
  두 라운드 연속 「수리가 새 차단 결함을 들여옴」.
- 운영자 선택: **「한 번 더 감사」**
- 결과: 라운드 3 = PASS 0.91.

## 결정 2 — Implementation Kickoff Approval (조건부)

- 물은 것: run 단계(실제 코드 수정) 진입 승인.
- 운영자 선택: **「감사 통과 후 자동 진행」** — 감사가 통과하면 재질의 없이 run
  진입, 실패하면 중단·보고.
- 조건 충족: 라운드 3 PASS 0.91 → 조건 성립. R3-1 수리 후 run 진입.

## 이 기록이 단언하지 않는 것

- 운영자는 **배포·릴리스를 승인하지 않았다.** 승인 범위는 run 진입까지다.
- 운영자는 **병합 창을 승인하지 않았다.** 창은 리드 지명 사항이다.
- 리드의 메시지는 승인이 아니다 — 리드는 이 카드의 사용자가 아니며, 그의 수용
  표명은 저울에 올린 입력이지 게이트 통과 근거가 아니다.

## 부수 관측 — SPEC 디렉터리 안의 잔류 런타임 상태

`.moai/specs/SPEC-UPDATE-MIRROR-HEAL-001/.moai/state/` 아래에 `config-cache.json` 과
`context-usage/<session>.json` 이 있다. 이 카드가 만들지 않았고 지우지도 않았다 —
untracked 라 삭제에 git 안전망이 없다. gitignore 되는 것은 확인했다(대조군 포함):

```
git check-ignore -v …/.moai/state/config-cache.json → .gitignore:228:**/.moai/state/  rc=0
git check-ignore -v …/spec.md                       →                                 rc=1
```

무언가가 CWD 를 프로젝트 루트가 아니라 SPEC 디렉터리로 둔 채 상대 경로
`.moai/state/…` 를 쓰고 있다. 이 카드의 범위가 아니므로 `/moai:feedback` 대상으로
남긴다.
