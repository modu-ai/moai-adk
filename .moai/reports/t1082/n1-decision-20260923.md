# t1082 — N1 수리안 선택 기록 (2026-09-23)

card: t1082 · SPEC-FACTORY-LANE-WORKTREE-HANDOFF-001 · 입력: `plan-audit-iter5.md` N1, super-advisor E2 자문(비구속)

## 결정

**② 단독 채택 — launcher 가등록 트랜잭션이 같은 slot 의 미종결 handoff 를 `NACK`/`STALE_GENERATION` 으로 종결한다. tombstone·BOUND receipt·dispatch release 는 쓰지 않는다.** 자문이 함께 제시한 백스톱 D(dead-source UserPromptSubmit 종결)는 넣지 않고 잔여 위험으로 기록한다.

## 근거

- ②는 불변식 하나로 닫힌다: 미종결 handoff 동안 slot 행은 reserved source tuple 과 같고, 그 행을 바꾸는 다른 커밋은 같은 트랜잭션에서 handoff 를 종결한다. REQ-FLH-016(admission)과 ②(등록)가 양쪽을 막아 ①이 전제한 "launch-pending 행 + 미종결 handoff" 상태가 도달 불가가 된다.
- launcher 등록이 커밋되는 조건(source owner 가 current 가 아니거나 같은 identity, `store.go:342-359`)은 곧 rebind CAS 가 영원히 실패할 조건이다. 따라서 즉시 종결은 결과를 바꾸지 않고 판정 시점만 앞당긴다(자문 추론, 코드 좌표는 자문이 읽어 확인).
- ①은 N1 순서 하나만 막는다. SessionStart 가 alias session 으로 먼저 결합한 뒤에는 행이 pending 이 아니어서 예외가 적용되지 않고, 죽은 handoff 가 t1074 alias 교정을 무기한 막는다(자문 F①-1, F①-2).
- REQ-FLH-017 은 launcher 가 이긴 경우 tombstone 을 금지한다(spec.md:132). 그래서 ②의 종결에는 tombstone 을 붙이지 않는다 — 리드 요청 문구의 "tombstone 포함"은 이 조항과 충돌해 채택하지 않는다.
- alias 교정 테스트 `TestFactorySessionStartCannotRotateAuthoritativeUserPromptBinding` 과 `TestFactoryUserPromptSubmitRebindsLaunchPendingPeer` 는 HEAD `cac8557af` 에서 PASS(자문 실행 출력 V10). ②는 handoff 가 없을 때 t1074 동작을 바꾸지 않는다.

## D 를 넣지 않은 이유

- 이번 iter-6 이 마지막 반복이다(리드 [HARD]). D 는 결과가 발화 순서에 따라 BOUND/NACK 로 갈리는 경로와, liveness 불명 → current 아님 판정이 §9 "liveness 불명 → ABANDONED" 와 부딪히는 긴장을 새로 들여온다.
- D 가 막는 F②-3(launcher 를 거치지 않은 재기동 — factory 환경변수를 가진 셸에서 직접 `codex resume`)은 발생이 관측되지 않았다.
- 감사자가 쓴 N1(launcher 재기동 + SessionStart 선행)은 ② 만으로 닫힌다.

## 잔여 위험 (SPEC 에 기록)

- F②-3: launcher 밖 재기동이면 lane 이 죽은 source 행에 묶여 UserPromptSubmit 이 REQ-FLH-018 로 거부된다. launch-pending 고아는 아니지만 REQ-FLH-017 의 목적은 어긴다.
- headless fork 결과가 NACK 뒤 도착하면 endpoint 없는 thread 가 남는다(정리 문제).

## 같이 반영하는 리드 전달 사항

`design.md:193` "Duplicate dispatch 는 t1074 idempotency key 에 handoff generation 을 결합한다" 는 AC-FLH-008("identical idempotency keys before/after BOUND … one body execution")과 모순된다 — generation 을 키에 섞으면 BOUND 전후 키가 달라진다. 현행 t1074 스키마의 키로 중복을 판정하고, generation 은 키가 아니라 stale NACK 판정에 쓰도록 문구를 고친다. 키 기준(송신 세션 vs lane slot)의 최종 결정은 t1100 몫이다.
