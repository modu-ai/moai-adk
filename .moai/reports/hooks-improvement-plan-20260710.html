2위험 평가

템플릿 hooks 레이어는 구조적으로 건전합니다 — 약 27개 wrapper는 충실한 thin stdin-forwarder이며 준수도 점수가 0.82~0.88로 모이고, matcher / handler-type / exit-code / CLAUDE_ENV_FILE 규율이 정확하며, 자체완결형 거버넌스 게이트는 미묘한 stdout JSON is honored only on exit 0 규칙을 올바르게 준수합니다.

실질적 위험은 두 곳에 집중됩니다. 첫째, 두 블로킹 품질 게이트(team-ac-verify.sh on TaskCompleted, sync-phase-quality-gate.sh on Stop)가 비정형 JSON을 출력합니다 — TaskCompleted는 잘못된 필드(decision:block 대신 continue:false+stopReason), Stop은 잘못된 네스팅(최상위 decision 대신 hookSpecificOutput+hookEventName)을 사용합니다. 이는 런타임이 JSON 스키마 검증을 강화할 때만 발현되는 잠재적 silent-disable 결함이지만, 발현 시 전체 품질강제 표면이 신호 없이 차단을 멈춥니다. 둘째, handle-pre-tool.sh.tmpl이 printf | moai; exit 0 패턴으로 moai binary의 exit 2(PreToolUse 거부)를 wrapper 단에서 덮어쓰고 stderr까지 로그로 redirect합니다 — moai가 exit-2 경로를 쓰면 거부 사유가 Claude에게 전달되지 않습니다(JSON permissionDecision:deny 경로는 보존).

추가로 권위적 레퍼런스 hooks-system.md가 공식 스펙과 8곳 이상에서 드리프트되어, 모든 차후 hook 작성자가 원천에서 잘못된 정보를 받게 됩니다. MEDIUM 등급의 운영 위험으로 마무리됩니다: 세 observation tap이 async가 정답인 user-prompt / turn-end 경로에 동기로 있고, 두 블로킹 게이트(TeammateIdle/TaskCompleted LSP 게이트, PreCompact memo 저장)가 5s로 과소 타이밍되어 부하 시 조용히 no-op가 되며, 공유 silent-exit-0 fail-open이 WorktreeCreate(fail-closed: 생성 중단)와 PermissionRequest(보안 부정: silent allow)에서 의미가 반전됩니다. 현재 관대한 런타임에서는 망가지지 않았지만, 단일 우선순위 패스(JSON 계약 수정 + doctrine 갱신 + async/timeout 조정)가 잠재적 silent-failure 표면을 상당히 줄입니다.

4공통 패턴 (Cross-cutting themes)

2개 이상 그룹에서 재발하는 패턴 — 최고 레버리지 수정 지점.

HIGH 블로킹 게이트 JSON 출력 계약 위반 (잘못된 필드 / 잘못된 네스팅)

영향 그룹: gates-doctrine · subagent-task-team · tool(직접분석). team-ac-verify.sh(TaskCompleted)와 sync-phase-quality-gate.sh(Stop)가 decision:block+reason을 잘못된 이벤트(TaskCompleted의 공식은 continue:false+stopReason) 또는 잘못된 네스팅(Stop은 hookSpecificOutput:{hookEventName,decision,reason} 요구, bare 최상위 decision 아님)으로 출력. 런타임은 현재 관대하지만, JSON 스키마 검증이 강화되면 거버넌스 게이트가 신호 없이 차단을 멈춤. 동일한 잘못된 TaskCompleted 형태가 2회 인코딩(GAP-GD-01 == GAP-STT-02)되고 agent-common-protocol.md Ledger Closure (b)에도 재인코딩.

MEDIUM hooks-system.md doctrine이 6그룹에 걸쳐 공식 스펙과 드리프트

영향 그룹: compact · subagent-task-team · observation · config-env-worktree · permission-elicitation · gates-doctrine (사실상 전체). 단일 권위 레퍼런스 파일이 최소 8곳에서 stale: PreCompact 비블로킹 오분류, SubagentStop stdout 불완전, Notification/SessionEnd/StopFailure matcher 과소산출, FileChanged literal-not-regex 제약 미문서화, UserPromptSubmit/PermissionRequest 필드집 불완전, 이벤트별 handler-type 행 누락, "exit 2 is universal" 과잉일반화, hook-independence.md row (g) stale 10s(실제 60s). 모든 차후 hook 작성자가 이 표를 참조하므로 드리프트가 곱해짐 — 단일 갱신 패스가 최고 레버리지.

MEDIUM async가 정답인 곳에 동기 observation tap 배선

영향 그룹: observation. PostToolUse observe tap은 올바르게 async:true를 가지지만, 세 형제 — UserPromptSubmit(가장 사용자 대면적), Stop, SubagentStop — 는 동기. observation tap은 비결정적이므로 async가 아무것도 잃지 않고 user-prompt 경로와 turn-end(death-spiral 위험) 경로에서 I/O 지연세를 제거. 체계적 비대칭, settings.json.tmpl에서 한 번 수정.

MEDIUM 블로킹 품질 게이트 5s 과소 타이밍

영향 그룹: subagent-task-team · compact. 보편적 5s fast-path 정책이 문서화된 목적이 실작업을 요구하는 이벤트를 저해: TeammateIdle/TaskCompleted는 실제 코드베이스에서 5s를 초과하는 LSP-error-threshold 게이트 실행, PreCompact는 PostCompact가 의존하는 session-memo 저장. 이들에서 timeout kill은 게이트를 silent no-op으로 만드는데, 정확히 tree가 느리고 오류가 많을 때 발생. sync-gate는 이미 60s 선례가 있음; 이 게이트들도 유사 여유 또는 fast-pre-check + async-deferred 분할 필요.

MEDIUM moai binary 미해결 시 silent fail-open / fail-closed

영향 그룹: subagent-task-team · config-env-worktree · permission-elicitation · tool(직접분석). 약 31개 wrapper가 silent exit 0로 끝나는 3-tier resolution chain 공유. 그 exit-0는 observer 이벤트에서는 의미론적으로 올바르지만 WorktreeCreate(exit-0+empty-stdout이 active-creator 계약에 따라 생성 중단 — fail-closed)와 PermissionRequest(exit-0 = ALLOW, 권한 게이트를 조용히 중화 — 보안 부정)에서 반전. 기존 hook-independence.md mode-A SessionStart-probe 권고가 모든 wrapper를 한 번에 표면화; WorktreeCreate/PermissionRequest 차원이 그 안에서 우선순위.

LOW 파일시스템·JSON 싱크로의 미검증·미이스케이프 입력

영향 그룹: subagent-task-team · gates-doctrine · tool(직접분석). MOAI_HOOK_STDERR_LOG가 모든 wrapper에서 미검증으로 읽혀 mkdir/mv/redirection에 투입, gateguard-fact-force.sh는 raw session_id/file_path interpolation로 state file 기록(JSON escaping 없음, 올바르게 awk-escape하는 자체 systemMessage 경로와 대조). 둘 다 로컬 위협모델에서 저위험이지만 validate/sanitize 모범사례에 일관되게 위배.
