# v3.1.0 릴리스 노트 (한국어)

### 요약

v3.1.0은 `v3.1.0-rc.0` → `-rc.1` → `-rc.2`로 이어진 후보 계열을 정식 릴리스로 승격한 버전이다. 세 가지 축이 이번 릴리스를 이룬다.

**칸반 모드**가 가장 큰 추가다. 여섯 개 칼럼(`backlog → plan → run → review → sync → done`)으로 이루어진 보드를 리드 세션이 운전하고, 운영자가 직접 띄운 동반 세션들에 카드를 지시한다. SPEC frontmatter를 건드리지 않는 단일 출처 보드 상태 저장소, 백로그 큐를 다루는 `moai todo` CLI, `/clear`를 넘겨도 살아남는 리드 세션 이름, 운영자 언어로 전달되는 부트스트랩 알림이 함께 들어왔다. 기존 `manager-lead` 에이전트는 `manager-kanban`으로, 런처 플래그 `-f/--factory`는 `-k/--kanban`으로 이름이 바뀌었다.

**`moai web` 콘솔**은 재설계를 마무리했다. 과도기로 남아 있던 설정·보드 계층을 셸 안으로 접어 넣었고, 콘솔 크롬을 4개 언어로 배선·번역했으며, 스키마 기반 폼은 값이 닫힌 필드를 닫힌 위젯으로 렌더링한다.

**모델 정책과 훅**은 더 촘촘해졌다. effort 행렬에 단계별 가중치가 들어갔고(plan은 최상위, run/review는 high, sync는 low), GLM 모델 티어는 Claude 슬롯당 한 모델로 정리됐다. 브랜치 가드 스캔은 명령이 데이터로 실어 나르는 문자열이 아니라 실제로 실행되는 명령만 보도록 좁혀졌고, `moai update`는 merge base를 계산해 템플릿에 새로 추가된 파일이 기존 프로젝트까지 실제로 도달하게 됐다.

### 추가됨

- **`moai todo` — `/moai todo`의 CLI 대응 표면과 잠금으로 보호되는 저장소.** 스크립트나 훅, 혹은 `AskUserQuestion` 채널이 없는 동반 세션에서도 큐를 읽고 쓸 수 있어야 했다. `moai todo`가 그 표면이다. 추가·조회·삭제가 같은 프로젝트 로컬 큐를 대상으로 동작하고, 잠금이 걸려 있어 한 체크아웃의 두 세션이 읽기-수정-쓰기를 교차시켜 항목을 잃는 일이 없다. 손상된 저장소는 초기화하지 않고 그대로 둔 채 보고한다 — 여기서 되살릴 수 없는 유일한 것이 운영자의 의도이기 때문이다.
- **여섯 칼럼 칸반 보드와 단일 출처 상태 저장소.** 칼럼 배정은 `lead` 역할만 쓸 수 있는 파일 한 곳에만 존재한다. 따라서 카드의 위치가 SPEC frontmatter와 경쟁하는 두 번째 사실로 갈라지지 않는다. 저장소는 git common 디렉터리를 기준으로 해석되므로(한 체크아웃의 모든 워크트리가 같은 보드를 본다) 원자적으로 쓰이고, 파일이 없으면 그것이 빈 보드이며, 잠금 보유자가 확실히 죽었을 때만 잠금을 정리한다 — 생존 여부가 불확실하면 살아 있는 것으로 취급한다. "죽었다"고 넘겨짚는 쪽이 살아 있는 보유자의 잠금을 풀어버리는 경로이기 때문이다.
- **칸반 리드 세션에 이름이 생겨 `/clear`를 넘겨도 유지된다.** 리드의 run id를 세션 이름에서 끌어오고, 운영자가 지정한 이름이 있으면 덮어쓰지 않고 그대로 채택한다. 컨텍스트를 비운 리드도 동반 세션들이 같은 이름으로 계속 부를 수 있고, 이것이 디스패치 프로토콜에서 단계 사이에 `/clear`를 넣어도 안전한 이유다.

### 변경됨

- **런처 플래그 `-f`/`--factory`가 `-k`/`--kanban`으로 바뀌었다.** 별칭을 남기지 않은 완전한 개명이라(패키지·환경 변수·함수·파일 이름까지 모두 이동) `moai cc -f`를 쓰던 스크립트는 `moai cc -k`로 바꿔야 한다. "factory"는 여섯 칼럼 보드가 대체한 이전 설계를 가리키던 말이라, 이름을 그대로 뒀다면 플래그와 기능이 서로 다른 말을 하게 됐을 것이다.
- **effort 행렬에 단계별 가중치를 넣고, GLM 세션 추론 기본값을 낮췄다.** 이제 effort는 일률적으로 적용되지 않고 작업 단계를 따라 배분된다. plan은 최상위(판단이 틀렸을 때 되돌리는 비용이 가장 큰 단계), run과 review는 high, sync는 low로 내렸다 — sync는 대체로 기계적이라 최고 추론을 지불해도 얻는 것이 없었다. GLM 세션 추론 기본값도 같은 방향으로 내려갔다. 모델과 effort는 계속 `moai model profile`로 해석되며, 어느 에이전트 파일에도 값이 박혀 있지 않다.
- **GLM 모델 티어를 Claude 슬롯당 한 모델로 정리했다.** 이전에는 여러 GLM 모델이 한 슬롯을 공유할 수 있어, 실제로 해석되는 모델이 슬롯이 아니라 순서에 좌우됐다. 이제 Claude 슬롯(Opus / Sonnet / Haiku / Fable)마다 GLM 모델이 정확히 하나씩 대응한다.
- **`moai web` 콘솔의 과도기 계층을 걷어냈다.** 설정은 셸 안으로, 보드 화면은 `/specs` 안으로 접혀 들어가면서, 콘솔 재설계 이후 비계처럼 남아 있던 2층 구조가 사라졌다. 콘솔 셸 크롬도 배선·번역돼 내비게이션·헤더·상태 표시가 영어로 떨어지지 않고 운영자의 언어로 렌더링된다.
- **내부 문서 노후 정리.** 낡은 참조 4건 폐기, 3건 재지정, 5건은 유효함을 확인했다.
- **`manager-lead`를 `manager-kanban`으로 개명.** 이 조정 에이전트는 이제 하나의 스킬 세트 위에 두 역할을 얹는다. **역할 A**는 기존 Tier L 세션 내 계층 팬아웃(진입 임계값·depth-2 봉인·컨텍스트 접기 절차 모두 그대로)이고, **역할 B**는 운영자가 띄운 동반 세션에 지시해 카드를 여섯 칼럼 보드 위로 옮기는 새 칸반 리드 역할이다. 개명은 살아 있는 배선 전반에 기계적으로 완결됐다(에이전트 파일, `CLAUDE.md` §4, `workflow.yaml`, 하네스 위임 맵과 v4 매니페스트, 에이전트 린트 표면, depth 봉인 CI 가드, README(en/ja/zh), 4개 언어 docs-site 페이지 — 기존 링크가 계속 열리도록 영구 리다이렉트 추가). 과거 기록은 의도적으로 고치지 않았다. 이전 CHANGELOG 항목과 종료된 SPEC 본문은 그 시점에 실제로 배포된 이름을 그대로 유지한다. 고쳐 쓰면 특정 릴리스가 무엇을 담았는지를 잘못 진술하게 되기 때문이다.

### 제거됨

- **GLM 팀 모드 설정 기록기와 `enableTeamMode`.** Agent Teams 정적 오케스트레이션이 폐기되면서(`--team`은 `MODE_TEAM_UNAVAILABLE`로 해석돼 서브에이전트로 폴백) 팀 모드 설정 기록기에는 호출자가, `enableTeamMode`에는 도달 경로가 남지 않았다. 둘 다 테스트 전용 표면과 함께 삭제했다. 네이티브 `moai cg`와 `moai worktree --team`은 영향을 받지 않는다 — 애초에 이 코드를 거치지 않았다.
- **`research.yaml` 설정 섹션과 `state.state_dir` 재삭제.** 두 항목은 이미 한 번 제거됐다가 템플릿 재동기화 과정에서 되살아났다. `research.yaml`은 읽는 곳이 없었고, `state.state_dir`은 쓰기 전용이었다 — 런타임의 모든 `.moai/state` 경로는 다른 곳에서 결정된다. 기존 프로젝트에 남은 고아 파일은 다음 `moai update`에서 정리된다.

### 수정됨

- **`moai update`가 merge base를 계산해, 템플릿 추가분이 기존 프로젝트까지 도달한다.** merge base 없이는 비교 기준이 어긋나 템플릿에 새로 추가된 파일을 이미 반영된 것으로 판정했고, 그래서 마지막 업데이트 이후 추가된 파일이 끝내 내려오지 않았다. 추가분을 놓친 프로젝트는 다음 `moai update`에서 받게 된다.
- **브랜치 가드 스캔이 데이터로 실린 문자열이 아니라 실제 실행 명령만 본다.** 매칭 전에 따옴표 구간을 접기 때문에 `moai todo add "… git switch …"`는 문자열 안에 브랜치 명령이 들어 있다는 이유로 거부되지 않고, `git switch main`과 `git checkout -b "feat/x"`는 그대로 거부된다. 같은 변경에서 면제 규정도 바로잡았다. `manager-git` 신원 축도, `MOAI_BRANCH_GUARD_EXEMPT` 센티넬도 도구로 생성된 서브에이전트 안에서는 닿지 않는다 — 훅은 가드 대상 명령이 실행되기 **전에** 별도 프로세스로 뜨므로, 그 명령 안에서 센티넬을 export해도 훅에는 전달되지 않는다. 브랜치 상태를 바꿔야 하는 서브에이전트는 대신 워크트리에서 작업한다.
- **권한 판정이 훅 핸들러 병합을 통과해 살아남는다.** 한 핸들러가 낸 판정이 결과 병합 과정에서 유실될 수 있어, 앞단에서 계산된 거부가 런타임까지 도달하지 못하는 경우가 있었다. 이제 판정이 병합을 관통한다.
- **칸반 부트스트랩 알림이 운영자에게, 운영자의 언어로, 진짜 새 세션에서만 전달된다.** 한 표면에 결함이 셋 있었다. 알림이 운영자가 볼 수 없는 내부 텍스트로 나갔고, `conversation_language`와 무관하게 영어로 렌더링됐으며, 세션을 재개할 때마다 다시 떠서 이미 끝난 부트스트랩을 다시 알렸다.
- **칸반 보드 잠금 해제 오류를 양방향으로 합친다.** 잠금 해제 실패가 그것이 지키던 작업의 실패를 가리거나, 어느 경로가 먼저 반환하느냐에 따라 그 반대가 되기도 했다. 이제 두 오류를 함께 묶어 어느 쪽도 조용히 사라지지 않는다.
- **statusline 사용량 조회에 상한 없는 `Retry-After` 방어를 넣었다.** 서버가 준 `Retry-After`를 곧이곧대로 따르다 보니 값이 크면 그만큼 조회 단계가 멈춰 있었다. 이제 헤더가 요구하는 값과 무관하게 단계 자체에 상한을 둔다(이슈 #1467).
- **테스트가 실제 홈 디렉터리에 쓰지 않는다.** 일부 테스트가 임시 디렉터리가 아니라 실제 `$HOME`을 기준으로 경로를 잡아, 수트를 돌리는 것만으로 개발자 본인의 설정이 바뀌는 부작용이 있었다.
