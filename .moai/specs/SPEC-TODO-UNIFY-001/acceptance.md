## §1 How a criterion is adopted

Each criterion is a pair of cells. The **RED-now cell** is the criterion observed red on the pre-implementation tree, with the reason it is red. The **green path cell** names the milestone that flips it and the command whose output becomes the pass. A criterion with one cell is unadopted.

Three classes, stated so no criterion borrows a stronger status than it has:

- **A, observed at plan time.** A read-only command already shows the pre-implementation state (ledger id cited). It is release-blocking.
- **B, to be observed at run time.** The criterion is a Go test that does not exist yet; plan time cannot run it (the card forbids `go test` here). It is **unadopted until the owning milestone's RED step records its failing output** (the failure must be the stated assertion, not a compile or fixture error) in `progress.md` §E.2. Once recorded it is release-blocking. Until then it is a pending criterion, not a pass.
- **G, regression guard.** Green by design today; it protects something this change must not move. It never counts as evidence that the work was done.

Every Go-test command below is a name-exact selector that names tests which exist now or which the owning milestone creates at RED; the verdict is read only after the run prints at least one `--- PASS: <TestName>` line for each named test (an empty or partial selection prints a pass-shaped result and proves nothing).

## §3 Edge cases

- A `moai gtd` invocation whose first word is a mistyped verb followed by a card id (`moai gtd lst 401`): the refusal comes from the command's argument validation, before any pre-run hook and before the run step, so no warning prints and the output equals the `todo` form's error (AC-TU-002 row 1). A missing required flag, a conflicting flag group, and a lane-guard refusal are the same (rows 4 to 6): each returns before the run step, where the warning is printed.
- `moai gtd` with no arguments renders the queue (the bare parent form): one warning, then the queue.
- `--help` on a subverb of `gtd`: no warning (AC-TU-002).
- A lane session running `done` with a card id in the `t<n>` form and in the bare `<n>` form: both resolve to the same own card (the existing normalisation).
- A card with landing evidence recorded by the operator (`todo landed --sha`) versus a subject on the landed ref: both are the closed forms; the lane path accepts either.
- A card whose verdict file exists in the working tree but is not in the merge commit's tree, whose `audited_sha` is not the recorded evidence commit, or whose card carries, after the evidence commit, a change outside `.moai/reports/<card-id>/` that the merge's first parent does not carry (a code commit after the audit, or an absorption conflict resolved to a third content): no receipt is issued and the card waits for the leader's manual approval (AC-TU-016 rows (c) to (e)). Main absorbed after the audit, with the absorbed paths equal to the first parent's, does not block the receipt (row (b)); the integrated tree is what the re-measure of fact 3 covers.
- A card whose re-measure record sits under the merged tree's file name but names another tree, or whose record's base is not the merge's first parent (the integration branch moved after the re-measure): no receipt is issued; the remedy is a fresh absorb, re-audit, and re-measure (AC-TU-016 row (f)).
- A card whose factory row is `pushed`: the automatic receipt is not issued; the card closes only under a leader-issued receipt and its factory row stays `pushed` (the edge is card t1639's; AC-TU-014 asserts both outcomes).
- The setter on a card that was unpicked and re-picked: the unpick cleared the queue spec_id, so the setter fills it again (AC-TU-021/022).
- The setter on a card leased without a spec_id whose SPEC the lane authored afterwards (the board record's wedge): admitted while the card is `leased`, `plan`, `plan-audit`, or `kickoff`; a lane in flight sees the factory version rise by one and retries its transition under the existing stale-version contract (AC-TU-021, AC-TU-022).
- The setter on a card already in `run` or later with empty carriers: refused for a first fill; a repeat that completes a half-written pair is admitted in any non-terminal state (AC-TU-021, AC-TU-025).
- The substitution script on a path that contains a space or begins with a dash: the script quotes every path (AC-TU-009 fixture row).
