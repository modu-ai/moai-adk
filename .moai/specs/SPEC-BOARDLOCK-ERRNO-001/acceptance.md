# acceptance.md — SPEC-BOARDLOCK-ERRNO-001

AC 본문의 단일 보유처. `spec.md §3` 은 REQ→AC 대조표만 갖는다.

**판정 범위**: `./internal/kanban/...` 한정. 이 저장소에서 로컬 전체 스위트는 금지이며, 전 패키지 판정은 CI 몫이다.

**측정 형태의 제약**: 이 SPEC 의 AC 는 "오분류 N건이 사라진다"로 쓸 수 없다 — 측정된 N 은 0 이다(`spec.md §1.3`). 그래서 AC 는 **양방향 분류 술어**를 잠근다.

### §D.0 시작 색 — AC 별 RED-now 여부 (감사 D3 교정)

`.claude/rules/moai/development/verification-completeness.md` §2 는 AC 채택을 **두 셀 한 쌍**으로 요구한다: 구현 이전 트리에서 관측된 **RED-now 셀**과, 어느 마일스톤이 그것을 뒤집는지 명시한 **green path 셀**. 종전 이 파일은 blocking AC 6개 전부에 RED-now 셀이 없었고, AC-BLE-001a 가 인용하던 프로브 관측은 *이미 초록인 사전 관측*이지 시작 RED 가 아니다 — 그것이 §2 가 잡으려는 공허성 방향 그 자체다.

**종전의 문서 수준 pin `3f03d9c36` 은 철회한다.** 001b·002 는 분류 seam 을 지나가는 계약 테스트로 재는데(`substrate 가 그 실패를 분류하면`), 옵션 A 아래에서 `3f03d9c36` 에는 그 진입점도 그 테스트 파일도 없다 — 거기서 관측되는 것은 기준 RED 가 아니라 **빌드 실패**다. 즉 그 pin 은 **잴 수 없는 측정을 가리키고 있었다**.

**그 측정 트리를 만드는 것이 M1 의 일이다.** 그런 트리는 아직 존재하지 않는다 — `3f03d9c36` 에 새 계약 테스트(분류 수리 이전 상태)를 얹은 형태가 **될 것으로 예상하지만**, 최종 형태는 M1 이 확정하며 이 문서가 미리 못박지 않는다. 따라서 각 행의 SHA pin 은 **실측 시점에 그때의 트리 SHA 로 기록한다** — 지금 어떤 SHA 도 미리 적지 않는다. `3f03d9c36` 은 이 표에서 계획 단계 프로브 관측(`§AC-BLE-001a` 의 대조 인용)의 출처로만 남는다.

| AC | 시작 색 | RED-now 획득 방법 | green path (뒤집는 마일스톤) | 등급 |
|---|---|---|---|---|
| AC-BLE-001a | **GREEN (RED-now 획득 불가)** | 경합 → held=true 는 `3f03d9c36` 에서 이미 참이다(프로브 관측). 어떤 올바른 사전 상태도 이것을 RED 로 만들지 않는다 | 뒤집히지 않는다 — M1 이후에도 GREEN 유지가 판정 | **회귀-가드** (§2.1 undecidable disposition 적용). 비공허성은 RED-now 가 아니라 **M-narrow 뮤턴트**가 공급한다 |
| AC-BLE-001b | **RED** | 새 계약 테스트를 **수리 이전 매핑**(= 넓은 매핑) 위에서 실행 → 비경합 errno 가 held=true 로 나와 RED. **잴 수 있는 트리는 M1 이 만든다**(계약 테스트 존재 + 분류 수리 이전); SHA 는 그 실측 시점에 기록 | M1(분류 seam) 착지 시 GREEN | **착지 차단** |

| AC-BLE-003 | **GREEN (RED-now 획득 불가)** | fd 위생은 `board_lock_unix.go:42` 가 이미 지킨다. 사전 트리에서 RED 를 만들 수 없다 | 뒤집히지 않는다 — 분기가 둘로 갈린 뒤에도 GREEN 유지가 판정 | **회귀-가드**. 비공허성 공급원으로 적혀 있던 **M-leak 은 현 정의로는 발화하지 못한다**(`plan.md §B.1` 부채-1) — M1 이 다시 놓기 전까지 이 AC 는 **비공허성 가드 없음**으로 읽는다 |
| AC-BLE-004 | **GREEN (구조상 RED 불가)** | 수리 전/후 실패 집합 비교이므로 "수리 전 RED" 라는 개념이 성립하지 않는다 | 뒤집히지 않는다 | **회귀-가드 — 뮤턴트 가드 없음.** 뮤턴트 표(`§AC-BLE-005`)의 셋 중 이 AC 를 지정하는 것은 없다. 이 AC 는 수리 전/후 실패 집합 **대조 게이트**라 뮤턴트로 잴 대상이 아니다. 대신 수리 **이전에** 실측한 기준선이 없으면 대조할 것 자체가 없어 이 AC 는 공허해진다 — 지금 식별된 공허화 조건은 이것이다(전수 열거는 아니다) |
| AC-BLE-005 | **RED (뮤턴트별)** | 각 뮤턴트를 심은 실행이 곧 RED 관측이다 — M-broad→001b RED, M-narrow→001a RED. **M-leak→003 은 정의 철회로 빠졌다**(M1 미정) | 되돌린 뒤 각각 GREEN | **착지 차단** |

**대체 수단을 선언하되, 종전의 일괄 주장은 철회한다.** RED-now 를 얻을 수 없는 세 AC(001a·003·004)를 **회귀-가드**로 분류하는 것은 그대로다. 그러나 "그 비공허성은 뮤턴트 3종이 공급한다"는 **셋 모두에 대해서는 성립하지 않는다** — 뮤턴트 표가 지정하는 것은 M-broad→001b, M-narrow→001a, M-leak→003 뿐이고 **004 를 지정하는 뮤턴트는 없다**. 좁혀 다시 적으면:

- **AC-BLE-001a** — M-narrow 가 지정돼 있다.
- **AC-BLE-003** — M-leak 이 지정돼 있으나 **현 정의로는 발화하지 못한다**(`plan.md §B.1` 부채-1). M1 이 다시 놓기 전까지 **가드 없음**으로 읽는다.
- **AC-BLE-004** — 지정된 뮤턴트가 없다. 위 표의 등급 칸이 그 이유를 적는다.

AC-BLE-005 가 필수라는 판단은 유지하되, 그것이 회귀-가드 셋 전부를 덮는다고는 적지 않는다.

**이 표의 RED-now 셀은 아직 측정되지 않았다.** 위 칸은 *무엇을 어떻게 재야 하는지*의 명세이며, 명령·출력 전문·종료 코드·**그때의 트리 SHA** 는 실측 시점에 채운다(§D.2 체크리스트). 계획 단계에서 채워 넣은 척하지 않고, 잴 수 없는 트리를 미리 pin 하지도 않는다.

---

**양방향 짝은 AC-BLE-001a ↔ AC-BLE-001b 다.** 한쪽만 통과하는 구현은 판정을 이루지 못한다 — AC-BLE-001a 단독은 술어를 항상 참으로 만드는 구현(= 현행 결함)도 통과시키고, AC-BLE-001b 단독은 술어를 항상 거짓으로 만드는 구현(= 규칙 비활성화)도 통과시킨다.

## AC-BLE-001a — 경합은 여전히 경합이다

**Given** 같은 board root 에서 board lock 이 이미 획득돼 있고,
**When** 같은 프로세스에서 `AcquireBoardLock(root)` 를 한 번 더 호출하면,
**Then** 반환 오류에 대해 `IsBoardLockHeld(err)` 는 `true` 이고, 오류는 `errors.Is(err, ErrBoardLockHeld)` 를 만족한다.

- 판정 명령: `go test ./internal/kanban/ -run '<계약 테스트 선택자>' -count=1 -v`
- 선택자 매치 수를 함께 기록한다 — 0 매치는 초록이 아니라 미실행이다.
- 기존 관측 대조(계획 단계 프로브, `.moai/reports/t379/errno-probe-output.txt`): `second AcquireBoardLock -> err=kanban board lock held IsBoardLockHeld=true`. 수리 후에도 같아야 한다.

## AC-BLE-001b — 비경합 errno 는 경합이 아니다

**Given** `EWOULDBLOCK`/`EAGAIN` 이 아닌 errno(최소 `unix.ENOLCK`, 그리고 `unix.EBADF` 를 포함한 2종 이상)가 `flock` 실패로 제시되고,
**When** substrate 가 그 실패를 분류하면,
**Then** 그 결과 오류에 대해 `IsBoardLockHeld(err)` 는 `false` 이고, `err != nil` 이다(오류가 삼켜지지 않는다).

- 오류를 조용히 `nil` 로 바꾸는 구현은 이 AC 를 통과하지 못한다 — `err != nil` 단언이 그 우회를 막는다.
- `EBADF` 는 실호출 지점에서 도달 불가이지만(`spec.md §1.3-2`), 분류 술어의 입력으로는 유효하다. **도달 불가와 분류 대상 아님은 다른 명제다.**

## AC-BLE-002 — errno 가 살아 있고 경로가 이름 지어진다

**Given** AC-BLE-001b 와 같은 비경합 errno,
**When** 분류 결과 오류를 검사하면,
**Then** `errors.Is(err, <그 errno>)` 가 `true` 이고, `err.Error()` 가 lock 아티팩트 경로 문자열을 포함한다.

- errno 보존이 이 SPEC 의 실체다. 메시지에만 errno 텍스트가 남고 `errors.Is` 가 깨지는 구현은 실패로 본다.

## AC-BLE-003 — 실패 경로에 fd 누수가 없다

**Given** `flock` 이 실패하는 경우(경합/비경합 양쪽),
**When** substrate 가 반환하면,
**Then** 그 시도를 위해 열린 디스크립터는 반환 전에 닫혀 있다.

- **판정 기제는 하나다**(감사 D4 교정 — 종전의 "대안 판정(동등 인정)"은 삭제됐다. "코드 경로를 지나감을 단언"은 어떤 입력이 그것을 RED 로 만드는지 말하지 않으므로 검사 명세가 아니다):
  - 같은 root 에 대해 반복 획득 실패를 N회(N=200) 유도한 **전후로 `/dev/fd` 하위 엔트리 수를 센다**(darwin·리눅스 모두 이 경로가 프로세스 자신의 열린 디스크립터를 노출한다). 사후 개수가 사전 개수 + 고정 여유(테스트 자신이 여는 파일 수) 이내여야 하며, N 에 비례해 증가하면 실패다.
  - 반복은 인프로세스 루프이며 **배경 프로세스를 띄우지 않는다**; 정리는 `t.Cleanup` 으로 보장한다.
- **이 기제는 M1 로 넘기는 부채를 안고 있다 — 지금 상태로는 판정을 이루지 못한다**(`plan.md §B.1` 부채-2). (a) "고정 여유"에 값이 없어 임계값이 미정이다. (b) darwin·리눅스 양쪽에 대한 위 괄호 안의 진술은 **어느 쪽에서도 측정되지 않은 추론**이며, 리눅스의 `/dev/fd` 는 `/proc` 경유라 환경 의존인데 **CI 러너는 ubuntu 다**. (c) AC-BLE-001a 가 가진 선택자-매치-수 절이 여기엔 없어, `/dev/fd` 를 못 읽는 러너에서 **조용히 `ok` 로 통과하고 이 AC 는 아무것도 단언하지 않는다**. 세 구멍은 M1 에서 함께 닫는다 — 이 iter 에서는 닫지 않고 기록만 한다.
- 종전에 "RED 를 만드는 입력"으로 적혀 있던 **M-leak 뮤턴트(비경합 분기의 `unix.Close(fd)` 제거)는 철회한다** — `plan.md §F M1` 이 규정한 공유 close 모양에는 그 분기가 없고, 위 유도는 경합만 만들어 비경합 반환 경로에 닿지 않는다(`plan.md §B.1` 부채-1). **따라서 이 AC 는 현재 비공허성 가드가 없다.** M1 의 A/B 결정과 함께 다시 놓는다.

## AC-BLE-004 — 측정된 도달 가능 입력에서 행동 불변

**Given** 수리 전 트리와 수리 후 트리,
**When** `go test ./internal/kanban/... -count=1` 를 각각 돌리면,
**Then** 실패 집합이 달라지지 않는다. 특히 `IsBoardLockHeld` 소비자 3곳(`board_store.go:173`, `integration_lock_mutation.go:103`, `backlog_store.go:736`)을 통과하는 기존 경합 테스트들이 수정 없이 계속 통과한다.

- 수리 **전** 기준선을 먼저 재고 기록한다(명령 + 출력). 사후에 기준선을 만들어 붙이지 않는다.
- 기지 플레이크(`TestConcurrencyStress` 계열)가 나오면 이 카드로 귀속하지 말고 계열명과 함께 별도로 적는다 — 상속 적색은 본 카드의 회귀가 아니다.
- 크로스 플랫폼: `GOOS=windows GOARCH=amd64 go build ./...` rc=0 (빌드 태그 분기 파일을 만졌으므로 필수).

## AC-BLE-005 — 비공허성 (정의된 뮤턴트 2방향)

**Given** 구현과 그 계약 테스트가 초록인 상태,
**When** 아래 표에서 **정의가 살아 있는 두** 뮤턴트(M-broad·M-narrow)를 각각 하나씩 심고 `./internal/kanban/` 의 해당 선택자를 돌리면,
**Then** 각 뮤턴트가 지정된 AC 를 RED 로 만들고, 되돌린 뒤 다시 GREEN 이 된다.

| 뮤턴트 | 심는 내용 | RED 가 돼야 하는 AC | 무엇을 재는가 |
|---|---|---|---|
| M-broad | 분류를 되돌려 모든 errno 를 `ErrBoardLockHeld` 로 (= 현행 결함 재현) | AC-BLE-001b | 분류 함수의 **넓은 방향** |
| M-narrow | 분류를 뒤집어 모든 errno 를 비경합 감싼 오류로 | AC-BLE-001a | **호출 지점 배선** — 아래 주석 |
| M-leak | ~~비경합 분기에서 `unix.Close(fd)` 제거~~ **정의 철회 — M1 미정** | (AC-BLE-003 지정이 성립하지 않는다) | — (`plan.md §B.1` 부채-1) |

- **정의된 두 뮤턴트**가 **서로 다른** AC 를 RED 로 만들어야 한다. 같은 AC 가 둘 다에 반응하면 짝이 실제로는 방향 하나만 재고 있는 것이다. (M-leak 은 정의 철회로 이 판정에 참여하지 않는다 — 3종을 요구하면 없는 뮤턴트를 보고하게 된다.)
- **M-narrow 가 배선 검출기다**(감사 D2 교정). AC-BLE-001b 는 분류 함수에 합성 errno 를 직접 먹이므로 `acquireBoardLockImpl` 을 지나가지 않는다 — 따라서 M-broad 는 호출 지점 배선 여부와 무관하게 001b 를 RED 로 만들고, 배선에 대해 아무 말도 하지 않는다. AC-BLE-001a 는 `AcquireBoardLock` 을 실제로 두 번 부르므로, M-narrow 아래에서 001a 가 RED 가 되는 것은 **호출 지점이 하드코딩된 sentinel 이 아니라 분류 함수의 결과를 반환한다는 증거**다. 배선이 없는 구현에서는 M-narrow 를 심어도 001a 가 **초록으로 살아남고, 그 생존이 신호다** — 이 AC 가 잡아야 하는 실패가 정확히 그것이다(`plan.md §F M1`).
- **M-leak 이 현 정의로는 심을 자리도 도달할 유도도 없으므로, REQ-BLE-004 는 지금 비공허성 가드가 없는 요구다** — 그리고 `spec.md` 자신이 그 성질을 "분기가 둘로 갈리는 변경에서 가장 흔하게 깨지는 성질"로 지목한다. 이 구멍은 닫힌 것이 아니라 M1 로 넘긴 부채다(`plan.md §B.1` 부채-1).
- 각 뮤턴트의 RED 출력 전문과 되돌린 뒤의 GREEN 출력을 증거에 남긴다. 되돌림은 `git status --short` 로 확인한다.
- **근거**: 이 SPEC 의 검사는 오늘 유도 불가한 입력을 대상으로 하므로, 통과하는 초록이 실제로 무언가를 보고 있음을 mutation 말고는 보일 방법이 없다.

## §D.1 심각도

**등급이 둘로 갈리고, 착지 차단 자격도 함께 갈린다**(§D.0). 종전에 여기 적혀 있던 "6개 모두 실패 시 착지 불가"는 철회한다 — `verification-completeness.md` §2.1 의 undecidable disposition 을 인용해 놓고 그 귀결(착지 차단 자격 상실)을 부정하는 문장이었다. 인용을 유지하므로 귀결을 따른다:

- **착지 차단(RED-now 셀 보유)**: AC-BLE-001b·002·005. 시작 RED 가 실제로 관측 가능하며, M1 이 그것을 뒤집는다.
- **회귀-가드(RED-now 획득 불가, 착지 차단 자격 없음)**: AC-BLE-001a·003·004. 사전 트리에서 이미 초록이므로 시작 RED 가 없고, §2.1 에 따라 **착지 차단으로 세지 않으며 PASS 로도 기록하지 않는다**. 보고는 그 등급으로 한다 — 초록이 초록으로 남는지 관측하고, 관측 결과를 등급과 함께 적는다. 그 초록이 무언가를 보고 있다는 증거는 RED-now 가 아니고, **대체 수단도 셋에 고르게 있지 않다** — 001a 만 뮤턴트(M-narrow)를 갖고, 003 은 지정된 뮤턴트가 발화하지 못하며, 004 는 지정된 뮤턴트 자체가 없다(§D.0). 종전의 "뮤턴트가 셋의 비공허성을 공급한다"는 일괄 선언은 철회한다.
- 따라서 착지를 막는 AC 는 **셋(001b·002·005)** 이다. 001b 가 빠지면 좁히기가 검증되지 않고, 002 가 빠지면 SPEC 의 실체가 사라지며, 005 는 그 둘의 비공허성 근거다. 나머지 셋(001a·003·004)은 관측·보고 대상이되 착지 차단 근거로 쓰지 않는다 — 그 셋의 회귀 관측이 실제로 적색이면 그것은 별개의 결함 보고이지 이 표의 PASS/FAIL 칸이 아니다.

## §D.2 Definition of Done

- [ ] **착지 차단 AC 셋(001b·002·005) PASS** — 각 판정에 **명령 + 출력 전문 + 종료 코드 + 선택자 매치 수**. 회귀-가드 셋(001a·003·004)은 같은 증거를 갖되 **PASS 로 세지 않고 등급과 관측 결과로 보고한다**(§D.1 · `verification-completeness.md` §2.1). 종전의 "001a ~ 005 전부 PASS" 요구는 철회했다
- [ ] **§D.0 의 RED-now 셀 3개(001b·002·005)가 실측돼 채워짐** — 명령 + 출력 전문 + 종료 코드 + **실측 시점의 트리 SHA**. 사후 작성 금지, 잴 수 없는 트리 pin 금지
- [ ] §D.0 의 회귀-가드 3개(001a·003·004)가 그 등급으로 보고됨 — RED-now 를 가진 척하지 않는다
- [ ] 수리 전 기준선(AC-BLE-004)이 수리 **이전에** 측정돼 기록됨
- [ ] `go vet ./internal/kanban/` rc=0
- [ ] `golangci-lint run --timeout=5m ./internal/kanban/...` — 신규 지적 0 (기존 baseline 과 구분해 보고)
- [ ] `GOOS=windows GOARCH=amd64 go build ./...` rc=0
- [ ] 배경 프로세스 0 — 검증이 남긴 살아있는 프로세스가 없음을 확인
- [ ] 증거는 5절 형식(Claim / Evidence / Baseline-attribution / Gaps / Residual-risk)으로 `.moai/reports/t379/` 에 남김

## §D.3 미검증으로 남기는 것 (명시)

- `ENOLCK` / `EOPNOTSUPP` / `EINTR` 의 **실제 커널 유도**. 합성 errno 로 분류 술어만 잠근다. 실동작은 미측정이며, 0 이 아니다.
- **`EINTR` 재분류의 행동 영향.** 오늘 `EINTR` 은 경합으로 매핑돼 재시도 예산에 흡수되고, 좁힌 뒤에는 즉시 하드 오류가 된다 — **행동 중립이 아니다**. 도달 가능성 논증은 "그럴듯하지 않다" 쪽이지만(`LOCK_NB` 는 대기하지 않고, flock(2) 의 EINTR 은 대기 중 중단에 대한 것) 그것은 **syscall 계약을 읽은 추론이지 측정이 아니다**. 이 변화는 받아들이는 것으로 기록되며(`spec.md §1.3.1`), REQ-BLE-005 의 보호 범위 밖이다.
- **리눅스에서의 관측**. 계획 단계 측정은 darwin/arm64 이다. 리눅스 판정은 CI(ubuntu)가 낸다.
- 다른 파일시스템(NFS, 오버레이)에서의 flock 동작.
