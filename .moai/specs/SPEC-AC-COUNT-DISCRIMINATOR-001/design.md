# 설계 — SPEC-AC-COUNT-DISCRIMINATOR-001

> **이 문서가 생긴 이유**: iter-2 감사가 배포 반송자 하나(`.codex` TOML)를 더 찾아 영향 파일이 16 이 됐고, Tier M 상한 15 를 넘어 **Tier L** 이 됐다(`plan.md` §F). Tier L 은 산출물 5종을 요구한다. 이 문서는 그 요구를 채우되, **`spec.md` 가 이미 결정한 것을 옮겨 적지 않는다** — 여기 있는 것은 결정의 *기계적 형태*(계약·스키마·경계)이고, 결정 자체와 그 근거는 `spec.md` §3 에 있다.

## §A 이 SPEC 이 만드는 것의 층위

세 층이고, 서로 다른 수명을 가진다.

| 층 | 산출물 | 수명 | 바뀌면 |
|---|---|---|---|
| 규약(문면) | B12 절의 개정 문면 — 예약 토큰·인접 규칙·세 상태 | 가장 길다. 배포되고, 정규화된 파일이 이것에 의존한다 | 이미 정규화한 파일과 배포된 절이 갈린다(M1 이 가장 되돌리기 어려운 이유) |
| 계약(출력) | 계수기의 출력 형태 — 정수 / `AMBIGUOUS` / 종료코드 | 중간. 읽는 쪽이 에이전트다 | 자가검사를 읽는 코드가 갈린다 |
| 검증(테스트) | `internal/spec/` 저장소 로컬 테스트 + fixture + baseline 스냅샷 | 가장 짧다. 저장소 안에서만 산다 | 테스트만 고치면 된다 |

**설계 원칙**: 위층이 아래층을 정한다. 검증층은 규약층을 **추출해서** 읽고 복사하지 않는다(REQ-ACD-005) — 복사하는 순간 절이 바뀌어도 테스트가 통과하는 쌍둥이 드리프트가 된다.

## §B 계수기 계약 (M2 가 확정할 것의 형태)

### B.1 출력 형태 — 셋뿐이다

| 상황 | stdout | 종료코드 |
|---|---|---|
| 모든 식별자가 판정됨 | live 개수, 정수 1개 | 0 |
| 부분 표시가 하나라도 있음 | `AMBIGUOUS <id> [<id>…]` + 해소 방법 한 줄 | ≠ 0 |
| live 가 0 | `0` + 기존 절의 RED 플래그 거동 | (기존 절이 이미 규정한 것을 유지) |

**애매 상태가 정수를 내지 않는 것이 이 설계의 축**이다. 정수를 내면 읽는 쪽이 그것을 답으로 쓰고, 이 SPEC 이 막으려는 "근거 없는 수" 가 그대로 CHANGELOG 에 실린다. 정수의 부재가 곧 "답 없음" 의 기계적 형태다(`spec.md` §3.2).

**해소 방법을 함께 내는 것이 계약의 일부**다(REQ-ACD-003). 정지는 규약을 처음 만나는 파일에서 걸리므로, 무엇이 애매한지만 말하고 어떻게 푸는지 말하지 않는 정지는 결함을 다른 결함으로 바꾼다.

### B.2 판정 단위와 상태 함수

```
등장(occurrence)  := 파일 안에서 식별자 패턴이 일치한 한 자리
표시됨(marked)    := 그 등장 바로 뒤에, 같은 행에서, 공백·탭만 두고 예약 토큰이 이어짐
상태(identifier)  := 그 식별자의 모든 등장의 marked 값으로 정해진다
                     ├ 하나도 없음 → live      (센다)
                     ├ 전부        → excluded  (제외)
                     └ 일부        → ambiguous (세지 않고 멈춘다)
```

`{하나도 없음, 전부, 일부}` 가 경우를 남김없이 가르므로 세 상태는 **망라적·배타적**이다. 이 성질은 판정 단위가 식별자일 때만 성립하고, 행 단위에서는 성립하지 않았다 — 그것이 D1 이다.

**`marked` 술어의 경계 두 개가 load-bearing 이다**(감사 N4·N5). 둘 다 실측에서 서로 다른 수를 냈으므로 구현이 자유롭게 고를 수 있는 자리가 아니다:

- **같은 행에 한한다** — 줄바꿈은 인접을 깬다. 허용 개입 문자는 스페이스와 탭뿐
- **공백·탭이 아닌 문자는 무엇이든 인접을 깬다** — 닫는 백틱 포함. 코드 스팬 안에서 표시하려면 토큰이 스팬 **안**에 들어와야 한다

### B.3 추출 앵커 — 왜 센티널인가

계수기 명령은 절 안의 셸 명령으로 살고, 검증자가 **문면에서 추출**한다. 앵커를 산문 구조("B12 헤딩 다음 fenced 블록")에 걸면 M1·M2 가 바로 그 산문을 다시 쓰는 순간 깨진다 — 세 상태 표, 정지 의무, 해소 메시지, 출력 예시가 모두 그 절에 들어간다. 절은 인라인 코드 명령도 담으므로 느슨한 앵커는 엉뚱한 것을 집는다.

그래서 앵커는 **문장이 아니라 센티널 주석 줄 한 쌍**이다. 절을 다시 쓰는 사람은 그 두 줄 사이만 건드리지 않으면 된다. 그리고 검증자는 추출이 **정확히 1건이며 비어 있지 않음**을 먼저 단언한다 — 앵커가 조용히 0건이나 2건을 집는 경우를 공허한 통과로 만들지 않기 위해서다.

## §C baseline 스냅샷 스키마 (M3-c · M5)

### C.1 파일별 항목의 두 형태

```
<경로>  COUNT <n>  live=<n> excluded=<n> ambiguous=0
<경로>  HALT <id> [<id>…]  owner=<SPEC-ID>  reason=<정지가 남은 이유>
```

`HALT` 는 **일급 항목**이지 예외가 아니다(`spec.md` §3.5). 정지 파일을 corpus 에서 빼거나 0 으로 세는 설계는 정지를 통과로 읽는 것이고, 이 SPEC 이 없애려는 병을 corpus 층에 되들이는 일이다.

### C.2 판정은 값이 아니라 **상태 변화**다

| 스냅샷 | 이번 실행 | 판정 |
|---|---|---|
| `COUNT n` | `COUNT n` | 통과 |
| `COUNT n` | `COUNT m` (n≠m) | 실패 |
| `COUNT n` | `HALT …` | 실패 |
| `HALT …` | `COUNT n` | **실패** — 정규화가 일어났는데 스냅샷이 따라오지 않았다 |
| `COUNT n` / `HALT …` | (글롭 밖) | 실패 — **사라짐**. 이미 잰 관측이 없어졌다 |
| (없음) | `COUNT n` | **보고, 실패 아님**(0.5.0) — 처음 생긴 관측이지 잰 값의 이동이 아니다 |
| (없음) | `HALT …` | **보고, 실패 아님**(0.5.0) — **부재를 먼저 판정한다**(`spec.md` §3.5 규칙 4) |

마지막 두 행은 0.5.0 개정이다. 종전 표는 `(없음) | HALT …` 를 실패로 두었고 `(없음) | COUNT n` 을 열거하지 않은 채 "어떤 차이든 실패" 로 흡수했다 — 그 결과 **무관한 카드가 새 SPEC 을 저작할 때마다** 이 검증자가 붉어졌다 — 신규 `acceptance.md` 추가 속도가 하루 여러 건이기 때문이며, 그 속도는 재유도 명령과 관측 트리로 `spec.md` §4 REQ-ACD-006 주석에 적혀 있다(수를 여기 얼리지 않는다). 좁힌 것은 **처음 보는 파일**뿐이며, 이미 잰 파일의 이동과 사라짐은 위 네 행이 그대로 잡는다. 부재 파일은 **매 실행 경로와 관측이 보고돼야 한다** — 보고 없는 좁힘은 검사를 끈 것과 구별되지 않는다.

### C.3 상태별 집계를 담는 이유 — 그리고 담아도 남는 위험

스냅샷은 재생성할 수 있고 M5 는 재생성을 정상 절차로 둔다. 즉 **나쁜 이유로 수가 움직인 실행도 재생성 한 번으로 통과한다.** 총계만 담으면 재생성 diff 가 "숫자가 바뀌었다" 로만 읽히지만, 상태별로 담으면 **live 가 excluded 로 옮겨 갔는지**가 diff 에 보여 검토가 가능해진다.

**이것은 방지가 아니라 가시화다.** 설계가 그 위험을 없앤다고 주장하지 않는다 — `spec.md` §3.5 와 REQ-ACD-006 주석이 같은 말을 하고, AC-ACD-006 의 주석이 이를 남는 위험으로 기록한다.

## §D 배포 표면 위상 — 반송자는 셋이다

```
.claude/agents/moai/manager-docs.md                      (로컬 · 사람이 편집)
        │  Template-First 미러
        ▼
internal/template/templates/.claude/agents/moai/manager-docs.md   (미러 · 사람이 편집 · 생성 원본)
        │  make agents-emit  (agentemit: templatesDir + .claude/agents/moai)
        ▼
internal/template/templates/.codex/agents/moai/manager-docs.toml  (기계 생성 · 손대지 않는다)

        그리고 별도 경로:
internal/template/catalog.yaml   ← make build 의 gen-catalog-hashes --all 이
                                    미러 `.md` 의 내용 해시를 다시 낸다
```

**두 갈래가 서로 다른 기제라는 점이 설계상 중요하다.** `catalog.yaml` 은 미러의 **해시**를 담고 `make build` 가 갱신한다. `.codex` TOML 은 미러의 **내용**을 담고 `make agents-emit` 이 갱신하며, `catalog.yaml` 에 엔트리가 없다(실측 `grep -c '\.codex'` → `0`). 따라서 둘은 서로를 대신하지 못하고, §F 에서 별도 파일로 센다.

**게이트의 위치가 순서를 강제한다.** `Makefile:23` 의 `build: agents-emit-check templ-generate` 에서 `agents-emit-check` 는 읽기 전용이라 스스로 재생성하지 않는다(`Makefile:31-38`). 그래서:

```
미러 편집 → make agents-emit → make build
                 (빠뜨리면 여기서 sha256 불일치로 정지 — 컴파일에 닿지 못한다)
```

이 배치는 **조용한 드리프트를 불가능하게 만드는 대신 순서를 모르는 사람을 빌드 실패로 세운다.** 설계상 옳은 교환이다 — 배포된 에이전트가 낡은 절을 담는 쪽이 훨씬 비싸다.

## §E 기각한 설계 대안

| 대안 | 기각 사유 |
|---|---|
| 파서(마크다운 구조를 읽어 기준을 식별) | 유효성은 구조가 아니라 의미다. 같은 헤딩이 한 SPEC 에서는 살아 있는 기준, 다른 SPEC 에서는 폐기된 기준을 담는다. 결국 표지를 읽어야 하므로 **규약을 없애지 못하고 마크업 형태 의존성(제약 1)만 얹는다** |
| 어휘 매칭(`retired` / `폐기` 낱말) | 양방향으로 불건전하다 — 플래그된 29개 중 8개가 폐기 *주제* SPEC 의 살아 있는 기준이었다(`spec.md` §2.1 · §8) |
| 세 번째 토큰(별칭 축 전용) | `[REF]` 의 뜻을 넓히면 토큰도 계수 규칙도 그대로다. 토큰을 늘리면 규약 표면만 커지고 잔여(상한 85 미소급)는 그대로다(`spec.md` §2.3) |
| 코드 스팬·fenced 블록을 계수에서 제외 | **마크업 앵커**이므로 REQ-ACD-004 위반. 규약을 예시하는 문서의 정지를 푸는 싼 우회로처럼 보이지만, 제약 1 을 다시 밟는다(`spec.md` §3.4) |
| 정지 파일을 corpus 에서 제외 | 정지를 통과로 읽는 것. 이 SPEC 이 없애려는 병을 corpus 층에 되들인다(`spec.md` §3.5) |
| 접두사 단위 애매성 판정(순수 인용까지 잡기) | 정당한 다중 도메인 SPEC(`AC-APO-*` + `AC-DCP-*`)까지 정지시킨다. 피하려면 **네이티브 접두사 선언**이라는 새 문법이 필요하고 이 카드의 크기를 넘는다 — 후속 카드 후보(`spec.md` §6) |
