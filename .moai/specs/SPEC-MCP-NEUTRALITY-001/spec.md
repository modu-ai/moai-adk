## §1 Problem

The `moai mcp-server` is protocol-clean enough for Claude Code and Codex both to connect, but it is not harness-neutral. The 2026-10-10 audit (`.moai/reports/audit-20261010/` lens reports, measured on main @ 2aab5f797) and the cross-harness redesign §6.3 (목표 MCP 모델) establish four defect families this SPEC owns:

1. **Policy refusals masquerade as errors.** Of 1,943 recent tool calls, 482 refusals were raised on the MCP error channel (`isError: true`), and the failure observer wrote 409 refusal rows into the lessons inbox as if they were tool failures. The refusal class is a policy decision (serial slot occupied, card owned elsewhere, raced claim, parent checkout required), not a malfunction — callers cannot distinguish "the queue refused you" from "the server broke".
2. **Identity and root depend on Claude-launcher spawn env.** Role is decided by the *absence* of env (`factoryLaneAdmission`/`factoryLaneRefusal` in `internal/cli/factory_card.go`): an unmarked Codex session reads as the operator. The Codex env allowlist (`internal/codexwiring/configtoml.go`, `mcpServerEnvVarsValue`) omits `MOAI_FACTORY_ROLE` and `MOAI_LAUNCH_PROVIDER`, so a Codex lane can never receive lane identity over MCP. Roughly 23 tools accept no `project_root` at all and fall back to the server's spawn cwd; a non-string value is coerced to the default; the validation branch accepts any directory containing `.moai`, the home directory included.
3. **The broker and the audit tool surface break their own contracts.** The factory message broker rotates claim tokens on every re-claim (three re-claim sites: Stop hook, UserPromptSubmit hook, `factory_msg_list`), invalidating tokens still in hand; a receiver generation change orphans delivered messages forever (9 real orphans in the production database); the 2,048-byte hook cut claims messages it never shows; every natural leader turn costs one extra forced turn. The audit tools: a codex FAIL receipt corroborates a PASS; receipts bind to no tree state; transport failures become verdict `fail`; convergence passes on the caller's own submitted verdict; codex children inherit the full environment with no sandbox policy; `claude_audit` scrubs env by denylist so `CLAUDE_CONFIG_DIR` and proxy variables pass through.
4. **Server lifecycle facts are invisible.** Staleness is advertised only at `initialize`; no tool result compares the serving process against the installed binary. Job registries outlive the server that created them. The runtime stamp write fails closed (a read-only project cannot start the server) and creates `.moai` in any cwd. `todo_claim` is registered but dead (absent from the catalogue), and the registration gate silently drops catalogue-absent names instead of failing the build.

Evidence: `lens-7-moai-mcp-cross-harness.md` (defects B1–B22), `lens-3-codex-glm-tools.md` (defects 1–28), `lens-4-factory-evidence-leases.md` §5 and `lens-6-stop-hook-chain.md` §5 (broker). Design target: the cross-harness redesign §6.3 and master plan stage-0 row 3.2-0-3.

## §2 Goals and Non-Goals

**Goals.** A caller — Claude lane, Codex lane, Codex gate session, or any generic MCP client — gets the same answer for the same call: policy refusals are structured data, not errors; identity and root are arguments with env as default only; the broker never loses or hides a delivered message; audit verdicts are bound to the tree state they judged and tell the truth about what ran.

**Non-Goals.** See §5 Out of Scope.

## §3 Requirements

Requirement IDs use the `REQ-MN-` prefix. File and function names anchor where behavior lives today; line numbers are deliberately omitted (they drift between trees — the audit's own numbers have already drifted once). The defect-to-requirement mapping in full detail lives in `plan.md` §B and `design.md` §D2.

### §3.1 M1 — Structured policy refusals and identity (P0)

- **REQ-MN-001** (structured policy refusal) — When a policy gate refuses a factory or todo MCP tool call — the serial slot is held by a live lease, the card is owned or leased by another endpoint, a claim is raced and lost, a parent-checkout operation is required, or the run id is stale — the tool shall return a successful MCP result (`is_error` false) whose structured content carries `refused: true`, a machine-readable `code` from the closed set `serial-slot | owned | raced | parent-checkout | stale-run`, and a human-readable reason; the same refusal JSON shall appear in the text content block. The MCP error channel shall not be used for a policy refusal.
- **REQ-MN-002** (observer split) — When the failure observer records tool-failure rows in the lessons inbox, it shall exclude results whose structure marks a policy refusal (`refused: true`); only genuine malfunctions — transport loss, unexpected handler failure — remain observable as mcp rows.
- **REQ-MN-003** (positive identity) — Every tool whose behavior depends on spawn-time identity (the factory card verbs, the `factory_msg_*` family, `todo_claim`, the `goal_*` family, and the `audit_multi` origin declaration) shall accept an explicit actor argument (lane label, session id, or launch provider) and shall treat the spawn environment only as its default; when a factory verb receives a run id that is not the currently active run in the factory database, it shall refuse with code `stale-run` and shall not read lease, stage, or evidence state from expired rows; where operator authority decides an operator-only verb (`factory_decide`, operator `todo_add`, operator `todo_claim`), a positive operator mark shall be required — the absence of lane environment variables alone shall not confer operator authority, and unknown attribution shall be refused with `refused: true`.

### §3.2 M2 — Common project_root contract, catalogue, schemas (P0)

- **REQ-MN-004** (common project_root contract) — The root-less tool families — `session_list`, the `goal_*` family, `audit_cache`, the `codex_job_*` family [superseded — surface removed by card t1909], the `glm_*` task/job family, the `session_msg_*` family, the `factory_msg_*` family, and `jev_ask` — shall accept `project_root` as a first-class argument and shall resolve it to the caller's git toplevel when the caller names a worktree (codex_task and codex_job_* removed by card t1909, 2026-10-23); behavior shall stop deriving from the server's spawn cwd wherever the caller can name the tree; mutating tools among them shall refuse when the argument is absent rather than fall back — the verbs that require `project_root` are now four: `factory_next`, `factory_stage`, `factory_complete`, `factory_renew`; every tool whose behavior depends on a root shall carry `_root {dir, source, warning}` in its result, with `warning` set whenever the root came from any fallback rather than the caller's explicit parameter; and the factory card verbs (`factory_next`, `factory_stage`, `factory_complete`) shall pass the caller's `project_root` as the integration lock root through the same repository resolver the CLI uses — one git-common-dir interpretation shared by CLI and MCP — with the parent-checkout requirement documented on all three verbs.
- **REQ-MN-005** (root confinement) — When a `project_root` is validated, the server shall confine it to a registered worktree of the server's own repository — the same confinement the codex audit launch path already applies via `codexAuditValidateRoot` (`internal/cli/codex_audit_launch.go`) — shall reject the home directory explicitly, and shall reject paths outside the repository's registered worktree set; a non-string value shall be rejected as an invalid argument, never coerced to a default (`resolveToolProjectRootWithSource` in `internal/cli/mcp_project_root.go` today coerces). The confinement does not apply to the audit/delegation surface (`codex_audit`, `audit_multi`, `glm_audit`, `claude_audit`), which is validated — symlink-canonicalized, `.moai` or an accepted linked worktree required, and a non-string root rejected by `codex_audit`, `glm_audit`, and `claude_audit` — but not confined to the server's repository, because an audit legitimately names another repository's tree. Two known gaps remain on that surface, recorded as debt and not as protection: the home directory is not rejected there (only the confined set rejects it), and `audit_multi` treats a non-string root as absent; see AC-MN-007.
- **REQ-MN-006** (catalogue as hard source) — The tool catalogue (`internal/mcp/catalog.go`) shall list `todo_claim` so the registered tool (`internal/cli/mcp_todo.go`) is served, and the registration gate shall turn a registered name absent from the catalogue into a build failure instead of silently dropping the tool.
- **REQ-MN-007** (schema strictness) — Every served tool's input schema shall declare its additional-properties policy, carry a description on every declared property (the eleven undescribed `factory_msg_*` properties included), declare every argument the handler actually reads (the undeclared `codex_task` model argument included — superseded — surface removed by card t1909, 2026-10-23; the obligation stands for every tool still served), and keep required-field declarations consistent with actual enforcement (`goal_status` included); read-only tools shall not report a destructive hint. A schema lint test shall sweep every served tool and fail on a violation.
- **REQ-MN-008** (wire honesty) — Where a tool returns structured content, the same JSON shall be serialized into the text content block (`toolJSON` in `internal/cli/mcp_server.go` today emits `"<tool>: ok"`), and collection-valued fields shall serialize as empty arrays rather than null when there is nothing to return; where the server emits `notifications/message` it shall declare the corresponding logging capability or stop emitting; progress and refusal phrases shall be harness-neutral (fixed Korean literals excluded); and the protocol versions the server actually negotiates shall be documented as served (the SDK-backed downgrade of `2026-07-28` documented, not advertised as non-negotiable).

### §3.3 M3 — Codex gate session containment (P0)

- **REQ-MN-009** (gate session containment) — When moai launches a Codex gate or audit child, the launch shall disable every non-moai MCP server for that child — the containment the role-audit path already applies via `codexAuditMCPDisableArgs` — and the moai server exposed to gate sessions shall present only the read-relevant subset: every served tool whose registered annotation is read-only and whose handler performs no write to project state, with mutating operations excluded (`audit_cache`'s store operation falls in that exclusion); the enumerated set is fixed in plan §F M3 and the exposure test asserts the served subset equals it.
- **REQ-MN-010** (input containment) — The moai MCP server shall not initiate elicitation requests toward its clients — the mcp-go v1.1.1 elicitation API (server→client) stays uncalled, and a guard test shall hold that invariant; where moai wires a Codex gate session's client connections, an elicitation request arriving from a nested server shall receive an automatic decline response instead of stalling the session or interleaving writes on the shared stdin stream; and while concurrent tool calls mutate shared state under the project's `.moai/state`, the server shall serialize those writes through one mutex so interleaved writers cannot corrupt or double-write the same artifact.
- **REQ-MN-011** (inbox empty-path async) — When a reader inspects the factory inbox and finds it empty, the counting path — the read-only observation a hook uses for counts — shall not take the write lock nor pay the bounded write-probe deadline (`CheckWritable` and the 200 ms hook inspection deadline produced 1,619 recorded "inbox context deadline exceeded" errors) and shall never claim messages; message delivery remains the distinct rendering path that renders the visible set and claims exactly it (REQ-MN-016).

### §3.4 M4 — Environment scrub, staleness, job lifetime, runtime hygiene (P0/P1)

- **REQ-MN-012** (claude child env allowlist) — The `claude_audit` child environment shall be built from an allowlist (replacing the `scrubClaudeAuditEnv` denylist in `internal/cli/mcp_claude.go`): `CLAUDE_CONFIG_DIR` and proxy or CA variables shall not pass through, the subscription config directory shall be pinned explicitly, any 429 response shall be labeled as rate limiting with the endpoint unverified rather than as subscription capacity, and the configured claude binary pin (`MOAI_CLAUDE_BIN` / `llm.claude_bin`) shall be honored for every claude invocation the server makes (no `claudeLookPath` bypass).
- **REQ-MN-013** (per-call staleness) — Every tool result shall carry `_server {version, commit}` compared against the installed binary on disk (commit and mtime of the executable serving the call); a mismatch shall annotate `stale_server: true` with reconnect guidance in the result, and mutating tools shall refuse while stale.
- **REQ-MN-014** (job lifetime) — Where the server tracks background jobs (GLM jobs, role-audit jobs; codex jobs [superseded — surface removed by card t1909]), each background job shall run under the server's lifetime — surviving its originating request's context end, bound by its own job deadline, cancellable through an explicit cancel surface, and cancelled when the server exits — while the foreground codex task shall run under its request's context [superseded — surface removed by card t1909]; and the server shall stamp the owning server identity into each record, report `stale` from status queries whose owning server is dead, expose a cancel tool for role-audit jobs (`codex_role_audit_cancel`, part of the read-only audit launcher family `codex_role_audit` start/status/result/cancel, which stays), prune job registries by TTL, and record the foreground codex task's thread id with partial output on timeout instead of losing the work [superseded — surface removed by card t1909]. Background jobs surviving a request's context end is the existing contract pinned by `TestCodexTask_BackgroundJobSurvivesRequestContextEnd` [superseded — surface removed by card t1909], `TestGLMTask_BackgroundJobSurvivesRequestContextEnd`, and `TestGLMTask_DetachedBackgroundJobIsStillCancellable`; this requirement does not reverse it. Since 2026-10-23 the requirement covers GLM jobs and role-audit jobs only: card t1909 (origin/main commit 8c36a7904b) removed the codex background jobs together with `codex_task` and the `codex_job_status` / `codex_job_result` / `codex_job_cancel` tools.
- **REQ-MN-015** (server runtime hygiene) — When the runtime stamp write fails, the server shall still serve (best-effort by contract), and a server started outside a moai project shall not create a `.moai` tree in that working directory (`writeMCPServerRuntimeRecord` in `internal/cli/mcp_server_runtime.go` today does both); and the server shall log one row per tool call (tool, duration, refused-or-error classification) to a rotated per-process call log under the project's `.moai/state/mcp-server/<pid>/` in addition to stderr, keeping stderr reserved for protocol traffic.

### §3.5 M5 — Broker and inbox repairs (absorbs t1622) (P0)

- **REQ-MN-016** (delivery integrity) — When a receiver re-registers and its generation advances (`internal/factorymsg/store.go`), messages addressed to the previous generation shall be migrated to the new generation or dead-lettered with a notification to the sender — no delivered message shall become permanently unclaimable by a generation change alone; and when a hook renders its bounded message context, the byte cut (the 2,048-byte `factoryHookContextLimit` in `internal/hook/factory_messages.go`) shall fall on a message-line boundary, and only messages actually visible in the rendered context shall be claimed — a claimed-but-invisible message shall not exist.
- **REQ-MN-017** (claim lifecycle) — When the same endpoint re-claims messages it still holds, the broker shall keep the existing claim token and extend the lease instead of minting a new one — a token emitted to hook or tool output shall remain valid until its lease genuinely expires (the three re-claim sites today are the mechanism behind the recorded "claim identity mismatch" failures); when `factory_msg_list` finds no eligible targets it shall return an empty array together with any messages already claimed under the caller's current token, never a null-valued field; and when the host session identity changes (a `/clear` or a relaunched session), the server shall resolve the live identity for peer attribution (`currentFactoryPeer` in `internal/cli/mcp_factory_msg.go` keeps serving the spawn-time `CLAUDE_CODE_SESSION_ID` today) or refuse with guidance.
- **REQ-MN-018** (Stop block scoping) — When the leader's Stop hook fires (`internal/hook/stop.go`), it shall force a continuation turn only for message kinds that require a decision (the blocker and status classes) and shall otherwise deliver counts without blocking; while the broker is degraded, that state shall be logged on the Stop side rather than silently swallowed (every natural leader turn currently costs one extra forced turn).

### §3.6 M6 — Audit tool integrity and the state-root seam (absorbs t1625 + t1597 seam) (P0/P1)

- **REQ-MN-019** (target honesty) — When a backend audit or review is asked for a declared target (a base branch, an adversarial pass), the backend leg shall apply the resolved target — the resolved base SHA and the diff instruction present in the prompt — or return inconclusive stating the target was not applied; the second-review record (`internal/cli/mcp_audit_multi_record.go`) shall state each backend's effective scope rather than claiming a baseBranch review that did not run (`internal/cli/mcp_convergence.go` codex leg and the `codex_audit` adversarial mode ignore the target today).
- **REQ-MN-020** (evidence binding) — An audit receipt (`internal/auditreceipt/store.go`) shall carry the head commit and a tree digest of the state it judged, shall refuse to corroborate a pass when the receipt's verdict is fail or when the stored tree state differs from the current one, and the store shall validate existence and digest match before any reuse (a codex FAIL receipt currently reinforces a PASS; the receipt carries no HEAD or digest); the `audit_cache` store shall persist its entries to disk under the project's state root instead of process memory, shall require the hash of an existing verdict file as each entry's evidence, and shall validate the verdict file's existence and SHA-256 match before storing or reusing an entry (today `compute_hash` returns the empty-input hash for a non-SPEC directory and the cache is process-local and self-attesting); and the auditor model shall be recorded on codex and GLM verdicts exactly as it already is on Claude verdicts.
- **REQ-MN-021** (verdict truthfulness) — When a backend review could not be performed (transport loss, unparsable reply), the result shall keep a not-performed verdict distinct from content failure, preserve the backend's stderr for diagnosis, and retry once before reporting (`applyGateUnmet` in `internal/cli/mcp_codex.go` and `enforceRequiredGateUnmet` in `internal/cli/mcp_convergence.go` convert could-not-run into verdict `fail` today); when a required backend is inconclusive or absent, convergence shall not pass on the caller's own submitted verdict (`claudeVerdictOrDefault` falls back to pass today) — below the participant-evidence threshold the result shall be a distinct not-converged outcome; and the GLM review decoder (`parseGLMReview`, `internal/cli/mcp_glm.go`) shall unmarshal model text into a narrow structure that cannot set provenance, receipt, gate, or review-base fields, with the GLM task content extraction (`internal/cli/glm_task.go`) selecting the assistant text content rather than the first block unconditionally.
- **REQ-MN-022** (codex child containment) — Every codex audit, review, and convergence leg shall run with a read-only sandbox policy and a scrubbed child environment (the containment the role-audit path applies via `codexChildEnv`), never the server's full inherited environment (the audit and review turn paths forward a sandbox policy only when the caller supplied one and set no `cmd.Env` today).
- **REQ-MN-023** (material marking) — Where review material is truncated (the 200,000-byte cap in `collectReviewDiff`, `internal/cli/mcp_review_material.go`) or untracked files are excluded, the result shall mark `truncated` and `excluded_untracked`; a backend audit asked to judge empty material shall refuse before invoking the backend (the guard `codex_audit` alone lacks).
- **REQ-MN-024** (gate state integrity) — Multi-review gate verdict state shall be keyed to the tree state it judged (a digest, not a per-session path a later pass overwrites), written atomically, and the session id shall be validated against a safe pattern before it is joined into a path; a could-not-run receipt shall not be reused as a gate pass within any cache TTL (the turn-end gate currently reuses a 24-hour-old inconclusive receipt as a pass).
- **REQ-MN-025** (state-root seam) — For every artifact class the MCP layer reads or writes (audit receipts, review and gate state, the broker store), the producer and every consumer shall resolve the same root by one canonical contract — the caller-named project root, falling back to the repository toplevel — so a reader in a nested session never resolves a different root than the writer (the Codex Stop chain's receipt reader and the receipt producer currently disagree in nested sessions, producing false "receipt absent" negatives). The full cross-harness state unification stays out of scope (§5).

## §4 Constraints

- **t1696 parallel repair.** `internal/cli/factory_card.go` is under parallel urgent repair by card t1696. Identity work in this SPEC lands at the MCP layer (`internal/cli/mcp_factory_card.go`) wherever possible; any portion that must touch `internal/cli/factory_card.go` itself merges or absorbs t1696 after t1696 lands (tracked as the lane board's conditional follow-up task).
- **Path drift.** The audit's line numbers were measured on main @ 2aab5f797 (2026-10-10) and have already drifted: the Codex env allowlist now lives in `internal/codexwiring/configtoml.go` (not `internal/cli/`), the hooks live under `internal/hook/` (not `internal/hooks/`), and the broker store is `internal/factorymsg/` (not `internal/messaging/`). Implementers re-locate each anchor before editing (`research.md` §R2 carries the verified inventory).
- **Trust-boundary validation is never simplified away.** The `job_id`/`session_id` path-joining validations (REQ-MN-024, job registries) and the root confinement (REQ-MN-005) are security-relevant; the simplicity ladder does not apply to them.
- **MCP server reconnect.** The server keeps serving the build it started with; after reinstalling the moai binary mid-run, new tools stay absent until the host reconnects the server. Run-phase verification accounts for this.

## §5 Out of Scope

### Out of Scope — full cross-harness state unification (card 3.2-2-1)
- Only the MCP/state-path resolution seam is owned here (REQ-MN-025): which root each consumer resolves.
- State layout unification, repo-id derivation, migration and tombstones belong to card 3.2-2-1.

### Out of Scope — the two audit base resolvers (lens-3 defect 1)
- `cardMergeBase` (`internal/cli/codex_review_scope.go`, reads `develop_branch`) versus `resolveReviewBase` (`internal/cli/mcp_review_material.go`, reads `worktree_base_branch`) disagreeing on mixed-key configs is a P0 defect observed by the audit but is not in the absorbed t1625 item list.
- Flagged to the stage owner (adjacent to the stage-0 audit-loop card 3.2-0-4); this SPEC does not repair it.

### Out of Scope — backend concurrency limiter and Retry-After backoff
- A machine-global codex/GLM call limiter with Retry-After-aware backoff was a lens-3 design recommendation without a card item; deferred to a follow-up card.

### Out of Scope — receipt TTL divergence by harness
- The Claude gate (24 h) and the Codex Stop-chain member (minutes) reusing different receipt TTLs was observed (lens-3 defect 27) but is not in the card list; deferred.

### Out of Scope — MCP protocol version upgrade
- Serving `2026-07-28` is bound by the mcp-go v1.1.1 SDK, not by this codebase; REQ-MN-008 documents what is served truthfully and does not upgrade the SDK.

### Out of Scope — factory v2, CLI refactor, and other stage cards
- The factory 8-state machine (3.2-2-2), worktree root unification (3.2-2-3), CLI package split (3.2-3-1), and language gates (3.2-3-2) are separate stage cards; this SPEC touches none of them.
- The graph tool backend and `session_msg_*` authentication semantics beyond the root contract stay as they are.
