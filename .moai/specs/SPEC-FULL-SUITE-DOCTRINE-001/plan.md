## §C. 사전 점검

1. `git rev-parse --show-toplevel` / `git branch --show-current` — 워크트리 안인지 확인.
2. `git rev-parse --short HEAD` — AC-FSD-009의 기준 SHA가 `d29b8942e` 와 같은지 확인. 다르면 실제 분기점으로 갱신하고 `progress.md` 에 기록.
3. **미러 계보 확인** — 손대는 파일마다 `.codex/` 쌍둥이가 있는지 본다. 최초 조사가 `internal/template/templates/.claude/` 아래만 확인해 미러가 하나뿐이라고 가정한 것이 세 번째 사본을 놓친 원인이다. 현재 확정 사실: 에이전트 정의는 `.codex/agents/moai/*.toml` 미러가 있고, 규칙 파일은 없다(`.codex/` 트리에 `rules` 디렉터리 자체가 없음).
4. **편집 전 baseline 재채집** — `acceptance.md` 각 AC의 사전 baseline을 이 트리에서 다시 돌려 기재값과 일치함을 확인한다. 불일치는 편집 시작 사유가 아니라 SPEC 재작업 사유다. **rc를 읽을 때 명령과 `echo $?` 사이에 파이프를 두지 않는다** — 파이프 뒤 rc는 마지막 명령의 것이라 앞 명령의 결과를 가린다.

**M1이 실제로 하는 일** — 위 계측점을 품은 완결된 문장 3종을 짓는 것:

1. **범위 규칙 문장.** S1·S2·S3를 대체한다. 판별자가 사라지므로 조건절 없이 한 문장이다. 정본 문구를 포함하되, STEP 4 지점에 반드시 놓는다.
2. **위임·미결 문장.** STEP 5 완료 보고 지시 안에 놓이며 두 정본 토큰을 **한 문장에** 담는다. 한쪽만 있으면 반쪽 위임이 되어 B5가 되살아난다.
3. **S4 배치 호출 문장.** 열거에서 전량 어휘를 걷어내고 1의 규칙과 정합시킨다.

**중립성 점검**은 문장을 쓰는 자리에서 함께 한다 — 세 문면 모두 배포된다. 상위 계약이 이미 쓰는 일반 근거를 모델로 삼고, 사고 서술·날짜·SPEC ID·브랜치명은 한 글자도 넣지 않는다.

산출: 확정 문면 3종을 `progress.md` 에 먼저 적고 편집에 들어간다. 세 사본에 **같은 문면**을 쓴다.

### M2 — 에이전트 정의 3벌 수리

순서: **C2(템플릿 md) 편집 → `make agents-emit` 으로 C3 재생성 → `make build` → C1(로컬 md 반영 확인).** 템플릿 먼저가 Template-First 규율이다.

**C3는 편집 대상이 아니라 재생성 대상이다.** `internal/template/agentemit` 가 C2와 매니페스트로부터 결정적으로 만들어내므로, 손으로 고치면 골든 테스트에 걸리고, 재생성을 건너뛰면 다음 방출이 수리를 조용히 되돌린다. `make build` 는 `agents-emit` 을 부르지 않으므로 재생성은 **명시적 별도 단계**다.

C2에서 S1·S2·S3·S4 전부 + 판별자 제거. C3는 그 결과가 방출로 옮겨온다.

검증: AC-FSD-001·002·003·012·014·007.

### M3 — 배치 정의 2개 지점 수리

- `agent-common-protocol-reference.md` — `# 1.` ~ `# 2.` 구간의 표제와 호출(REQ-FSD-004).
- `verification-batch-pattern.md` — Group A 행의 호출과 시간 추정치 셀(REQ-FSD-005 두 절).

두 파일 모두 로컬·템플릿이 현재 byte 동일하므로 수리 후에도 동일해야 한다. codex 미러는 없다.

검증: AC-FSD-004·005·006·013·015.

임베드 재생성 후 세 쌍의 diff가 baseline 델타와 일치하는지 확인. C3는 로컬 쌍이 없으므로 이 항목 대상이 아니며, 직접 측정 AC들이 대신한다.

## §G. 안티패턴

- 네 지점 중 일부만 고치기 (B1).
- `.md` 두 사본만 고치고 `.toml` 을 두기 (B2) — AC 여럿이 C3를 직접 재므로 이제는 잡히지만, 애초에 하지 않는다.
- **C3를 손으로 편집하기** — 생성 산출물이라 골든 테스트가 sha256 불일치로 떨어뜨린다. 고칠 곳은 C2다.
- **C2를 고치고 `make agents-emit` 을 건너뛰기** — C3가 낡은 채로 남아 다음 방출이 수리를 되돌린다. B7이 이름 붙인 조용한 되돌림의 생성-계보 판본이고, 내용만 재는 AC로는 보이지 않는다(되돌아가기 전까지는 내용이 옳기 때문이다). 이 경로를 잡는 것은 AC-FSD-010의 **맨 앞에 오는 읽기 전용 골든 실행**과 fail-closed인 `make agents-emit` 자체다 — 재생성 **뒤에** 도는 골든은 잡지 못한다(update 분기가 비교를 건너뛰고 덮어쓴 뒤 0으로 끝나므로, 그 시점엔 두 실패 경로가 이미 지워져 있다).
- 배치 정의를 두고 에이전트 정의만 고치기 (B2).
- 형용사를 갈아끼워 전량 지시를 유지하기 (B3).
- 정본 문구를 STEP 4가 아닌 자리에 심기 (B4).
- 위임은 말하되 미결을 빠뜨리기 (B5).
- 판별자를 남겨 아무것도 가르지 않는 조건을 방치하기 (B6).
- 로컬 편집 후 템플릿 미러를 잊기 (B7).
- 위임 문장에 `origin/develop` 을 쓰기 (B8).
- AC의 계측점 문자열을 "더 나은 표현" 으로 바꾸기 — AC가 통째로 무효가 된다 (§D C6).
- 물려받은 49분 40초를 이 SPEC이 측정한 값처럼 인용하기.
- 검증하겠다고 전체 스위트를 돌리기 (§D C4).
- AC가 막는다 싶으면 `acceptance.md` 를 고치기 — run-phase 행위자에게 금지된 소유권 교차다. 막히면 blocker 보고로 되돌린다.
