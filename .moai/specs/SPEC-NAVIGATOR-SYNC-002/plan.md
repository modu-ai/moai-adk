## §B. Known Issues + Pre-flight Decisions

- **B1 — edge `source_path` is absolute**: the changed path from PostToolUse `ToolInput.file_path` is also absolute. Comparison strategy: normalize both to absolute via `filepath.Abs` before string-equality. No relative-path inference needed (avoids the macOS `filepath.Join(cwd, absPath)` trap from CLAUDE.local.md §6).
- **B2 — graph may be absent at first edit**: M0's `nav-graph.json` is generated by `moai navigator-sync` (Hidden CLI). On a fresh checkout or before the first `/moai project` run, the graph is absent. REQ-NS2-004 fail-open covers this; the Detect branch emits one log line and returns empty.
- **B3 — the `MxBridgeSpec` edge's source_path is the code file, not a design doc**: `@MX:SPEC` associations produce edges whose `source_path` is the code file (e.g. `internal/foo/bar.go`). Editing that code file therefore surfaces the SPEC back-pointer — the highest-value Detect case.
- **B4 — `NotebookEdit` carries `notebook_path`, not `file_path`**: the Detect branch extracts the path from whichever field is present (`file_path` for Write/Edit, `notebook_path` for NotebookEdit). Both normalized to absolute. **Run-phase reconnaissance step (D3 lift)**: existing `internal/hook/*.go` branches do not visibly handle `NotebookEdit` as a distinct tool name (no PostToolUse branch matches `NotebookEdit` in the current source). The M1 run-phase MUST verify, BEFORE relying on NotebookEdit delivery, that (1) PostToolUse actually fires for `NotebookEdit` events, and (2) `ToolInput.notebook_path` is parseable into an absolute path the traversal can compare. **Decision branch — recorded as an explicit run-phase decision point, NOT a silent assumption**: IF the recon shows NotebookEdit does NOT fire a PostToolUse event (or the payload lacks a parseable `notebook_path`), THEN downgrade NotebookEdit from REQ-NS2-001's SHALL to a separate SHOULD REQ (or drop NotebookEdit from M1 scope entirely and document the deferral). In that case, REQ-NS2-001 stays as-is for Write/Edit only; the recon outcome governs NotebookEdit only. The decision + its evidence MUST be recorded in `progress.md §E.2` at M1.2.
- **B5 — no separate `moai hook navigator-detect` subcommand**: the existing `handle-post-tool.sh` wrapper already invokes `moai hook post-tool`, which dispatches to `postToolHandler.Handle`. M1 is a branch inside that handler. Adding a parallel subcommand would fork the chain (REQ-NS2-009 forbids).

## §C. Design Questions Resolved

### C.1 — Trigger surface

**Decision**: PostToolUse for `Write`, `Edit`, `NotebookEdit` only. `Bash` is excluded.

**Rationale (REQ-NS2-001)**: Write/Edit/NotebookEdit carry a structured `file_path` (or `notebook_path`) in `ToolInput`; Bash file mutations (`sed -i`, `mv`, `git checkout -- <path>`) have no structured path — extracting one reliably is a heuristic problem with real failure modes (glob expansion, pipe targets, subshell rewriting). Including Bash would violate the verification-claim-integrity doctrine: a "mapped to affected row" claim built on an unreliable path-extraction is an unattributed claim. The boundary is principled, not merely convenient.

**Integration point (REQ-NS2-009)**: a new branch in `postToolHandler.Handle` at `internal/hook/post_tool.go`, placed after the existing `runMemoryAudit(input)` branch (line ~217) and before the `logEvidence(input)` branch (line ~223). The branch is:
```go
// (sketch — NOT run-phase code)
if (input.ToolName == "Write" || input.ToolName == "Edit" || input.ToolName == "NotebookEdit") {
    runNavigatorDetect(ctx, input, projectRoot)
}
```
`projectRoot` resolves via the existing `$CLAUDE_PROJECT_DIR` → `os.Getwd()` helper (`internal/hook/observer.go`, per `internal/hook/CLAUDE.md` B7). The new logic lives in `internal/hook/navigator_detect.go` (new file).

### C.2 — Reverse edge traversal algorithm

**Decision**: linear scan of `Graph.Edges`, filter by absolute-path equality on `Edge.SourcePath`.

**Algorithm**:
1. Read `nav-graph.json` in a single `os.ReadFile` (atomic — REQ-NS2-006).
2. Parse into `sync.Graph` (`internal/navigator/sync/schema.go`). On parse failure → REQ-NS2-004 fail-open.
3. Normalize the changed path to absolute: `changedAbs, _ := filepath.Abs(changedPath)`.
4. For each edge `e` in `graph.Edges`: if `filepath.Abs(e.SourcePath) == changedAbs`, add `e` to the affected-edge set, and add both `e.SourceNode` and `e.TargetNode` (as `<entity_type>:<identifier>` keys, resolved against `graph.Nodes` for `display_name`) to the affected-node set.
5. Deduplicate + sort both sets deterministically (by entity_type, then identifier; edges by edge_type, source_node, line_number — mirroring M0's `sortEdges`).
6. Return the affected-row set.

**Why linear scan, not an index**: the M0 graph for this repo is O(hundreds) of edges; even a 10K-edge graph scans in <10ms. A path→edge index adds state that must be invalidated on every regen; linear scan is stateless and reads the committed graph each time. Simplicity ladder (CLAUDE.md §7 Rule 4) — do not build an index before the linear scan proves too slow. The 200ms p99 budget (§D Constraints) leaves 20× headroom.

**Reuse of `navigator-audit.sh` matching (REQ-NS2-010) — honest framing**: the primary path→graph-edge mapping is absolute-path string equality — both the changed path (from PostToolUse `ToolInput.file_path`) and `Edge.SourcePath` are already absolute (`filepath.Join(projectRoot, …)` per `internal/navigator/sync/scan.go:120-126`), so `filepath.Abs` on both sides yields string-equality matching. `navigator-audit.sh`'s `heuristic_match()` (`.claude/skills/moai-workflow-project/scripts/navigator-audit.sh:406-422`) — which solves commit-title/path → design-doc name matching, NOT path → graph-edge mapping — is cited as **INSPIRATION for the directory-prefix fallback case** ONLY. When the changed path is a directory prefix (e.g. editing `internal/foo/`), the Detect layer falls back to matching any edge whose `source_path` is under that prefix; the last-segment resolution idea is borrowed from `heuristic_match()`'s last_seg/lastnorm logic. **The script itself is NOT the mapping engine**, and M1's Go code does NOT execute the shell script — the Go function in `internal/hook/navigator_detect.go` cites the script by file path + line range as the inspiration for the fallback, and re-implements the prefix check in Go.

### C.3 — Output surface (read-only / advisory)

**Decision**: two surfaces, both read-only.

1. **`systemMessage`** (user-visible, advisory): a short multi-line string naming the changed path and the affected rows, capped at 12 lines (the Claude Code `systemMessage` surface is not scrollable). Format:
   ```
   Navigator Detect: <changed_path> touches <N> graph row(s):
   - <entity_type> <identifier> (<edge_type> @ <source_path>:<line>)
   … (≤10 rows; "…and N more" if overflow)
   ```
   Appended to the existing `systemMessage` (which may already carry LSP / AST findings). The Detect branch runs after the diagnostic branches and appends, never replaces.

2. **`.moai/state/navigator-detect/<session-id>.jsonl`** (machine-readable, for M2 Route): one JSON line per detection, schema:
   ```json
   {"changed_path":"…","changed_at":"<git committer-date or (no-git)>","affected_nodes":[{"entity_type":"spec","identifier":"SPEC-AUTH-001"}],"affected_edges":[{"edge_type":"spec-edge","source_node":"symbol:pkg.Foo","target_node":"spec:SPEC-AUTH-001","source_path":"…","line_number":42}]}
   ```
   Append-only. Session-scoped (one file per session id). This is the bridge M2 Route consumes; M1 itself performs NO promotion to a work item (REQ-NS2-003).

**NOT emitted** (forbidden): a GitHub issue, a TODO file, a work-item, a block decision, an exit-2, a mutation of any source file or SPEC.

### C.5 — Concurrency safety (atomic read during regen)

**Decision**: single `os.ReadFile`, rely on M0's `atomicWrite` (`.tmp` + `os.Rename`) guarantee. No mutex, no file-lock, no retry.

**Mechanism (REQ-NS2-006)**: `os.ReadFile` on a Unix filesystem is atomic with respect to `os.Rename` — the reader observes either the old inode or the new inode, never a partial. M0's `atomicWrite` (`internal/navigator/sync/write.go:35-55`) writes to `<path>.tmp` then renames; a concurrent reader therefore observes the prior committed graph atomically. If the prior graph yields no affected rows for the changed path (e.g. the change is to a path the prior graph did not index), the Detect branch fail-opens per REQ-NS2-004 — it does NOT retry against the not-yet-renamed new graph.

**Test hook**: M0's `NAVIGATOR_PRE_RENAME_BARRIER` env var (`write.go:41-49`) holds the writer mid-rename. M1's concurrency test sets the barrier, spawns the Detect reader, and asserts the reader observes the prior graph without error. This reuses the existing barrier — no new test hook added.

### C.6 — Fail-open semantics

**Decision**: the Detect branch is fail-open on EVERY error mode (REQ-NS2-004 / REQ-NS2-012). Failure modes and their handling:
- `nav-graph.json` absent → log one line to `.moai/logs/navigator-sync.log`, return empty.
- `nav-graph.json` unparseable JSON → log one line, return empty.
- Graph schema invalid (missing required fields) → log one line, return empty.
- Reverse-traversal error (e.g. malformed node key) → log one line, return empty.
- Per-detection timeout exceeded (context cancellation) → return whatever partial set was collected (possibly empty), no log (context cancellation is not an error to advertise).
- `projectRoot` unresolvable → log one line, return empty.

In ALL cases: exit 0, `Decision: "allow"`, no user-facing error, no cascade into sibling PostToolUse branches. The Detect branch wraps its entire body in a `defer recover()` + a `context.WithTimeout(ctx, 200*time.Millisecond)` — a panic in the traversal cannot escape into the post-tool handler.

## §E. ≥80% Coverage Measurement Methodology (REQ-NS2-007)

**Definition of "changed file"**: a file path reported by PostToolUse for Write/Edit/NotebookEdit, normalized to absolute, that falls within the M0 graph's scan roots — i.e. `.moai/project/{product,structure,tech}.md`, `.moai/docs/**/*.md`, or Go source `*.go` (excluding `*_test.go` / `vendor/`). Files OUT of these scan roots (e.g. `.moai/specs/` internals, `.claude/` config, unrelated config) are **excluded from both numerator and denominator** — they are out-of-scope for the graph by construction.

**Definition of "mapped to an affected row"**: the reverse-traversal yields ≥ 1 affected node OR ≥ 1 affected edge for that changed path.

**Measurement procedure** (the command that produces the percentage — acceptance.md §D.AC-NS2-007 binds the test to this):
1. A fixture corpus at `internal/hook/testdata/navigator-detect-corpus/` containing N≥20 fixture files: design-doc fragments with `@NAV:DEC` / `@NAV:SYM` tokens, Go source fragments with `@NAV:SYM` / `@MX:SPEC`, and (deliberately) 4-5 files OUT of scan roots (the excluded class, to prove the partition).
2. A pre-built `nav-graph.json` fixture covering the in-scope corpus.
3. A Go test `TestNavigatorDetectCoverage` runs the Detect layer against every fixture file, classifies each as in-scope-mapped / in-scope-unmapped / out-of-scope, and emits:
   ```
   coverage = (in-scope-mapped) / (in-scope-mapped + in-scope-unmapped)
   ```
4. The test asserts `coverage >= 0.80` and prints the observed percentage on failure. The percentage is the observed output of `go test ./internal/hook/ -run TestNavigatorDetectCoverage -v` — NOT a narrative.

**Why fixture-driven, not repo-driven**: a repo-driven measurement would re-scan the live repo and produce a number that drifts with every commit (every edit changes the denominator). A fixture corpus is deterministic and isolates the Detect layer's correctness from the repo's current shape — it measures the LAYER, not the repository.

## §F. Milestones (priority-ordered, no time estimates)

Ordered by decision-reversibility — the decisions most likely to change lead.

### M1.1 — Reverse-traversal engine (pure function)

Pure-Go function: input `{graphPath, changedPath, projectRoot}`, output `{affectedNodes, affectedEdges, error}`. No I/O side effects beyond the single graph read. Wire M1.1 into `postToolHandler.Handle` as the `runNavigatorDetect` branch (after `runMemoryAudit`, before `logEvidence`). Extract `file_path` / `notebook_path` from `ToolInput`. ## §G. Anti-Patterns (carry forward from M0 + add M1-specific)

- **AP-NS2-001 — forking the PostToolUse hook chain**: creating a parallel `moai hook navigator-detect` subcommand + a new `handle-navigator-detect.sh` wrapper. FORBIDDEN (REQ-NS2-009). The branch pattern is the only acceptable integration.
- **AP-NS2-002 — blocking on a detection finding**: returning `Decision: "block"` or exit 2 from the Detect branch. FORBIDDEN (REQ-NS2-012).
- **AP-NS2-003 — promoting to a work item in M1**: creating a GitHub issue, TODO file, or SPEC draft from a detection. FORBIDDEN — that is M2 Route (§F Out of Scope).
- **AP-NS2-004 — narrative coverage claim**: writing "coverage is ≥80%" in an AC without naming the command + observed output. FORBIDDEN (REQ-NS2-007 + verification-claim-integrity).
- **AP-NS2-005 — overclaiming navigator-audit.sh reuse**: claiming `heuristic_match()` IS the path→graph-edge mapping engine. FORBIDDEN (REQ-NS2-010 honest framing) — the engine is absolute-path string equality; the script is inspiration for the directory-prefix fallback only. The fallback's inspiration source MUST be cited by file:line, but the engine MUST NOT be presented as reused shell logic.
- **AP-NS2-006 — modifying M0 / mx producers**: writing to `internal/navigator/sync/` or `internal/mx/`. FORBIDDEN (REQ-NS2-005).
- **AP-NS2-007 — building a path→edge index**: premature optimization before the linear scan proves too slow. Violates the Simplicity ladder. Defer until p99 > 200ms is observed.
- **AP-NS2-008 — carrying the coverage percentage across SPECs**: a coverage number from M2 or a prior measurement is a carry-over, not a baseline (verification-claim-integrity §2). The fixture corpus is the baseline.
