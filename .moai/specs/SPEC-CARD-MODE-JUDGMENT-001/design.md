## D-5 The scope marker and the per-line trap

REQ-MJ-010 is checked with one marker phrase, `while the lane executes the card`, on every line that arms or keeps the cron. Two traps:

- **Per physical line.** AC-MJ-008a's regex works line by line. `auto-semantics.md` §5.1 is hard-wrapped near 80 columns, and today the phrase "kept until the completion report." sits alone on line 118. ## D-11 The closed-world check (AC-MJ-020)

The per-criterion cells are open-world: each looks for known tokens or pinned lines, so a line added where they do not look is invisible (four stem-less additions passed AC-MJ-005 (d) and AC-MJ-006). The remedy is a check whose unit is the file, not the claim.

- **Unit.** For each of the eight documents, on the template side and on the deployed side, the multiset of non-blank lines of the working copy is compared with the multiset of non-blank lines of the same path at a pinned base commit. A surplus line is an added line; a missing line is a removed line. Five numbers per side are printed — added-not-listed, listed-not-added, removed-not-listed, listed-not-removed, and code-fence placement changes against the base — and the command decides by exit status. The fifth number sums three marks: fences whose nearest preceding non-blank line, walking past the manifest's listed rows, differs; occurrences of an unlisted line (fences included) present on both sides whose segment — the number of fences before it — differs; and listed rows inside a code block beyond the base's count. It sees a code fence moved across any line, whether alone or carried together with its preceding line or any run of lines (defect D28 of the iteration 3 audit: the pair comparison alone missed a fence moved with its predecessor), which the line multiset the first four numbers compare cannot distinguish. Listed rows added or removed outside a code block, and an unlisted line added or removed, leave the segment and inside marks unchanged, so correct work prints `0` on the fifth number whatever position outside a code block the rows land in (no listed row of the manifest belongs inside one).
- **Allowlist.** `closed-world-manifest.txt`, a plain-text file in this directory: one `file:` row per document and one `+ ` or `- ` row per allowed whole line. The plan phase writes it and freezes it, from the planned post-run text. A list filled in by the run phase would let the party the check constrains write its own allowlist; a wording change the run phase wants is a blocker report instead (the pinned cells already work this way).
- **Why the RED-now cell is red for the right reason.** Today the working copy equals the base, so the first and third numbers are `0` (no unlisted line exists) and the second and fourth are positive (the listed additions and removals have not happened). The cell flips only by the work being done: deleting files or editing unrelated ones turns the first or third number positive instead.
- **Other paths.** `paths` lists the changed or new paths that the manifest does not name, that are not the repository-root file `CHANGELOG.md`, and that are not under one of the four paths a run of this SPEC legitimately writes (`.moai/specs/SPEC-CARD-MODE-JUDGMENT-001/`, `.moai/reports/`, `.moai/state/`, `.moai/logs/`) — tracked `.moai/` projections (`.moai/policies/**`, `.moai/workflows/gtd.md`, the config, docs and archive copies) and every other `CHANGELOG` path included — so an agent file, the `.codex` emission, `docs-site`, a Go file, or a widening written into a tracked projection cannot be touched unseen (the exemption narrowed in the ceiling-exception round; before it, everything under `.moai/` passed). `CHANGELOG.md` is admitted as one exact path, not a prefix, because it is the sync phase's output: every Tier L SPEC's sync commit adds its `[Unreleased]` entry, so without the admission the path half could never be green on the closing tree (sync-audit amendment 2, S2). Known failing inputs: an old base commit (`E-020c`), a simulated edit inside `.moai/policies/**` (`E-020f`) and inside `.moai/workflows/gtd.md` (`E-020g`), `CHANGELOG.md.bak` (`E-020k`) and `docs/CHANGELOG.md` (`E-020l`); green control `CHANGELOG.md` (`E-020j`).
- **Freezing.** Neither the manifest nor the check is in the plan-artifact hash subject set, so their SHA-256 values are pinned in `acceptance.md` E-020d (a hashed file): any change to either file changes the plan-artifact hash through acceptance.md.
- **Commit shape.** `pairs` decides the run-phase obligation of AC-MJ-011: both sides of every pair in the same milestone commit, with the expected number of pairs.
- **Tooling.** One read-only Python file, called as `python3 -I <file> <mode> <manifest> [...]`. It runs the needed read-only git queries itself, so each ledger cell is a single invocation the worktree guard accepts, with no pipe, redirection or shell variable.
- **Limits.** The order of non-fence lines within one fence-delimited segment and blank lines are not compared; a non-fence line moved without change inside its segment stays unseen; where outside a code block a listed row lands is not compared; only fences of three backticks at column 0 are recognised (none of another form exists in the sixteen files, and adding one is an added line); nothing here judges whether a listed line is right (the audit reads the manifest); the admitted `CHANGELOG.md` is judged as a path only, so an edit to it outside this SPEC's `[Unreleased]` entry is not seen. Tested on 80 document mutants, all red, the fence+predecessor pair-move among them (`acceptance.md` AC-MJ-020, `E-020h`), and on 3 mutants of the `CHANGELOG.md` admission (prefix, base name, none), each red on one of `E-020j`/`E-020k`/`E-020l`.
