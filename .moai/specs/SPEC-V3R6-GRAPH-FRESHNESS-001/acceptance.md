# Acceptance Criteria — SPEC-V3R6-GRAPH-FRESHNESS-001

Given-When-Then scenarios, binary-testable. REQ→AC traceability at §D.2 must be 100% in both directions (every REQ covered by ≥1 AC; every AC traces to ≥1 REQ). Mutant discipline (card t241): every check-type AC states its red condition, the input that produces it, and the failure's reachability path — the two representative mutants named by the card are covered at AC-GF-004 (mutant A) and AC-GF-008 (mutant B).

## §D. Acceptance Criteria

### AC-GF-001 — Numeric per-layer staleness report (REQ-GF-001)

- **Given** a fixture git repository (`t.TempDir()`) whose three gated artifacts carry provenance blocks and are in sync with their sources
- **When** `moai graph check` runs
- **Then** the output contains, for each of codemaps / mx-index / edges.jsonl: the layer name, a metric kind token, an integer measured value, the threshold, and a verdict of `fresh`; and the process exits 0

### AC-GF-002 — Per-layer metric correctness (REQ-GF-002)

- **Given** a fixture repository where (a) codemaps are stamped at commit C with 3 described-source files changed since C, (b) the mx-index inventory lists 1 file whose content now differs, (c) edges.jsonl's stamped codemaps fingerprint mismatches the current codemaps content
- **When** `moai graph check` runs
- **Then** codemaps reports 3, mx-index reports 1, edges reports a fingerprint mismatch (stale) — each layer's value derives from its own metric column in spec.md §D REQ-GF-002, not from a shared formula

### AC-GF-003 — Provenance blocks present (REQ-GF-003)

- **Given** the three artifacts freshly regenerated by this SPEC's commands
- **When** each artifact is read
- **Then** each carries tree root, generation commit SHA (or `dirty` + fingerprint), and the layer's source fingerprint; and an artifact with the provenance block removed is reported as freshness-unjudgeable, not fresh

### AC-GF-004 — MUTANT A: staleness signaled by exit code, not merely reported (REQ-GF-004)

- **Given** a fixture repository where codemaps are stamped at commit C and ≥ threshold described-source files change after C (red input: the deliberately-aged layer)
- **When** `moai graph check` runs
- **Then** the process exits 1 and stderr names the layer, value, and threshold
- **Mutant A killed**: an implementation that prints the staleness but always exits 0 fails this AC — observed as exit code 1 vs 0, a binary observable. **Reachability of the failure it guards**: CI jobs and `moai gate` consume only the exit code; a reporting-only implementation silently disarms both consumers, which is exactly the 740-commit silent-drift defect class.
- **Given** the same fixture restored to sync
- **When** `moai graph check` runs
- **Then** exit 0

### AC-GF-005 — Absent is a distinct, failing verdict (REQ-GF-002, REQ-GF-004)

- **Given** a fresh worktree of a fixture repository (no mx-index, no edges.jsonl — the untracked-artifact state observed in real worktrees)
- **When** `moai graph check` runs
- **Then** each missing layer reports verdict `absent` with an explicit reason string (not value 0, not `fresh`), and the process exits 1 under REQ-GF-004's absent clause

### AC-GF-006 — `moai gate` integration, notice-not-silence (REQ-GF-005)

- **Given** a stale fixture project with the graph-freshness gate step enabled in gate configuration
- **When** `moai gate` runs
- **Then** the gate fails and its output names the graph-freshness step; **Given** the step in warn-only mode, the gate passes while emitting the check's verdict on stderr; **Given** the step disabled, the gate emits an explicit skip notice — never silence on any of the three paths

### AC-GF-007 — CI job actually turns red (REQ-GF-006)

- **Given** a branch whose head contains a deliberately-aged codemaps provenance stamp (stamped at an ancestor commit, threshold-exceeding source drift accumulated since) and the CI graph-freshness job
- **When** the job runs on that head
- **Then** the job conclusion is failure attributable to the graph-freshness step (verified on a non-main branch; main is never the demonstration vehicle)
- **Given** an otherwise-clean head where the job's bootstrap has refreshed the mechanical layers (`moai mx scan`, `moai graph build`) and codemaps are freshly regenerated within threshold
- **When** the job's `moai graph check` step runs
- **Then** the check exits 0 and the job is green — a healthy head has a green path; the job is not structurally always-red

### AC-GF-008 — MUTANT B: refresh actually re-reads, not stamp-only (REQ-GF-007)

- **Given** a fixture repository with an mx-index (or edges build) in sync, and a query answer A1 recorded
- **When** a scanned source file's content is edited (uncommitted) and the same query runs again
- **Then** the new answer A2 reflects the edited content, and the refreshed artifact's content fingerprint matches the post-edit file content — not merely a newer timestamp
- **Mutant B killed**: an implementation that updates the stamp/fingerprint but serves cached content produces A2 = A1 with a fresh stamp and fails this AC. **Reachability**: agents act on query answers; a stamp-only refresh propagates stale answers into audit judgments (the `init.go:773` vs `:898` stale-misjudgment lineage).

### AC-GF-009 — Changed-files-only refresh, no LLM (REQ-GF-007)

- **Given** an in-sync fixture and a counting instrument on file reads (test wrapper), a second query with zero content changes re-reads 0 source files; **When** exactly 2 of N files change, the next refresh re-reads exactly those 2
- **Then** both counts hold, and the refresh code path has no LLM-client or network dependency (verified by dependency inspection of the refresh package — see §D.3 indirect verification)

### AC-GF-010 — Per-tree cache isolation (REQ-GF-008)

- **Given** two worktrees of the same fixture repository with different uncommitted edits, and no cache entries for either
- **When** the same query runs in each worktree
- **Then** each answer reflects its own worktree's edits, each answer names its own tree root + commit, and the cache contains distinct entries per tree root — cross-tree cache reuse produces a wrong-tree answer and fails this AC (the CR #8/t246 wrong-tree defect family)

### AC-GF-011 — Update-cost budget warning (REQ-GF-009)

- **Given** a fixture with the update-cost budget configured below the actual refresh cost (synthetic small budget)
- **When** a query triggers a refresh exceeding it
- **Then** the command emits a warning naming measured cost and budget, and still returns the answer (exit reflects the query, not the overrun)

### AC-GF-012 — Citation canon in codemaps/reports (REQ-GF-010)

- **Given** codemaps (or a generated report) regenerated under this SPEC
- **When** a code citation is rendered
- **Then** it carries an excerpt and a content hash; a line number, if present, appears alongside as convenience — a citation whose only anchor is a line number fails

### AC-GF-013 — mx-index hash anchoring (REQ-GF-011)

- **Given** an mx-index produced by this SPEC's scanner
- **When** a tag's location is read
- **Then** it is anchored by file path + content hash with line numbers as convenience data; **When** lines are inserted above a tag in the cited file and the index refreshes, the tag resolves to the same symbol — the hash covers the cited region's content, and inserting lines above the region leaves that content identical, so the anchor holds

### AC-GF-014 — Two-tree identical-target guarantee (REQ-GF-012)

- **Given** one citation (excerpt + content hash) and two copies of a fixture tree where the cited file differs only by N blank lines inserted at the top
- **When** the citation is resolved in both trees
- **Then** both resolutions name the same target symbol/file; a line-number-anchored resolution drifts by N and fails

### AC-GF-015 — Measured-tree SHA co-stamp (REQ-GF-003, REQ-GF-008)

- **Given** any query answer or regenerated artifact from this SPEC's surfaces
- **When** its provenance is inspected
- **Then** the measured tree's SHA (or `dirty` + fingerprint) is co-stamped alongside the content anchor

### AC-GF-016 — astx consumable without navigator (REQ-GF-013)

- **Given** a non-navigator consumer package (the graph builder's extraction seam)
- **When** it imports astx for symbol/edge extraction
- **Then** the consumer's transitive dependency set contains no navigator-tier packages (verified by `go list -deps` on the consumer — see §D.3)

### AC-GF-017 — Undocumented call edge appears in blast radius (REQ-GF-014)

- **Given** a fixture repository where function A calls function B, and no doc-derived layer records that relationship
- **When** `moai graph build` runs with the code-derived layers enabled, followed by a blast-radius query at B
- **Then** A appears in B's blast radius via a `code-call` edge, and the edge carries the resolution grade used to derive it

### AC-GF-018 — Additive layering and disagreement exposure (REQ-GF-014, REQ-GF-015)

- **Given** a fixture whose doc-derived layers produce edge set E_doc before the code-derived layers are enabled
- **When** the build runs with code-derived layers enabled
- **Then** every edge in E_doc is present and unchanged in the output; **Given** a doc-derived edge that contradicts a code-derived edge on the same relationship, **When** the artifact is read, **Then** both edges are present with an explicit disagreement marker — dropping E_doc entries or silently selecting one layer fails

### AC-GF-019 — Resolution-grade matrix, no empty cells (REQ-GF-016)

- **Given** the published per-language resolution-grade matrix
- **When** it is validated against the supported-language list (16 languages)
- **Then** every language cell carries `full` | `name-based` | `none`; **Given** a matrix with one grade removed, **When** the build runs, **Then** the build reports a defect verdict naming the language — an omitted cell may not pass silently

### AC-GF-020 — `graph_file_api` signatures-only (REQ-GF-017, REQ-GF-019)

- **Given** a Go file with exported declarations, at least one non-exported declaration, and non-trivial function bodies — the non-exported declaration is load-bearing: an exported-only fixture would pass the filtering assertion vacuously (CR #1665 3865025045) — **and** a non-Go fixture carrying at least one lowercase-first declaration, which Go-only filtering would have dropped had it been (wrongly) applied
- **When** `graph_file_api` is called on each fixture
- **Then** the response lists exported signatures and contains no function bodies; the response names the tree root + commit it answered from; for non-Go languages the response returns the extracted declaration set without non-exported filtering — exported-identifier filtering is Go-only (first-rune upper-case, `isExported` in codequery.go), per the implemented export rule

### AC-GF-021 — `graph_find_code` + `graph_trace_calls` answer from the code layer (REQ-GF-018, REQ-GF-019)

- **Given** the M4 code-derived layer for a fixture where A→B→C calls exist and are absent from doc layers
- **When** `graph_find_code` searches for B and `graph_trace_calls` traverses from B
- **Then** find returns B with its provenance, trace returns {A} as caller and {C} as callee via code-call edges; both responses name tree root + commit

## §D.3 Indirect Verification (Where direct grep is insufficient)

- **No-LLM/no-network refresh path** (supports AC-GF-009): dependency inspection — `go list -deps` of the refresh package contains no LLM-client package; grep of the package shows no network dial sites. Direct runtime assertion is impractical (absence of a call cannot be observed positively), so dependency-surface inspection is the accepted evidence.
- **astx decoupling** (supports AC-GF-016): `go list -deps <consumer>` filtered for `internal/navigator/` (excluding `navigator/astx` itself) returns empty.
- **No-mtime trust** (supports REQ-GF-002): static inspection — the staleness computation code contains no `os.Stat` mtime read on gated artifacts; the worktree-checkout-resets-mtime evidence is in research.md §Anchor Re-Verification.

## §D.4 Closure Gates (Definition of Done)

1. All MUST ACs PASS with observed evidence (command + verbatim output recorded in progress.md §E.2).
2. Both card-named representative mutants demonstrably killed (AC-GF-004, AC-GF-008) — a red-input execution is recorded, not an assertion.
3. `moai spec lint` clean on all three core artifacts.
4. Affected-package tests pass (`go test ./internal/graph/... ./internal/cli/... ./internal/navigator/astx/...`) and CI green on the delivering PR.
5. No new dependencies in go.mod (constraint §E verified by diff).

## §D.6 Edge Cases

- Fresh worktree, no untracked artifacts: AC-GF-005's `absent` path — must not crash, must not report 0-as-fresh.
- Dirty working tree at generation: provenance records `dirty` + fingerprint, not a misleading clean SHA.
- Reverted churn: commit-count spikes while endpoint content is identical — codemaps metric (endpoint diff) stays fresh; this is why REQ-GF-002 rejects commit-count for the tracked layer.
- Empty repository / no commits yet: check reports layers absent, exits per REQ-GF-004, no panic.
- Cited region itself edited (not just lines above): content hash changes — citation resolves to the old content and the resolver must report the mismatch rather than force-resolve (honest staleness, not silent drift).
