## 2. Records

- **Receipt** (`auditreceipt.Receipt`, additive): `audited_commit`, full 40-hex or empty; `audit_target`, the review target string the call named or empty. A legacy file decodes with both empty (`json.Unmarshal`, no `DisallowUnknownFields` in the package, `research.md` §12). No migration, no rewrite.
- **Verdict citation line**: the sync workflow already defines an orchestrator binding-statement line `audit_receipt: <ids|none>` (`.claude/skills/moai/workflows/sync.md:91`). REQ-LVM-018 does not add a key: it makes that line the machine-read citation at landing, strict (`none`, empty, duplicated or malformed refuses while the gate is on; `none` remains the correct statement on a tree whose plan does not require codex, where the gate is not meaningful, spec C11).

## 3. The audit and receipt binding (N3, N4, O1, O4)

Facts read from the tree: the SPEC-less readiness path binds `audited_sha` to HEAD tolerating a difference only under the card's evidence directory (`factorylane/merge_specless.go`, `specLessSHAPattern`, and the refusal text of `checkSyncAuditVerdictFile`); the SPEC path reads only `sync_status` (`factorylane/merge.go:245`); the stage chain reads the newest `<phase>*.md` verdict through `readAuditVerdict`/`newestVerdictFile` (highest `-iter<N>`, then latest modification) and admits it through `auditverdict` (`homestate/card_evidence_readers.go:84-260`); `auditverdict.Parse` has no `audit_receipt` key and no Go code reads receipt ids from a file; `ParseVerdictLine` (`store.go:1223`) parses the final-message `AUDIT-VERDICT:` line; `CheckCitedReceiptsSince` (`store.go:1257-1323`) checks existence, tree, start time and codex tool at verdict-write time and refuses an empty citation; measured verdicts of merge-ready SPEC cards cite receipts in mixed forms (2 of 8 with a top-level `audit_receipt:` line).

Decisions (decision-index Q14, Q19, Q21, Q22, Q23, Q24):

- **Locator.** A SPEC card: the newest `sync-audit*.md` under `.moai/reports/<card-id>/`, by the stage chain's rule, whose ranking function moves to `internal/auditverdict` so the stage chain and the binding share one copy. A SPEC-less card (classes A and B): the fixed file `.moai/reports/<card-id>/verdict.md` that its readiness path already reads. The receipt binding and the citation line apply to both kinds (otherwise Class A and B cards would carry no receipt binding while Q13 binds `complete`); a SPEC card with only `verdict.md`, or any card with no file, is refused while the gate is on.
- **Citation line.** The verdict must carry exactly one machine line `audit_receipt: rcpt-<id>[,rcpt-<id>…]`; ids match `rcpt-[a-z0-9]{20,40}`; a missing, duplicated, empty, `none` or malformed line, or an id absent from the store, refuses. This closes the vacuous pass of "every cited receipt" for an empty citation.
- **Qualification.** At least one cited receipt must qualify. It is looked up at `auditreceipt.StoreRoot(audited tree)` — for a config-orphaned worktree that is the primary checkout (`storeroot.go:242-251`) — and must be readable; tool codex or multi-backend; **`tree_root` equal to `auditreceipt.Canonical` of the audited tree's path** (`treeroot.go:37`: symlinks resolved, else cleaned), which is the normalization the writer applies (`TreeRoot: root`, `mcp_audit_receipt.go:63-73`; the existing guard compares the same quantity, `store.go:1290`); unmet gate empty; codex verdict pass; `audited_commit` equal to HEAD. The store root is where the file lives, not the compared identity: comparing `tree_root` with the store root would refuse every valid receipt of an orphaned worktree and accept the primary's receipt for the same commit. Failed or inconclusive extra citations are recorded and never replace the pass; the verdict itself is still admitted by `AdmitWithRequired` with the configured required backends (`runtime.ResolveRequiredBackends`, injected by the caller so the required-backend set is resolved by the caller; the binding does import `internal/auditreceipt` directly for `ReadReceipt`, `StoreRoot` and `Canonical`, a new direct dependency of `internal/factorylane` with no import cycle, since `auditreceipt` imports only `config` and `gitenv`).
- **Equals HEAD, nothing else.** The verdict's audited commit and the receipt's audited commit must each equal the card's HEAD. An ancestor whose diff to HEAD is empty, patch-identical or confined to `.moai/reports/<card-id>/` does not qualify (boards 0577 P3 and 5d4d). The evidence-directory tolerance that merge-readiness condition (a) keeps today for SPEC-less cards is not carried into the binding: `.moai/reports/*` is ignored by git in this repository (`.gitignore:235`), so it had almost nothing to tolerate, and it contradicted the no-backfill ruling.
- **Placement.** `complete` evaluates the binding after the integration branch and tree are resolved and the provisioning refusals have passed, before the window is acquired, so a refusal leaves the window free and the card at `merge-ready`. The binding also precedes adoption (step 2, which records a card as merged-local from an existing merge commit), so an adopted landing is bound too.
- **Receipt stamping.** The two files that call the writer (`mcp_codex.go` at :2112 and :2163, `mcp_convergence.go` at :928) capture the audited tree's HEAD and the review target at entry and pass both to `recordAuditReceiptAt`; the writer re-reads HEAD when writing and leaves `audited_commit` empty if it moved. Existing receipts are never rewritten and are read as unbound.
- **Audit target (decision-index Q23).** New receipts also record `audit_target`, so a reviewer can see what scope the receipt covers. It is recorded, not gated: the set of legitimate full-scope target values is not enumerated at plan time, and gating on a guess could refuse valid audits. A partial-scope audit stamped with the current HEAD is accepted residual R5, beside the dirty-tree residual R4.

## 4. Gate state, switch, binary and recovery (N2, board 470c)

- **Source.** The committed blob `<integration-branch>:.moai/config/sections/workflow.yaml`, read in the repository, consulting no working tree. The branch is the window record's when a window is held, else `configuredIntegrationBranch()` (`internal/cli/integration.go:291`); `complete` uses the branch it is about to merge into (`factory_card.go:2131-2139`, which resolves to the same two sources). The branch name is resolved once as `refs/heads/<branch>^{commit}` and every later read uses that SHA: a bare `<branch>:<path>` resolves a same-named tag before the branch (reproduced in `research.md` §13), which would let a tag silently turn the gate off. The merge verb's further fallback to `develop` for an empty name is not used for the gate: `LoadGitFlowIntegrationConfig` returns the zero configuration when git-strategy is absent or has no profile (`config/loader_integration_branch.go:95-97`), and a project that never opted in to the window must keep the gate off. Measured why not a working tree: the primary checkout is a stale detached HEAD that an enabling commit on `main` never reaches, and `integrationLockRoot()` returns it (`integration.go:49-77`); reading the main worktree would tie correctness to one local layout.
- **Fail-modes (board 5d4d).** No integration branch configured and no window held → off (the project has not opted in). A branch configured whose ref cannot be resolved → the landing is refused with the named error `gate_state_integration_branch_unresolvable`, fail-closed; this is not a deadlock, because the merge step cannot run without that branch and repairing the branch configuration or ref needs no landing. With the branch resolved: `git cat-file -e <branch>:<path>` separates an absent path (off) from a failed read; an absent key or explicit false → off; explicit true → on; a failed read of a present path, an unparseable file or a non-boolean value → on with `gate_state_unreadable` and one JSON line appended to `.moai/logs/landing-gate-audit.jsonl` under the integration lock root (event, branch, SHA, path, cause, UTC time). On is the safe state for those: it never silently disables the gate, and it does not wedge landings, because a landing that satisfies the gate (bound audit) is admitted, including the card that repairs the file. In `complete` the provisioning refusals (`factory_card.go:2178`) already stop a configured branch with no worktree, so the named error is reached chiefly by the status display; the reader is one function with the full table so the later consumers of piece A1 inherit the same answers.
- **Consumers in this SPEC.** `complete` (mutating: a refusal exits non-zero before any state change) and `moai integration status` (a report, whose existing queue refresh already makes it a mutating-queue verb, so it prints the named error and keeps its own exit status). Piece A1's consumers (merge step, condition (d), `manifest verify`) read the same function and keep the exit-non-zero semantics for read-only evaluations.
- **Observation.** AC-LVM-017 uses a temporary repository whose detached stand-in primary never receives the commits; the enable commit takes effect when it lands on the integration branch and the revert likewise. `moai integration status` prints the gate state with its source branch, path and commit so the effect is observable in the field.
- **Order.** This branch never enables the key. The enabling is a later, separate commit on the integration branch made only after this SPEC and piece A1 have both landed and a binary built from a HEAD containing both exists; the first gated landing is the next one (decision Q27, board 6404: with A2 alone on, `complete` would be bound while the direct merge path stays a side door). Cards already merge-ready are not re-audited for the switch.
- **Binary and server (prerequisites, not steps of this card).** The governed commands are invoked by path from a binary built from the landing HEAD's main; the receipt-writing MCP server must run a build containing the writer change before a receipt is bound. Neither implies reinstalling the installed binary.
- **Recovery.** The reversal is a one-path card setting the key false. It lands through the gated path with the audit binding intact. Residual: if the gated path itself is the defect, the operator-held manual edit of the integration branch's configuration is the accepted fallback; an agent does not perform it.

## 5. What "gate on" means for this SPEC alone

The key is read, and while it is true `complete` requires a verdict that names the current HEAD, a machine citation line, and at least one qualifying receipt bound to that HEAD. That is a real check, not an empty switch. It does not add re-measure completeness: the record checks of `complete` (`factory_card.go:2281`) and of the merge step are unchanged, so with only this SPEC landed the gate on would enforce the audit half of the 2c51 ruling in `complete` and nothing else. That state is not shipped: the key stays off until piece A1 has landed and adds its checks and the direct-merge-path binding under the same key (decision Q27).

## 6. Residuals

- **R4** — `audited_commit` records HEAD only; the writer cannot see uncommitted edits in the audited tree.
- **R5** — a partial-scope audit stamped with the current HEAD is accepted (the target is recorded, not gated).
- **R6** — the audit binding applies in `moai factory complete`. The direct merge verb (`moai integration merge --card`, which the lane protocol also allows) and merge-readiness condition (a) do not apply it under decision Q28's default, so a lane that skips `complete` is not bound, and `factory merge ready` can read ready where `complete` then refuses (condition (a) keeps today's evidence-directory tolerance for SPEC-less cards). Accepted for A2 (decision Q28, board 6404): the key stays off until A1 has landed, and A1 adds the binding to the direct merge path — merge-readiness condition (a) at `factorylane/merge.go:174` and `:245` and the merge step's landing check at `integration_merge_step.go:321-325` — as an acceptance requirement (spec §7 row 12), so the gate is never on with the side door.
- **R7** — a hand-edited receipt or verdict is the existing trust model; the binding defends against a stale audit, not against an actor who writes the store.
