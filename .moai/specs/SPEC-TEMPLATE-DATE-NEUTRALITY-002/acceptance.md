## §A Criterion discipline

The predecessor's acceptance record documents three of its own criterion defects, and its `AC-TDN-019` exhibited a fourth. All four are treated here as binding authoring constraints.

### §A.1 Run from the worktree root

Every command below runs from `/Users/goos/MoAI/moai-adk-go/.claude/worktrees/date2025` with repo-root-relative paths. No command uses a bare filename, and none uses `go test .` or any form that presumes `cwd=internal/template`. The predecessor's defect was a criterion that only passed when run from the package directory.

### §A.2 Non-vacuity

A measurement that returns `0` because the path was wrong is indistinguishable from one that returns `0` because the tree is clean. The predecessor's defect was an `awk` that errored on a missing file and returned `0` — silently its own PASS value.

Each criterion therefore carries a **control**: either a paired positive measurement over the same path with a non-zero expected value, or an explicit existence check. Where the control is another criterion, it is named.

### §A.3 Exclude generated paths

`internal/template/catalog.yaml` is regenerated by the build step and is never a remediation target. Measured at plan phase: `grep -cE '2025-[0-9]{2}-[0-9]{2}' internal/template/catalog.yaml` → `0`. No criterion scans it.

### §A.4 No coupling to incidental formatting

Per REQ-TDN2-020, no criterion depends on quoting style, line numbers, or whitespace. **Property** criteria are written quoting-agnostically and hold both before and after the normalization; **normalization** criteria assert the formatting change explicitly and are labelled as such. The two shapes are never merged — that merge is exactly what produced the predecessor's `AC-TDN-019` defect, where a criterion returned its expected value only because three sibling invocations were quoted inconsistently.

## §B Given-When-Then scenarios

### GWT-1 — The widening is gated on a clean tree

**Given** the strict tier is green at `202[6-9]` and 48 `2025` findings exist in the template tree,
**When** the `S1-internal-date` year class widens to `202[5-9]` before every REMOVE row is remediated and every PRESERVE row carved out,
**Then** the strict tier reports a non-zero finding count and the CI step fails.

The correct response is to complete M3 and M4, not to add allowlist entries covering the reported findings. An entry added to silence an unexpected finding converts a missed deletion into a permanent carve-out.

### GWT-2 — A green guard does not prove a removal

**Given** `.claude/skills/moai-workflow-spec/references/examples.md` carries both a `DC-2a` REMOVE row and a `DC-5` row under the same literal `2025-12-07`,
**When** the `DC-5` row is adjudicated PRESERVE and receives a `(file, date)` allowlist entry,
**Then** the strict tier is green whether or not the `DC-2a` row was actually deleted, because the entry masks both rows.

The removal is therefore verified by AC-016, a file-scoped grep that does not consult the guard.

### GWT-3 — A documentation example survives remediation

**Given** `.claude/skills/moai-foundation-cc/reference/skill-formatting-guide.md` contains `updated: 2025-11-25 # Optional: last update date` inside a frontmatter block shown as a syntax example,
**When** the remediation sweeps prose authoring stamps,
**Then** this line is preserved and receives an allowlist entry, because deleting it removes the value the example exists to demonstrate.

### GWT-4 — The 2026 baseline is untouched

**Given** the predecessor drove the `202[6-9]` set to a carved, guard-clean state,
**When** this SPEC remediates the `2025` set,
**Then** no `202[6-9]` literal changes and no existing allowlist entry is rewritten, verified by AC-013.

## §C Edge cases

| Case | Handling |
|---|---|
| A `DC-2a` row inside a fenced block (1 measured) | Adjudicated explicitly per REQ-TDN2-012; the `DC-2a` rule does not inspect fence state. |
| A finding spanning two categories with conflicting dispositions (4 measured) | Each row keeps its own disposition (REQ-TDN2-004); the file-scoped control AC-016 covers the two REMOVE-bearing cases. |
| A structured-data example in a `.json` file | No fence markers exist in that file, so no fence-based rule can reach it; it is adjudicated by sub-shape code `EX-DATA`. |
| A composite footer carrying the stamp mid-line (2 measured) | Removal is a line edit, not a line deletion. The edit must not leave a placeholder token (REQ-TDN2-009). |
| A `2025` date in a file extension the guard does not scan | Measured at zero: the classifier row set and the raw grep line set are identical for `2025`, and no `2025` literal exists outside the scanned extensions. |
| `internal/template/catalog.yaml` | Build-generated, measured at zero `2025` literals, excluded from every criterion (§A.3). |
