## §B Given-When-Then

### AC-AIG-001 — 정방향: 통과하되 공허하지 않게

**Given** `readEmbeddedAsset(t, "app.js")` 로 읽은 현재의 임베드 app.js 소스가 있을 때,
**When** 가드 규칙을 그 소스에 적용하면,
**Then** 위반은 **0건**이고, **그리고 동시에** 규칙이 실제로 검사한 bare-identifier 핸들러 개수가 **0이 아니어야** 한다.

두 단언은 **함께** 걸려야 한다. 위반 0 만 단언하면, 아무 핸들러도 찾지 못하는 고장난 규칙이 그 단언을 만족시킨다 — 그것이 이 카드가 막으려는 공허한 통과다.

- 현재 트리의 기대값: 위반 0, 검사 대수 4 (spec.md §B.4 정방향 실측)
- 검사 대수를 정확히 4로 고정할지, `> 0` 으로 느슨하게 둘지는 run-phase 판단이다. 고정하면 핸들러가 정당하게 추가될 때마다 테스트가 깨지고, 느슨하게 두면 3건으로 줄어든 퇴행을 놓친다. **어느 쪽을 골랐든 그 이유를 테스트 주석에 남긴다.**

```bash
go test ./internal/web/ -run 'IIFE|Scope' -v
```

### AC-AIG-002 — 역방향: 그 결함을 거부하고 지목한다

**Given** 같은 소스에서, `stampRefreshed` 를 핸들러로 넘기는 등록 줄을 찾아 지우고 **첫째 IIFE 안**에 다시 끼워 넣어 합성한 돌연변이 문자열이 있을 때,
**When** 가드 규칙을 그 돌연변이에 적용하면,
**Then** 위반이 **정확히 1건** 보고되어야 하고, 그 보고는 **식별자 `stampRefreshed` 와 등록 줄 번호를 모두** 담아야 하며, **그리고** 검사 대수는 정방향과 **같은 값을 유지**해야 한다.

세 번째 단언이 양성 대조다. 검사 대수가 정방향과 달라졌다면 돌연변이가 규칙이 보는 표면 자체를 바꾼 것이고, 그러면 "규칙이 이 결함을 잡는다"가 아니라 "입력이 달라졌다"만 보인 셈이 된다.

- 프로토타입 실측(spec.md §B.4 역방향): 위반 1건 `line 552: stampRefreshed — declared in IIFE#[1] not #0`, 검사 대수 4 유지
- **전제 단언 필수:** 돌연변이 합성이 대상 줄을 찾지 못하면 `t.Fatal` 로 중단해야 한다. 이 단언이 없으면 합성 실패가 "위반 0" 으로 나타나 테스트가 조용히 뒤집힌다.

### AC-AIG-003 — 기존 계약 회귀 없음

**Given** `internal/web` 패키지의 기존 테스트 전부가 있을 때,
**When** 이 SPEC 의 신규 테스트를 더한 뒤 패키지 테스트를 돌리면,
**Then** 기존 테스트가 전부 통과해야 하고, 특히 `TestAppJsInitConsoleBoundToBothEvents` 와 `TestAppJsHxBoostPreserved` 가 **수정되지 않은 채로** 통과해야 한다.

```bash
go test ./internal/web/ -count=1
git diff --stat -- internal/web/appjs_reinit_test.go   # 기대: 출력 없음
```

> `internal/web` 는 규모가 크다. FAIL 요약이 실패 0건과 함께 나오면 타임아웃을 의심하고 `-timeout 30m` 으로 재측정한다. 판정은 요약 행과 종료 코드로 가른다.

### AC-AIG-004 — 함수 표현식 핸들러는 대상 밖

**Given** 현재 app.js 의 `addEventListener` 호출 20건 중 16건이 함수 표현식을 핸들러로 넘길 때,
**When** 가드 규칙을 적용하면,
**Then** 그 16건은 검사 대수에 포함되지 않아야 한다 — 즉 검사 대수가 20이 아니라 4여야 한다.

AC-AIG-001 의 검사 대수 단언이 이 조건을 함께 만족시킨다(4 ≠ 20). 별도 테스트가 필요하지는 않으나, 그 의미를 주석으로 남긴다.

### AC-AIG-005 — 좌표 하드코딩 없음

**Given** 완성된 테스트 소스가 있을 때,
**When** 리터럴을 훑으면,
**Then** IIFE 스팬(`39`, `660`, `673`, `796`)과 등록 줄 번호(`727`)가 **판정에 쓰이는 상수로 등장하지 않아야** 한다. 주석 안의 설명용 언급은 허용한다.

```bash
grep -n -E '\b(39|660|673|727|796)\b' internal/web/appjs_iife_scope_test.go
```

적중이 있으면 그 줄이 주석인지 코드인지 눈으로 가른다. 코드면 실패.

### AC-AIG-006 — 범위 침범 없음

**Given** 이 SPEC 의 구현 diff 가 있을 때,
**When** 변경 파일 목록을 재면,
**Then** `internal/web/assets/` 아래 파일이 **0개**여야 하고, `go.mod` / `go.sum` 이 변경되지 않아야 하며, `.github/workflows/` 아래 파일이 0개여야 한다.

```bash
git diff --stat <base>..HEAD -- internal/web/assets/ go.mod go.sum .github/workflows/
```

기대: 출력 없음. (귀속을 정확히 하려면 두 끝점 diff 가 아니라 `git log <base>..HEAD -- <경로>` 로 재고 양성 대조를 붙인다.)

### AC-AIG-007 — 한계가 소스에 적혀 있다

**Given** 완성된 테스트 소스가 있을 때,
**When** 파일 상단 주석을 읽으면,
**Then** spec.md §F 의 세 한계(다른 형태의 최상위 문장 / 중첩 함수 안의 선언 / 함수 표현식 본문의 교차 참조)가 모두 서술되어 있어야 한다.

## §D 미검증으로 남는 것 (Gaps)

이 인수조건이 **주장하지 않는** 것을 명시한다.

- **런타임 동작은 검증되지 않는다.** 이 가드는 소스 문자열만 본다. 실제 브라우저에서 리스너가 붙는지는 여전히 수동 E2E 소관이다(기존 `appjs_reinit_test.go` 주석의 §E Gaps 와 같은 입장).
- **spec.md §F 의 세 한계에 대한 음성 결과는 측정되지 않는다.** 그 셋을 잡지 못한다는 것을 돌연변이로 보이지 않는다 — 잡지 못함을 의도적으로 선언했을 뿐이다.
- **다른 정적 자산은 재지 않는다.** `i18n.js` 등에 같은 계열이 있는지는 이 카드에서 측정되지 않았다.
