# SPEC-CODEX-INIT-001 — 구현 계획

## §A. 이 SPEC 이 생긴 이유

런처 SPEC 이 Tier M 예산 16 REQ / 16 AC 에 닿았고, 상한을 맞추려 AC 2건을 형제 항목으로 통합했다. **그 통합이 곧 커버리지 삭감이었다** — 4차 감사에서 시험가능성이 3회 연속 0.50 에 머문 것이 그 신호다. 개별 구멍은 매 라운드 막았지만 커버리지의 *형태*(상태 × 동사 교차곱, 의미 수준 검증)를 넓힐 예산이 없었다.

분리는 그 압박을 푸는 조치다. 이 SPEC 은 옮겨온 2개 REQ 를 8개로 펴고, 그러면서 4차 감사의 F2·F3 를 흡수한다.

## §B. 경계 — 무엇이 어느 SPEC 소관인가

| 관심사 | 소관 |
|---|---|
| 배선 상태를 **판정** 하고 리드아웃에 **보고** | `SPEC-CODEX-LAUNCHER-001` (REQ-CL-006) |
| 그 상태에서 **제안·초기화·계약 확보** | 이 SPEC |
| 배선 파일의 **내용** 과 생성 로직 | `SPEC-CODEX-WIRING-001` (`moai init --agent`) |
| 이미 깔린 배선의 **표류 보고** | `moai doctor` |

판정 로직은 한 곳에서만 산다. 이 SPEC 은 런처의 판정을 호출하고 **그 반환값에 따라 행동한다** — 부르기만 하고 디스크에서 자체 재분류하면 판정이 둘로 갈린 것과 같다. AC-CI-002 가 분류기를 디스크와 **모순되는** 상태를 반환하도록 스텁해 게이트가 반환값을 따르는지 판정하고, 자체 파일 검사 0건도 함께 강제한다. 같은 이유로 생성기도 호출만 하고 무엇을 까는지 다시 정의하지 않는다.

## §C. 설계

### C.1 파일 배치

| 파일 | 성격 | 내용 |
|---|---|---|
| `internal/cli/codex_init.go` | 신규 | 제안 게이트 + 생성기 호출 위임 |
| `internal/cli/codex_contract.go` | 신규 | `AGENTS.md` ↔ `CLAUDE.md` 연결 확보 (멱등) |
| 각 `_test.go` | 신규 | §D 시험 |

런처의 `codex_launcher.go` 에는 **호출 지점 한 줄** 만 는다 — launch 동사가 기동 직전 이 게이트를 통과한다.

### C.2 제안 게이트

```
launch 동사 진입
  → 런처의 배선 상태 판정 호출 → state   (재구현 금지, AC-CI-002)
  → state == wired ? 그대로 기동 : 계속   (판정은 오직 state — 디스크를 다시 보지 않는다)
  → 대화형 아님 ? 상태·조치 보고 후 비성공 종료 (프롬프트 발행 0회, 기동 안 함)
  → 제안 → 거절 ? 무쓰기 + 취소 코드 종료 : 계속
  → 생성기 호출 1회
      └ 실패 ? 보고 + 비성공 종료 (계약 단계 미실행, 기동 안 함)
  → 지시 계약 확보
      └ 실패 ? 보고 + 비성공 종료 (기동 안 함)
  → 기동
```

**게이트의 입력은 분류기가 돌려준 상태 하나뿐이다.** 여섯 상태(`not wired` / `partial` ×2 배치 / `invalid` / `wired`) 중 `wired` 만 통과시키고 나머지 다섯은 전부 불완전으로 다룬다. `invalid`(화이트리스트 위반 `hooks.json`)를 빼면 파일 두 개의 존재만 보는 구현이 통과한다.

두 launch 동사가 **같은 함수** 를 통과한다 — 동사별로 분기하면 한쪽만 게이트되는 구현이 나온다. AC-CI-001 이 **6상태 × 2동사 = 12칸** 교차곱으로 그 대칭을 고정하고, AC-CI-002 가 네 상태를 모순 배치에 주입해 게이트가 디스크가 아니라 상태의 함수임을 고정한다.

비대화형 판정은 프롬프트 가능 여부로 한다 (TTY 부재 등). 자동화가 프롬프트에서 멈추는 것이 미배선 기동보다 낫지 않으므로 그 경로는 **묻지 않고** 보고 후 종료다 — AC-CI-004 가 답이 오는지가 아니라 **프롬프트 발행 횟수 0** 을 판정한다.

**실패는 기동을 막는다.** 생성기나 계약 쓰기가 실패하면 exec 하지 않는다. 특히 생성기 실패 뒤에는 계약 단계로 넘어가지 않는다 — 반쯤 깔린 배선 위에 지시 파일을 고치면 실패 상태가 더 복잡해진다. AC-CI-010 이 세 실패 fixture × 2동사로 그 순서를 고정한다.

### C.3 지시 계약 확보

**연결만 만든다 — 내용은 만들지 않는다.** 없는 파일은 생성기·템플릿이 주는 기본 본문으로 만들고, 있는 파일은 손대지 않는다.

```
AGENTS.md 없으면 생성
CLAUDE.md 없으면 생성
CLAUDE.md 가 @AGENTS.md 줄을 이미 담고 있나?
  ├ 예 → 아무것도 하지 않는다        (I5 — 바이트 무변경)
  └ 아니오 → 그 줄 하나만 추가       (I1~I4)
```

멱등은 이 분기에서 나온다 — "이미 있으면 아무것도 안 함" 이 2회차를 1회차와 바이트 동일하게 만든다. AC-CI-006 이 7종 fixture 를 2회씩 돌려 확인한다.

**경로 봉쇄가 계약 확보보다 먼저다.** 세 지시 파일 경로 각각을 만지기 전에 `Lstat` 으로 **일반 파일** 인지 보고, 해석된 경로가 프로젝트 안인지 본다. 심링크·디렉터리·FIFO·소켓은 전부 거부하고 그 경로를 명명해 보고한다. 심링크는 링크 자체가 프로젝트 안에 있어 디렉터리 스냅샷 판정을 통과하면서 바깥에 쓰므로, 봉쇄는 스냅샷이 아니라 이 구조 검사로 건다 (AC-CI-011).

**로컬 파일 도달성**: `CLAUDE.local.md` 를 **한 곳에서만** 가리킨다. 두 하네스가 모두 도달해야 하지만 양쪽에서 각각 가리키면 같은 내용이 두 번 로드되므로, `AGENTS.md` 가 가리키고 `CLAUDE.md` 는 `@AGENTS.md` 를 통해 이어 받는 형태로 한 줄만 둔다. 판정은 파일명 grep 이 아니라 **sentinel 내용이 양쪽 진입 파일에서 도달되는가** 로 한다 (AC-CI-007) — 불활성 산문 한 줄이 파일명 검사를 통과하는 구멍을 막는다.

## §D. 마일스톤

| M | 내용 | 산출 |
|---|---|---|
| M1 | 제안 게이트 + 교차곱 + 상태 주입 | `codex_init.go`, **12칸** 표 시험 (AC-CI-001) + 네 상태 모순 주입 (AC-CI-002) |
| M2 | 생성기 위임 + 거절·비대화형 | 인자 포착 seam, 스냅샷 시험, **프롬프트 발행 횟수 0** 판정 (AC-CI-003·004) |
| M3 | 실패 경로 | E1·E2·E3 fixture × 2동사, exec 0 + 생성기 실패 후 계약 호출 0 (AC-CI-010) |
| M4 | 경로 봉쇄 | `Lstat` + 해석 경로 검사, 심링크·비일반 타입 거부, 외부 sentinel 무변경·미도달 (AC-CI-011) |
| M5 | 지시 계약 + 멱등 | `codex_contract.go`, 7종 × 2회 바이트 비교 (AC-CI-005·006) |
| M6 | 로컬 파일 도달성 | sentinel 도달 시험 (AC-CI-007), 프로젝트 밖 무쓰기 (AC-CI-008) |

M4(경로 봉쇄)는 M5 보다 **먼저** 온다 — 계약을 쓰기 전에 경로가 안전한지 알아야 한다. M1 은 런처의 launch 동사가 있어야 붙으므로 `SPEC-CODEX-LAUNCHER-001` M3 이후에 시작한다 (`depends_on` 이 그 순서를 기록한다). 게이트 판정은 AC-CI-009 가 전 REQ 를 덮는다.

## §E. 위험

| 위험 | 완화 |
|---|---|
| 제안이 자동화 파이프라인을 멈춘다 | 비대화형에서는 **묻지 않고** 보고 후 종료 (REQ-CI-009). AC-CI-004 가 프롬프트 발행 0회를 세고 케이스 타임아웃으로 무한 대기를 실패로 만든다 |
| 초기화가 반쯤 실패한 채 기동한다 | 생성기·계약 실패는 exec 을 막고, 생성기 실패 뒤 계약 단계로 넘어가지 않는다 (REQ-CI-010, AC-CI-010) |
| 지시 파일이 프로젝트 밖을 가리킨다 | `Lstat` + 해석 경로 봉쇄로 일반 파일만 받는다 (REQ-CI-011, AC-CI-011). 스냅샷만으로는 심링크를 못 잡는다 |
| 기존 지시 파일을 덮어쓴다 | 없는 파일만 만들고 있는 파일엔 연결 한 줄만. AC-CI-005 가 사용자 내용의 부분 문자열 존속을 판정 |
| 로컬 파일이 두 번 로드된다 | 직접 참조를 한 곳으로 제한, AC-CI-007 이 참조 1건을 판정 |
| 배선 판정이 런처와 갈라진다 | 반환 상태로만 판단하고 자체 파일 검사 0건. AC-CI-002 가 모순 주입으로 반환값 소비를 강제 |
| 생성기 계약이 바뀐다 | 이 SPEC 은 호출 여부까지만 판정하고 산출물은 SPEC-CODEX-WIRING-001 의 인수 기준에 맡긴다 |

## §F. 검증 (run-phase)

```
go build ./...
go vet ./...
GOOS=windows go vet ./...
go test ./internal/cli/... -run 'Codex' -timeout 600s
golangci-lint run
MOAI_TEMPLATE_LEAK_STRICT=1 go test ./internal/template/...
```

`internal/cli` 전체 스위트는 로컬 하한 600s — 타깃 실행 후 push 하고 전체 판정은 CI 로 넘긴다.
