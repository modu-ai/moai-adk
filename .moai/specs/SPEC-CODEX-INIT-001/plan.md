# SPEC-CODEX-INIT-001 — 구현 계획

## §A. 이 SPEC 이 생긴 이유

런처 SPEC 이 Tier M 예산 16 REQ / 16 AC 에 닿았고, 상한을 맞추려 AC 2건을 형제 항목으로 통합했다. **그 통합이 곧 커버리지 삭감이었다** — 4차 감사에서 시험가능성이 3회 연속 0.50 에 머문 것이 그 신호다. 개별 구멍은 매 라운드 막았지만 커버리지의 *형태*(상태 × 동사 교차곱, 의미 수준 검증)를 넓힐 예산이 없었다.

분리는 그 압박을 푸는 조치다. 이 SPEC 은 옮겨온 2개 REQ 를 8개로 펴고, 그러면서 4차 감사의 F2·F3 를 흡수한다.

## §B. 경계 — 무엇이 어느 SPEC 소관인가

| 관심사 | 소관 |
|---|---|
| 배선 상태를 **판정** 하고 리드아웃에 **보고** | `SPEC-CODEX-LAUNCHER-001` (REQ-CL-006) |
| 그 상태에서 **제안·초기화·계약 확보** | 이 SPEC |
| 배선 파일의 **내용** 과 생성 로직 | `SPEC-CODEX-WIRING-001` (`moai init --agent`) |
| 이미 깔린 배선의 **표류 보고** | `moai doctor` |

판정 로직은 한 곳에서만 산다. 이 SPEC 은 런처의 판정을 **호출** 하며, AC-CI-002 가 호출 횟수와 자체 파일 검사 부재로 그것을 강제한다. 같은 이유로 생성기도 호출만 하고 무엇을 까는지 다시 정의하지 않는다.

## §C. 설계

### C.1 파일 배치

| 파일 | 성격 | 내용 |
|---|---|---|
| `internal/cli/codex_init.go` | 신규 | 제안 게이트 + 생성기 호출 위임 |
| `internal/cli/codex_contract.go` | 신규 | `AGENTS.md` ↔ `CLAUDE.md` 연결 확보 (멱등) |
| 각 `_test.go` | 신규 | §D 시험 |

런처의 `codex_launcher.go` 에는 **호출 지점 한 줄** 만 는다 — launch 동사가 기동 직전 이 게이트를 통과한다.

### C.2 제안 게이트

```
launch 동사 진입
  → 런처의 배선 상태 판정 호출          (재구현 금지, AC-CI-002)
  → 배선됨 ? 그대로 기동 : 계속
  → 대화형 ? 제안 : 상태·조치 보고 후 종료 (기동 안 함)
  → 거절 ? 무쓰기 종료(취소 코드) : 계속
  → 생성기 호출 1회 → 지시 계약 확보 → 기동
```

두 launch 동사가 **같은 함수** 를 통과한다 — 동사별로 분기하면 한쪽만 게이트되는 구현이 나오고, 그것이 F2 가 지적한 실패 형태다. AC-CI-001 이 10칸 교차곱으로 그 대칭을 고정한다.

비대화형 판정은 프롬프트 가능 여부로 한다 (TTY 부재 등). 자동화가 프롬프트에서 멈추는 것이 미배선 기동보다 낫지 않으므로, 그 경로는 **보고 후 종료** 다.

### C.3 지시 계약 확보

**연결만 만든다 — 내용은 만들지 않는다.** 없는 파일은 생성기·템플릿이 주는 기본 본문으로 만들고, 있는 파일은 손대지 않는다.

```
AGENTS.md 없으면 생성
CLAUDE.md 없으면 생성
CLAUDE.md 가 @AGENTS.md 줄을 이미 담고 있나?
  ├ 예 → 아무것도 하지 않는다        (I5 — 바이트 무변경)
  └ 아니오 → 그 줄 하나만 추가       (I1~I4)
```

멱등은 이 분기에서 나온다 — "이미 있으면 아무것도 안 함" 이 2회차를 1회차와 바이트 동일하게 만든다. AC-CI-006 이 7종 fixture 를 2회씩 돌려 확인한다.

**로컬 파일 도달성**: `CLAUDE.local.md` 를 **한 곳에서만** 가리킨다. 두 하네스가 모두 도달해야 하지만 양쪽에서 각각 가리키면 같은 내용이 두 번 로드되므로, `AGENTS.md` 가 가리키고 `CLAUDE.md` 는 `@AGENTS.md` 를 통해 이어 받는 형태로 한 줄만 둔다. 판정은 파일명 grep 이 아니라 **sentinel 내용이 양쪽 진입 파일에서 도달되는가** 로 한다 (AC-CI-007) — 불활성 산문 한 줄이 파일명 검사를 통과하는 구멍을 막는다.

## §D. 마일스톤

| M | 내용 | 산출 |
|---|---|---|
| M1 | 제안 게이트 + 교차곱 시험 | `codex_init.go`, 10칸 표 시험 |
| M2 | 생성기 위임 + 거절·비대화형 경로 | 인자 포착 seam, 스냅샷 시험 |
| M3 | 지시 계약 + 멱등 | `codex_contract.go`, 7종 × 2회 바이트 비교 |
| M4 | 로컬 파일 도달성 | sentinel 도달 시험 |

M1 은 런처의 launch 동사가 있어야 붙는다 — `SPEC-CODEX-LAUNCHER-001` M3 이후에 시작한다 (`depends_on` 이 그 순서를 기록한다).

## §E. 위험

| 위험 | 완화 |
|---|---|
| 제안이 자동화 파이프라인을 멈춘다 | 비대화형에서는 제안하지 않고 보고 후 종료 (REQ-CI-004 마지막 절, AC-CI-004) |
| 기존 지시 파일을 덮어쓴다 | 없는 파일만 만들고 있는 파일엔 연결 한 줄만. AC-CI-005 가 사용자 내용의 부분 문자열 존속을 판정 |
| 로컬 파일이 두 번 로드된다 | 직접 참조를 한 곳으로 제한, AC-CI-007 이 참조 1건을 판정 |
| 배선 판정이 런처와 갈라진다 | 판정 함수 호출로만 접근, AC-CI-002 가 자체 파일 검사 0건을 강제 |
| 생성기 계약이 바뀐다 | 이 SPEC 은 호출 여부까지만 판정하고 산출물은 SPEC-CODEX-WIRING-001 의 인수 기준에 맡긴다 |

## §F. 검증 (run-phase)

```
go build ./...
go vet ./...
GOOS=windows go vet ./...
go test ./internal/cli/... -run 'Codex' -timeout 600s
golangci-lint run
MOAI_TEMPLATE_LEAK_STRICT=1 go test ./internal/template/...
```

`internal/cli` 전체 스위트는 로컬 하한 600s — 타깃 실행 후 push 하고 전체 판정은 CI 로 넘긴다.
