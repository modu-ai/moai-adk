## 1. Problem and measured basis

The operator cannot see, inside the session UI, the three operational states that MoAI's own tooling tracks elsewhere: the context window and rate-limit figures (visible only in the status line and the gates' log lines), inbound lane notifications (visible only when the operator happens to read the right terminal), and the health mismatches `moai doctor` knows about — a stale binary, a stale MCP server, an over-cap memory store (visible only when someone runs `moai doctor`).

Claude Code 2.1.287 can host a **mod** — a plugin of function hooks that runs inside the session and draws above the prompt, appends to the spinner, raises toasts and pins a status line. This SPEC defines an MVP mod, `moai-status`, with three features and no actions at all:

1. **Usage/context warning strip + spinner suffix** — a band above the prompt and a spinner suffix that appear when the session's usage figures cross thresholds that mirror the in-repo gates.
2. **Lane notification toast** — a one-line toast for each inbound cross-session delivery, observed without ever holding, rewriting, or answering it.
3. **Health/status warning line** — a background timer compares the installed `moai` binary against the running MCP server, reads the memory-retention state, and pins a warning line under the prompt while something is wrong.

## 2. Boundary — strictly additive observer

[HARD] The mod is **additive-only and read-only**. Its complete behavior is drawing (band, suffix, toast, status line) and holding state. An **action** — running a command, asking the person, altering turn flow — does not exist in this mod:

- **No hook alters turn flow.** Every event handler the mod registers passes its event through: `session.measure` and `session.receive` return `next(e)` on every path, including the error paths; a `session.receive` hook that answers without `next` consumes the delivery (M-5) — that return shape is never produced. No `tool.*`, `prompt.*` or `turn.*` event is registered at all.
- **The mod runs no command outside its fixed argv table** (plan §B.3: three diagnostic argvs — two read-only; the MCP check deletes the CLI's own dead-stamp files as it runs, disclosed in the bullet below). It makes no network call, no file write, no tool call, no prompt submission, and no model, agent, settings or environment access.
- The two `ui.render` hooks draw or pass; the Spinner hook touches only `props.suffix`, never `word`, `message` or `mode`.
- Absent or disabled, existing behavior is unchanged: the mod draws only where the engine gives it a site, yields the AbovePrompt band to a survey (`e.props.hasSurvey`), and clears its own status line when it has nothing to say.
- One side effect rides inside a called command, not in the mod: `moai doctor --check "MCP Server Version"` prunes the server's own dead PID stamp files as it runs (M-9, `internal/cli/doctor_mcp_version.go:50-51`). The mod neither reads nor writes those files itself.

Everything not in §3 is out of scope (§6): actions, polling `$.session.usage()` on a clock when `session.measure` pushes the same figures, answering or holding deliveries, fixing what the health line reports, and any Go, template or CI change.

## 3. Requirements (GEARS)

- **REQ-MSM-001** (Ubiquitous) — The mod shall live in `mods/moai-status/` as a standalone plugin directory named `moai-status`, shall register every hook from one hooks module (`hooks/hooks.json` naming exactly one module), and shall make no change to any turn-flow surface: no hook alters, holds, delays, or answers the turn's events beyond returning `next(e)`.
- **REQ-MSM-002** (Ubiquitous) — The mod shall call only the `$` nouns its manifest validates — `$.state.get`, `$.state.set`, `$.ui.toast`, `$.ui.status`, `$.ui.resolve`, `$.clock.every`, `$.clock.after`, `$.process.run` — and shall make no network call, no file write, no tool call, no prompt submission, and no model, agent, settings or environment access; every command runs as an argv list from the fixed table of plan §B.3 through a single `$.process.run` call site in the hooks module.
- **REQ-MSM-003** (Event-driven) — When the engine raises `session.measure`, the mod shall classify the pushed figures — `e.context.percent` against the context band of M-7 (warn at `softThresholdPct(e.context.window)` — 50 for a window of at least 500,000 tokens, else 90; critical at `hardCeilingPct(e.context.window)` — min(95, 85 + 10), clamped up to the warn level), and each `e.rateLimits[]` entry's `percentUsed` against its window's gate hold (90 for `five_hour`, 95 for `seven_day`, warn only for those two `kind` values) — shall store the classification in `$.state`, and shall return `next(e)` on every path, including when a figure is absent (`percent` and `rateLimits` entries are optional; absent means no reading, never zero).
- **REQ-MSM-004** (Event-driven) — When the AbovePrompt band is drawn (`ui.render`, `{ component: 'AbovePrompt' }`) and the stored classification carries a warn or critical level, the mod shall draw a one-line warning strip; when the band carries a survey (`e.props.hasSurvey`) or the classification carries nothing above info, the mod shall draw nothing and return `next(e)` unchanged; when it draws, the mod shall compose — resolve the upstream drawing through `next(e)` and place its own strip so the upstream tree still draws.
- **REQ-MSM-005** (Event-driven) — When the spinner is drawn (`ui.render`, `{ component: 'Spinner' }`) and the stored classification carries a warn or critical level, the mod shall rewrite only `props.suffix` — passing `next` a copy of the event whose `props.suffix` carries the incoming suffix plus one short marker (context percentage or the worst rate-limit window) — and shall pass `next(e)` unchanged when there is nothing to say; it shall never rewrite `word`, `message` or `mode`.
- **REQ-MSM-006** (Event-driven) — When a delivery arrives (`session.receive`), the mod shall show a one-line toast naming the origin kind and a bounded excerpt of `e.text`, shall attempt the toast before passing the delivery on, and shall return `next(e)` on every path — the delivery passes even when the toast call fails — and shall never produce a `{ consumed }` result, hold, rewrite, or answer a delivery.
- **REQ-MSM-007** (State-driven) — While the session runs, the mod shall run the health check on one `$.clock.every` timer at an interval no shorter than 15,000 ms, with at most one check cycle in flight and a per-command timeout of 20,000 ms; the cycle runs the fixed argv table's three diagnostic commands, and the timer is cancelled at `session.end`.
- **REQ-MSM-008** (Event-driven) — When a health cycle classifies its results, the mod shall pin at most one line under the prompt through `$.ui.status` naming the failing parts — binary behind its tree (with both short SHAs), a stale running MCP server (with pid and commits), or a memory store over its cap (with count and cap) — and shall call `$.ui.status(undefined)` when nothing fails, so the line is the mod's only and shows warnings only.
- **REQ-MSM-009** (Event-detected) — When a health command cannot start (including `moai` missing from PATH), times out, or returns no parseable box row for the asked check — which includes a non-zero exit with no such row — the mod shall treat that source as unknown — showing it as unknown, never as healthy and never as a failure of the session — shall keep the last good classification, and shall let no exception leave a hook, so that Claude Code continues unaffected (a throwing hook is skipped with one line naming mod, event and reason — the engine's own fail-soft, M-3).
- **REQ-MSM-010** (Ubiquitous) — The mod shall hold its strip classification and health state in `$.state` under a contract declared in `types/index.d.ts` named by `plugin.json`'s `types` pointer (`interface PluginState` for the plugin's own name, exports led by the PascalCase plugin name), and shall hold no data in module variables beyond what a hot reload may lose at the cost of one recompute.
- **REQ-MSM-011** (Ubiquitous) — The mod shall not be embedded in or deployed by `moai init` or `moai update`, shall not appear in release archives or CI, and the repository `.gitignore` shall ignore the engine-written `mods/*/.claude-plugin/types/` without ignoring the mod's own sources.
- **REQ-MSM-012** (Ubiquitous) — The mod shall treat the doctor single-check exit code as advisory (exit 0 with a `warn` row was observed, M-9) and shall classify each check from its box row's STATUS token and MESSAGE text, parsing the row first: a non-zero exit means unknown only when no parseable row for the asked check is present. The STATUS tokens the classification knows are `ok` and `warn` — the only tokens the two asked checks assign (in-tree: `internal/cli/doctor.go:629-679` assigns CheckWarn/CheckOK only for Binary Freshness; `internal/cli/doctor_mcp_version.go` assigns CheckOK/CheckWarn only for MCP Server Version), so a `fail` token, while it exists in the doctor's wider vocabulary, is unreachable from the fixed argv table and is not a verdict either: any row whose STATUS token is not `ok`/`warn` classifies as unknown (REQ-MSM-009), never healthy. The mod shall never classify from a summary line (`0 ok, 1 warn, 0 fail`) that merely contains the same words.

## 4. Platform constraints (from the laid 2.1.287 typings, M-4/M-5; the contract is early access)

- `$.session.usage(args?: SessionUsageArgs): Promise<SessionUsage>` — `{ startedAt, context: { tokens?, window, percent?, breakdown? }, rateLimits: { kind, percentUsed, resetsAt? }[], cost? }`. The plain call costs nothing; `breakdown: 'full'` counts tokens over the network. **The design-given names `rateLimits` and `context.percent` exist verbatim — no deviation (M-5).** The mod does not poll this call: the engine pushes the same figures as `session.measure` (below).
- **`session.measure`** fires when the engine measures the session and a unit moved — after each main-thread turn, and when a rate-limit window moves a whole point. Input `{ context, rateLimits, cost?, changed: ('context'|'rateLimits'|'cost')[] }`; observe-only — `next(e)` echoes `{ changed }`. "One at a time, a burst folding into one more."
- `$.ui.toast(text, options?): void` — one line under the plugin's name, over the transcript's top right corner (or the notification bar where nothing floats); `timeoutMs` default 4000; leaves the transcript and model untouched. `$.ui.status(text | undefined): void` — pins the plugin's one status line under the prompt; `undefined` removes it; one per plugin.
- `ui.render` matcher `{ component: 'AbovePrompt' }` — the band directly above the prompt; the engine draws nothing of its own there; props `hasSurvey` (yield), `isWorking`, `maxRows`, `bodyColumns`, `scroll`, `view`. Raised on terminal and desktop only. A hook draws a tree, or passes; `next(e)` resolves to the upstream drawing, which a drawing hook wraps so later mods still draw.
- `ui.render` matcher `{ component: 'Spinner' }` — props `word`, `message`, `suffix` (the engine's default suffix is one ellipsis), `mode`. A hook rewrites the props it names via `next({ ...e, props })`, or draws a tree in place of all of it. Terminal and desktop only.
- `session.receive` — one inbound delivery, sanitized, before it is queued: `origin.kind` (`bridge`, `peer`, `coordinator`, `task-notification`, …), `text`, optional `event` wake, optional `agentId`. Returning `next(e)` queues the delivery (`{ text }`); answering without `next` consumes it (`{ consumed }`) — the latter shape is forbidden to this mod (§2).
- `$.clock.every(ms, fn)` runs until `cancel()`; `$.clock.after(ms, fn)` once. `$.process.run(argv, init)`: argv list, no shell; default timeout 30 s, ten minutes at most; stdout and stderr cut at 4,194,304 bytes with `isStdoutTruncated` / `isStderrTruncated`; rejects when the command cannot start or is still running at the timeout.
- `$.state` is reactive: a `get` made while a `ui.render` hook draws subscribes that instance, and a later `set` redraws it without `$.ui.invalidate` (M-5). State survives a hot reload; `$.store` is the persistent tier (not used by this MVP). `plugin` and `key` are literals in source.
- A hook has a 10,000 ms budget of its own time per dispatch; a `$` call in flight does not count against it. A hook that throws is skipped with one line naming mod, event and reason, and the chain continues (M-3, observed).
- `$` never crosses an import: `claude plugin validate` refuses `$` passed to a function imported from another file (sibling M-17, unchanged contract); every `$.…` call is spelled in the hooks module and helpers receive functions as arguments.
- The `types` pointer in `plugin.json` is required once `$.state` is used; the contract file exports a PascalCase-led type and declares `interface PluginState` (sibling M-17).
- `claude plugin validate`'s `calls:` line is a static listing, not an existence check (M-2, fake-noun control), and it lists `$` uses only where its analysis reaches (M-11) — so the allow-list AC asserts the listed token set is a **subset** of REQ-MSM-002's eight nouns, with a control proving the listing catches noun spellings (`$.ui.ask`, M-12), and all `$` uses live inside `register`'s scope. The same validate output carries the state-contract lines the types pointer produces (`state writes:` / `state reads:`, M-13).
- The engine test environment implements none of the mod's nouns for free: `session.usage`, `ui.status`, `ui.toast` and `session.measure` are all stubbed per test with `on('<event>', …)` returning `{ value }`, and the test `$` can raise any event noun at the mod's hooks (M-3).
- The typings are laid by a session load into `<mod>/.claude-plugin/types/` (M-4) — the path the repository `.gitignore` must ignore (REQ-MSM-011).

**D-1 — Location (decided, with evidence).** The mod lives in `mods/moai-status/` at the repository root, mirroring the sibling `mods/moai-board/` layout (SPEC-MOAI-BOARD-MOD-001, unmerged at authoring time — its structure is mirrored, its code is not depended on). Final deployment scope waits on card t1434, as for the sibling (Q7).

**D-2 — Feature 1 reads the pushed event, not a poll (decided, with evidence).** The design spoke of `$.session.usage()`; the laid typings provide `session.measure`, which carries the same figures pushed after each turn and on rate-limit movement (M-5, "pushed, not polled"). The mod classifies on the push and holds the result in `$.state`; the render hooks draw from state. `$.session.usage()` is not called at all, so the strip costs nothing between turns.

**D-3 — Thresholds mirror the in-repo gates' default configuration, re-derived as constants (decided, with evidence; weakened from the iter1 claim "cannot contradict a gate it mirrors" — the gates are runtime-configurable, G-12).** The strip's warn/critical levels re-derive `softThresholdPct` and `hardCeilingPct` (M-7) from `e.context.window`, and use the quota-gate hold percentages per window kind — as those gates' **defaults** are set in the tree. The gates themselves are configurable at runtime (`getAutoCompactThreshold` reads `CLAUDE_AUTOCOMPACT_PCT`, memory.go:45-52; the quota holds load through `LoadQuotaGate`, loader_quota_gate.go:64), while REQ-MSM-002 forbids the mod any env/settings access, so the mod shows its own frozen values and can diverge from an overridden gate; the quota gate's release margin (5) means a held gate also keeps holding below the strip's warn level (G-12 records both divergences). The classifier takes the band as explicit inputs (plan §B.4) and the mod instantiates it with the mirrored defaults; which levels the band chooses to *display* beyond that is a display decision (Q2). The values live as named constants in the pure module (plan §G), never inline.

**D-4 — Health parse target is the single-check box row (decided, with evidence).** `moai doctor --check "<name>"` prints one box row and exits 0 on warnings (M-9) — leaner than the full run (141 lines, exit 1 from unrelated checks) and free of the `--export` file write. The row's STATUS token and MESSAGE text are the parse surface; the message spellings are pinned from the in-tree sources (M-9) and treated as a versioned contract of the CLI with a stated drift risk (plan §H).

## 6. Out of Scope

### Out of Scope — actions and turn flow

- Any user action: no button, no press target, no `$.ui.ask`, no command the person can invoke from the mod.
- Holding, rewriting, answering or consuming an inbound delivery; sending a message; any `session.send`, `tool.*`, `prompt.*` or `turn.*` registration.
- Polling `$.session.usage()` on a clock (the engine pushes `session.measure`; D-2), calling `$.session.compact()`, or acting on any threshold beyond drawing.

### Out of Scope — health remediation and deeper signals

- Fixing what the health line reports: rebuilding the binary, reconnecting the MCP server, archiving memory files. The line names; it never acts.
- Health sources beyond the three fixed argvs: `moai doctor`'s other checks, `.moai/state` trace/runs retention files, hook-runtime log retention (`DefaultTraceRetentionDays` and kin — a different "retention" reading; Q1), and any network fetch of release feeds.
- The `.moai/state/mcp-server/<pid>.json` records as a direct `$.fs.read` source: the doctor check already reads and prunes them; reading them from the mod would duplicate the CLI's liveness logic (M-9).

### Out of Scope — deployment, Go, template, CI

- Installing the mod through `moai init`, `moai update`, a marketplace, or a user mods folder; deciding its final load scope (card t1434, Q7).
- Adding a CI job, a Go test, a release step, or `tsc` in CI for the mod.
- Changing any `moai` Go code — including a slimmer `memory doctor` payload or a JSON output for `doctor --check`; that would be a separate card.
- Any change to `mods/moai-board/` or any other t1436 file (parallel card; merge-safe `.gitignore` line only).
