## §A. Problem Statement

MoAI-made worktrees live inside the repository directory: `moai worktree new` and the factory card materializer create `<root>/.moai/worktrees/<name>` (`internal/cli/session_worktree.go:48,223`), while the `moai cc -w <name>` short-name path and the `-w <name> --branch <existing>` path land in `<root>/.claude/worktrees/<name>` (`internal/cli/worktree_branch_flag.go:109`; Claude Code creates the tree itself for a bare short name). Measured at HEAD `74ad197380` with `git worktree list`: 251 registered entries — 1 primary checkout, 192 under `<root>/.moai/worktrees`, 46 under `<root>/.claude/worktrees` (31 named `agent-<hex>`, 15 other), 12 under `~/.codex/worktrees` (Codex-app managed). Operator measurement 10-19 recorded 191 and 46 for the first two; the one-tree difference is this card's own tree (research.md §R1).

Consequences the operator and the cards name: the working copies share a directory subtree with the repository they belong to (scanners, ignore lists and path-prefix classifiers all special-case `worktrees`), 238 trees hold branches that may exist nowhere else, and the storage convention is split across two in-repo roots plus a third, never-used home root (`~/.moai/worktrees/<project>`, the old "L2" layout, which now holds only seven empty or near-empty directories). The operator decision (cadf, 10-19) lifts the 3.3 deferral: unify the location now.

Two hazards make this more than a path change, and the SPEC is built around them:

1. **Trees hold the only copy of unpushed work.** Any migration that is not strictly non-destructive can destroy the work of the 191-192 live trees (operator invariant, cadf).
2. **Many readers identify trees by path shape.** A tree moved to `~/.moai/worktrees/projects/<project-name>/<name>` is misread by at least five concrete readers unless they change (research.md §R3): the card-id-from-path derivations resolve the card id to the literal `projects`; the `todo --auto` owner-liveness probe looks only at two in-repo candidate paths and would judge a live owner dead; the `done`/`sweep` tier classifier would reclassify a moved session tree as an L2 registry tree (a disposal-eligible class); the factory card status bases, the factory card landing-directory resolver and the launcher short-name resolvers do not know the new root; and the factory card record stores an absolute `worktree_path` that the record layer refuses to change.

## §B. Scope

In scope (components):

1. **Location resolver** — one function family that maps (repository, name) to the home-root path, owns the project-key assignment, the collision guard and the legacy-root candidates (REQ-WHR-001..004, 022, 023).
2. **Creation paths** — every MoAI creation path places new trees at the home root; none creates under a legacy root (REQ-WHR-005, 006).
3. **Readers** — card-id derivation, owner liveness, status bases, factory landing-directory resolution, launcher/anchor/hook-seed short-name resolution, launcher auto-cleanup, tier classification, `moai worktree list` (REQ-WHR-007..010, 014).
4. **Stored-path migration** — card record rebind, the other path-bearing state and the move-list record (REQ-WHR-011, 012).
5. **Migration engine** — `moai worktree migrate` (dry-run default, apply, verify, rollback) and the `moai update` consolidation, which applies through the same engine with the same classifier, destination and safety devices (REQ-WHR-013..019, 024).
6. **Retirement** — legacy in-repo roots stop being written; the empty MoAI legacy directory is removed; the Claude-owned directory is never touched (REQ-WHR-020).
7. **Pre-kickoff measurement gate** — EnterWorktree, Codex `/cd` and launcher-backend entry into a home-root tree, measured before the plan→run Kickoff (REQ-WHR-021; §F).
8. **Location guidance (t1610 absorbed part)** — agent-facing surfaces state the new location and carry only the entry facts the measurement record shows (REQ-WHR-025). The boundary with card t1879 is stated in §G ("Out of Scope — guidance rewrite owned by card t1879").

## §C. Requirements (GEARS notation)

The `<subject>` is generalized per the GEARS guide. "Home root" means `<MoaiHome>/worktrees/projects/<project-key>`; "legacy roots" means `<primary>/.moai/worktrees` and `<primary>/.claude/worktrees`; "moai-made tree" is defined by REQ-WHR-013. The `<project-key>` is the project name, hash-suffixed only on a cross-repository collision (REQ-WHR-002/003).

### Location and key

**REQ-WHR-001** (Ubiquitous — home root). The location resolver shall return, for a repository and a tree name, the path `<MoaiHome>/worktrees/projects/<project-key>/<name>`, where `<MoaiHome>` is obtained only through `paths.MoaiHome()` so that `MOAI_HOME` relocates the whole tree and tests stay hermetic.

**REQ-WHR-002** (Ubiquitous — project key and its stability). The location resolver shall derive `<project-key>` from the repository's primary checkout, never from the invoking worktree: at first assignment the key is the sanitized basename of the primary checkout root (characters outside `[A-Za-z0-9._-]` become `-`), disambiguated only per REQ-WHR-003. The assignment shall be recorded twice — in a record that travels with the repository (so it survives a move of the checkout and a rename of the clone's directory) and in an owner marker `<MoaiHome>/worktrees/projects/<project-key>/.moai-project.json` holding the schema version, an owner identity, the primary checkout root last seen, and the creation time. Once assigned, a repository's key shall never change: every later resolution shall return the recorded key, and re-running resolution or migration shall be idempotent.

**REQ-WHR-003** (Event-detected — collision guard). When a folder under `<MoaiHome>/worktrees/projects/` whose name equals the candidate key compared case-insensitively already exists and its marker names an owner other than the requesting repository, the location resolver shall select the disambiguated key `<project-name>-<first 8 hex of SHA-256 of the case-folded canonical primary root>` for the later-arriving repository, leave the first repository's plain name untouched, and shall not place a tree under the other repository's folder; a repository that already owns an assignment shall not be re-keyed by the arrival of another; when the disambiguated folder is itself owned by a third repository, or when a marker exists but cannot be read or parsed, creation shall refuse with a message naming the marker path.

**REQ-WHR-004** (Where — operator pin). Where `git_strategy.worktree_project_key` is set to a non-empty value and the repository has no recorded assignment, the location resolver shall use that value (validated as a single safe path segment) as the first-assigned `<project-key>`, subject to the collision guard in refusing form: a folder of that name owned by another repository makes creation refuse, never suffix. Where the repository already has a recorded assignment that differs from the pin, the resolver shall keep the recorded key and report the mismatch; a pin never re-keys an assigned repository. The default is empty, which reproduces REQ-WHR-002 exactly.

### Creation

**REQ-WHR-005** (Event-driven — creation paths). When any MoAI creation path creates a worktree — `moai worktree new`, the factory card materializer (`factory next` and its three other callers), the session-worktree auto-entry, and the launcher `-w <name> --branch <existing>` path — the system shall create it at the home root through the one shared materializer, preserving that materializer's existing guarantees (configured base branch, `WT-` branch convention, global `safe.directory` registration, worktree-scoped identity, Codex hook seeding, existing-destination refusal). No creation path shall create a tree under a legacy root.

**REQ-WHR-006** (Event-driven, conditional on PM-3 — launcher short name). When `moai cc -w <name>` or `moai glm -w <name>` receives a short name that resolves to an existing tree in the home root or a legacy root, the launcher shall enter that tree. When the short name resolves to no existing tree: where measurement PM-3 recorded PASS (branch X), the launcher shall materialize the tree at the home root through the shared materializer and hand the backend the absolute path, instead of letting Claude Code create `.claude/worktrees/<name>`; where PM-3 recorded FAIL (branch Y), the launcher shall pass the short name through unchanged, create nothing itself, and the short-name-without-existing-tree case shall be the single documented exception to "no creation path names a legacy root". PM-3 shall be recorded PASS or FAIL before the Kickoff (REQ-WHR-021); an unrecorded PM-3 is a Gap that blocks it.

### Readers

**REQ-WHR-007** (Ubiquitous — path-independent identity). Every component that derives a card or tree identity from a directory path, or looks a tree up by card id, shall resolve it through the shared location resolver (home root first for listing candidates, then the legacy roots while the transition lasts), with the recorded card `worktree_path` taking precedence over any derived candidate, and with the move-list record of REQ-WHR-012 as the fallback that yields a tree's new path when only its pre-move path is held. The components are: the SessionStart card-id derivations (`cardIDFromRegisteredWorktree`, `cardIDFromPath`), the `todo --auto` owner-liveness probe (`autoOwnerWorktrees`), the factory card status bases (`DefaultWorktreeBases`), the factory card landing-directory resolver (`factoryCardWorktreeDir`) with its two callers — the REQ-SD-011 foreign-tree refusal (`factoryRefuseForeignWorktree`) and the previous-worktree carry-over (`factoryCarryPreviousWorktree`), reached from `factoryNextClaim` and `factoryNextValidate` — the launcher short-name resolvers (`launch_chain`, `factory_anchor_guard`, `codex_hooks_seed`, `ccWorktreeWriterPrecheck`), `resolveCodexWorktreeDir`, and `cleanupMoaiWorktrees`.

**REQ-WHR-008** (Unwanted — misidentification). A tree whose parent segment is the project key shall not resolve to a card id equal to `projects` or to the project key; a card whose recorded tree is outside every legacy root shall not be judged "owner not alive" because no in-repo candidate path exists.

**REQ-WHR-009** (Ubiquitous — tier by creation class). The system shall classify a worktree as an L1 session tree or an L2 registry tree by how it was created, never by whether its path lies under a fixed in-repo prefix: every moai-made tree at the home root — including a tree whose branch does not begin with `WT-` — is an L1 tree, `moai worktree done` shall refuse it with or without `--force`, and `moai worktree sweep` shall report it as tier L1 and dispose of it only on its existing landing predicates. The legacy in-repo roots remain L1 for as long as trees exist there.

**REQ-WHR-010** (Ubiquitous — `moai worktree list`). The system shall provide `moai worktree list [--json]`, read-only, that enumerates every worktree registered with the repository and reports for each: name, absolute path, root kind (home / legacy-moai / legacy-claude / codex-managed / other), class (moai-made / claude-native / codex-managed / integration / primary / unclassified), branch, short HEAD, dirty flag, commits not present on any remote, and whether a live session is anchored. Two spellings of one directory shall be reported as one tree (REQ-WHR-023).

### Stored paths

**REQ-WHR-011** (Event-driven — card record rebind). When migration moves a tree that a factory card record names, the system shall rebind the card's recorded `worktree_path` from the old path to the new path through a dedicated record operation that (a) accepts only the transition `old → new` for the card whose current value equals `old`, (b) verifies, when called, that `new` is a registered worktree of the same repository at the same HEAD and branch (the reverse rebind of REQ-WHR-017 is called only after the tree is back at its pre-move path, which is then `new`), (c) updates every run row of that card that carries `old`, so that `PreviousCardWorktree` cannot carry a stale path into a replacement run, and (d) appends one `card.fields` event recording both paths. The existing refusal to move a card onto a different tree through `RecordCardWorktree` shall remain unchanged.

**REQ-WHR-012** (Event-driven — other path state and the move-list record). When a migration run settles a tree — through `moai worktree migrate --apply`, through the `moai update` consolidation (REQ-WHR-019) or through a rollback — the system shall (a) for a moved tree, re-key the entry of that tree in the project worktree state file (`.moai/state/worktrees.json`) as a journaled, reversible step beside the card rebind, leave the session registry and the origin-trail chain ledger entries that name the old path unmodified (live sessions are skipped by REQ-WHR-016; the ledger is history), and record in the journal (REQ-WHR-017) every path-bearing store it did or did not touch, with a done/pending status per step; and (b) append the tree's outcome to the move-list record, a JSON Lines file at the fixed location `<primary>/.moai/state/worktree-migrate/move-list.jsonl`, where `<primary>` is the parent of `git rev-parse --path-format=absolute --git-common-dir`, so that one file serves every tree of the repository. Each line is one self-contained JSON object with the fields `schema` (1), `ts` (UTC, RFC 3339), `run` (the id of the journal of the run), `trigger` (`update`, `migrate` or `rollback`), `tree` (directory name), `card` (card id, or empty), `old_path`, `new_path`, `result` (`pending`, `moved`, `skipped`, `failed`, `reversed`, `restored` or `refused`) and `reason` (the skip, failure or refusal reason; empty otherwise); for a skip `old_path` is the source and `new_path` the planned destination, and a `pending` line is the intent record written immediately before the `git worktree move` of a tree, naming the same two paths and carrying one more field, `ident`, the tree's stable identity (design.md D-11). A line is appended under the migration lock (REQ-WHR-017) with one write in append mode after its step settles; an unterminated tail is closed with a newline first, so it never absorbs the new line; the file is never rewritten or truncated; an entry is not appended when it equals in `old_path`, `new_path`, `result` and `reason` the latest entry of the file that names either of its two paths, so a repeated run adds nothing while a move re-applied after a rollback is appended; and a dry run writes nothing (REQ-WHR-015). Rollback (REQ-WHR-018) and automatic reversal (REQ-WHR-017) append `restored` and `reversed` entries — `old_path` the path the tree left, `new_path` the path it arrived at — and never edit an earlier line. A lane that holds only a tree's pre-move path shall find its current path by the lookup of design.md D-11, which returns a path only when `git worktree list` registers it and, wherever a card record or an unsettled `pending` line decides the answer (the kill window between the move and its settling line), only for the tree whose `ident` matches. The factory card record's rebound `worktree_path` (REQ-WHR-011) remains the primary pointer; the move-list record is the fallback and the audit trail.

### Migration

**REQ-WHR-013** (Ubiquitous — moai-made classification). The system shall classify a registered tree as moai-made when it is neither the primary checkout, nor an integration worktree (the tree that holds the configured integration branch), nor a Claude-native agent-isolation tree (directory name matching `agent-[0-9a-f]+`), nor a Codex-managed tree, and at least one creation-class witness holds: (a) its directory lies under `<primary>/.moai/worktrees`, (b) its branch begins with `WT-`, or (c) its directory lies under `<MoaiHome>/worktrees/projects/<project-key>/` and the owner marker of that key names this repository. Witness (c) survives the move, so a non-`WT-` tree migrated from witness (a) remains moai-made at the home root. A tree that fits no class is `unclassified`; it shall be listed with that label, never moved, and never counted as moai-made. The same classifier shall serve `moai worktree list`, `moai worktree migrate`, the tier decisions of REQ-WHR-009 and the `moai update` consolidation (REQ-WHR-019).

**REQ-WHR-014** (Ubiquitous — non-destructive invariant, migration and post-migration cleanup). The migration shall be non-destructive. The only filesystem mutations it may make to a tree are `git worktree move <source> <destination>` and, for rollback, the same command in the opposite direction; it shall never run `git worktree remove`, `git worktree prune`, `git branch -D`, `git reset`, `git clean`, `git checkout`, `git stash`, `rm`, or a recursive delete, and it shall never dispose of a tree. The invariant extends past the migration: the launcher's automatic worktree cleanup (run on every `moai cc` launch) shall remove a registered tree, whatever its location or name, only when its branch is integrated and landed on a remote by the same predicate the disposal verbs use, so that a branch pushed but not integrated, a branch integrated locally but present on no remote, and a branch whose remote check fails are never removed, and shall not remove a tree the migration moved (the tree whose current path is the `new_path` of the latest `moved` entry of the move list that names it, found by the reverse lookup of design.md D-11). Disposal remains with the existing landing-gated verbs and requires integration plus remote landing of the tree's branch.

**REQ-WHR-015** (Event-driven — dry-run default, idempotence). When `moai worktree migrate` runs without `--apply`, it shall perform no mutation of any kind and shall print, for every registered tree, its class, source, destination and skip reason; `--apply` shall be required to move trees; a second `--apply` over an already migrated repository shall move nothing further; `--verify` shall re-read the journal and the registered state and report each recorded move as intact, drifted or rolled back.

**REQ-WHR-016** (State-driven — skip conditions). While a tree is locked, prunable, missing, or blocked by an existing destination, or contains the current working directory of any running process (the tree itself or any directory inside it, a terminal-multiplexer pane process included), or is anchored by a live session whose recorded working directory is the tree or any directory inside it, or while its destination lies on a different filesystem than its source, or while the process working directories cannot be inspected, the migration shall skip the tree, leave it at its old path, print the reason and append the skip to the move-list record (REQ-WHR-012). An existing destination shall be reported and shall never be overwritten, merged into or removed. A skipped tree shall remain fully usable at its old path.

**REQ-WHR-017** (Event-driven — manifest, ordered steps, automatic reversal, locks). When the migration moves a tree, it shall first record a manifest and a journal entry, and after the move it shall recompute the same manifest at the destination. The manifest holds HEAD, branch, the commits listed by `git log HEAD --not --remotes` (count and SHA set), a hash of `git status --porcelain=v1 --untracked-files=all`, the count of ignored files, the file count of the tree's `.moai/reports`, and a content digest over the tracked-change diff, the untracked files, `.moai/reports` and the ignored files within a recorded bound (design.md D-12; the manifest states the bound and the number of ignored files left unhashed). The journaled step order is: manifest, intent line (REQ-WHR-012), move, `.moai/state/worktrees.json` re-key, card rebind, manifest comparison. When any field differs, or any step fails, the migration shall reverse the completed steps in one fixed order — the move first (`git worktree move` back), then the state re-key, then the card rebind, so that the reverse rebind targets a registered worktree (REQ-WHR-011(b)) — and report the tree as not migrated, appending the reversal to the move-list record (REQ-WHR-012); explicit rollback (REQ-WHR-018) uses the same order. When a reverse step also fails, it shall record that step as pending in the journal, leave the stores as they are, and exit non-zero. After any failure, kill, or re-run, the registered worktree path, the `.moai/state/worktrees.json` entry and the card record shall agree with the tree's real location. Every mutating entry point — `migrate --apply`, `migrate --rollback` and the `moai update` apply — shall take one repository-wide migration lock once, for the whole run (the engine does not re-take it), and a second mover that finds it held shall end its run without moving anything and report why. Every read-modify-write of `.moai/state/worktrees.json` — the migration re-key and each registry writer (`registerWorktree`, `RegisterLauncherWorktree`, `unregisterWorktree`) — shall take one cross-process state-file lock and write by temp file and atomic rename, and a state file that does not parse shall fail the step for every writer and shall never be rewritten as an empty file. Each lock is held by the operating system and released when its holder exits, a kill included, so a dead holder blocks no later mover.

**REQ-WHR-018** (Event-driven — explicit rollback and recovery). When `moai worktree migrate --rollback <journal>` runs, the system shall move each recorded tree back to its recorded source if that source path is free and the tree's manifest still matches, reverse the state re-key and the card rebind in the order of REQ-WHR-017 (move first), under the migration lock, complete any step the journal records as pending (the command is idempotent and converges on re-run), and report each tree restored or refused with the reason, appending each outcome to the move-list record (REQ-WHR-012). The manifest-match precondition applies to the ordinary rollback of a settled move only; completing a step recorded pending — a reverse move after an automatic reversal triggered by a manifest mismatch included — is unconditional of the manifest, and needs only that its source path is free.

**REQ-WHR-019** (Event-driven — `moai update` consolidation applies, with the safety devices). When `moai update` runs in the primary checkout without `--dry-run` and legacy-rooted moai-made trees exist, the `moai update` consolidation shall apply the migration through the same engine as `moai worktree migrate --apply`: it shall hold the migration lock of REQ-WHR-017 for the run, select trees with the classifier of REQ-WHR-013 (never a Claude-native agent-isolation tree, never an `unclassified` tree), shall name the home root as the destination of every move (never `<primary>/.moai/worktrees`), and shall hold to these safety devices as required behavior of every move it makes — (a) each move is `git worktree move` and nothing else, never a delete and never a bare filesystem move (REQ-WHR-014); (b) a tree with an active process or a live session is skipped, not moved (REQ-WHR-016); (c) a destination collision skips that tree, is reported, and never overwrites the existing destination (REQ-WHR-016) — while the before/after manifest verification and automatic reversal of REQ-WHR-017 and the move-list record of REQ-WHR-012 apply to each move. When `moai update` runs with `--dry-run`, the consolidation shall print the plan and the skip reasons and shall move nothing. A failure of the consolidation, a held lock included, shall be reported without failing the update, and a later update shall retry the trees that were skipped. Relative to the current consolidation (`internal/cli/update.go:410`, `runUpdateWorktreeMigration(lockRoot, false, out)`) only the destination and the selection change; the call at `update.go:366` remains the preview that `--dry-run` runs.

### Retirement and transition

**REQ-WHR-020** (Event-driven — retirement). When no registered tree and no entry remain under `<primary>/.moai/worktrees`, the system shall remove that directory only if it is empty, using a non-recursive removal; it shall never remove, move or modify `<primary>/.claude/worktrees` or any tree in it that is not moai-made; and no creation path shall name either legacy root after the run phase completes, except as a read candidate for the transition (REQ-WHR-022) and as the REQ-WHR-006 branch-Y exception.

**REQ-WHR-021** (State-driven — pre-kickoff measurement gate). While the pre-kickoff measurement record (§F) is absent from `.moai/reports/t1640/`, or does not carry each gating id (PM-1a, PM-1b, PM-1c, PM-1d, PM-2, PM-3) on exactly one line, and that line carries the classification PASS or FAIL — a Gap, any other outcome (an `ERROR` line included, alone or beside a valid line), a missing id, a duplicate and a conflicting pair all counting as unmet — the plan→run Kickoff shall not be taken. Each gating cell shall carry exactly one classification, PASS or FAIL, with the command, verbatim output, exit status, tool versions and tree SHA; every FAIL shall carry the consequence stated for it in §F. The measurement runs before the Kickoff and outside the run-phase milestones (plan.md milestone M-1).

**REQ-WHR-022** (Ubiquitous — transition resolver). For as long as legacy-rooted trees exist, every lookup of a tree by name or card id shall collect the distinct trees (compared per REQ-WHR-023) found at the home root and at both legacy roots, and shall return the tree when exactly one is found; when two or more distinct trees carry the name — across any two of the three roots, including the two legacy roots — the lookup shall report the name as ambiguous, name every candidate, instruct the use of an absolute path, and shall not prefer any root; the transition shall end by a later release removing the legacy candidates, not by elapsed time.

**REQ-WHR-023** (Ubiquitous — spelling-safe path equality). Every path equality or containment test introduced or changed by this SPEC — the live-session and process working-directory containment tests of REQ-WHR-016 included — shall treat two spellings of one directory as equal on a case-insensitive volume (compared after symlink resolution and, on darwin and windows, case folding) and shall never fold case on a case-sensitive volume. The case-insensitive project-folder name test of REQ-WHR-003 and the case-folded hash input of the disambiguated key are name-level rules and are exempt from the volume-dependent clause.

**REQ-WHR-024** (Unwanted — scope creep into Claude-owned state). The migration and the resolver shall not create, move, rename, prune or remove any tree under `<primary>/.claude/worktrees` that is classified claude-native, any tree under `~/.codex/worktrees`, or the integration worktree, and shall not register a `WorktreeCreate` or `WorktreeRemove` hook.

**REQ-WHR-025** (Ubiquitous — location guidance, scoped to t1610). The guidance surfaces in scope shall state the home-root location of MoAI-made trees, shall separate a terminal launch (`moai cc -w <absolute-path>`, `codex -C <absolute-path>`) from an in-session move only by naming the in-session mechanism (`EnterWorktree` / `ExitWorktree` for Claude Code, `/cd <absolute-path>` for Codex), and shall assert only entry behavior that the pre-kickoff measurement record shows. This requirement does not require, and the run phase shall not attempt, the removal of every sentence that instructs a session to run `moai cc -w` from inside Claude Code; that criterion belongs to card t1879. AGENTS.md shall not grow beyond its measured pre-change size of 23,780 bytes.

## §D. Constraints and invariants

- **I-1 Non-destructive (operator invariant, cadf).** REQ-WHR-014 is the invariant; every other requirement is subordinate to it. A requirement that can only be met by disposing of a tree is not met — the migration skips instead.
- **I-2 Evidence of non-loss.** "Nothing was lost" is proven per tree, for the scope the manifest hashes, by the manifest comparison of REQ-WHR-017 and by `moai worktree migrate --verify`, never by the absence of an error message. The manifest states what it did not hash (ignored files beyond the bound); I-2 claims nothing about those files.
- **I-3 Claude and Codex own their trees.** Per dab5, Claude Code owns its `agent-*` trees; per the Codex worktree facts (research.md §R6) Codex owns `~/.codex/worktrees`. MoAI's home root holds only MoAI-made trees. This is also how the t1611 requirement "do not mix with Codex-app-managed trees; split storage and cleanup ownership" is met.
- **I-4 No time-based transitions.** Neither the transition window nor retirement is tied to elapsed time; both end on observed state.
- **I-5 Always-loaded budget.** AGENTS.md is 23,780 bytes against a 24,576-byte Codex budget (796 bytes of headroom); every guidance edit there is net-neutral or net-negative in bytes. Any other always-loaded rule edit states its byte size and non-invoking-session cost per `rule-authoring.md`.
- **I-6 Template-First.** Every change to a deployed surface lands in `internal/template/templates/` and is mirrored to the local tree; the run phase regenerates embedded assets with the repository's own build step.
- **I-7 GEARS/AC budget.** Tier L ceilings are 25 requirements and 25 acceptance criteria; this SPEC carries 25 and 25 (sub-labelled criteria such as AC-WHR-002a/b count once under their parent).
- **I-8 Key stability.** A project key, once assigned, is never recomputed (REQ-WHR-002). A later-arriving same-name repository takes the suffix; the first keeps the plain name.
