# The launcher retires -l/-a: --name is the only way to name a session, the role is entered inside it

## Intent

카드 C-449 예요. 사용자 결정 D-1(`docs/decisions-2026-11-08.md` 166줄, 2026-11-09)은 런처 `-l`/`-a` 를 "폐기(deprecate) — 경고 후 제거, `--name` 만 유지, 역할은 세션 안 `/moai --mode-leader|--mode-agent` 로만" 으로 정했어요. 2026-11-24 에 사용자가 다시 말했어요: "-l, -a 은 더이상 사용하지 않기로 했잖아." 그런데 지금도 `moai cc --help` 가 `-l/--leader`·`-a/--agent` 를 보여 주고, `moai glm -l --dry-run` 이 돌고, `CLAUDE.md` 와 문서와 리더의 배차 습관이 그것을 말해요(`SPEC-20261118-launcher-agent-entry` 는 `-l|-a` 를 "이름과 권한만 정하는" 플래그로 도움말에 남겼어요).

D-1 의 인용(`/moai --mode-leader|--mode-agent`)은 2026-11-09 의 원문이에요. 지금 역할에 들어가는 길은 이래요(사용자 선택 2026-11-22T23:49Z, `SPEC-20261124-moai-leader-route` D-1, 착지됨): `moai cc|glm` 으로 띄운 세션 안에서 레인은 `/moai work`, 조정 창은 `/moai leader` 를 쳐요. `mode-leader`·`mode-agent` 는 출하 글의 금지어이고(`tests/next_flow_skill_scan.rs` 의 `REQ8_WORDS`), 판 1 은 이 낡은 철자를 거절 문장과 문서에 넣었어요(리더 정정 노트 8241). 판 2 가 고쳐요.

판 3 은 같은 날 이 카드에 합친 일 하나를 더해요(리더 노트 8256): 사용자가 2026-11-24T05:46:10Z 에 직접 골랐어요 — 커밋 메시지는 영어로 써요(프로필 `language.commit_messages: en` 과 같게, 카드 노트 8252). 그런데 `CLAUDE.md` 의 "Language" 절은 커밋 메시지를 한국어 목록에 넣고 있어요(101줄). 같은 파일을 이 카드가 쥐고 있어서 별도 카드로는 `CLAUDE.md` 를 같이 못 고쳐요. 이미 올린 커밋은 다시 쓰지 않아요. 또 판 3 은 노트 8245 와 8256 이 정한 D-5 의 변형을 SPEC 에 맞춰 적어요(레인 배차 줄은 새 카드 없이 이 카드의 마지막 조각).

판 4 는 사용자 결정 하나를 더해요(리더가 전한 것, 노트 8259, 사용자 직접 지시 2026-11-24T05:57:38Z: "moai cc 때에는 auto mode, glm danger-bypass 모드로 변경하자."): 런처의 권한 기본값을 호스트마다 나눠요 — `moai cc` 는 `--permission-mode auto`(지금과 같음), `moai glm` 은 `--dangerously-skip-permissions`. 리더가 전한 배경은 z.ai 게이트웨이의 GLM 세션이 다음 Claude Code 릴리스부터 자동 모드 분류기의 대체 경로를 잃는다는 것인데, 이 SPEC 은 그 배경을 확인하지 못했어요(`unverified`). 순서는 CLI `--permissions` > `launcher.role_access` > 호스트 기본값이에요(D-3 그대로). 이 일은 권한 기본값을 낮추는 선택이라 `guarded` 설정에 닿아요. 이 SPEC 은 사용자 결정의 승인을 스스로 기록하지 않고, 승인은 리더 노트로만 남아요(D-7). 이 판은 승인을 받기 전에 코드를 쓰지 않아요.

공식 문서에서 읽은 bypass 모드(`--dangerously-skip-permissions` = `--permission-mode bypassPermissions`)의 효과 — 연구 에이전트가 2026-11-24 05:58:55Z~05:59:43Z 에 `https://code.claude.com/docs/en` 의 permissions, permission-modes, hooks, sandboxing, cli-reference, settings 쪽을 WebFetch 로 읽었어요. permissions 와 cli-reference 는 페이지 본문 그대로의 인용이고, permission-modes·hooks·sandboxing 은 WebFetch 요약기를 거친 인용이라 정확한 문구는 구현 전에 다시 읽어요:
- deny 규칙은 bypass 에서도 막아요: "Deny rules block in every mode, including `bypassPermissions`."(permission-modes) 어느 범위(user·project·local·managed)에서든 deny 가 allow 를 이겨요: "If a tool is denied at any level, no other level can allow it."(permissions). 단 deny 는 "isn't a security boundary around the program": Bash 규칙은 명령 글자만 맞춰서 같은 프로그램을 경로나 `sh -c` 로 돌리면 못 막아요.
- allow 규칙은 bypass 에서 효과가 없고("Allow rules have no effect in `bypassPermissions`."), 명시한 ask 규칙은 bypass 에서도 물어요("Tools matched by an explicit ask rule" 는 어느 모드도 자동 승인하지 않아요). 모드가 자동 승인하지 않는 동작이 따로 있어요(예: 인식된 `rm`·`rmdir` 중요 경로 삭제 — "no allow rule or `PreToolUse` hook \"allow\" approves").
- PreToolUse 훅: 문서에는 "훅이 bypass 에서도 돈다"를 한 문장으로 말한 곳이 없어요(`not stated`). 이어지는 문장들이 그것을 함축해요: 훅이 받는 `permission_mode` 값에 `bypassPermissions` 가 들어 있고, "A hook that exits with code 2 stops the tool call before permission rules are evaluated, so the block applies even when an allow rule would otherwise let the call proceed."(permissions), "PreToolUse hook decisions don't bypass permission rules."(permissions). 훅이 시간 초과하면 `onFailure: "block"` 이 없는 한 막지 않고 "the call continues through the normal permission flow"(hooks). 그래서 이 SPEC 은 "훅이 bypass 에서도 막는다"를 문서로 함축된 것이지 관측한 것이 아니라고 적어요.
- 보호 경로: bypass 는 보호 경로 확인을 건너뛰어요("`bypassPermissions` mode disables permission prompts and safety checks … including writes to protected paths", `.git`·`.claude` 포함). 그러므로 bypass 세션에서 `.git` 과 `.claude` 쓰기를 막는 것은 확인 창이 아니라 deny 규칙과 PreToolUse 훅뿐이에요.
- 샌드박스는 권한 모드가 아니라서 설정이 그대로 적용돼요(`deniedDomains` 는 모든 모드에서 거절). 다만 bypass 에서는 허용 목록 밖 호스트가 허용되고 샌드박스 밖 재시도가 묻지 않고 돌아요(`allowUnsandboxedCommands: false` 로 막아요). 샌드박스가 꺼져 있는 것이 기본이에요.
- `permissions.blockWritesOutsideWorkingDirectories`·`blockReadsOutsideWorkingDirectories` 는 bypass 에서도 작업 폴더 밖 경로를 거절해요(v2.1.314 이상). 관리자는 `permissions.disableBypassPermissionsMode: "disable"` 로 bypass 를 막을 수 있어요. 프로젝트·로컬 설정의 `defaultMode: bypassPermissions` 는 효과가 없어요. 루트나 sudo 로는 시작하지 않아요.
- 읽지 못한 것(`unverified`): permission-modes 의 뒷부분 약 22k자, hooks 의 뒷부분 약 94k자, sandboxing 의 뒷부분 약 12k자, settings-reference 의 `disableBypassPermissionsMode` 항목, `allowManagedHooksOnly`·`disableAllHooks` 와 bypass 의 관계. 또 이 저장소의 실제 훅(`moai claim-verify . --hook` 의 PreToolUse·Bash, `moai hook-dispatch --host claude --event tool-preflight` 의 위험 Bash·`.git` 쓰기 차단, `docs/hooks-generation.md` §3)이 bypass 세션에서 막는지는 실제 호스트로 관측하지 않았어요(`not_run`, 이 SPEC 은 실제 호스트 시작을 쓰지 않아요).

읽어서 확인한 사실(코드, 2026-11-24, 브랜치 기준 NeXT `efb3a80ae9`):

- `-l`/`-a` 가 하는 일은 셋뿐이에요: 세션 이름(`-l` → `leader`, `-a` → 프로젝트의 다음 `agent-N`, `src/main.rs` 의 `launch`), 저장된 모델 고르기(`session::apply_saved_choice` 가 `launcher.models.<host>.<leader|agent>` 를 읽어요, 역할 없는 세션은 읽지 않아요), 안내 한 줄(`session::role_entry_note`). 권한은 이미 역할과 상관없어요: `launcher.role_access`(`auto|full|prompt`)는 역할이 있든 없든 모든 실행에 같아요(`session::launch_access`, SPEC-20261123-launcher-auto-mode).
- `agent-N` 번호는 런처가 `take_agent_number` 로 잡고 `.live` 잠금으로 살아 있음을 알려요. `lane_registry::live_agent_numbers` 가 같은 폴더(`session::agent_seq_dir`)를 읽고, `session-register` 가 이름 충돌을 막는 쪽이에요. `--name` 만 준 세션도 `<name>.live` 잠금을 잡아요(SPEC-20261120-launcher-liveness REQ-4).
- 상태 줄(`src/statusline/**`)은 `-l|-a` 를 말하지 않아요. 역할은 `session-register --mode` 가 세션 안에서 적고 상태 줄이 읽어요(`lane_registry::mode_of`).
- RC1(`2026.11.0-rc.1`)은 게시 전이에요(`docs/release-notes/2026.11.0-rc.1.md`: 초안, `release blocked`). 경고를 받을 바깥 사용자가 없고, 쓰는 사람은 운영자 한 명이에요.

## Non-goals

- 역할을 세션 안에서 들어가는 길(`/moai work`, `/moai leader`)과 `session-register --mode` 는 바꾸지 않아요.
- 레인 배차 줄을 만드는 `src/lane_loop.rs`, `src/lane_duty.rs`, `src/leader_round.rs` 와 그 시험(`/loop 5m /moai --mode-agent 레인 …`)은 이번 조각들에서 고치지 않아요. 새 카드는 열지 않고, 이 카드의 마지막 조각이 그 파일을 쥔 카드가 놓은 뒤에 고쳐요(D-5).
- 커밋 메시지 규칙 말고는 `CLAUDE.md` 의 "Language" 절 내용(SPEC·카드·결정 글, 채팅·보고서 언어, 레인 지시 언어)을 바꾸지 않아요. 이미 올린 커밋과 이 SPEC 의 이전 커밋 메시지는 다시 쓰지 않아요.
- 옛 `moai session --role` 명령은 그대로예요(REQ-00F-06, 기록된 답 `tests/fixtures/protocol/v1/current/18-session-dry-run.json`).
- `install/moai-switch.sh` 와 `src/shim_check.rs` 의 `-l|-a|--leader|--agent` 줄은 그대로 둬요: 그 낱말도 Rust 로 가야 거절 문장이 보여요. 사용자 HOME 의 shim 은 이 카드가 건드리지 않아요.
- 과거 기록(결정 기록 `docs/decisions-2026-11-08.md`, 닫힌 SPEC, `docs/design-review/**`, `docs/session-hub-research-2026-11-08.md`, `docs/release-notes/**`)은 고치지 않아요. 결정 기록에는 승인 뒤 리더가 한 줄을 더해요.
- `launcher.role_access` 의 이름과 값은 바꾸지 않아요(D-3).
- 실제 HOME, 실제 호스트 시작, 네트워크는 쓰지 않아요.

## Requirements

- REQ-1: IF a launch is given `-l`, `--leader`, `-a` or `--agent`, THEN the launcher shall refuse it with one message that names `--name`, `/moai work` and `/moai leader` and start no host, take no number or lock and write no file.
- REQ-2: The launcher help and usage shall name no role flag as a launcher option.
- REQ-3: The launcher shall name a session as `--name` gives, hold its `.live` lock as before and add no name and no `agent-N` number when `--name` is absent.
- REQ-4: The launcher shall fill the model and effort it was not given from the saved entry of its host under `launcher.models`, and from the defaults of a session without a role when no entry exists.
- REQ-5: IF the saved settings hold a role entry under `launcher.models`, THEN the launcher shall start without reading that entry and add one note that names the key paths and `moai update`.
- REQ-6: The `moai update` model pick shall ask one model and effort per host, save it under `launcher.models` and list a saved role entry among the keys that its write replaces.
- REQ-7: The launcher notes and help shall say that `launcher.role_access` sets the permission mode of every launch and which default each host gets.
- REQ-8: The start-up instructions of the repository shall name `moai cc` or `moai glm` with an optional `--name` and the entry commands `/moai work` and `/moai leader` and tell nobody to use `-l` or `-a`.
- REQ-9: The `CLAUDE.md` section "Scope and sessions" shall say that `-l|-a` are retired and that a session types `/moai work` for a lane and `/moai leader` for the coordination window.
- REQ-10: The rule provenance file shall list the `CLAUDE.md` sentences that this change replaces.
- REQ-11: The launcher help and notes and the start-up instructions of the repository shall name no `mode-leader` or `mode-agent` spelling.
- REQ-12: The language rules of the repository and of the moai skill shall say that commit messages follow the profile's `language.commit_messages`, which is `en` in this repository.
- REQ-13: IF a launch gives neither `--permissions` nor a valid `launcher.role_access`, THEN the launcher shall start `cc` with `--permission-mode auto` and `glm` with `--dangerously-skip-permissions`.
- REQ-14: The permission documents of the repository shall name the permission default of each host and say what bypass mode keeps and drops, quoting the official page.
