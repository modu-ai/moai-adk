What this decides:

- `/clear` is documented by both hosts under that name, so one line serves both; a new chat in Codex is a new thread (source), and in Claude Code the session id is not documented either way, which is why a lane's reservation must not depend on the session id after a clear (a separate card's work).
- Claude Code takes the next step as the argument of `/compact`; Codex `/compact` takes none and does not run during a running turn, so the next step is a second line sent after the compaction, only when the lane is idle.
- Only Claude Code has a documented program-readable percentage (the status line). For Codex the round has no documented value; the lane itself prints `LANE-COMPACT` when its footer shows the limit, and the observer may fill `context_used_pct` from the footer text when it can read it.
