# Research: Bash worktree session-anchor mechanism and cross-lane misresolution (moai-adk-go, t1337 / t1339)

**Coverage gap (explicit):** the `anchor-mechanism` lens — the lens that would have directly inspected how the per-session Bash isolation anchor is stored and keyed inside the runtime — returned **nothing**. Its questions are answered here only **indirectly**, via moai's own anchor stores, incident shape-matching, and prior measured precedent. No claim below about the runtime anchor's internal keying is a direct measurement; treat the runtime-keying portion of the task hypothesis as corroborated-by-shape, not proven.

---

## 1. The anchor that emits the Bash rejection is Claude Code runtime state, not a file in this repo

All three lenses converge on this, from three independent repo surfaces:

- `internal/hook/post_tool_failure.go:40-48` states verbatim: the worktree-isolation guard "belongs to the Claude Code runtime, not to this codebase, so this string is an observed dependency on upstream wording rather than a contract we control." The repo only pins the refusal token `const worktreeGuardAnchor = "isolated in the worktree"` (card t529) and classifies refusals as error category `WorktreeGuardRefusal`, pinned anchor-only by `internal/hook/worktree_guard_refusal_test.go` with two documented killed mutants (incident-evidence; prior-SPEC-memory).
- Doctrine repeats it: `.claude/rules/moai/workflow/worktree-integration-ops.md:114` — "if the runtime rewrites that opening clause, detection goes silently to zero" (prior-SPEC-memory).
- No file under `internal/` emits the rejection (incident-evidence).

Consequence: **the "shared anchor file" the t1339 card asks to locate does not exist inside moai-adk-go** as the emitter (incident-evidence). What the repo owns is a family of *adjacent* anchor stores — all of them shared and non-session-namespaced — plus read/classification seams onto the runtime's state.

## 3. How a lane's anchor moves — event-driven, fail-open, riding a platform gap

- Claude Code emits **no `CwdChanged` for `EnterWorktree`/`ExitWorktree`** (t236/#1640), so registry-cwd relocation rides `PostToolUse` (`handleWorktreeMove`) and `CwdChanged` (`relocateSessionCwd`); every error path returns silently ("fail-open by construction"); a hook timeout silently skips relocation; a payload carrying another tree's cwd relocates the entry with no error and no audit trail (constraints-risks).
- SPEC-WORKTREE-REAPER-001 §B.3 measured this exact staleness: the git lock named 5/5 live anchors, the registry named **1 of 5** — "a session entering a tree via `EnterWorktree` keeps its launch-time CWD until the `CwdChanged` hook calls `RelocateSession`, and that relocation is not happening for 4 of 5 lanes" (prior-SPEC-memory).
- A wrong-tree cwd arriving in one hook event followed by a correct one later matches t1339's "misresolved for several minutes, then reverted" shape — but moai retains **no log of relocations**, so this is shape-match, not reproduction (constraints-risks).

## 4. Incident t1337 — a parent's `EnterWorktree` move poisoned a live subagent's anchor

Timeline: ~15 Bash + many Edits/Writes succeeded in t1337 → two `pre_tool.go` Edits succeeded → the next test-file Write was rejected citing t1315 → thereafter **all** Bash (including non-git `pwd`/`grep`), Write, and Edit were rejected, persisting without restart. Corroborated by the lead report (`/Users/goos/MoAI/moai-adk-go/.moai/reports/lead/autonomy-report-inputs-20260929.md` row 2) and 13 fail-open rows for t1337 in `.moai/logs/subagent-write-guard.log` 07:25–07:56Z.

## 6. Why no wrong-tree execution occurred — the cwd-match seam (ownership disputed, see contradictions)

- The repo-side seam: `resolveProjectRootFromInputOrEnv` (`internal/hook/path_resolve.go:98-103`; input.CWD → `CLAUDE_PROJECT_DIR` → `os.Getwd()`) feeds `checkBranchState` (`internal/hook/branch_guard.go:1052-1064`) as **Seam A** of SPEC-WORKTREE-BRANCH-GUARD-DISCRIM-001: the guard judges the **command's actual cwd**, never the session's claimed project dir; git-context uncertainty fails OPEN with the resolved cwd recorded to `.moai/logs/branch-guard-audit.log` (AP-D-003). DISCRIM-001's measured root cause was exactly this defect family: the pre-fix discriminant preferred `$CLAUDE_PROJECT_DIR` and "answered 'is the primary checkout the primary checkout?' instead of 'is the cwd the agent is about to operate in the primary checkout?'" (prior-SPEC-memory; incident-evidence).
- The counter-claim from the constraints lens: the cwd-mismatch rejection variant seen in t1339 is quoted in moai's test fixture but is **not a moai-enforced guard** — the wrong-tree-write protection "lives in the runtime, outside this repo" (constraints-risks).
- Either way, the observable outcome is agreed: t1337 and t1339 produced denials only; zero wrong-tree writes landed.

## 7. Non-unique keying is a measured defect class across this codebase

- SPEC-SESSION-REGISTRY-READ-ANCHOR-001 Gap G4: "One pid is recorded in two different worktrees under two session ids, so at most one of those recorded working directories is where it actually sits" (prior-SPEC-memory; constraints-risks).
- Live on-disk: pid 41489 under three session_ids in the shared registry, cwd fields disagreeing (constraints-risks).
- t958: inherited `MOAI_SESSION_PID` collapsed two sessions launched from one shell onto a single pid — "every pid-keyed ownership check downstream read them as one owner" (constraints-risks).
- t667: card-id worktree **names** are not ownership-unique — `EnterWorktree("t667")` resumed lane-3's same-named tree; zero writes landed only because the resumed-tree verb was caught before editing (incident-evidence; prior-SPEC-memory).
- Liveness compounds over-attribution: registry anchoring counts a session live on `alive || now.Sub(LastHeartbeat) < stale`, no per-turn heartbeat driver exists, and the Windows pid probe "measures nothing" (constraints-risks).

## 8. Constraints and regression gates on any t1339/P7 fix

1. **R1 landing gate (REQ-RAR-005/006, REQ-RAR-008):** single-sourcing the `LiveAnchoredSessions` read path to the registry is gated on migrating still-live orphan-only entries or a recorded operator decision — un-gated, worktrees flip from "a live session is anchored here → refuse disposal" to "free," which "is what stands between a live lane and the destruction of an unpushed branch's only copy" (constraints-risks).
2. **Relocation ordering is load-bearing** (REQ-RAR-002/003/004): two-pass candidate ordering (upward walk, then primary registry) and fail-open behavior are pinned (constraints-risks).
3. **Seam separation must persist** (DISCRIM-001 Seam A): git-context query at `input.CWD`; audit-log dir stays `$CLAUDE_PROJECT_DIR`-anchored — the two "were a single variable before this SPEC and MUST stay separate."
4. **Mutation-target constraint:** `MOAI_HOME` redirects only the mutation target; `RefuseMutationFromNonCanonicalTree` (t952) must keep refusing worktree-tree callers mutating canonical-root state (constraints-risks).
5. **Upstream wording fragility:** the classification anchor is a pinned string, contract-uncontrolled; an upstream rewording silently zeroes detection (all lenses).
6. **Hook-copy constraint (t1064):** `.claude/hooks/moai/*.sh` resolve through `CLAUDE_PROJECT_DIR` frozen at session start — after mid-session `EnterWorktree` the **primary checkout's hook copy executes**; any anchor-recording instrument added to a worktree-local hook copy is structurally dead, and instrumenting the primary copy means writing state other live sessions execute (constraints-risks; prior-SPEC-memory).
7. **Per-agent anchor registration is doctrine-rejected** (worktree-integration-ops.md §143-156) (prior-SPEC-memory).
8. Repair-route precedent for the t1337 wedge: `feedback_worktree_cd_wedge.md` — `ExitWorktree` (keep) + re-`EnterWorktree` reset the tool's cwd (prior-SPEC-memory).

## 10. Hypothesis verdict

**"A shared, last-writer-wins anchor store keyed by something non-unique (not per-session)" is structurally TRUE for every anchor store moai-adk-go owns** (per-tree single-slot git lock keyed card-id+pid; per-checkout single registry with last-writer-wins `cwd`; path-keyed `worktrees.json`; single-slot `current-session-id.txt`; shared `CLAUDE_ENV_FILE` stamp), and non-unique keying has four independent measured instances (G4, live pid 41489 ×3, t958, t667). **For the runtime Bash anchor — the one that actually emitted both rejections — the hypothesis is corroborated but unproven**: the parent-child sharing is directly measured (t1337 lesson; t281; t741 12/12 re-resolution), the cross-lane rebind shape is observed twice (t707, t1339), and no repo mechanism exists that writes another lane's tree into a session's own anchor (`RelocateSession` matches `session_id` exactly) — so if the runtime anchor is a shared last-writer-wins store, **that store lives outside this repo**, and with the anchor-mechanism lens empty, its byte-level keying is unknown.
