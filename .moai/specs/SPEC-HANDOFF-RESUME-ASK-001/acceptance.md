# SPEC-HANDOFF-RESUME-ASK-001 — Acceptance Criteria

Every machine AC is verifiable without a terminal and without a live session: instruments are Go tests on `t.TempDir()` factory databases, in-memory streams, and assignable seams (the `isInteractiveStdin` / `launcherPromptInteractive` pattern of SPEC-LANE-JOIN-RUN-SELECT-001). The form is a single invocation, one package per command:

```text
go test <one package> -run '^(<TestName1>|<TestName2>)$' -count=1 -v
```

**Swept-count rule.** A Go-test AC passes only when the `-v` output shows one `--- PASS` line per named test; `[no tests to run]`, a PASS count below the named count, or a missing name is a FAIL. The `-run` pattern anchors every alternation branch.

**Two-cell discipline.** Each AC is either (a) RED-now with the ledger entry showing the named tests do not exist on the pre-implementation tree (empty sweep, exit 0 — red for the stated reason that the asserted behavior does not exist yet, and not vacuous because the swept-count rule turns the empty sweep into a FAIL) plus a green-path cell naming the flipping milestone, or (b) explicitly labeled a **regression guard**: green on the pre-implementation tree by design, kept to pin behavior this work must not change, never release-blocking. Behavioral REDs are recorded at each milestone's RED step in `progress.md` §E.2. The three manual ACs (AC-HRA-008 TTY half, AC-HRA-009 measurement half, AC-HRA-014) are measured once in run phase and recorded verbatim; their machine halves are ordinary Go tests.

**Verification command classes.** `go-test` (per-package `-run` invocation), `go-test-budget` (a `-run` invocation whose test asserts elapsed wall time under the budget constant), `grep` (fixed-pattern sweep, exit status is the verdict), `build` (`make build` + `git status --porcelain`), `manual-once` (a human-driven measurement recorded in the report).

## Edge cases

- A pending row that expires between the launcher's read and the operator's resume choice: the claim fails atomically; the launcher starts fresh and reports nothing lost (the claim loser path of AC-HRA-003/009).
- A session whose stored `conversation_language` is empty or non-CJK: every localized surface falls back to en (AC-HRA-002, AC-003's error line, AC-008's catalogue).
- `/clear` on a project whose factory database does not exist yet: the capture creates the store through the existing open-or-create path or fails open — either way session end is never blocked (AC-HRA-007).
- Two sessions ending concurrently with `reason: clear` and no pending row: both captures race on the one-pending unique index; exactly one row survives and the loser fails open (the same CAS discipline as AC-HRA-003's concurrent claim).
- A launcher started with an explicit resume/continue flag (session reuse): the launcher question still fires only when a live pending row exists; the flag changes nothing about the record.
- `capture_on_clear` toggled between save and clear: the toggle is read at session end; a false value skips the capture entirely (matrix cell, AC-HRA-006's reason axis extended by the toggle axis in the same test).
