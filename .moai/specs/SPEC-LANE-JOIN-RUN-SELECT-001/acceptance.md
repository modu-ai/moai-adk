# SPEC-LANE-JOIN-RUN-SELECT-001 — Acceptance Criteria

Every AC is verifiable without a live factory run and without a terminal: instruments are Go tests on `t.TempDir()` factory databases (a scripted spy chooser and in-memory streams stand in for the operator). The form is a single invocation, one package per command:

```text
go test <one package> -run '^(<TestName1>|<TestName2>)$' -count=1 -v
```

The run phase invokes it with the factory environment scrubbed (`MOAI_FACTORY_WORKERS`, `MOAI_FACTORY_WORKER`, `MOAI_FACTORY_ROLE`, `MOAI_FACTORY_CLEAR_POLICY`, `MOAI_FACTORY_AUTO_DISPATCH`, `MOAI_KANBAN`, `MOAI_KANBAN_ID`, `MOAI_KANBAN_LABEL`, `MOAI_KANBAN_LEAD_NAME`, `MOAI_KANBAN_LEAD_ADDR`, `MOAI_KANBAN_SETTINGS_INJECTED` unset — a lane-stamped environment falsifies tests that read `MOAI_KANBAN_ID`, and the join-environment assertions below read it).

**Swept-count rule.** A Go-test AC passes only when the `-v` output shows one `--- PASS` line per named test; `[no tests to run]`, a PASS count below the named count, or a missing name is a FAIL. The `-run` pattern anchors every alternation branch.

**Spy chooser (shared by AC-LJR-003 and AC-LJR-005..007).** A test double of the chooser seam that, on every entry, records three things before returning its scripted choice: the value of `os.Getenv(config.EnvFactoryRunID)`, a snapshot of the `runs` table and a snapshot of the `events` table. "Presentation-entry snapshot" below means those recordings. Each test clears the ambient factory environment with `clearFactoryTestEnv` and then asserts, before entering the gate, that `config.EnvFactoryRunID` (`MOAI_KANBAN_ID`, `internal/config/envkeys.go:195`) is empty, so a leaked value fails the test instead of masking a premature set.

**Two-cell discipline.** Each AC is either (a) RED-now with a named failing command — the ledger entry showing it red on the pre-implementation tree, and why — plus a green-path cell naming the milestone that flips it, or (b) explicitly labeled a **regression guard**: green on the pre-implementation tree by design, kept to pin behavior this work must not change, and never release-blocking. The RED-now evidence for every Go-test AC of kind (a) is the same for a package: the named test does not exist, so the sweep is empty — red for the stated reason that the criterion asserts a behavior that does not exist yet, and not vacuous, because the swept-count rule turns the empty sweep into a FAIL. A behavioral RED (test present, assertion failing against the old code) cannot be observed now because the tests are written in the run phase; manager-develop records it at each milestone's RED step in `progress.md` §E.2.

## Edge cases

- Ambiguity with a named `--leader` and zero verified leaders: the refusal stands and the chooser is not shown (a named target is a decision; AC-LJR-008).
- A chosen `join` whose run vanished or changed status between the read and the choice: the explicit-join error is returned, as for `--factory-run`, with no re-presentation.
- A start time or activity value that does not parse as RFC 3339 renders unchanged and never panics (AC-LJR-002).
- A chooser whose terminal is closed before any input: cancel, not a hang (AC-LJR-004, end of input).
- A run retired by another process before the cleanup call: the behavior of `RetireRunIfDead` on an already-retired run belongs to SPEC-FACTORY-RETIRE-GUARD-001 (its REQ-RRG-003); this SPEC's loop re-reads and omits the run either way, and no criterion here pins the event count for that case.
- A cleanup that succeeds and leaves no active run: the gate returns `NO_ACTIVE_FACTORY`; nothing is joined.
- Cancel after the reconciler or an earlier chooser cleanup: those retirements persist; the cancel path adds nothing (AC-LJR-005, AC-LJR-006).
