## §A 맥락

`spec.md` §A의 실측 대조표가 이 계획의 출발점이다. 배포 실패가 경고로 내려앉는 지점은 `initializer.go:208-212` 한 곳이고, 성공 카드는 `init.go:914`에서 무조건 인쇄된다. 두 지점을 함께 바꾸지 않으면 절반짜리 수정이 된다 — 종료 코드만 바꾸면 사용자는 여전히 "초기화 완료" 카드를 읽고 나서 셸 종료 코드를 확인해야 하고, 카드만 억제하면 자동화는 여전히 초록불을 본다.

## §B 이미 알려진 사항

- `Init()`의 다른 반환 지점들(`create .claude/ structure`, `create CLAUDE.md`, `initialize private MoAI home layout`)은 이미 오류를 그대로 반환한다. 즉 **치명적 경로는 이미 존재**하며, 이 작업은 새 메커니즘을 만드는 것이 아니라 한 부류를 그 경로로 옮기는 것이다.
- `internal/cli/init.go:846-855`가 `executor.Execute` 오류를 `initialization failed: %w`로 감싸 반환하고, cobra가 이를 0이 아닌 종료 코드로 바꾼다. 카드 인쇄(914행)는 그 분기 뒤에 있으므로, 오류가 위로 올라오면 **카드는 자연히 인쇄되지 않는다.**
- 경고 요약 패널(`warnCollector.emitSummary`)은 성공·실패 양쪽에서 종료 시 한 번 방출되도록 이미 설계돼 있다(`init_warnings.go` 머리말). 따라서 REQ-IDE-004는 새 코드가 아니라 **보존 대상**이다.

## §F 마일스톤

되돌리기 어려운 결정부터 앞에 둔다.

### M1 — 실패 표면의 문안과 형태 (가장 바뀔 여지가 큼)

사용자가 읽게 될 오류 메시지를 먼저 정한다. 여기서 정한 문안이 M2·M3의 테스트 단언에 그대로 들어가므로 순서상 맨 앞이다.

- 실패한 템플릿 경로를 지목할 것 (기존 오류 문자열이 이미 `template render "<path>"`를 담고 있으므로 래핑으로 보존 가능).
- 프로젝트 트리가 **불완전**하다는 사실을 명시할 것 — 사용자가 부분 트리를 완성된 것으로 오인하지 않게 한다.
- 다음 행동(재실행, `--force` 재초기화) 안내를 한 줄 덧붙일지 결정. 기존 `already initialized` 힌트 패턴(`init.go:851`)과 같은 형태를 따른다.
- 열린 질문: 실패 시 남은 부분 트리를 사용자에게 어떻게 서술할지. "일부 파일만 배포됨"을 파일 수와 함께 밝힐 것인지, 아니면 사실만 말할 것인지.

### M2 — `Init()` 계약 반전 (initializer 층, RED→GREEN)

- RED: `TestInit_WithDeployerError`를 새 계약으로 뒤집는다 — `Init()`이 오류를 반환하고, 오류 문자열이 템플릿 배포를 지목할 것. 이때 실패를 먼저 관측한다.
- GREEN: `initializer.go:208-212`의 경고 추가를 오류 반환으로 교체. `// Template deployment is non-fatal` 주석은 남기지 말고, 왜 이 부류만 치명적인지 관측 사실로 대체한다(519 파일 손실).
- 나머지 일곱 지점이 변하지 않았음을 회귀 테스트로 고정 — 배포 이외 경고를 내는 경로가 여전히 `Init()` nil 반환을 유지하는지 확인.

### M3 — CLI 층 검증 (init.go)

- `executor.Execute` 오류 경로에서 성공 카드가 인쇄되지 않고 경고 요약은 여전히 방출됨을 CLI 층 테스트로 고정.
- stdout에 경고·오류 텍스트가 없음을 단언.
- `--force` 경로와 `--llm gpt` 경로에서 동일 동작임을 확인.

### M4 — 바이너리 수준 대조 프로브

`spec.md` §A.1 표를 재현하는 실행 가능한 프로브로 마감한다. 템플릿에 `$REPO` 토큰을 주입 → `make build` → `moai init` 실행 → 종료 코드가 0이 아니고 성공 카드 문자열이 부재함을 단언 → 토큰 원복. 양성 대조(무수정 템플릿 → 종료 코드 0, 카드 존재)를 같은 회차에 포함한다.

### M5 — 문서 정합 (기계적, 맨 뒤)

- `initializer.go` 주변 주석 갱신.
- 다른 곳에 "배포 실패는 비치명적"을 주장하는 서술이 있는지 조회하고, 있으면 정정.

## §G 안티패턴

- **일괄 규칙으로 번지기**: "경고 있으면 실패" 규칙을 도입하는 것. `spec.md` §C가 이를 명시적으로 기각한다.
- **대조군 없는 프로브**: 실패 조건만 재고 양성 대조를 생략하면, 종료 코드가 0이 아닌 이유가 내 변경 때문인지 프로브 자체의 고장 때문인지 가릴 수 없다.
- **토큰 주입 원복 누락**: 측정용으로 템플릿을 건드린 뒤 원복하지 않으면 배포본이 오염된다. 매 회차 끝에 `git status --porcelain`로 확인한다.
- **테스트 수정으로 RED 건너뛰기**: `TestInit_WithDeployerError`를 구현과 함께 고치면 계약 반전이 실제로 관측되지 않는다. 테스트를 먼저 뒤집고 실패를 본다.
