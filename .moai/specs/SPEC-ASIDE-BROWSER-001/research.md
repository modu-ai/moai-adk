> Facts below were measured in this worktree during plan-phase authoring and the iteration-2 revision (tree `4bf547bcad7c155b1e91485921569db709ec3ac2`, Aside CLI `1.26.916.1741`). Unmeasured items are listed as such. No clarification marker is open.

## 1. What Aside exposes (observed with `--help`, no browser launched)

- `aside [prompt]` and `aside exec`: browser agent session. `--permission <ask|guard|full-access>`; the help states "`--permission ask` and `--permission guard` are the same (Guard). Omit for Guard." One shipped example in the help is `aside --permission full-access "Install the CLI from the project README"` — the very pattern the policy prohibits.
- `aside repl [code...]`: "Run Playwright-style JavaScript in Aside Browser", 120 s timeout, `page` starts unset (call `openTab(url)` or `getTabs()` first). Options: `--account`, `--host` only. **There is no permission option**, so the session's Guard/full-access setting does not constrain repl code.
- `aside mcp`: MCP server over stdio, tools `exec` (browser agent on logged-in sites, stays off the chat list) and `repl` (Playwright-style JavaScript, 120 s timeout).
- `aside skills install`: "Install the aside-browser skill into your coding agents (Codex, Claude Code, Cursor, OpenCode)" — it edits the operator's agent configuration.
- `aside guide`: exec is recommended for most tasks; repl only when a screenshot or the DOM must be inspected directly (reported in the card; not re-read here).

## 3. Safety analysis behind the requirements

| Surface | What can go wrong | How the SPEC bounds it | Residual risk |
|---------|-------------------|------------------------|---------------|
| `--permission full-access` | Agent session gains broad authority over the operator's machine and accounts | Prohibited in the skill; the checker's closed two-literal allow-list fails any other line containing `full-access` | A model could still emit the flag despite the text; the text and the guard make that visible, they do not prevent it |
| `aside repl` | Arbitrary page JavaScript in the logged-in session, no permission flag | Limit stated: navigation, reading, screenshot; write actions need orchestrator-obtained operator confirmation | Enforcement is discipline, not mechanism |
| Subagent use | A subagent drives the operator's browser | Orchestrator-only (operator verdict): the skill and the e2e-tester definition each say a subagent never invokes Aside; a task that needs it returns a blocker report; each sentence is pinned by a test with a deletion mutant | No hook enforces the boundary; an Aside MCP tool registered by the operator is still visible to subagents, and only the prompt text stands between them and it |
| Auto-install | `aside skills install` rewrites agent configuration | Advise only; no install command near Aside in any template text | None beyond operator error |
| Secrets in outputs | Cookies or tokens copied into reports or memory | Prohibition in the skill, pinned by the checker | Page content the operator asked to read may itself be sensitive; the skill tells the agent to report observations, not raw session data |
| Default exposure | Aside wired for every user | Guard test pins absence in `.mcp.json` and settings templates | None while the guard runs |
| Silent fallback | The operator cannot tell that Aside was skipped | Operator verdict: silence; the run report still names the toolchain actually used | The check is lexical: it proves the text instructs silence and no note, not what a model emits at run time |
| Orchestrator context | Driving the browser step by step grows the orchestrator's context | Verbose output to `e2e/.runs/`, exit code and bounded tail only, screenshots cited by path | A long journey still costs orchestrator turns |

## 4. Alternatives considered

- **Skill in an optional pack**: rejected by the operator (Q2) because every non-core entry is hidden from slim installs while core `moai` and `e2e-tester` would reference it. Core adds the description to every install's listing, which is why the listing cap is measured.
- **Delegated execution by the e2e-tester on an authorized prompt**: rejected by the operator (Q1); the condition lives in prompt text a subagent cannot authenticate.
- **A fallback note in the run report**: rejected by the operator (Q3).
- **MCP-first e2e path**: rejected; `e2e.md` hard rules require CLI-first and no MCP prerequisite, and `aside repl` is the CLI form of the same capability.
- **A new `moai aside` Go command**: rejected; `moai mcp add` already registers the server, and a wrapper would duplicate it.
