## §C. 사전 점검

1. `git rev-parse HEAD` = `6a46c0edb…`, `git branch --show-current` = `WT-ghost-skills-measure` 확인
2. `.moai/reports/t533/` 생성
3. **[HARD] `~/.codex` 하위 기준 스냅숏을 증거 파일로 남긴다** — `codex-entries.before` + `codex-mtimes.before`(AC-CGM-001). **읽기만 한다.** 기준값이 산출물에 없으면 읽기 전용 [HARD] 는 사후 검산이 불가능하다. 파일 하나의 mtime 으로 대신하지 않는다: `--force` 가 **가장 먼저** 만드는 것이 새 백업 파일이라, 백업만 남기고 중단된 쓰기는 `config.toml` mtime 에 나타나지 않는다.
4. **[HARD] `~/.codex` 하위 쓰기 0건 확인** — 라운드 2 수리 중 이 항목이 사라지고 그 자리에 **쓰기**(뮤턴트 `touch`)가 들어갔다. 안전 점검이 안전 위반으로 대체된 것이므로 복원한다. 확인 방법: `stat -f '%Sm' ~/.codex/config.toml` 이 카드 착수 이전 시각이고, `ls ~/.codex/ | grep -c 't533'` 이 `0` 이며(이 셀렉터는 실제로 수를 찍는다), 3번 스냅숏 이후 재측정 diff 가 무출력.
5. **격리 디렉터리에서 셀렉터 판별력 증명** — 뮤턴트는 `~/.codex` 가 **아니라** `mktemp -d` 한 임시 디렉터리에서 돌린다. **가드의 물성을 증명하는 데 실제 사용자 트리를 쓸 이유가 없다**(감사 지적에 따른 대안 채택). 실측으로 성립 확인:

```
D=$(mktemp -d); touch "$D/a" "$D/b"
ls -la "$D" | awk 'NR>1{print $NF}' | sort > before
touch "$D/.mutant"
ls -la "$D" | awk 'NR>1{print $NF}' | sort > after
diff before after     → `2a3 > .mutant`, rc=1   ← 셀렉터가 새 엔트리를 잡는다
rm -rf "$D"
```

   같은 셀렉터가 파일 1개 추가를 잡아내므로, `~/.codex` 에 적용했을 때도 잡는다. 임시 디렉터리는 `mktemp -d` 산출물이라 중단돼도 사용자 트리에 잔재가 남지 않는다.

- **D-2** 부재를 PASS 로 삼는 모든 검사는 **더 느슨한 대조군**을 짝으로 갖는다. 대조군은 검사 대상 절단 **밖**에 있어야 하며, **프로브와 실제로 무언가가 달라야 한다** — 다른 도구, 다른 코퍼스, 또는 다른 수단으로 존재가 이미 증명된 needle. 같은 바이너리·같은 플래그·같은 로케일·같은 파일로 두 번 도는 대조군은 같은 실패를 두 번 겪을 뿐이다(§F.2 의 실사건).
