# SPEC-REVIEW-GATE-REPAIR-001 — 설계: 상태 모델과 판정 표

이 문서는 요구사항을 실현하는 상태 모델을 적는다. 함수 이름과 자료 구조의 세부는 run 단계가 정한다. 여기서는 어떤 상태에서 무엇이 일어나야 하는지만 고정한다.

## 1. 리뷰 키와 영수증 상태

리뷰 키는 영수증의 결합 필드 다섯 개의 조합이다: head, tree_digest, config_digest, command, tool_version(`internal/verify/receipt.go:70-76`). 키가 하나라도 다르면 영수증은 다른 키의 것이다.

영수증 상태는 여섯 가지다.

| 상태 | 정의 |
|---|---|
| absent | 같은 키의 영수증이 없다 |
| stale | 같은 키의 영수증이 있으나 유효기간(24시간)이 지났다 |
| fresh-pass | 같은 키, 유효기간 안, 판정 pass |
| fresh-fail | 같은 키, 유효기간 안, 판정 fail |
| fresh-inconclusive | 같은 키, 유효기간 안, 판정 inconclusive |
| key-mismatch | 결합 필드 중 하나 이상이 다르다 |

## 2. 상태별 행동: 현재와 목표

| 상태 | 진입(프롬프트) 현재 | 진입 목표 | 턴 종료 현재 | 턴 종료 목표 |
|---|---|---|---|---|
| absent, stale, key-mismatch | 허용 | 허용 | 검토 시작 후 허용 | 검토 시작 후 허용 |
| fresh-fail, 전달 기록 없음 | 차단 | 허용, 추가 맥락으로 상세 전달, 전달 기록 | 차단 (stop-hook-active 가 거짓일 때) | 차단. 연속 차단이 C 에 닿으면 허용하고 미검토 상태 표시 |
| fresh-fail, 전달 기록 있음 | 차단 | 허용, 반복 없음 | 동일 | 동일 |
| fresh-pass | 허용 | 허용 | 허용 | 허용 |
| fresh-inconclusive | 허용 | 허용 | 허용(재사용) | 재검토 시작, 간격은 Q4 |
| 스위치 꺼짐 | 검토 없음 | 검토 없음 | 검토 없음 | 검토 없음 |

목표 열의 "검토 시작"은 진행 중 표식을 존중한다. 진행 중 표식이 있으면 새 검토를 시작하지 않는다(기존 메커니즘).

## 3. 데이터 모델: 전달 기록과 연속 차단 카운터

**전달 기록**은 리뷰 키 단위로 하나 있다. 내용은 전달 시각과 키다. 키가 바뀌면 그 기록은 해당하지 않는다. 턴 종료에서 같은 키의 pass 가 기록되면 제거한다.

**연속 차단 카운터**도 리뷰 키 단위다. 턴 종료가 차단할 때마다 1을 더한다. 다음 중 하나가 일어나면 0 으로 돌아간다: 허용, pass 기록, 키 변경. 값이 C 에 닿으면 REQ-RG-004 에 따라 허용하고 미검토 상태를 드러낸다.

두 기록은 영수증 저장과 같은 상태 루트에 둔다. 위치의 세부는 run 단계가 정한다. F1 이 영수증 결합 기준을 바꾸면 이 두 기록의 키도 함께 바뀔 수 있다. 이 SPEC 은 그 변경을 하지 않는다.

## 4. 기준 해석 함수 (M2)

입력은 트리 루트와 설정의 두 값(worktree_base_branch, integration target)이다.

1. **후보 집합.** 각 설정 값의 로컬 ref 와 원격 추적 ref 를 후보로 둔다. 정확한 집합은 plan.md §C 가 정한다.
2. **선택.** 해석되는 후보마다 merge-base(후보, HEAD) 를 구한다. 그중 `rev-list --count <merge-base>..HEAD` 가 가장 작은 것을 고른다. 최근접은 "HEAD 까지 커밋이 가장 적게 남는 공통 조상"이다.
3. **키 불일치.** 두 설정 값이 다른 ref 를 가리키면 REQ-RG-007 의 규칙을 적용한다. 이 규칙은 Q1 이 정한다.
4. **후보 없음.** 어떤 후보도 트리에서 해석되지 않으면 inconclusive 이며, 다른 기준으로 넘어가지 않는다(REQ-RG-008).
5. **출력.** 선택된 ref 의 이름과 merge-base SHA 를 함께 낸다. 영수증이 이름을 싣는 현재 방식과 호환되어야 한다.

이 함수가 세 소비자(턴 종료 게이트, card 범위 리뷰, 감사 도구)의 유일한 원천이다(REQ-RG-005). 소비자마다 따로 계산하는 경로는 남기지 않는다.

## 5. 실행 단위 스위치 (M4)

스위치는 실행 단위에서 값이 하나다. 형태(환경 값 또는 주 체크아웃의 미추적 재정의)는 Q3 가 정한다.

두 층(셸 래퍼와 Go 처리기)은 같은 값의 원천을 읽는다. 원천이 하나이면 "두 독립 읽기가 서로 다른 루트를 읽는" 불일치가 구조적으로 없어진다. 트랙된 per-tree 키는 스위치 권한을 잃는다. 그 키를 남길지 기본값 역할로 줄일지는 Q3 결과를 따른다.

## 6. 판정 표

| 조건 | 결과 | 기록 |
|---|---|---|
| 키 일치, 기준 해석 성공 | 정상 판정 | 기준 ref 이름, merge-base SHA |
| 두 설정 값이 다른 ref | Q1 규칙 | 두 이름 |
| 후보 없음 | inconclusive | 사유 |
| inconclusive 영수증 | 재검토 시작, 간격 Q4 | 시작 시각 |
| 스위치 꺼짐 | 검토 없음 | 스위치 출처 |
| 연속 차단이 C 에 닿음 | 허용, 미검토 표시 | 카운터 값 |

## 7. 관측 가능성

- 미검토 상태는 systemMessage 로 드러난다. REQ-RG-004 의 상한 뒤 메시지가 최소 범위다. 차단 사유 전반의 가시성은 F2 가 확장한다.
- 스위치 출처(환경 값인지 재정의 파일인지)는 검토가 꺼진 이유로 함께 기록한다.
