## §A. User Story

**As a** developer or agent staring at a Navigator graph that has drifted — a capability-map row whose code was just refactored, a design decision whose SPEC anchor moved, a symbol binding whose declaration site renamed —
**I want** the stale doc subtrees auto-drafted into a corrected form and presented for one-click approval,
**so that** I can close the drift in seconds (approve) rather than minutes (open the file, find the section, retype it, re-run the chain) — and so the doc map stays a living document instead of degrading into a stale snapshot.

Today M1 Detect surfaces *that* a change touched bound rows (advisory), and M2 Route surfaces *which* code path owns the follow-up (a work item with an `action` hint). Neither **fixes** the drift — neither produces a corrected doc, neither applies a patch, neither closes the loop. The three predecessor chains (001 regen / 002 audit / 003 enrich) are regenerate-and-replace: they rebuild the whole artifact from scratch, which is expensive, non-incremental, and discards human edits to untouched sections. M3 is the **incremental alternative** — diff-scoped, AI-drafted, idempotent, provenance-attributed, and gated behind a human approval the regenerate-and-replace chains never offered. M3 alone does not force adoption — a drift the engineer chooses to ignore stays ignored (the draft is advisory until approved); but once approved, the corrected subtree lands atomically and the loop closes.

**Falconer framing**: *"한 번 생성되고 다시 갱신되지 않는 문서는 살아있는 게 아니라 출처가 더 좋은 스냅샷이다"* (design report §2 line 207). M3 is the **갱신 인프라** (renewal infrastructure) that converts the Navigator from a snapshot into a living document. Without M3, M1+M2 surface drift but never close it; with M3, each surfaced drift has a concrete path to resolution.

## §B. Scope

### In scope

- An on-demand Fix layer that reads `.moai/project/navigator/work-items.{md,json}` (M2) + `.moai/state/navigator-detect/*.jsonl` (M1) + `.moai/project/navigator/nav-graph.json` (M0) + the live doc surfaces (capability-map / audit-report / capability-symbols / nav-graph subtrees) and produces an AI-drafted incremental regeneration of the stale subtrees.
- **Diff-scope contract**: the Fix layer diffs the current tree against a baseline commit (the CodeWiki `--compare-to <commit>` pattern) and regenerates ONLY the stale subtrees identified by the M2 work-items + M1 detect rows — NOT a full regenerate-and-replace.
- **Split-architecture decision** (defended in design.md §A): the deterministic parts (diff-scope computation, draft-request manifest, apply-on-approval) live in a Go engine at `internal/navigator/fix/`; the AI-draft step is an **orchestrator-mediated `manager-develop` delegation** scoped to the draft-request (NOT a Go-embedded LLM call — moai-adk has no Go-embedded LLM client in the navigator subsystem; the LLM rides Claude Code's subagent runtime).
- **Draft-not-auto-apply safety boundary**: M3 produces a DRAFT (the AI-written regen) at a staging surface (`.moai/project/navigator/fix-drafts/<draft-id>/`), NOT an auto-applied mutation. The draft is presented for 1-click human approval via an orchestrator-mediated `AskUserQuestion` gate. M3 NEVER auto-writes a live doc surface without approval — this is the safety boundary for the most complex milestone.
- **Incremental, not regenerate-and-replace**: the existing three chains (001 regen / 003 enrich / M0 sync) are regenerate-and-replace; M3 is the INCREMENTAL alternative — diff-scoped, AI-drafted, idempotent, provenance-attributed.
- Trigger surface: an on-demand Hidden cobra subcommand `navigator-fix` (sibling of `navigator-sync` / `navigator-route` / `navigator-enrich` / `navigator-tiers`), invoked from the existing `/moai project` surface. **No PostToolUse real-time path in M3** — the decision is defended in plan.md §C.1 (the cadence is wrong: a per-edit draft would flood the engineer; M3 is a batched, on-demand, human-gated operation).
- Fail-open semantics: every error mode (work-items absent / detect state absent / nav-graph absent / baseline-commit unresolvable / parse error / LLM-delegation unavailable) degrades to "no draft produced" + exit 0 + one log line.
- Reuse of M0's `atomicWrite` pattern + `Provenance` model + the M2 work-item `action` field (the fix-strategy hint) + the M1 `changed_path` (the diff-scope seed).
- Template-first distribution: any new distributed config keys ship in `internal/template/templates/` first.
- ≥50% Fix automation-rate success metric, mechanically measurable (design report §9 line 443: "AI 초안이 수정 없이 1-click 승인으로 들어가는 비율").

### Excluded from M3 (full list in §F)

M5 brownfield reverse-extraction (`tessl document --code`), auto-applying a draft without human approval, modifying 002's audit chain / M0's sync layer / M1's detect layer / M2's route layer / M4's tiers layer / the three predecessor Navigator chains, embedding an LLM client in the Go binary, PostToolUse real-time drafting, regenerating the entire doc artifact (full regen is the 001/003/M0 regenerate-and-replace contract — M3 is incremental only). The canonical exclusions live in §F with `### Out of Scope — <topic>` sub-headings.

## §C. Functional Requirements (GEARS)

### §C.1 Trigger + input consumption

#### REQ-NS5-001 (Event-driven — on-demand CLI invocation, no PostToolUse)

**When** the `navigator-fix` Hidden cobra subcommand is invoked (sibling of `navigator-sync` / `navigator-route` / `navigator-enrich` / `navigator-tiers`, wired into the existing `/moai project` surface the same way M2's route step is wired), the Fix layer SHALL consume the latest available inputs, compute the diff-scope against the baseline commit, produce a draft-request manifest at the staging surface, and signal the orchestrator that a draft-request is ready for AI-draft delegation. The Fix layer SHALL NOT register a PostToolUse hook branch, SHALL NOT create a `handle-navigator-fix.sh` wrapper, and SHALL NOT spawn a parallel real-time path — M3 is on-demand, batched, and human-gated only (decision defended in plan.md §C.1: a per-edit draft would flood the engineer with one draft per keystroke; M3's cadence is a deliberate, batched operation the engineer invokes when ready to close drift).

#### REQ-NS5-002 (Ubiquitous — four read-only inputs, consumed latest-available)

The Fix layer SHALL consume exactly four read-only inputs, each tolerated as absent via REQ-NS5-009 fail-open:
- **(a) M2 work-items** (`.moai/project/navigator/work-items.{md,json}`) — the `work_items[]` array; each item carries `source_kind`, `source_entry`, `owner_path`, `action`, `confidence`. M3 consumes `owner_path` (WHERE the stale doc is) + `action` (WHAT fix strategy to apply — the hint that decides whether M3 drafts a SPEC stub, re-links a symbol, or regenerates a capability-map row) + `source_kind` (the fan-in dimension).
- **(b) M1 detect impact record** (`.moai/state/navigator-detect/<session-id>.jsonl`) — the accumulated per-detection rows `{changed_path, changed_at, affected_nodes[], affected_edges[]}`. M3 reads ALL `*.jsonl` files, deduplicating by `changed_path` (the latest `changed_at` wins). The `changed_path` set is the diff-scope seed — the concrete file paths whose bound rows are stale.
- **(c) M0 nav-graph.json** (`.moai/project/navigator/nav-graph.json`) — the graph context for subtree identification: the `nodes[]` + `edges[]` whose `source_path` matches a `changed_path` or an `owner_path` define the stale doc subtrees. M0's `provenance.extract_commit_sha` is ALSO the default baseline commit for the diff-scope (REQ-NS5-003) — the last time the doc map was known-consistent.
- **(d) the live doc surfaces** (`.moai/project/navigator/capability-map.md`, `audit-report.{md,json}`, `capability-symbols.{md,json}`) — READ-ONLY inputs the AI draft regenerates portions of. M3 reads them to produce the draft; it does NOT write them directly (REQ-NS5-008 — the draft lands at the staging surface, and applies only on human approval).

### §C.2 Diff-scope + draft-request (the deterministic core)

#### REQ-NS5-003 (Ubiquitous — diff-scope: compare current tree to baseline commit, identify stale subtrees)

The Fix layer SHALL compute the diff-scope by comparing the current working tree against a baseline commit (the CodeWiki `--compare-to <commit>` pattern). The baseline commit SHALL resolve, in priority order: (1) an explicit `--compare-to <commit>` flag if the user passed one; (2) the `provenance.extract_commit_sha` from the most recent `nav-graph.json` (the last known-consistent doc-map state — M0's own provenance); (3) if `nav-graph.json` is absent or its provenance is empty, `HEAD~1` as a degenerate fallback (one commit of history, logged as a degraded baseline). The diff-scope formula (the **single source of truth** — design.md §C.3 + acceptance.md AC-NS5-003c quote this formula verbatim, never re-derive a divergent one): `diff_scope = (git_diff_paths ∪ M1_changed_paths ∪ M2_owner_paths) ∩ graph_bound_paths`, where `git_diff_paths` = the `git diff --name-only <baseline>..HEAD` output, `M1_changed_paths` = the deduplicated M1 detect `changed_path` set across all session JSONL files, `M2_owner_paths` = the M2 work-item `owner_path` set, and `graph_bound_paths` = the set of paths that appear as a `source_path` on at least one M0 graph edge. This is **UNION semantics**: a path in git-diff alone (graph-bound, not yet surfaced by M1/M2), a path in M1 alone (real-time catch, not yet committed), and a path in M2 alone (owner-bound, not yet detected) each independently seed a stale subtree — the three input sets are OR'd, not AND'd. The `∩ graph_bound_paths` filter is the ONE exclusion: a path NOT graph-bound does NOT seed a subtree regardless of which input set it is in (there is no doc row to fix). A subtree is "stale" iff at least one of its bound source paths is in the union. The Fix layer SHALL NOT regenerate subtrees whose source paths are unchanged since the baseline (the incremental, not regenerate-and-replace, contract). The diff-scope output is a deduplicated, sorted list of `(doc_surface, subtree_id, stale_reason)` triples — the manifest the AI draft consumes.

#### REQ-NS5-004 (Ubiquitous — draft-request artifact: deterministic Go engine output at staging surface)

The Fix layer's Go engine SHALL emit a draft-request artifact at `.moai/project/navigator/fix-drafts/<draft-id>/request.json` where `<draft-id>` is a deterministic hash of the sorted diff-scope + the baseline SHA (NOT a wall-clock-derived id). The `request.json` SHALL carry: a `provenance` block (`fix_commit_sha` = `git rev-parse HEAD`, `baseline_commit_sha` = the resolved baseline, `captured_at` = committer date of `fix_commit_sha` via `git log -1 --format=%cI`, NO wall-clock timestamp), a `diff_scope[]` array (the stale-subtree triples from REQ-NS5-003), a `work_item_refs[]` array (the M2 work-item identifiers — `source_kind` + `owner_path` + `action` — that seeded each stale subtree, preserving M2 provenance), and a `draft_instructions` block (per-subtree strategy hints derived from the M2 `action` field — e.g. "regenerate capability-map row from current code", "re-link @NAV:SYM symbol to renamed declaration", "draft SPEC stub for missing design feature"). The draft-request SHALL be idempotent: two runs on the same HEAD + same baseline + same inputs produce byte-identical `request.json`. The Fix layer SHALL NOT produce the AI draft itself — the `request.json` is the handoff artifact the orchestrator's manager-develop delegation consumes (REQ-NS5-007).

### §C.3 Non-overlap + consumer-only (bridge-not-absorb carries forward)

#### REQ-NS5-005 (Ubiquitous — consumer-only on M0/M1/M2/M4 + mx + predecessors; bridge-not-absorb carries forward)

The Fix layer SHALL treat `internal/navigator/sync/` (M0), `internal/navigator/detect/` + `internal/hook/navigator_detect*.go` (M1), `internal/navigator/route/` (M2), `internal/navigator/tiers/` (M4), `internal/mx/`, and the three predecessor Navigator chains as READ-ONLY inputs. The Fix layer SHALL NOT modify any producer surface. This carries forward the M0 bridge-not-absorb principle (REQ-NS-005, REQ-NS-012), the M1 consumer-only principle (REQ-NS2-005), and the M2 consumer-only principle (REQ-NS4-005) to the M3 read surface: M3 consumes the graph + the detect state + the work-items + the live doc surfaces, never mutating producers. The ONLY write surfaces M3 owns are its staging surface (`.moai/project/navigator/fix-drafts/`) and its advisory log (`.moai/logs/navigator-sync.log`) — until a human approves a draft, at which point the apply step (REQ-NS5-008) writes the approved subtrees to the live doc surface via atomic-rename.

#### REQ-NS5-006 (Ubiquitous — non-overlap with the 3 predecessors + M0/M1/M2/M4)

The Fix layer SHALL NOT write to `.moai/project/navigator/capability-map.md`, `audit-report.{md,json}`, `capability-symbols.{md,json}`, `nav-graph.json`, `tiers.json`, `work-items.{md,json}`, `.moai/project/blueprint/*`, `.moai/decisions/*`, `.moai/project/navigator/symbols/*`, or any `.moai/specs/` SPEC surface — EXCEPT via the apply-on-approval path (REQ-NS5-008 sub-assertion c), which writes ONLY the approved subtrees to the target live doc surface, atomically, after a human approval. The Fix layer SHALL NOT modify the three predecessor Navigator chains' regen / enrich / audit surfaces, M0's sync layer, M1's detect layer, M2's route layer, or M4's tiers layer — carries forward REQ-PN-016 (001), REQ-NA-011 (002), REQ-NT-018/019 (003), M0's REQ-NS-013/015/016, M1's REQ-NS2-008, M2's REQ-NS4-006, and M4's REQ-NS3-016/017/018. The full-regen surfaces (capability-map.md / audit-report / capability-symbols / nav-graph.json) remain owned by their respective chains; M3's apply-on-approval patches ONLY the stale subtrees within them, never replacing the whole file.

### §C.4 AI draft + approval (the human-gated surface)

#### REQ-NS5-007 (Capability gate — AI draft via orchestrator-mediated manager-develop delegation, NOT Go-embedded LLM)

**Where** the AI draft is produced (the step that turns the deterministic `request.json` into a rewritten doc subtree), the draft SHALL be authored by an **orchestrator-mediated `manager-develop` delegation** scoped to the draft-request — the orchestrator spawns `manager-develop` (or a per-spawn `Agent(general-purpose)` with navigator-fix instructions per the archived-agent-rejection migration) with the `request.json` path + the live doc surface paths + the per-subtree strategy hints injected into the spawn prompt. The Go engine at `internal/navigator/fix/` SHALL NOT embed an LLM client, SHALL NOT call an LLM API directly, and SHALL NOT produce the draft text itself — the LLM call rides Claude Code's subagent runtime, not a Go-embedded inference path. This split is the Tier-L architecture decision defended in design.md §A: moai-adk has no Go-embedded LLM client in the navigator subsystem (the LLM is reached only through Claude Code's `Agent()` runtime, which a Go CLI binary cannot invoke), AND CLAUDE.md mandates the orchestrator delegates writes to manager-develop (M3's draft IS a write — a doc rewrite). The Go engine produces the deterministic scope + request; the orchestrator produces the AI draft via delegation; neither layer crosses into the other's authority. A CI guard test SHALL assert the Go engine source (`internal/navigator/fix/*.go` excluding `_test.go`) contains zero LLM-client imports (no `openai` / `anthropic` / `langchain` / `mcp__` references) — mirroring the subagent-boundary grep pattern (C-HRA-008 family) and the M1/M2 non-overlap guards.

#### REQ-NS5-008 (Ubiquitous — draft-not-auto-apply safety boundary; 1-click human approval via AskUserQuestion)

The Fix layer SHALL produce a DRAFT and SHALL NOT auto-apply it. The draft SHALL land at the staging surface `.moai/project/navigator/fix-drafts/<draft-id>/draft/` as a set of patched doc subtrees (one file per stale subtree, in the target doc's format) + a `draft.json` manifest listing each patched subtree with its target live-doc path + a unified-diff preview (`*.patch`). The draft SHALL be presented for 1-click human approval via an orchestrator-mediated `AskUserQuestion` gate offering at minimum: (a) **approve + apply** — apply ALL patched subtrees to their live doc surfaces atomically; (b) **approve selected** — apply a subset (the engineer selects which subtrees to apply); (c) **edit then apply** — open the draft for manual editing before applying; (d) **reject** — discard the draft (the staging surface is ephemeral; a rejected draft leaves no trace on the live doc). The apply step SHALL: (c1) write ONLY the approved subtrees to their target live doc surfaces via atomic-rename (`.tmp` + `os.Rename`, carrying forward M0's `atomicWrite`) — **apply idempotence (DBT-2)**: re-applying the same approved set is safe; the `applied.json` ledger records each applied subtree ID, and a resume after a crash-mid-set skips already-applied subtree IDs (the apply is idempotent within one approval token's lifetime); (c2) record an apply-ledger entry at `.moai/project/navigator/fix-drafts/<draft-id>/applied.json` with the approver, the approval timestamp (git-committer-date, NOT wall-clock), the applied subtree IDs, and the resulting live-doc SHA; (c3) NOT touch any live doc surface that was not in the approved set; (c4) **approval_token model** — on approval, write an `approval.json` token at `fix-drafts/<draft-id>/approval.json` carrying the draft-id, the approval option (a/b/c), the approver, the approval timestamp (git-committer-date), and a token value (a deterministic hash of draft-id + approval option + the `request.json` provenance — NOT a random nonce, so the token is reproducible for the same approval). The `--apply` CLI entry point (plan.md §C.6) is an **orchestrator-internal tool**: a direct shell invocation `moai navigator-fix --apply <draft-id>` MUST be refused unless a valid `approval.json` token for that draft-id is present at the staging dir AND the token's draft-id matches AND the token's provenance matches the current `request.json` provenance. A refusal SHALL exit non-zero with a message naming the missing/invalid token, and SHALL NOT mutate any live doc surface. M3 SHALL NEVER write a live doc surface without a prior human approval — the approval_token (c4) makes this mechanically enforceable (the approval is a real artifact, not just "someone typed a command"), and this is the one structural advantage M3 holds over the regenerate-and-replace chains (which apply without asking).

#### REQ-NS5-013 (Capability gate — draft scope-conformance validation: each draft subtree MUST be ∈ diff_scope[] before gate/apply)

**Where** the AI-drafted subtrees are presented for approval or applied, the orchestrator (or `internal/navigator/fix/apply.go`) SHALL validate that every subtree ID in the draft is a member of the `diff_scope[]` recorded in `request.json` (REQ-NS5-003). If the draft contains a subtree NOT in `diff_scope[]` (manager-develop over-produced — drafted an extra subtree outside the stale set), the validation SHALL: (a) refuse to present the extra subtree in the approval gate (the gate preview shows ONLY `diff_scope[]`-conformant subtrees); (b) refuse to apply the extra subtree if it reaches the apply step; (c) emit a warning naming the extra subtree ID + the `diff_scope[]` it is not in, logged to `.moai/logs/navigator-sync.log`. This makes REQ-NS5-003's "SHALL NOT regenerate subtrees whose source paths are unchanged" mechanically enforceable — the validation runs before the gate AND before the apply, so an over-producing draft cannot reach the live doc surface even if the engineer approves without reading every diff. The prior draft relied on a spawn-prompt instruction + a source-code grep (AC-NS5-006) that catches forbidden write-target literals in the Go engine, NOT the draft output content; REQ-NS5-013 closes that gap by validating the draft output against `diff_scope[]` at runtime. A CI guard test SHALL assert the validation fires on a fixture draft containing one in-scope + one out-of-scope subtree (the out-of-scope subtree is excluded from the gate + apply; the in-scope subtree proceeds normally).

### §C.5 Fail-open + verification

#### REQ-NS5-009 (Event-driven — fail-open on every error mode)

**When** the Fix layer encounters any failure — `work-items.json` absent (M2 not yet run), `nav-graph.json` absent (M0 not yet run), the detect state directory absent or empty (M1 not yet run or no edits), the baseline commit unresolvable (no `--compare-to`, no `nav-graph.json` provenance, AND `HEAD~1` fails on a shallow clone), any input unparseable as JSON, any input schema-invalid, an empty diff-scope (the baseline-to-HEAD diff + the M1/M2 sets yield zero stale subtrees — the doc map is already consistent), OR the orchestrator-mediated AI-draft delegation unavailable (the `navigator-fix` CLI ran outside a Claude Code session, so no `Agent()` runtime exists) — the Fix layer SHALL degrade silently to "no draft produced": write NO staging artifact (or write an empty draft-request with `diff_scope: []` if the CLI completed but found nothing stale), return exit code 0, surface NO user-facing error, and append a single diagnostic line to `.moai/logs/navigator-sync.log`. The Fix layer SHALL NEVER abort the calling `/moai project` step, SHALL NEVER emit exit 2, and SHALL NEVER cascade a failure into sibling project steps. A partial input set (e.g. work-items present + detect absent) SHALL produce a draft from the available inputs only, scoped to the M2 work-items' owner_paths, not fail the whole run. An empty diff-scope is NOT an error — it is the success case where the doc map is already consistent, and the CLI SHALL exit 0 with a one-line "0 stale subtrees, doc map consistent" message.

#### REQ-NS5-010 (Capability gate — ≥50% Fix automation rate, mechanically measured)

**Where** the ≥50% Fix automation-rate success metric is evaluated (design report §9 line 443: "AI 초안이 수정 없이 1-click 승인으로 들어가는 비율"), the automation rate SHALL be produced by the mechanical measurement procedure named in acceptance.md §D.AC-NS5-010 (a fixture corpus of stale-subtree scenarios + the draft→approval simulation emitting the ratio of drafts approved unmodified (option (a) approve + apply, no edit) / total drafts produced). The automation rate SHALL NOT be a narrative claim, a sampled estimate, or a carried-over number — every automation assertion MUST be attributable to a run command + observed output (per `verification-claim-integrity.md` §1.1 surface 3 + §2 attribution). "Approved unmodified" is defined as: the draft was applied via option (a) WITHOUT a prior edit (option (c)); drafts that went through option (b) subset-selection or option (c) edit count toward the denominator (total drafts) but not the numerator (unmodified approvals), honestly reflecting that the AI draft needed human adjustment.

#### REQ-NS5-011 (Capability gate — Hidden cobra subcommand, sibling pattern)

**Where** the Fix layer plugs into the CLI surface, it SHALL register as a Hidden cobra subcommand named `navigator-fix` — mirroring the `navigator-sync` Hidden subcommand (M0, `internal/cli/navigator_sync.go:22-32`), the `navigator-route` Hidden subcommand (M2, `internal/cli/navigator_route.go`), the `navigator-enrich` Hidden subcommand (003, `internal/cli/navigator_enrich.go:31`), and the `navigator-tiers` Hidden subcommand (M4, `internal/cli/navigator_tiers.go:35-41`). The Fix layer SHALL NOT introduce a new top-level `moai` subcommand, SHALL NOT create a new wrapper script, and SHALL be invoked from the existing `/moai project` surface as a sibling step. A CI guard test SHALL assert `navigator-fix` is Hidden (mirroring `internal/cli/navigator_tiers_test.go:65-70` which asserts the same for `navigator-tiers`).

#### REQ-NS5-012 (Capability gate — template-first distribution)

**Where** the Fix layer ships any new distributed surface — a new `settings.json` config key, a new hook block, or any artifact under `.claude/` — the template source at `internal/template/templates/.claude/` SHALL carry the change first, `make build` SHALL regenerate the embedded catalog (`catalog.yaml`), and the local copy SHALL mirror — per CLAUDE.local.md §2 [HARD] Template-First Rule + §25 Template Internal-Content Isolation. The run-phase touch list (template paths + mirror paths) is named in plan.md §D so compliance is planned, not discovered late. If the Fix layer ships NO distributed surface (env-var-only gate or pure CLI — the expected case, since the AI-draft step rides the orchestrator's `Agent()` runtime, not a distributed config), this REQ reduces to "no template path in the diff, no catalog regen required" — documented in the PR body.

## §D. Constraints (Non-Functional)

- **Performance budget**: the Fix layer's deterministic Go engine (diff-scope + draft-request) runs inside the existing `/moai project` timeout envelope. The diff-scope computation SHALL complete in < 1s p99 for a baseline-to-HEAD diff of up to 500 changed files + a work-item set of up to 200 items + a detect state of up to 500 rows (the current repo's scale is O(tens); the budget headroom is for fan-out). The AI-draft delegation (the orchestrator-spawned manager-develop step) is NOT bound by this budget — it runs in the orchestrator's turn envelope, not the CLI's. The apply-on-approval step SHALL complete in < 500ms p99 (atomic-rename of the approved subtrees).
- **Read-only invariant (pre-approval)**: the Fix layer's only write surfaces BEFORE a human approval are `.moai/project/navigator/fix-drafts/` (the staging surface: request.json + draft/ + applied.json) and `.moai/logs/navigator-sync.log` (advisory diagnostic). No live doc surface mutation occurs without approval (REQ-NS5-008).
- **Idempotence / determinism**: for the same input set (work-items + detect state + nav-graph at the same HEAD) + the same baseline commit + the same Fix layer code, the Go engine SHALL produce the same `request.json` byte-for-byte (sorted diff-scope, no wall-clock, provenance-attributed per REQ-NS5-004). Re-running `navigator-fix` on unchanged inputs with no new detections is a no-op write (the draft-id is deterministic; the staging artifacts are byte-identical).
- **Split-architecture boundary**: REQ-NS5-007 is the load-binding contract. The Go engine SHALL NOT embed an LLM client; the orchestrator SHALL NOT bypass the Go engine's draft-request (the orchestrator consumes `request.json`, never re-derives the diff-scope). The two layers are separable — the Go engine is testable without an LLM, and the AI-draft delegation is testable against a fixture `request.json`.
- **Incremental, not regenerate-and-replace**: REQ-NS5-003 + REQ-NS5-006 together forbid M3 from regenerating a whole doc artifact. M3 patches ONLY the stale subtrees. Full regen remains the 001/003/M0 contract; M3 is the incremental complement, not a replacement.
- **Provenance alignment** (`verification-claim-integrity.md`): every automation-rate / diff-scope-coverage claim in an AC is attributable to a mechanical command + observed output. The `request.json` + `applied.json` artifacts are the Evidence; the automation claim is the Claim.
- **Language neutrality**: the Fix layer's diff-scope is language-neutral (operates on `git diff --name-only` + graph edges, not source ASTs); it inherits the language coverage of the M0 graph + the M1 detect + the M2 work-items without re-detecting language markers. The AI-draft step inherits whatever language coverage manager-develop provides.
- **Fail-open**: REQ-NS5-009 binds every error mode to exit 0 + empty/log, never abort.

## §E. Verification Surface

- **Automation-rate AC**: acceptance.md §D.AC-NS5-010 names the exact fixture-corpus directory, the draft→approval simulation command, and the ratio formula. The percentage is the observed output of that command, not a narrative.
- **Fail-open ACs**: one AC per error mode (work-items absent / detect absent / nav-graph absent / baseline unresolvable / unparseable JSON / schema-invalid / empty diff-scope / no-LLM-runtime) — each Given-When-Then, each asserting exit 0 + no staging artifact (or empty diff-scope) + a log line.
- **Split-architecture AC**: a grep-based test asserting the Go engine source contains zero LLM-client imports (carries forward the C-HRA-008 subagent-boundary pattern + the M1/M2 non-overlap guards).
- **Draft-not-auto-apply AC**: a test asserting no live doc surface is mutated by the `navigator-fix` CLI run alone — mutation occurs ONLY after the orchestrator's apply-on-approval path fires (verified by checking the live-doc SHA before and after the CLI run; unchanged = PASS).
- **Approval-token AC**: a test asserting `moai navigator-fix --apply <draft-id>` without a valid `approval.json` token at the staging dir refuses (exit non-zero, no live-doc mutation) — making REQ-NS5-008 sub-clause (c4) mechanically enforceable.
- **Scope-conformance AC**: a test asserting each draft subtree ID ∈ `diff_scope[]` — an over-produced subtree (drafted by manager-develop outside the stale set) is excluded from BOTH the gate preview AND the apply (REQ-NS5-013).
- **Non-overlap AC**: a grep-based test asserting the Fix source files do not name forbidden write surfaces as direct targets (carries forward M0's `nonoverlap_test.go` + M1's `navigator_detect_nonoverlap_test.go` + M2's route non-overlap test pattern).
- **Idempotence AC**: two consecutive `navigator-fix` runs on the same inputs + same baseline produce byte-identical `request.json` (provenance included — same HEAD, same `fix_commit_sha`, same `captured_at`).
- **Incremental AC**: a test asserting the diff-scope for a fixture where only 2 of 10 subtrees are stale yields exactly 2 patched drafts, NOT 10 (the incremental-not-regenerate-and-replace contract).
- **Hidden-subcommand AC**: a test asserting `navigator-fix` is Hidden, mirroring `navigator_tiers_test.go:65-70`.

## §F. Out of Scope

### Out of Scope — M5 brownfield reverse-extraction

- Reverse-extracting design docs from existing code (M5, design report §6 line 383-387, the `tessl document --code` pattern). M3 regenerates EXISTING doc subtrees that have drifted; it does not extract NEW design docs from code that has no doc. M5 is a separate milestone with its own SPEC.

### Out of Scope — auto-applying a draft without human approval

- Writing a corrected doc subtree directly to a live doc surface without the REQ-NS5-008 approval gate. M3's entire safety value proposition is that it asks before applying. An auto-apply mode (e.g. a `--yes` flag that skips the AskUserQuestion gate) is explicitly out of scope for M3 — it would collapse M3 into a regenerate-and-replace variant with none of the safety. If a future auto-apply mode is desired, it is a follow-up SPEC that MUST defend why the safety boundary is droppable in that context.

### Out of Scope — embedding an LLM client in the Go binary

- Adding an LLM client (OpenAI / Anthropic / a local model) to the `moai` Go binary so the `navigator-fix` CLI can produce the AI draft itself, without orchestrator mediation. REQ-NS5-007 forbids this: the LLM rides Claude Code's subagent runtime, not a Go-embedded inference path. A Go-embedded LLM client would (a) duplicate the model-config surface that `llm.yaml` + Claude Code already own, (b) bypass the orchestrator's write-delegation discipline (CLAUDE.md: the orchestrator delegates writes to manager-develop), and (c) introduce a new secret-management surface (API keys in the Go binary's env). Out of scope.

### Out of Scope — PostToolUse real-time drafting

- Registering a PostToolUse hook that drafts a fix in real time on each edit. M3 is on-demand, batched, and human-gated (REQ-NS5-001, decision defended in plan.md §C.1). A real-time draft would (a) usually find no work-items to consume (M2 is on-demand), and (b) flood the engineer with one draft per keystroke — the cadence is wrong for a human-gated, batched operation. M1 already owns the real-time advisory surface; M3 owns the coarser-cadence, human-gated fix surface.

### Out of Scope — full artifact regeneration (regenerate-and-replace)

- Regenerating the entire `capability-map.md` / `audit-report.{md,json}` / `capability-symbols.{md,json}` / `nav-graph.json` from scratch. Full regen is the 001/003/M0 regenerate-and-replace contract (carried forward as the non-overlap boundary REQ-NS5-006). M3 is the INCREMENTAL complement — it patches ONLY the stale subtrees identified by the diff-scope. A future mode that falls back to full regen when the diff-scope exceeds a threshold (e.g. > 50% of subtrees stale) is a follow-up SPEC candidate, NOT an M3 deliverable.

### Out of Scope — M0/M1/M2/M4 + predecessor producer modification

- Modifying `internal/navigator/sync/` (M0), `internal/navigator/detect/` or `internal/hook/navigator_detect*.go` (M1), `internal/navigator/route/` (M2), `internal/navigator/tiers/` (M4), `internal/mx/`, or the three predecessor chains (`internal/navigator/astx/`, `navigator-audit.sh`, `navigator-regen.sh`, `navigator-enrich.sh`). REQ-NS5-005 / REQ-NS5-006 forbid this.

### Out of Scope — external-tracker writes from an approved draft

- Creating a GitHub issue, a Linear ticket, or a SPEC draft FROM an approved M3 draft. M3 applies the approved draft to the live doc surface (`.moai/project/navigator/`); it does NOT write to any external tracker. Tracker integration is a follow-up SPEC that would consume the `applied.json` ledger read-only, the same way M2 consumes audit-report.json read-only.
