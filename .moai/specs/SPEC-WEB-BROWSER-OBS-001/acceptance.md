## §B Given-When-Then 시나리오

### AC-BO-001 — 판별식이 살아 있는 브라우저 관측이다

- **Given** cd99336bf 에서 빌드한 `moai` 바이너리의 `moai web` 서버와, 원격 디버깅 포트를 연 Chrome, 그 서버에 CDP 로 연결된 프로브
- **When** 프로브가 실패 유도 페이로드로 폼을 제출하고 세션을 마친다
- **Then** 판정 기록이 (1) 실패 문구가 `save__msg save__msg--error` + `role="alert"` 슬롯에 도달했는지, (2) 그 슬롯이 보이는 상태인지(표시 계산값 근거), (3) 슬롯의 관측 텍스트가 유도한 seam 의 기대 안정 문구(t1051 §5.1 표 — plan M1.2 가 기록한 값)와 **일치**하는지(안정부 substring 일치 규칙), 그리고 일반 폴백 문구(`Some fields could not be saved`)가 **아니**는지 — 폴백 문구를 전달하는 스왑은 불합격이다 — 를 **브라우저 세션의 관측 출력 전문**으로 담는다. 페이지 소스·`curl` 본문·코드 판독만으로 쓰인 판정은 불합격이다.
- **모순 시** — 슬롯 도달 실패 또는 풀페이지 내비게이션 전달 관측은 REQ-BO-007 의 새 결함 발견으로 기록된다(무분류 FAIL 없음).

### AC-BO-002 — 스왑 vs 내비게이션의 분류가 판별 신호 전문과 함께 기록된다

- **Given** 실패 제출 교환 동안 `Page`/`DOM`/`Runtime` 이벤트 캡처가 활성화돼 있다
- **When** 판정 기록이 전달 양식을 분류한다
- **Then** 분류값(htmx-swap / full-page-navigation / swap-failed-no-nav)과 함께 (a) 메인 프레임 내비게이션 마커(`Page.frameNavigated` 메인 프레임 도달 / 신규 로드 `Page.loadEventFired`)의 유무, (b) 부스트 컨테이너 안 슬롯 DOM 변이의 위치·내용 — **두 판별 신호의 관측 출력 전문**이 기록되고, `location.href` 값이 **기록 전용** 항목으로 함께 남는다(기대 변화: 성공 스왑에서도 pushState 로 action URL 로 바뀜 — plan-audit §4 D1 측정). 판별 신호의 근거 전문 없는 분류 문장, 또는 href 를 내비게이션 증거로 쓰는 분류는 불합격이다.

### AC-BO-003 — 전제가 측정값으로 승격된다

- **Given** 같은 실패·성공 세션의 캡처가 존재한다
- **When** 판정 기록의 대조표를 읽는다
- **Then** (a) 실패 제출 콘솔 에러 수, (b) 성공 제출 콘솔 에러 수, (c) 실패 응답 본문 바이트 수가 각각 **본 run 의 관측값**과 그 근거(캡처 이벤트·명령)로 기록되고, t1051 전제값(2 / 0 / 약 110KB)은 「전제」 칸에 분리 표기된다. 전제값이 측정값 칸에 있으면 불합격이다.

### AC-BO-004 — htmx 비-2xx 부수 기록이 존재한다

- **Given** 같은 브라우저 세션에서 검증 거부 제출을 시도했다
- **When** 판정 기록의 부수 절을 읽는다
- **Then** 4xx 응답에 대한 스왑 여부·이벤트 발화의 관측 **또는** 「본 세션에서 관측 불가」와 그 이유가 기록된다. 어느 쪽이든 합격이고, 절 자체의 부재는 불합격이다. 이 기록은 판정(결함 present/absent)을 쓰지 않는다 — 결정적 관측이면 리드 라우팅 메모 한 줄까지만(HARD-4).

### AC-BO-005 — 독립성·비소급·운용 코드 무변경

## §C 에지 케이스

1. **htmx 스왑이 비동기로 늦는 경우** — 제출 직후 즉시 DOM 질의하면 스왑 완료 전 오타가 난다. 프로브는 고정 drain 대기(t1041 패턴) + 변이 관측 완료 조건으로 잡는다.
2. **세션 환경에서 실패 유도가 불가능한 경우**(예: 권한 구조상 비가록화 불가) — 유도 불가 사실과 시도한 방법을 판정 기록에 기록하고 AC-BO-001은 관측 불가 기록으로 합격 처리하지 **않는다**. 실패 유도는 판별식의 전제다: 유도 불가는 판정 이연 기록이며, run 을 조기 종료로 닫지 않는다 — 대안 유로 방법(예: 다른 seam 표적)을 1회 재설계한 뒤에도 불가하면 blocker 보고로 운영자 판정을 요청한다.
3. **검증 거부 세션이 4xx 대신 다른 상태를 낼 경우** — 그 관측 자체가 REQ-BO-004 의 기록 대상이다(상태 코드 관측값을 그대로 남긴다). 예상 상태와 다르다고 세션을 폐기하지 않는다.
4. **콘솔 에러가 프로브 자신의 스크립트 오류인 경우** — 콘솔 에러 집계는 프로브 주입 코드 기인(`User Script Source` 계열 출처)과 페이지 기인을 구분한다. 구분 없는 집계는 AC-BO-003 을 오답으로 만든다.
