### B-1. `CLAUDE.md` 템플릿↔라이브 의미 분기 — **보존**, 이 카드는 해소하지 않는다

두 사본은 의미 수준에서 다르다. 라이브 루트 §15 는 "CG Mode (`moai cg`, requires tmux)" 를 살아 있는 기능으로, 템플릿 §15 는 "`moai cg` is retired. Run `moai migrate cg`" 로 서술하며 §10 의 GLM 라우팅 문장도 같은 축이다.

**어느 쪽이 낡았는지는 실측으로 확정됐다**(2026-09-25, 이 트리):

```
$ moai cg --help
moai cg is retired; run moai migrate cg to preview an explicit teammate-role migration
$ moai migrate cg --help
  Preview migration of legacy CG teammate roles
```

따라서 **템플릿 사본이 옳고 라이브 루트 사본이 낡았다.** 은퇴한 기능을 살아 있다고 서술하고 있다.

판정: **보존한다.** 낡음은 적재 바이트 수를 전혀 건드리지 않아 지시문 예산 다이어트와 직교하는 축이고, 내용 정정을 같은 diff 에 접으면 커밋 하나가 질문 둘에 답하게 되어 감사가 둘 다를 판정해야 한다. 별도 카드로 제기된다.

귀결: AC-ALD2-003 의 미러 판정에서 `CLAUDE.md` 를 제외한다. **이 제외는 범위 결정이지 두 사본이 일치한다는 주장이 아니다.** 두 사본은 각각 독립적으로 감축되고 각각 구속 조항 동결을 지킨다.

**[개정 — 리드 판정] 미러 판정의 술어가 `diff` 0 이 아니다.** `diff` 0 은 템플릿 중립성(`CLAUDE.local.md §2.1`, 카탈로그 `.moai/docs/template-internal-isolation-doctrine.md §25.1` C1-C8)과 동시에 성립할 수 없어 어떤 실행으로도 만족 불가였다 — 기준선 ref `172ef22eb` 에서 이미 30쌍 중 11쌍이 그 사유로 분기해 있었다. 현행 술어는 **"이 카드가 만든 구조 변경 중 미미러 0건"** 이며, 분기 hunk 를 열거된 16개 허용 클래스에 대고 분류해 판정한다(`acceptance.md §AC-ALD2-003.1`~`.4`). 따라서 M7 의 작업은 "두 사본을 같게 만들기"가 아니라 **"이 카드가 만든 구조 변경을 빠짐없이 미러하고, 남는 분기는 전부 허용 클래스로 설명되게 두기"** 다.

대조 판단을 나란히 둔다 — `skill-routing.md` 의 미러 결함은 범위 **안**이다. 그것은 always-loaded 배포를 직접 일으켜 이 카드의 주제 자체이기 때문이다. 두 결함의 취급이 다른 것은 일관성 없음이 아니라 이 판별식의 적용이다. (`spec.md §D`)

M2 의 `CLAUDE.md` 작업은 이제 막히지 않는다.

### B-2. 중복 제거와 구속 조항 동결의 경계 — 기본 입장 유지, **요구사항으로 승격**

`design.md §2` 의 M1′(중복 제거)은 "정본이 path-scoped 룰에 이미 있는 문단을 지우고 가리킨다"이다. 지우려는 문단이 구속 조항 줄을 담으면 AC-ALD2-002 해시가 깨진다.

판정: SPEC 이 채택한 입장을 그대로 유지하되 마커에서 **REQ-ALD2-013 으로 승격**한다 — always-loaded 사본의 의무는 같은 의무가 path-scoped 룰에 있다는 이유로 지우지 않는다. 그 룰이 로드되지 않는 턴에는 의무가 사라지므로, **중복 제거로 위장한 REQ-AMC-002 강등**이다. 중복 제거는 비구속 산문에만 적용된다.

이 위험을 감수할 예산 압력도 없다 — 종전 근거는 `design.md §3.3` 투영의 net 여유 11,238자였으나, 그 여유는 폐기된 목표 150,000 에 대고 뺀 값이라 더 이상 정의되지 않는다(`acceptance.md §AC-ALD2-001` 개정 표시). 현행 근거는 방향이다: 구속 조항을 지우면 AC-ALD2-002 해시가 깨져 **즉시 FAIL** 이고, 지우지 않아 생기는 부족분은 AC-ALD2-001 의 문턱 미달로 **기록될 뿐**이다. 비대칭이 명확하므로 압력이 성립하지 않는다. `CLAUDE.md` 의 구속 조항 줄은 4개뿐(실측)이라 실무 충돌 여지도 작다.

측정으로 이미 해소된 항목:

- `AGENTS.md` 는 **템플릿 미러가 없다**(`internal/template/templates/AGENTS.md` 부재, 실측). 저장소 로컬 파일이므로 REQ-ALD2-007 이 적용되지 않는다.
- `CLAUDE.md` 는 템플릿 미러가 **있다**(19,553자, 라이브 19,305자).

## §C. 마일스톤

되돌리기 어려운 순. M1 → M2 는 판단이 무겁고, M5 이후는 기계적이다.

### M1 — 재배치 설계 확정 (우선순위: High · 되돌리기 비쌈)

> **[선행 조건 — iter4 감사 요구]** M1 의 산출물이 **재배치 표 그 자체**이므로, 범위 의존 술어의 수정은 표를 채우기 **전에** 끝나 있어야 한다. 채운 뒤에 술어를 고치면 채워진 행을 전부 다시 걸어야 한다. 이 SPEC 의 v0.5.0 이 그 수정을 이미 담고 있으므로 순서는 충족돼 있으나, run phase 가 이 사실을 잃지 않도록 여기 적는다 — **표를 채우기 전에 `acceptance.md` AC-ALD2-004 의 선택 술어를 읽고 시작한다.**

각 stub 을 열어 **옮길 절을 이름 단위로 확정**하고 `design.md §4` 의 재배치 표를 채운다. 이 단계에서 아직 아무 파일도 고치지 않는다.

절 하나를 표에 올리려면 세 조건을 모두 만족해야 한다:

1. 그 절 안에 `[HARD]` / `MUST` / `MUST NOT` / `shall ` 을 담은 줄이 **한 줄도 없다**.
2. 그 절을 가리키는 교차참조를 역방향 grep 으로 열거했고, stub 포인터로 살아남는지 판정했다.
3. 목적지 companion 의 `paths:` 가 그 절이 필요해지는 작업의 도메인 경로를 이미 담고 있거나, 담도록 고칠 계획이 있다.
4. **목적지가 이동 후 40,000자 미만으로 끝난다**(REQ-ALD2-014). 기존 companion 에 여유가 없으면 신규 companion 을 만든다. 이미 40,000을 넘긴 파일은 목적지로 쓰지 않는다(REQ-ALD2-015). 배정은 `design.md §2.2`.

조건 4 가 뒤늦게 붙은 경위를 남긴다 — 원래 `design.md §2` 는 "새 companion 을 만들지 않는다"였고, 근거는 14개 룰이 전부 companion 을 갖고 있다는 것이었다. 그 근거는 목적지의 **존재**만 논하고 **수용량**을 논하지 않았으며, 파일당 축이 범위에 들어오면서 계획대로 실행하면 이 SPEC 자신의 AC-ALD2-009 를 위반하게 됨이 드러났다. 설계를 고쳤다(`design.md §2` 개정 표시).

조건 1 이 애매한 절은 **옮기지 않는다.** 두 모양이 있다 — (a) 구속 조항이 없지만 구속 조항이 **의존하는** 표·제목·열거인 절, (b) 구속 조항의 **범위를 좁히는** 비구속 문장. (b) 를 지우면 남은 조항이 더 넓게 읽히는데, 결손이 아니라 증가 방향이라 어떤 손실 탐지기도 발화하지 않는다. 이것이 범위 이탈 위험이며 — 구속 줄은 제자리에 바이트 동일로 남아 해시가 **통과하는데** 그 줄이 구속하는 대상이 조용히 바뀐다 — 기계 검사로는 잡히지 않는다. 전문 `acceptance.md §D.3`.

산출: 채워진 `design.md §4` 표. 표는 행마다 **범위 의존** 칸을 갖는다 — 제거되는 절에 **지배받는** stub 내 구속 조항을 열거하고 조항마다 Q1(도달)·Q2(폭)에 답한다. 술어는 **열린 정의**다 — "이 절이 사라지면 이 조항이 구속하는 대상이 달라지는가". 참조·인접·용어 의존은 흔한 경로의 **예시이지 목록이 아니며**, 셋 다 근접성을 요구해 **룰 전체의 적용 범위를 세우는 절** 같은 원거리 지배를 놓친다(iter4 N7 확인 사례). 세 검사를 돌리지 말고 지배 관계를 판단한다.

### M7 — 미러 동등화와 검증 (우선순위: Medium · 기계적)

수정한 모든 룰의 템플릿 사본에 **이 카드가 만든 구조 변경을 빠짐없이 반영하고**, 남는 분기가 전부 열거된 중립성 허용 클래스로 분류되는지 hunk 단위로 확인한다(AC-ALD2-003 — 술어는 `diff` 0 이 아니다, §B-1 개정 표시 참조). 이어서 앵커 스윕(AC-ALD2-005)과 companion 증식 검사(AC-ALD2-008)를 돌린다.

마지막으로 AC-ALD2-001 합계와 AC-ALD2-002 해시를 최종 측정한다. **AC-ALD2-001 의 문턱은 런타임 한도 150,000 이 아니라 구조적 하한 171,695 다** — 도출과 성분별 출처는 `acceptance.md §AC-ALD2-001.1`, 하한이 업고 있는 미측정 Gap(M1 조건 2·3·4)은 `§AC-ALD2-001.3`. 측정값이 문턱을 넘으면 **초과분과 그 귀속을 적어 FAIL 로 보고한다** — 달성분에 문턱을 맞추지 않는다.

검증 범위: `go test ./internal/config/... ./internal/template/...` — 템플릿 사본 변경이 임베드·중립성 검사를 건드린다. **전체 스위트를 로컬에서 돌리지 않는다**(CLAUDE.local.md §4). 전 패키지 판정은 CI 몫.

## §D. 기술적 접근

- 기제는 M1(companion 재배치)·M1′(`CLAUDE.md` 중복 제거)·M2(제자리 압축) 셋이다. **목적지는 수용량으로 고른다** — 여유 있는 기존 companion 우선, 없으면 신규 companion, 이미 40,000자를 넘긴 파일에는 쓰지 않는다(`design.md §2`, 최종 배정은 §4.1). M6.5 에서 신규 companion 2개가 생긴다.
- 구속 조항 줄은 **축자 동결**된다. 재작성도, 재배치도, 재들여쓰기도 하지 않는다.

  **이것은 규율이지 검사가 아니다 — 둘을 구분해 둔다.** AC-ALD2-002 의 해시가 강제하는 것은 이보다 **느슨하다**: 파이프라인의 `sed` 가 들여쓰기를 정규화하고 `sort` 가 파일 내 순서를 정규화하므로, **재들여쓰기와 파일 내 재배치는 해시를 깨지 않고 통과한다.** 검사가 실제로 금지하는 것은 셋뿐이다 — 16파일 밖으로 내보내기, 삭제, 문구 수정(AC-ALD2-002 § 이 해시가 구속하는 것).

  그럼에도 위의 더 엄격한 규율을 작업 규칙으로 유지한다. 구속 조항 줄을 건드리지 않으면 범위 이탈(`acceptance.md §D.3`)의 표면이 그만큼 줄고, 해시가 못 보는 축에서 사고가 날 여지도 줄기 때문이다.

  이 문단이 있는 이유: 나중에 조항 순서를 바꾼 뒤 해시가 통과하는 것을 보고 **"검사가 깨졌다"고 결론 내리는 것을 막기 위해서다.** 그때 통과한 것은 검사가 옳게 동작한 결과이고, 어긋난 것은 규율이다.
- 파일 단위 순차 처리 + 파일마다 해시 재측정. 배치 처리는 원인 지목을 불가능하게 만든다.

## §G. 안티패턴

- 구속 조항 줄을 "어차피 companion 에도 있으니" 지우는 것 — 그것이 REQ-AMC-002 가 금지하는 강등이다(REQ-ALD2-013).
- 해시가 통과했다는 이유로 범위 이탈을 확인하지 않는 것 — 해시는 구속 *줄*만 보고 그 줄이 무엇을 구속하는지는 보지 않는다.
- `CLAUDE.md` 의 낡은 CG 서술을 "보는 김에" 고치는 것 — 범위 밖이며, 커밋 하나가 질문 둘에 답하게 된다.
- 이미 40,000을 넘긴 companion 에 "어차피 넘었으니" 더 옮기는 것 — 그 순간 그 파일의 초과가 이 카드의 몫이 된다(REQ-ALD2-015).
- 합계 축이 통과했다고 파일당 축을 안 재는 것 — 두 축은 계량기가 다르고, 한쪽의 통과가 다른 쪽을 함의하지 않는다.
- 여러 파일을 한꺼번에 고치고 해시를 한 번만 재는 것 — 깨졌을 때 어느 파일인지 못 가린다.
- companion 에 "정리하는 김에" 설명을 덧붙이는 것 — REQ-ALD2-006 위반.
- `paths:` 에 부모 stub 경로 하나만 적는 것 — 그 companion 은 부모를 편집할 때만 로드된다.
- 요구 감축량(96,943)에 딱 맞춰 파일별 목표를 잡는 것 — 한 파일만 미달해도 전체가 미달한다.
