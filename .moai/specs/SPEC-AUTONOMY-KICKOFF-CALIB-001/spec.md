### §A.1 이 카드가 답하는 질문

`workflow.autonomy.kickoff.decider: llm+jev` 는 LLM 답에 Jev 를 교차 확인하는 두 번째 신호를 더한다(A3 R1). Jev 쪽 신뢰도가 `jev_min_confidence` 미만이면 `llm` 단독으로 대체한다(A3 R2, 사유 `jev_low_confidence`). 그런데 이 문턱값 0.50 에는 근거가 없다 — §29 가 잠정값이라 밝힌 16장·영어 번역 표본이 전부다.

A5 는 과거 운영자가 Implementation Kickoff Approval 게이트에서 실제로 낸 결정의 모집단을 세션 전사본에서 뽑아, **판사(1차 후보: Jev)가 운영자 결정을 얼마나 예측하는지**를 상수 응답 기준선과 나란히 재고, 그 결과로 `jev_min_confidence` 채택·기각을 판정하는 측정을 **설계**한다. 실행은 run-phase 몫이며 이 SPEC 은 설계와 사전 등록만 담는다.

측정 대상은 판사 **출력**과 운영자 **라벨**의 대조다. 결정자를 구현하지 않고, `internal/contract` 를 고치지 않고, A3 의 규칙을 개정하지 않는다 — 프로토콜과 분석의 카드다.

### Out of Scope

- **결정자 구현** — `moai contract decide`·`kickoff-check` 등 결정 경로의 구현은 A3(t1236) 소유다. 이 카드는 판사 출력과 운영자 라벨의 대조만 하고 어떤 결정 경로도 만들지 않는다.
- **`internal/contract` 코드·`workflow.autonomy` 설정 기본값 변경** — `jev_min_confidence` 기본값(0.50)의 정의와 변경은 A1 0.5.2 소유다. 측정 결과를 설정이나 코드에 반영하는 일은 후속 카드다.
- **A3 규칙·문서 개정** — R3 해제와 Jev 원칙 개정(REQ-GR-013·025 연동 커밋)은 A3 소유다. A5 의 판정서는 그 판단의 근거로 읽힐 수 있을 뿐 개정 자체를 하지 않는다.
- **t943 실험의 재실행** — `CLAUDE.local.md` §30 이 카드 전제 판정 영역의 재실험을 금지했다. A5 의 모집단·과업·라벨 공간은 t943 과 다르므로 재실험이 아니지만, 카드 전제 판정에 대한 어떤 재측정도 하지 않는다.
- **영어 번역 표본에 의한 보조 측정** — §30 영어 대조군이 이미 쟀고 결론을 바꾸지 못했다. A5 는 한국어 원문만 잰다.

## §C. 요구사항

### REQ-CALIB-001 — 모집단 정의와 추출 술어 (Ubiquitous)

The 측정 shall **Implementation Kickoff Approval 게이트에서 운영자가 낸 결정 라운드**만을 모집단으로 삼으며, 라운드 확정은 다음 두 단계 술어로 한다. **1단계(구조)** — 세션 JSONL 을 파싱해 assistant `tool_use` 블록 중 `name == "AskUserQuestion"` 이고 `input.questions`의 header·question·option label 어느 하나에 `kickoff`(대소문자 무관, 한국어 `킥오프` 포함)가 나타나는 블록을 후보로 삼고, 같은 파일 안에서 일치하는 `tool_use_id`의 `tool_result` 응답이 있는 후보만 채택한다. **2단계(게이트 필터, 한국어 원문 규칙 — 측정 전 고정)** — 다음을 모두 만족하는 후보만 게이트 라운드다: (P1) 질문 텍스트가 카드 id 토큰 `t[0-9]+` 또는 `SPEC-[A-Z0-9-]+` 를 포함한다. (P2) 질문 텍스트 또는 선택지에 run 진입 승인 어휘(`승인`·`착수`·`run 진입`·`kickoff`·`킥오프`)가 있다. (P3) 선택지 집합에 승인 계열 라벨과 보류·중단·거절 계열 라벨이 각각 1개 이상 있다. (P4) 1단계의 응답 짝이 존재한다 — 응답 없는 후보는 `excluded_unanswered` 로 건수만 집계한다. 제외 규칙: (X1) P1–P3 를 하나라도 빠뜨리는 후보 — kickoff 가 맥락 인용에 불과한 다른 결정(카드 발행, 범위·일정, 리뷰 렌즈 등)이다. (iii) 스캔 적중은 전송을 **막는다** — 적중을 조용히 벗겨 보내는 일은 없고, 적중 건은 run 기록에 보고된다. **(4) 근거와 확장** — 이 조항은 `CLAUDE.local.md` §29 「키와 경계」(키는 `~/.moai/.env.typesafe` 한 곳, chmod 600, 설정·커밋에 넣지 않는다)와 §29 의 전송 전 확인 의무(「카드 본문이 외부로 나간다. 비밀·고객 데이터가 섞이지 않는지 전송 전에 확인한다」)를 측정 코퍼스로 확장하고 그 검증을 기계적으로 만든 것이다. **(5) fail-open의 경계** — 판사 도구 부재의 기능 저하(REQ-CALIB-008)가 스크럽 게이트를 느슨하게 하지는 않는다. 도구가 없으면 실행이 저하될 뿐, 스크럽 없는 전송은 없다

### REQ-CALIB-012 — 자율 Kickoff 운영자 결정과 세 가지 묶음 조건 (When)

The 측정 shall 다음 운영자 결정 아래에서만 실행된다 — **「모든 킥오프 승인은 자율적으로 진행한다」(운영자 결정 2026-09-26, 리드 경유, §A.2)**: card t1244 의 측정 실행은 plan-audit 이 끝난 뒤 별도의 운영자 게이트 없이 진행할 수 있다. 이때 다음 세 조건이 **묶음**으로 구속하며, run 기록은 세 조건의 이행을 기계로 판정 가능한 형태로 남긴다. **(a) 사전 등록 커밋** — REQ-CALIB-001·002·004~008·011 의 판정 기준(모집단·술어·라벨·대조·기준선·문턱·상한·스크럽)은 첫 판사 호출 전에 카드 브랜치에 **커밋으로 고정**돼야 하고, run 기록이 그 커밋 해시를 `criteria_commit:` 필드로 기록한다 — 커밋 해시가 사전 등록의 증거다. **(b) 세 중복 상한** — LIVE 모델 호출에는 턴 상한·호출 수 상한·벽시계 상한 셋이 모두 첫 호출 전에 run 기록에 `turn_cap:`·`call_cap:`·`wall_clock_cap:` 필드와 각각의 `declared_at` 시각으로 선언돼야 하고, 실행은 셋 안에 머문다. **(c) 스크럽 게이트** — REQ-CALIB-011 의 게이트가 모든 전송 전에 통과한다. 이 정책은 **이 배차에 한해 기록된 것**이다 — 다른 카드나 미래 행동의 독트린으로 일반화하지 않는다

## §E. 잔여 위험과 미해결 표지

- **밴드 기준 수치는 사전 판단값이다.** n≥20·+10%p·≤10% 는 t943 교훈에서 뽑은 측정 전 판단이고, 운영자는 **측정 전에만** 바꿀 수 있다(본문 결정 NC-1 — 기본값 유지, 바꾸면 HISTORY 에 기록). 측정 후 바꾸는 길은 없다.
- **모집단 편향.** 과거 라운드는 모두 `guided` 모드·사람 게이트에서 나왔다. 판사가 과거 사람 결정을 예측한다는 것과 미래 계약 모드에서 좋은 결정을 내린다는 것은 다른 명제다 — 판정서 Residual-risk 에 항상 적는다.
- **복합 응답의 카드 단위 귀속은 부분 정보다.** 질문 단위 라벨이 1차 판정 기준이고 카드 단위는 보조 보고다(본문 결정 NC-2 — REQ-CALIB-002).
- **판사 입력 최소주의.** 질문 원문만 주는 1차 배치는 판사에게 불리하게 짜여 있다 — 문맥을 더 주면 나아질 수 있지만 그 확장은 이 측정이 닫힌 뒤의 일이다(REQ-CALIB-007).
- **배차 범위의 자율 Kickoff.** 운영자 결정(§A.2)은 이 카드의 측정 실행에만 적용된 기록이다 — 다른 카드·미래 행동의 독트린 근거로 인용되면 안 된다(REQ-CALIB-012).
