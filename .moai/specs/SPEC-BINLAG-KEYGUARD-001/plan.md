## §A 설계 의도 — 가드가 실제로 판정하는 것

새 가드의 질문은 하나다: **허용목록에 적힌 키가, 지금 이 트리의 `doctor.go`에서 실제로 추출되는가.**

- 1차 단언: `namesAddedAfterBaseline`의 모든 키 `k`에 대해, `checkNamesFromSource`가 현재
  `internal/cli/doctor.go`에서 만든 집합에 `k`가 존재한다. 어느 쪽에도 없는 키는
  **증명 가능하게 무력**하다 — 그 키는 어떤 이름도 허용하지 못한다.
- 2차(표적) 진단, **양방향**: 실패한 키 `k`의 따옴표 변형 중 하나가 추출 집합에 있으면, 실패
  메시지는 어느 방향의 실수인지 지목하고 그 방향의 교정을 제시한다 —
  따옴표 **탈락**(`k`가 bare이고 `"k"`가 집합에 있음)이면 backtick raw string으로,
  따옴표 **덧붙임**(`k`가 따옴표에 감싸였고 알맹이가 집합에 있음)이면 평범한 문자열 키로.
  이 분기가 있어야 실패가 **자기 원인을 말한다**. 카드의 실제 불만이 바로 이것이다.
  트리 `93fb36344`의 허용목록은 두 모양을 나란히 담고 있으므로 두 실수 모두 실재 가능하다.
- 비공허성: 허용목록에 실질 키가 0인 상태에서 초록이 나오면 안 된다. 검사 대상이 비면 단언은
  아무것도 주장하지 않는다(`feedback_an_empty_operand_makes_a_set_comparison_assert_nothing`).

위 세 가지는 **설계 의도**이지 최종 코드가 아니다. run-phase가 이 의도를 만족하는 최소 형태를 쓴다.

### [HARD] 「검사 대상 0」과 「통과」가 같은 신호로 합쳐지면 안 된다

REQ-BLKG-005의 규율이다. 금지 대상은 셸 종료코드 일반이 아니라 **그 합쳐짐**이다.
종료코드 **0을 통과로 읽는** 판정 줄은 **비공허성 단언과 짝지어질 때에만** 쓴다.
종료코드 **≠ 0을 실패로 읽는** 판정은 공허한 경우가 실패로 떨어지므로 제약 밖이다.

두 실측이 이 규율을 낳았다. 카드 **t474**에서 grep 뮤턴트가 exit 0을 돌려주며 게이트를 뒤집었고,
이 트리 `93fb36344`에서는 **러너의 종료코드조차** 안전하지 않음이 드러났다 — 가드가 없는데도
`-run`이 0매치인 실행이 `ok` + exit 0을 낸다(`acceptance.md` AC-BLKG-001 RED-now).
근거 규칙: `.claude/rules/moai/development/verification-completeness.md` §1.1.

## §B 안 선택 — (a) 채택, (b) 기각

### (a) 허용목록 키-모양 가드 — **채택**

`namesAddedAfterBaseline`의 키가 현재 `doctor.go`의 추출 집합에 실재하는지 단언하는 새 테스트를 더한다.
따옴표가 벗겨진 키는 아무것도 매치하지 않으므로 **즉시** 실패하며, 실패 메시지가 원인을 지목한다.

- 폭발 반경: 테스트 파일 1개. 프로덕션 코드 무변경.
- 기존 가드의 의미를 바꾸지 않는다 — 더해질 뿐이다.

### (b) `exprSource` 정규화 — **기각**

두 등록 방식(상수 식별자 / 문자열 리터럴)이 같은 모양을 내도록 추출기를 정규화하면 문제의 뿌리를
없앨 수 있다. 그러나 **여기서는 실행 불가능**하다.

`beforeNames`는 현재 트리가 아니라 **과거 blob**에서 파싱된다 —
`lagBaselineSHA = "22f90b1c7"`를 `git show`로 읽어온 `doctor.go`다. 오늘 존재하는 상수가 그 트리에는
**아예 없을 수 있다.** 정규화는 서로 다른 두 소스 트리에서 상수를 각각 해석해야 하고, 그러면
before/after 두 집합의 의미가 갈린다 — 개선하려던 그 가드를 깨뜨린다.

기각은 「더 나쁜 안이라서」가 아니라 **「이 자리에서는 성립하지 않아서」**다. 등록 방식이 언젠가
한쪽으로 통일되면 (b)는 다시 검토 가치가 있다.

## §C 착지 순서 — **이미 흡수했다**

전제(t466·t477)는 착지했고, 흡수도 끝났다. 이 절은 그 사실의 기록이자, 판정 ref를 잘못 잡지
않도록 하는 못이다.

### [HARD] 착지 판정과 흡수의 ref는 **로컬 `develop`**이다 — `origin/develop`이 아니다

    $ git merge-base --is-ancestor 4e91bf6a9 origin/develop; echo $?
    1          ← 조상 아님

    $ git merge-base --is-ancestor 4e91bf6a9 develop; echo $?
    0          ← 조상

    $ git rev-list --count origin/develop..develop
    130

`origin/develop`은 `25a3212a9`에 멈춰 있고 로컬 `develop`보다 **130 커밋 뒤**다.
**레인은 develop을 push하지 않으므로**(`CLAUDE.local.md` §4.1) origin은 구조적으로 뒤처지며,
이는 이상이 아니라 정상 상태이고 앞으로도 그렇다.

그 ref로 착지를 판정하면 전제는 **영원히 미착지로 읽히고**, `git merge origin/develop`은 이미
조상이라 **no-op**이다. 문자 그대로 따르면 아무것도 흡수되지 않은 채 흡수했다고 믿게 된다.

### 실제로 일어난 일 (귀속)

1. **t466 착지** — `"Hook Delivery"` 리터럴 체크가 `doctor.go`에 들어왔다. 이것이 있어야
   따옴표가 하중을 지는 표본이 트리에 존재한다.
2. **t477 착지** — 그 체크가 backtick raw string 키로 허용목록에 등록됐다.
3. **흡수 완료** — 로컬 `develop @ a825183dd`를 이 워크트리에 병합. 결과가 현재 HEAD인
   병합 커밋 **`93fb36344`**(부모: `25a3212a9` + `a825183dd`)다.
4. 남은 것은 §F 마일스톤 M2 이후다. M1은 이 절의 기록으로 **충족됐다**.

흡수 후 트리에서 재측정한 값은 `spec.md` §4에 있다: `Hook Delivery` 매치 **1**, 기존 가드 GREEN,
허용목록에 두 모양 공존.

**착지 전에 짜면 안 됐던 이유**(이제는 지나간 위험): 허용목록의 유일한 키가 상수 등록(따옴표 없음)이라,
「따옴표가 하중을 진다」는 사례를 한 번도 보지 못한 채 초록을 얻게 된다. 그 초록은 공허하다.

**앞으로**: run-phase가 다시 흡수해야 할 일이 생기면 대상은 그때의 **로컬 `develop`** tip이며,
그 SHA와 결과 병합 커밋을 여기에 같은 방식으로 덧붙인다.
