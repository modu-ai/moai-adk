## §A. 맥락

이 카드는 측정과 판정만 한다. 산출물은 판정서 `.moai/reports/t1226/verdict.md`(뼈대는 plan 단계에서 작성), 후보 표 TSV 두 개, 절 분할 스크립트, 증거 파일이다. 18개 계수 파일과 그 템플릿 미러는 한 바이트도 바뀌지 않는다(REQ-ALH-013).

기준선(오케스트레이터 실측, 이 트리): `199111 total`, 잔여 49,111, 동결 해시 `d97b33d9…c6c3`.

## §B. 결정 지점 — 되돌리기 비싼 순서

### D1. 판정 대상 표면 — `S_init` 을 1차로, `S_live` 를 병기 (기본값 채택, 리드 재정 가능)

산출물에서 답이 나온다고 판단해 `[NEEDS CLARIFICATION]` 을 달지 않았다. 근거:

- 카드 본문이 「상시 로드 **템플릿** rules 풀」을 대상으로 적었다.
- 경고는 사용자 세션에서 나고, t1184 가 격리된 `moai init` 트리에서 같은 경고를 관측했다(`SPEC-ALWAYS-LOADED-DIET-002/spec.md §A`, 249.2k — 그 값은 t1175 감축 **이전** 트리의 것이므로 이 카드에서 재측정한다).
- 템플릿은 `AGENTS.md` 와 두 yaml 을 `.tmpl` 로만 갖고 있어, 렌더링된 `moai init` 트리가 아니면 사용자가 받는 실물을 잴 수 없다. 미렌더링 원본 합계는 203,611 로 `S_live` 199,111 과 4,500자 다르다(`research.md §1`).

그래서 한도 판정은 `S_init` 에 대해 내리고, t1175 채무의 직접 승계를 위해 `S_live` 도 같은 방법으로 잰다. 두 표면의 판정이 갈리면 둘 다 적는다. 리드가 다르게 정하면 M1 전에 이 절만 고치면 되고, 나머지 마일스톤은 표면 수만 달라진다.

### D2. `S_init` 의 동결 다중집합 — 템플릿 쪽 기준선을 따로 잰다

동결 해시 `d97b33d9…c6c3` 는 라이브 16개 마크다운에 대해 정의됐다. 템플릿 사본은 중립성 때문에 구속 조항 줄 일부가 다를 수 있으므로, 같은 파이프라인을 `S_init` 트리의 16개 파일에 돌려 **그 표면의 기준선 해시**를 기준 커밋에서 먼저 잰다. `S_init` 후보 판정은 그 해시에 대고 한다. 두 해시가 다르다는 것 자체는 결함이 아니며 판정서에 두 값을 병기한다.

## §C. 마일스톤

### M1 — 표면 생성과 18경로 대조 (우선순위: High)

- 이 트리에서 `go build -o <scratch>/moai ./cmd/moai`, 격리 `HOME` 으로 `moai init --non-interactive` 실행. 실제로 쓴 명령을 판정서에 기록.
- `S_init` 트리에서 18경로 존재 여부 확인, `wc -m` 합계와 파일별 값 기록. `S_live` 도 같은 형식으로 재측정(기준선 199,111 재현 확인).
- D2 의 `S_init` 동결 해시 기준선 측정.
- 산출: 판정서 `## S_init` · `## S_live` 절의 측정 행.

### M2 — `P절` 재조정 확정 (우선순위: High)

- `SPEC-ALWAYS-LOADED-DIET-002/design.md §4.0` 이 쓴 절 분할 스크립트(`python3 /tmp/claude-501/sec.py 3` — plan 단계 확인 시점에 `/tmp` 에 존재, 1,661 bytes)를 `.moai/reports/t1226/sec.py` 로 복사해 커밋한다. `/tmp` 사본은 증거로 인용하지 않는다(REQ-ALH-008).
- `git archive 172ef22eb <18경로> | tar -x -C <scratch>/orig` 로 원 트리를 풀고 스크립트를 돌려 `kanban-dispatch.md` 의 구속 0 절 자수를 재산출한다. 결과로 (a) 열 합 92,332 가 맞는지, (b) 적힌 합계 93,641 이 맞고 `J` 에 1,309 가 이중 차감됐는지를 가른다.
- F 를 단일값으로 확정해 `F = N` 줄로 적는다.

### M3 — 후보 전수와 조건 1~4 판정 (우선순위: High)

- 표면마다 스크립트로 모든 절(구속 0 절 → M1 후보)과 구속 절 안의 비구속 문단(→ M2 후보)을 나열한다. `CLAUDE.md` 의 비구속 중복 산문은 M1′ 후보로 따로 적는다.
- M1 후보마다 조건 2(역방향 인용 `grep -rIn -F "§ <절 제목>"`), 조건 3(목적지 `paths:`), 조건 4(목적지 `wc -m`, 라이브·템플릿 두 트리)를 걸고 증거 파일을 남긴다.
- `AGENTS.md` 후보는 M2 로만 분류(REQ-ALH-004). 구속 줄을 담은 후보는 `REJECT`(REQ-ALH-005).
- 산출: `candidates-init.tsv`, `candidates-live.tsv`(열 규약 `acceptance.md §D`).

### M4 — M2 압축 시도 (우선순위: High)

- M2 후보를 scratch 사본에서 실제로 압축하고, 사본의 동결 해시가 표면 기준선과 같은지 확인한다. 같으면 줄어든 자수를 `chars` 로, 달라지면 `REJECT`(사유 `rewraps-binding-line`)로 적는다.
- 시도하지 못한 후보는 `미측정` 으로 두고 Gaps 로 보낸다. 10.77% 같은 수율 외삽은 쓰지 않는다(REQ-ALH-006).
- scratch 사본은 커밋 트리 밖에 둔다. 18개 계수 파일에는 쓰지 않는다.

### M5 — `R`·`T_min`·판정 토큰 (우선순위: Medium)

- 허용 M1 후보를 목적지별로 묶어 stub 에 들어갈 포인터 줄 원문을 쓰고 `wc -m` 으로 `R` 을 잰다.
- 표면마다 `current_*`·`A_adm_*`·`R_*`·`T_min_*`·`U_*` 줄과 `verdict_*` 토큰을 적는다(규칙 REQ-ALH-010).

### M6 — 동결 해제 상신 절차 (우선순위: Medium · `S_init` 이 INFEASIBLE 일 때만)

- 구속 조항 줄마다 「그 줄이 동결시키는 문단·절의 자수」를 재고, 자수 대 해제 줄 수 비율 순으로 정렬해 150,000 에 닿는 최소 해제 집합을 구한다.
- 해제 형태를 셋으로 나눠 적는다 — (U1) 구속 줄의 companion 재배치 허용, (U2) 구속 줄의 문구는 두고 하드랩만 풀기(바이트 동결 → 의미 동결), (U3) `AGENTS.md` 에 M1 허용. 각각의 위험을 적는다: U1 은 REQ-AMC-002 강등(로드되지 않는 턴에 의무가 사라짐), U3 은 `AGENTS.md` 자기충족성 선언과 비-Claude 하네스 읽기 경로 훼손, 템플릿에 걸리는 해제는 중립성 검사 대상.
- 절의 결론은 `RECOMMEND:` 문장으로만 쓴다. 결정은 운영자가 하고, 리드가 `AskUserQuestion` 으로 상신한다(REQ-ALH-011·012).

### M7 — 인수 조건 일괄 검증 (우선순위: Low · 기계적)

- `acceptance.md` AC-ALH-001~008 명령을 한 턴에 병렬로 실행하고 출력을 `.moai/reports/t1226/ac-verify.md` 에 저장한다.
- `moai spec lint SPEC-ALWAYS-LOADED-HEADROOM-001` 재실행.

## §D. 제약

- 18개 계수 파일과 템플릿 미러 수정 금지(REQ-ALH-013). 압축 시도는 scratch 사본에서만.

- 환경 격리가 필요한 실행은 `unset … && <명령>` 한 호출로 한다.
- 수치는 모두 이 트리·이 실행의 명령 출력으로만 적는다. 197,897·198,361 은 폐기 수치다.
