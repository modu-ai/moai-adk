# Research: Single source of truth for `~/.moai` path resolution — `internal/paths` + `MoaiHome()`

Scope: design research for a new `internal/paths` package exposing `MoaiHome()` (honoring `MOAI_HOME`) plus typed sub-path accessors, migrating the 16 inline `filepath.Join(home|homeDir, ".moai", ...)` call sites (15 tracked across `internal/{statusline,config,cli,update,kanban,hook,glmcred}` + 1 untracked `internal/cli/migrate_profiles.go`). Explicit NON-goal: relocating the `~/.moai` directory itself. Four lenses were merged (codebase-precedent, external-docs, constraints-risks, prior-SPEC-memory); conflicts are surfaced verbatim in "contradictions" below, not reconciled.

## 1. How the 16 target sites obtain home today — three incompatible styles, zero caching

All sites resolve home per call; **no caching or `sync.Once` for home exists anywhere** (all `sync.Once` uses in `internal/` are unrelated: sunset notices, notice-once flags, output profiles).

**Style 1 — inline `os.UserHomeDir()`:** `internal/statusline/task.go:46`, `internal/statusline/builder.go:110` (fallback for the `HomeDir` opt), `internal/config/resolver.go:230` and `:313` (user tier `~/.moai/settings.json` + `~/.moai/config/sections`), `internal/cli/deps.go:118`, `internal/cli/launcher.go:493` and `:923`, `internal/update/local.go:48`, `internal/update/cache.go:34`, `internal/kanban/status_read.go:62`, `internal/hook/pre_tool.go:275`, `internal/hook/session_start.go:1102`.

**Style 2 — HOME-first wrapper `userHomeDir()`** (`/Users/goos/MoAI/moai-adk-go/internal/cli/homedir.go`, 19 lines): checks `os.Getenv("HOME")` before `os.UserHomeDir()`, explicitly so `t.Setenv("HOME", tmp)` works on Windows where `os.UserHomeDir()` ignores `HOME`. Introduced by commit `8b83b7aeb` ("fix(windows): fix cross-platform test failures on Windows CI"), with no SPEC linkage found. A verbatim duplicate lives at `internal/cli/preference/cmd.go:152-167` with a comment acknowledging the duplication, guarded by `internal/cli/preference/home_isolation_test.go` ("HOME must win over os.UserHomeDir"). The untracked `internal/cli/migrate_profiles.go` uses it (home resolved near line 62, joined at `:64`; its tests override via `t.Setenv("HOME", ...)`). Untracked status confirmed: `git status` shows `?? internal/cli/migrate_profiles.go` and `?? internal/cli/migrate_profiles_test.go`; `git ls-files` returns empty.

**Style 3 — injected seams (no resolution at the site):** `internal/statusline/usage.go:75` (`NewUsageCollector(homeDir string)`), `internal/statusline/model_cache.go:17/48` (`ReadModelCache(homeDir)` / `WriteModelCache(homeDir, ...)` per SPEC-V3R3-STATUSLINE-FALLBACK-001), `internal/statusline/builder.go` (`BuilderOpts.HomeDir`), `internal/glmcred/glmcred.go:32` (`var HomeDirFn = os.UserHomeDir`), `internal/cli/glm_tools.go:123` (`var userHomeDirFn = userHomeDir` — note: the function-variable default is the HOME-first variant), `internal/cli/migrate_agency.go:711` → injected into a struct field at `:184`.

**Error contracts diverge per site** — a unified accessor forces a behavioral choice no current site makes uniformly: `task.go` returns an empty `statePath` (silently no data); `glmcred.Path()` returns `""` and `Save` errors out; `internal/profile/profile.go` `GetBaseDir()` prints to stderr and returns **`"."`** (a relative-to-cwd fallback — a latent hazard if replicated); kanban `DefaultWorktreeBases` leaves a zero-value struct; `launcher.go` sites silently skip.

**Sweep risk:** 41 total non-test `os.UserHomeDir` call sites exist in `internal/` — the 16 are a subset; unification must not silently sweep the other ~25. `internal/cli/userHomeDir` is used at only 7 non-test sites while sibling cli files call `os.UserHomeDir()` directly — `internal/cli/update.go` contains both styles in one file (`os.UserHomeDir()` at :827, `userHomeDirFn()` at :900; synthesizer spot-check). The migration surfaces this inconsistency rather than resolving it unless the wrapper's fate is decided.

## 3. `MOAI_HOME` registration discipline (envkeys.go)

`MOAI_HOME` **does not exist anywhere in the repo today** — zero grep hits across `.go`/`.sh`/`.md`/`.yaml`/`.json`, and zero hits for `internal/paths` / `paths.MoaiHome` across `.moai/specs/`, `.moai/research/`, `.moai/plans/`. It is a genuinely new env var, so the full registration discipline applies:

- All env names live as documented constants in `/Users/goos/MoAI/moai-adk-go/internal/config/envkeys.go` (~119 `Env` occurrences; MoAI block at `:14-197`). `internal/cli/CLAUDE.md`: "Use constants from `internal/config/envkeys.go` — never inline … Hardcoded env names are a §14 violation per CLAUDE.local.md."
- SPEC-KANBAN-BOOTSTRAP-001 REQ-KS-009 / AC-KS-009 encodes it EARS-style: no call site may inline the name or value as a string literal **in any access direction** — reads (`os.Getenv`/`os.LookupEnv`) *and* writes (`os.Setenv`/`os.Unsetenv`/test `Setenv`). Reinforced by SPEC-CLI-TUI-MODERNIZE-001 (D2) and CI lint that catches inline `os.Getenv` outside envkeys.go.
- **Import-cycle constraint:** glmcred is stdlib-only *by design* (imported by both `internal/cli` and `internal/web`). `internal/paths` must be stdlib-only or glmcred cannot adopt it — but the `MOAI_HOME` constant must live in `internal/config/envkeys.go`, which would cycle if config ever imports paths. glmcred currently solves this shape of problem by aliasing constants (glmcred.go:22-27 pattern). A literal string in `paths` would be a §14 violation; importing `config` from `paths` risks a cycle.
- **Shell-readability invariant:** envkeys.go:108-117 (EnvAutonomyTier) documents that pure-shell hooks MUST be able to read env vars without invoking the moai binary — directly relevant to whether `MOAI_HOME` needs shell-side honoring (see §4).

## 5. External precedent: CLAUDE_CONFIG_DIR, XDG semantics, Go stdlib

- **Claude Code `CLAUDE_CONFIG_DIR`** (official env-vars doc, fetched live): "Override the configuration directory (default: `~/.claude`). All settings, session history, and plugins are stored under this path, as are credentials on Linux and Windows; on macOS, credentials are in the system Keychain. Useful for running multiple accounts side by side." Two design signals: (1) it is an explicit full-home override, the strongest precedent for `MOAI_HOME`; (2) an overridable home does **not** relocate OS-level credential stores.
- **Parent-directory override naming:** `CLAUDE_CODE_PLUGIN_CACHE_DIR` "sets the parent directory, not the cache itself: marketplaces and the plugin cache live in subdirectories under this path" — the exact shape of `MoaiHome()` + typed sub-path accessors. `CLAUDE_CODE_TMPDIR` similarly overrides a root with tool-appended subdirectories.
- **Empty-vs-unset:** XDG Base Directory spec — "If `$XDG_CONFIG_HOME` is either not set or empty, a default equal to `$HOME`/.config should be used", and values "must be absolute"; relative values "should be disregarded". Claude Code documents empty-string-as-unset only for provider-selection vars ("Claude Code treats the empty value as unset for provider selection. Subprocesses still inherit the empty value.") — its empty-`CLAUDE_CONFIG_DIR` behavior is **not documented**. In-repo convention is uniformly empty==unset: `internal/config/manager.go:70/106/246` (`os.Getenv(EnvConfigDir) != ""` for `MOAI_CONFIG_DIR`), `internal/profile/profile.go:95-96`, tests neutralize with `t.Setenv("CLAUDE_CONFIG_DIR", "")` (`internal/cli/launcher_test.go:918`, `launcher_project_scope_test.go:36`). `MOAI_HOME=""` must fall back to home, not a literal empty path; relative `MOAI_HOME` is an XDG-violating edge case needing an explicit decision.
- **Go stdlib:** `os.UserHomeDir()` is a pure env-var read (Unix `$HOME`, Windows `%USERPROFILE%`; error if unset) — deliberately chosen over `os/user.Lookup` in golang/go#26463 (Go 1.12), which makes HOME-overridability a feature. Third-party `mitchellh/go-homedir` (archived Jul 2024) is the caching precedent in implementation, but its README documents no `sync.Once` contract — no documented external contract endorses caching home.
- **`testing.T.Setenv`** (go1.17+): "Because Setenv affects the whole process, it cannot be used in parallel tests or tests with parallel ancestors."

## 6. Test-isolation constraints

- **107 `t.Setenv("HOME", ...)` usages across 20+ test files** (internal/cli, internal/hook, internal/cli/preference — incl. `home_isolation_test.go` files in both cli and preference) rely on per-call re-resolution of home. A cached `MoaiHome()` would ignore later env changes and race under parallel tests.
- **Hard prohibitions:** CLAUDE.local.md §13 [HARD]: `금지: t.Setenv("HOME", tmpDir) (병렬 테스트 오염)` — forbidden in parallel tests; §6 (cited by `internal/cli/glm_tools_test.go:5-8`): never `t.Setenv("HOME",...)` in parallel tests; §2/WARN: no `t.Setenv("OTEL_EXPORTER_*)` in parallel tests (global-state race).
- **Comment conventions already enforce non-parallel:** `internal/cli/migrate_profiles_test.go:201` "Cannot run in parallel: t.Setenv mutates process-wide state"; `internal/cli/launcher_test.go:18` "does not call t.Parallel() because it sets HOME via t.Setenv".
- **Parallel-safe seams deliberately avoid env:** `profile.BaseDirOverride` (global var), `glmcred.HomeDirFn` (func var), `userHomeDirFn` (func var, wired to glmcred via the glm.go init closure), `NewUsageCollector(homeDir)` / `ReadModelCache(homeDir)` (parameter injection). Any `MoaiHome()` honoring `MOAI_HOME` needs an equivalent non-env seam for parallel tests, and any `t.Setenv("MOAI_HOME", ...)` tests must be non-parallel.

## 7. Profile-system interaction: profile-relative vs global `~/.moai`

- **Profile-relative sites** (under `~/.moai/claude-profiles/`): `internal/profile/profile.go:64` (`GetBaseDir()`/`BaseDirOverride`), `internal/cli/migrate_profiles.go:64`, `internal/cli/profile*.go`, `internal/web/server.go:66`. `SPEC-PROFILE-MEMORY-001` records the SSOT: `~/.moai/claude-profiles/<name>` as `CLAUDE_CONFIG_DIR`, last profile in `~/.moai/claude-profiles/launch.yaml`. `internal/cli/profile.go:4`: "Each profile is an isolated CLAUDE_CONFIG_DIR in ~/.moai/claude-profiles/".
- **Global sites** (plain `~/.moai`): `.env.glm`, `cache/`, `state/`, `releases/`, `worktrees/`, user-tier `settings.json` + `config/sections` (`internal/config/resolver.go:318-319`).
- **Path canonicalization is load-bearing:** `GetCurrentNameForProject` derives the profile name via `filepath.Rel(baseDir, configDir)` and rejects `rel` starting with `..`; PR #1569 / commit `e63551b7d` ("fix(profile): match the launch ledger by directory, not by path spelling", merged 2026-08-16, +100/−? in `internal/profile/profile.go` + new `project_key_casing_test.go` +240) fixed exactly a path-spelling mismatch: case-divergent spellings of the same directory produced two `launch.yaml` ledger keys → silent fallback to default profile → `--continue`/`--resume` found no prior session (default profile keeps transcripts in its own CLAUDE_CONFIG_DIR). Fix resolves keys via `os.SameFile` on exact-string miss. Hazard for the design: if `MOAI_HOME` changes `GetBaseDir` while a stale `CLAUDE_CONFIG_DIR` (set by launcher/tmux `set-environment`, `internal/cli/launcher.go:348`) points at the old spelling, `Rel()` fails → silent "default" fallback. `MOAI_NO_PROFILE_FALLBACK=1` (`launcher.go:81,143`) is the existing opt-out.
- **Security-policy coupling:** `internal/hook/pre_tool.go:275-277` whitelists `filepath.Join(home, ".moai")` (and `.claude`) as allowed-external paths for the project-boundary check. If the accessor honors `MOAI_HOME` but this whitelist resolves real home (or vice versa), writes to the overridden dir get denied — or both dirs become allowed.

## 9. Design-decision checklist (synthesis of all lenses)

1. **Semantics choice:** HOME-first (Windows test-override rationale, homedir.go) vs `os.UserHomeDir()` (~13 current sites). Either pick changes behavior for the other camp on Windows.
2. **Error contract:** no current accessor returns an error uniformly; do not replicate profile's `"."` fallback.
3. **Caching:** none — `sync.Once` breaks 107 `t.Setenv("HOME")` tests; defer resolution per call (HOOK-CWD-LEAK precedent argues for deferral anyway).
4. **Empty==unset** per XDG + in-repo convention; decide relative-value handling (XDG: disregard).
5. **Stdlib-only** `internal/paths` (glmcred adoption) vs envkeys constant placement (§14) — needs the glmcred aliasing pattern or equivalent.
6. **Coupled consumers to migrate in lockstep:** `pre_tool.go` security whitelist, `core/project/root.go` home special-case, profile `GetBaseDir` (Rel()-matching + stale tmux `CLAUDE_CONFIG_DIR` hazard).
7. **Shell-side honoring:** `.env.glm` dual-reader (status_line.sh vs Go) forces either shell support for `MOAI_HOME` or an explicit Go-only scoping statement in the non-goal.
8. **Sweep boundary:** 41 total `os.UserHomeDir` sites; decide whether the 16 (or 17+, see contradictions) are the entire migration or whether `userHomeDir`/`userHomeDirFn`/`HomeDirFn` get absorbed.
9. **Supersede or amend** SPEC-V3R6-SESSION-HANDOFF-AUTO-001's "no abstraction layer exists" mandate.
