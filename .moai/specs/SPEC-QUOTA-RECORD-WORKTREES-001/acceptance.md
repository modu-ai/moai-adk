## §A Scope of verification

The criteria verify: a reading that exists only in a linked worktree's record directory is seen (three layouts plus a metadata entry whose name differs from its directory, and the on-disk layout git itself writes); freshest-wins across directories (a stale primary copy of a session id against a fresh worktree copy, the reverse, per window, tie, not-max); the single-directory entry point and every old `TestQAS_` test unchanged; unusable worktree entries contributing nothing and consuming the bound; the entry bound and its configuration key `workflow.quota_gate.max_scan_dirs`, read through the accessor `config.LoadQuotaScanBound` (default, range, the predecessor's type-mismatch behaviour for the whole block, template, local twin, inventory, cache schema, and the production seam applying it); the offline, spawn-free, read-only, non-recursive property of the new code; nothing read or enumerated while the gate is disabled; the lane gate (CLI and MCP), status block, and acquire warning seeing a worktree-only reading with unchanged output form; the no-git-metadata root reading its own directory alone; the measurement record and its commit ordering; and the untouched writer, thresholds, record schema, and predecessor files. Not verified here, and recorded as Gaps rather than criteria: the end-to-end observation of the gate reading a real lane's records (it needs a binary built from a tree containing the predecessor SPEC; the installed `moai` build contains none of the quota code, `plan.md` §C), a real Claude Code statusline writing windows (the installed binary writes schema 2, no windows), real quota consumption, kanban mode, and any codex or GLM lane.

## §B Test-environment constraint (binds every AC)

- Every test builds its own roots with `t.TempDir()` (a primary root, and worktree directories under the same or a second temporary directory); the MoAI home is redirected to a temporary directory. No test reads or writes the real `~/.moai` or a real `.moai/state`. Metadata entries are written by the test as `<root>/.git/worktrees/<entry>/gitdir` files, except the one subtest that runs the installed `git` in a temporary repository (`real_git_worktree_layout`, which clears `GIT_*` environment variables with `t.Setenv`, skips with a named reason only when `git` is absent from `PATH`, and is a Gap in that case).
- cli worktree fixtures use real git: a cli fixture that needs a registered linked worktree makes it with `git worktree add` inside the `initGitRepo`-style temporary repository (the cli path runs git through `identifyPrimaryCheckout`, `internal/auditreceipt/storeroot.go:142-171`, which parses git's own `worktree list --porcelain` output). Whether a hand-written `.git/worktrees/<entry>/gitdir` without a `HEAD` file survives that listing was not measured (`plan.md` §G U20), so synthetic metadata entries are used only in the statusline tests, where no git runs.
- Time is an injected clock (`factoryCardNow`, `factoryNextWaitSleep` for the factory seam; explicit `now` arguments for the aggregator). Record files are fixtures with `os.Chtimes` set per case; no test sleeps or reads the wall clock for a verdict.
- `./internal/cli` runs only with an anchored `-run` naming the AC tests; a whole-package run is not a verdict (it measures the machine, `gitflow-lane-protocol.md` §8). `./internal/statusline` may run whole-package once at the end. Heavy runs take a `moai slot` lease: every `./internal/cli` decider, and the `./internal/config` run that includes `TestShippedConfigKeysHaveReaders` (it type-checks the production tree through `go/packages`), each in the scrubbed single compound `unset … && go test …` form.
- Pass convention: an AC passes only when every command it names exits 0 and each test's verbose output carries a `--- PASS: <name> ` line for exactly the test the command names (name then a space). `[no tests to run]`, `no tests ran`, or a zero swept count is a Gap, never a pass (`verification-completeness.md` §1.1); a skipped subtest is a Gap named in the AC, not a pass.
- RED sequence for every test-decided AC, stated once (it closes the apparent clash of two M1 obligations): **before** a test file is written, its anchored selector is run once and must print `[no tests to run]` (the zero-sweep rows E1-E3 of §E.1 are that observation, measured at plan time); **after** the file and the M1 stubs (`plan.md` §E, M1) are committed, each selector is run again and the verbatim failing assertion — never a compile error — is recorded in `progress.md` §E.2 ("E8" of the predecessor's convention).
- Defaults the tests assert come from the predecessor: hold 90 / 95, margin 5, max age 30m, clock-skew tolerance 5m; this SPEC adds one configuration key, `workflow.quota_gate.max_scan_dirs` (default 128, range 1-1024, unmeasured; AC-QWR-013), and one compiled constant, the 4 KiB `gitdir` read bound. Identifiers fixed by the plan: `statusline.AggregateQuotaDirs(stateDirs []string, now time.Time, maxAge time.Duration) QuotaAggregate`, `statusline.QuotaStateDirs(root string, maxDirs int) []string`, the cli package variable `factoryQuotaStateDirs` (default `statusline.QuotaStateDirs`), and the config accessor `config.LoadQuotaScanBound(root string) int` (with the default constant `config.DefaultQuotaGateMaxScanDirs` = 128 and the range constants 1 and 1024; `plan.md` §D).

- RED-now: E1, E4, E8. Green path: M3 (the enumerator and the multi-directory reading).

### AC-QWR-002 — freshest wins across directories (not max, not min)

- **Given** a primary directory and one worktree directory, **when** the multi-directory reading runs at `now`, **then**: `stale_primary_copy_fresh_worktree_copy` (the same session id; primary copy captured now-20m at 95%, worktree copy captured now-2m at 60%) reads 60%; `newer_primary_copy_wins` (the reverse placement: primary now-2m at 60%, worktree now-20m at 95%) reads 60%; `not_max_across_dirs` (older record in one directory at 97%, newer in the other at 70%) reads 70%; `not_min_across_dirs` (older at 40%, newer at 80%) reads 80%; `per_window_across_dirs` (a newer record carrying only the seven-day window in one directory does not hide an older fresh record's five-hour window in the other); `tie_keeps_primary` (equal capture time, different percentages: the primary directory's record wins because it is listed first); `skew_and_age_apply_to_worktree_records` (a worktree record captured 5m1s ahead of `now`, or 30m1s behind, contributes nothing).
- Decider: `go test ./internal/statusline -run '^TestQWR_AC002_FreshestAcrossDirectories$' -count=1 -v` → PASS with the seven subtests listed. Mutants pinned: first-directory-wins, last-directory-wins, maximum over directories, minimum over directories, a worktree record exempt from the skew or age rule.
- RED-now: E1, E4, E8. Green path: M3.

### §E.3 Continued firing (verification-completeness §1.3)

How a reader learns that a check stopped firing, per check class, without asking:

- **Go-test deciders.** CI runs the full suite on every push (`.github/workflows/ci.yml:229`, `go test -json -coverprofile=coverage.out -covermode=atomic ./... > test-stream.json`), so each decider appears by name in that stream; a renamed or deleted decider is a missing name there, and the pass convention (§B) turns a selector that matches nothing into a Gap. The comparison of the AC roster against the stream is a manual read, not an automatic one — stated rather than implied.
- **The on-disk layout assumption (the failure that is silent by construction).** If git changed the layout of `<common>/worktrees/<entry>/gitdir`, the enumeration would silently return the primary directory alone: nothing fails and nothing is read, the exact "nothing failed, and there was nothing there to fail" shape. `real_git_worktree_layout` in AC-QWR-001 creates a worktree with the `git` on the CI runner and asserts the enumeration finds it, so a layout change turns red on the next push instead of leaving the gate blind; it skips (a named Gap) only when `git` is absent from `PATH`.
- **Sweep (AC-QWR-006).** Sweeps globs plus two named files, so a vanished or renamed `quota_dirs.go` fails the test by name, and a new `quota*.go` file joins the sweep automatically.
- **Disabled-gate silence (AC-QWR-007).** The static subtest names the one allowed reference to the enumerator, so a second reference (a new call site that bypasses the gate) turns red by itself.
- **Commit ordering and scope (AC-QWR-011, -012).** One-shot, pre-merge evaluations recorded once in `progress.md` §E.2 at the close of the run phase; vacuous after the card merges (the merge-base moves). Not recurring checks and not claimed to fire later.
- **Ledger rows (E1-E10).** Starting observations only; their continued life is the Go test of the same AC.

## §F Edge cases

- The same session id fresh in two directories (a lane that moved between trees inside `max_age`): the later capture time wins; equal capture times keep the primary directory's copy.
- A worktree listed in the metadata whose directory was removed with `rm -rf` (not `git worktree remove`): the `gitdir` target is missing → skipped, no error; it still consumed one position of the bound.
- A worktree created with `moai cc -w <abs-path>` outside the repository root: read through its `gitdir` (AC-QWR-001 `outside_root_layout`).
- A worktree whose `.moai/state` does not exist yet (no session has rendered there): skipped (AC-QWR-004 `record_dir_absent`).
- Windows paths in the `gitdir` file (`C:/…`): read with the platform's absolute-path rule; the Unix-style absolute-path fixtures skip with a named reason on Windows (a Gap there, not a pass).
- A gate that is enabled while the repository has more linked worktrees than `max_scan_dirs` (128 by default): entries beyond the bound are not read, in name order, so on this repository's naming (`agent-*` before `t*`) a late-named lane tree is the one dropped; fail open, and the template comment tells the operator to raise the key.
- `max_scan_dirs` set to a numeric value outside 1-1024: the accessor returns the default 128 and `LoadQuotaGate` honours the other keys of the block. `max_scan_dirs` set to a **string or an integer literal too large for an `int`** (both observed at M1): the YAML decode of the whole file fails and the predecessor's behaviour applies unchanged — `LoadQuotaGate` resolves the whole `workflow.quota_gate` block to defaults with the gate **off** (the predecessor's documented residual risk) and the accessor independently returns 128; this SPEC does not add per-key tolerance (AC-QWR-013 `type_mismatch_defaults_the_whole_block_gate_off`). `max_scan_dirs` set to a **real number such as `2.5`**: observed at M1 NOT to fail the decode (the other keys of the block were honoured); what value the decoder assigns to the `int` field, and so what the accessor returns, is **not observed** and no AC names it — M2 records one observed accessor value for `2.5` in `progress.md` §E.2 as a data point, and whatever the decoder assigned goes through the same 1-1024 range check.
- A `gitdir` target whose `.git` file does not name this metadata entry back (a stray metadata entry): not validated — see spec.md §F; the read is of record files only and every failure direction is "no hold".
