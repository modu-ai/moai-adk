# design.md — SPEC-USERASSET-DEPLOY-GUARD-001

> 설계 구속사항(WHAT+시임 수준). 구현 세부(함수 시그니처·내부 자료구조)는 런 페이즈 소관이다.

## §1 설계 원칙

1. 부모 계약(SPEC-USER-ASSET-INSTALL-001) 우선 — C2 경계, REQ-010 불가침, REQ-023 백업, 저널-매니페스트 원자적 해제는 어떤 수리도 우회하지 않는다.
2. 최소 침입 — 각 결함은 관측된 메커니즘 자리에서 고치고, 계층 재배치나 신규 추상화로 확장하지 않는다.
3. 결정화 우선 — 타이밍 민감 결함(잠금·중단·FIFO)은 시임 주입과 표 테스트로 결정화해, 재현이 플랫폼·타이밍에 흔들리지 않게 한다.
4. 관측/릴레이 구별 유지 — relayed-unverified 항목(13a/13b, 9a 집합 불포함)은 재현 확정 전까지 설계 확정으로 취급하지 않는다.

## §2 저널 가족 (M1) — 원장 3, 6a, 10, 10a-재정식

- 순서 결정: 회수 항목 반입을 첫 스테이징 **이전**으로 이동한다. 스테이지 구성 = (신규 installable 엔트리) ∪ (회수·분류된 기존 저널 항목)이 하나의 불변식이 되고, 이후 어느 중단 지점에서도 저널 파일이 그 불변식을 유지한다(REQ-JRN-001).
- 파일별 영속화: 각 자산 쓰기 완료 직후 해당 엔트리의 플래그를 저널에 반영한다. 기존 `stageChanged` 일괄 경로는 폐쇄하되, 원자 쓰기 경로(`atomicWrite`)를 재사용해 쓰기 증폭을 최소화한다(REQ-JRN-003).
- 해시 갱신: refresh가 일어난 반입 항목의 `ExpectedSHA256`를 갱신된 값으로 기록한다 — 저널이 "다음 런의 판정 근거"로서 참이어야 한다는 원칙의 직접 귀결(REQ-JRN-002).
- 버전 게이트: `LoadJournal`이 현재 `SchemaVersion`과 다른 파일을 진단과 함께 거절한다. 하위 호환 정책(현 세대 1만 존재 — 관측)상 "미인식 = 거절"이 안전한 방향이다(REQ-JRN-004).
- 유지 계약: 저널 해제는 매니페스트 저장 성공과 함께(설계 §2.2 승계), RF8 토큰·B3 반입 계약과 충돌 없음 — 반입 시점만 이동하고 반입 규칙 자체는 유지.

## §3 잠금 가족 (M2) — 원장 1, 10-P1

- 소유권 증거: `.guard`/`.acquire-guard` 마커에 획득자 PID를 기록한다. `lock.go`의 `.lock` 파일이 이미 갖는 자세(pid 기록 + `lockOwnerGone` 사망 확인 후 인수)를 마커에 동일 적용한다 — 같은 패키지에 같은 정책이 두 체계에서 다르게 동작하는 비대칭이 결함의 근원이다.
- 레거시 마커(라운드 8 재정의 — 이전 "형태+연령 회수" 지침은 **폐기·대체**): pid 없는 마커의 연령 기반 자동 회수는 UNSAFE하다 — 일시중단(suspend) 상태로 생존한 프로세스의 빈 마커가 연령 조건을 만족해 제2 소유자가 인수하고, 제1 소유자의 늦은 release가 제2 소유자의 마커를 삭제하는 재현이 게이트에서 관측됐다("A release deleted B marker: true" — 게이트 실측). 계약: 소유자 사망이 입증되지 않는 마커는 자동 회수하지 아니한다 — (a) pid 기록이 있는 마커는 기존 자세(사망 확인 후 인수)를 유지하고, (b) pid 없는(소유 증거 없는) 마커는 자동 회수 대상이 아니라 사용자 가시 회복 경로(doctor 보고 + 명시적 확인 제거 절차)로만 해소한다. REQ-LOCK-001·AC-001 사례 2.
- 회수 의미: 사망 확인 전 인수 금지(연령만으로 인수하지 않는 F5 자세)를 유지한다. 판독 불가·기형 기록은 실패 폐쇄(`lockOwnerGone`의 현행 의미)를 따른다.
- 패리티: windows 마커와 unix guard의 회수 의미를 동일하게 한다. unix는 이미 flock 기반이므로 windows 마커가 unix 자세로 수렴하는 방향이다(REQ-LOCK-002).
- 검증 전략: 플랫폼 중립 표 테스트(마커 상태×소유자 생존 행렬) + `GOOS=windows` 빌드 게이트(AC-024). CI windows 매트릭스는 릴레이 시점 미검증이므로 로컬 판정 가능성을 설계 단계에서 확보한다.

## §4 Codex 정규화 가족 (M3) — 원장 7a, 13a, 13b

- 관측 정정(라운드 3 부록): 초기 관측("harnessFS는 배포 필터이지 내용 변환기가 아니다")은 반박됐다 — `internal/template/harness_fs.go`는 변환 면을 이미 갖는다: 공개 `NormalizeCodexRoleForDeploy`(:180)와 내부 `normalizedOpen`(:209, :271-277 배선)가 정책·스킬·워크플로·인스트럭션 파일 참조를 변환하며, doctor 배출물 검사도 이미 이 변환 바이트와 비교한다(doctor_agentemit_embed.go:297 관측). **신규 변환기를 설계하지 않는다.**
- 재사용 설계: 기존 변환기(`NormalizeCodexRoleForDeploy`/`normalizedOpen`)를 userassets 설치 경로에 배선한다 — (1) 설치 바이트 산출(fileTarget/applyTarget의 원문 판독 지점)과 (2) 매니페스트·저널 해시 산출에 동일한 변환 바이트를 쓴다. 변환 바이트가 기록·해시의 대상이어야 한다는 것이 출처 규율(AGENTS.md §231-234)의 직접 요구다 — 원문 해시와 변환 기록이 섞이면 다음 런의 상태 판정이 오류를 누적한다.
- 범위 안전: 변환 규칙의 과잉 일반화 금지 — 재현 좌표 외의 참조를 추측으로 변환하지 않는다. 13a/13b 반박 시 7a만 남는다.
- 좌표 표류 처리: :584는 applyTarget의 원문 판독 지점일 뿐이며 실 복사 결정은 :392 경로다 — 재현 확정 후 하나의 결함으로 통합하거나 분리 확정한다(AC-007의 13b 팔 — 병합 절차).

## §5 동결 가드 가족 (M4) — 원장 9a

- 적재면 관측: 보호 집합은 config 적재다(`internal/hook/pre_tool.go:355` `zoneLoader → config.LoadProtectedZone`). `internal/hook`은 `internal/userassets`를 임포트하지 않는다(관측) — 의존 방향을 새로 만들지 않는다.
- 설계(경로 모델 확장): config 목록에 "절대 경로 추가"는 불가능하다 — 적재기가 절대 항목을 기각한다(internal/config/protected_zone.go:258 `must be repository-relative` 관측). 따라서 두 면을 함께 확장한다: (a) config 목록에 사용자 루트 상대 항목 종류(`user-root:<slug>/…` 형태 — userassets 루트 해석 위임)를 신설하고, (b) `resolveZoneTarget`이 프로젝트 루트 내부 매치만 형성하는 것(protected_zone_path.go:235-255 관측)을 사용자 홈 루트 매치로 확장한다. 보호 판정은 매니페스트 추적 파일로 한정한다(과잉 보호 방지 — 기존 원칙 유지). userassets 루트 정의와의 패리티 테스트(드리프트 시 적색)는 유지한다.
- 보호 대상 한정: 사용자 루트 아래 **moai 관리 파일**(매니페스트 추적 대상)로 한정한다. 사용자 자작 파일까지 보호하면 합법 편집을 차단하는 과잉 보호가 된다(REQ-GRD-002의 "관리 자산" 한정 근거).
- 집합 불포함 주장의 상태: relayed-unverified — 재현(AC-009 RED)이 확정할 때까지 config 현행 집합의 실제 내용을 가정에 넣지 않는다.

## §6 충돌 판정 가족 (M5) — 원장 8c, 12

- Lstat 선행: 충돌 사전 판정은 항목 유형을 먼저 분류한다. 비정규 항목(FIFO 등)은 읽기를 시도하지 않고 자체 분류(스킵+보고)로 처리한다 — os.ReadFile의 블록 성질을 회피하는 유일한 안전한 순서다(REQ-COL-001).
- 부모 핸들 고정 쓰기: 경로 기반 재검증은 TOCTOU를 닫지 못한다 — 검증과 사용 사이의 창이 구조적으로 남는다(725→729→750 관측). 설계는 부모 디렉터리를 핸들로 고정하고 핸들 경유로 생성·기록하는 것(openat 계열 — 저장소 go 1.26.8로 stdlib `os.Root` 가용)이다. 핸들은 검증된 디렉터리 inode를 고정하므로 이후 부모 경로가 교체(symlink-swap)되어도 기록은 검증된 inode로 향하거나 거부된다 — 경로 재해석에 의한 외부 기록이 불가능해진다. 잔여 경합의 명시: 핸들 고정은 "검증 시점의 부모 inode"를 대상으로 하며, 검증 이전에 이미 치환된 부모는 검증 단계의 해석이 거르는 바깥의 문제다 — 두 층이 겹치는 창은 없다.
- 검증 전략: FIFO 재현은 unix 표 테스트(mkfifo) + windows 빌드 게이트; symlink-swap 재현은 시임(os.Lstat/EvalSymlinks 주입)으로 결정화.
- 실행 권한 보존: confined 쓰기 경로의 설치 모드 결정은 스크립트 자산(.sh 등)의 실행 비트를 잃지 않게 한다(REQ-COL-003) — 0644 하드코딩 제거가 지점이며, 실행 자산 0755·나머지 현행 최소 권한 유지가 방향이다.

## §7 배포·번들 표면 가족 (M6) — 원장 4, 5-잔여, 8a, 8b, 8d, 11a-가드, 11b

- 미러 사본 분류·삭제 조건(REQ-SRF-001, 라운드 8 재정의): shipped 해시 일치는 소유권 증명이 아니다 — 사용자가 직접 복사한 파일도 해시가 일치한다(보존 가드 TestRF2F3b_MigrationPreservesUntracked·TestRF5_IdenticalUntrackedNotJournaled가 지키는 계약). 삭제 조건은 둘 중 하나다: (a) 생성 출처 입증(매니페스트·저널의 moai 생성 증거) 또는 (b) 명시적 삭제 승인 단계. 해시 일치와 사용자 대응물 확인은 분류·보고의 입력일 뿐 삭제 근거가 아니며, 보존 기본 + 가시적 보고로 "영구 무보존 방치"를 해소한다. AGENTS.local.md의 사용자 소유 파일 보존 규칙이 상위 계약이다.
- emission 집계(REQ-SRF-002, 회귀 가드): 현행 집계는 compared 미달을 CheckFail로 보고한다(doctor_agentemit_embed.go:150-165 관측) — **CheckFail 유지가 설계 판정이다**(`CheckWarn` 완화 변경은 철회). 본 가족의 과업은 변경이 아니라 그 불변의 회귀 가드 테스트 상륙이다.
- skills disable 폴백(REQ-SRF-003): 생 면은 `internal/cli/skills.go`의 미러 해석(cwd 기반 `<root>/.agents/skills`)이다. 사용자 계층(`~/.agents/skills`) 폴백을 해석 사슬에 추가하고 absent(0) 무시를 없앤다. 원장 좌표(deployer_mode.go:37)는 퇴역 — 이 문서가 재표현 근거다.
- 동명 에이전트 행(REQ-SRF-004) — 저장 계약 포함: 게이트 실측에 따르면 `parseAgentFMForm`은 `pins[a.Name]`에(agentfm.go:317 관측), `applyAgentOverrides`가 이를 `llm.agent_overrides`에(:330 관측) 저장하며 `LLMConfig.AgentOverrides`·`config.validateAgentOverrides`(:167)는 이름당 하나의 값만 유지·수용한다 — (i) 폼 키 분할만으로는 한쪽 설정이 다른쪽을 조용히 덮어쓰고, (ii) 스코프 접미사 저장 키는 검증기가 기각한다(양안 오버레이 확인). 선택한 계약: **동명 행의 단일 설정 통합** — 같은 이름의 사용자·프로젝트 에이전트는 하나의 설정으로 통합되어 폼에 한 행(스코프 출처 병기)으로 렌더되고, POST는 그 단일 설정을 저장하며, 저장소 키와 검증기는 변경하지 않는다. 기각 대안(스코프 저장 키 + 검증기 수용)은 공유 설정 스키마·검증 면을 건드리는 더 큰 반경 때문에 기각했다. AC-015는 폼→파싱→저장→재독록(end-to-end)으로 이 계약을 판정한다.
- depends_on 클로저(REQ-SRF-005): 설치는 `collectEntries`에서 선택 번들의 `DependsOn`을 순환 없이(사이클 검출) 전개한다. 보존 집합은 보존 번들의 의존을 포함한다. prune 측 R-f-② 유예 팔(remove.go RF2)은 이미 존재 — M0 변별 결과에 따라 prune 절반은 유지·보강만.
- 취소 불변(REQ-SRF-006): 회귀 가드 테스트 상륙만 — 이미 수리된 이전(확인창 뒤 제거)의 퇴행 감시.
- init 재개(REQ-SRF-007): "already initialized" 거절에 사용자 자산 부족분 조건의 재개 분기 추가. 재개 범위는 ensure만(템플릿 재배치 아님) — 실패 원인과 무관하게 최소 재개다.

## §8 doctor 진단 가족 (M7) — 원장 2, 7b, 9b

- 읽기 전용 적재(REQ-DOC-001): doctor는 매니페스트를 진단 목적으로 읽는다 — 복구 사본 덮어쓰기·.corrupt 이동 같은 부수 쓰기를 유발하는 적재 경로를 doctor에서 쓰지 않는다. 실패 등급은 별도 행.
- 공허 비교 정직화(REQ-DOC-002): 비교 가능한 면이 0일 때 "일치"가 아닌 공허 보고. 루트 게이트(projectCommonAssetRels)와의 관계를 메시지에 드러낸다.
- 필수 파일 기반 선택(REQ-DOC-003): 워크플로 루트 선택은 요구 파일(예: 4개 워크플로 파일)의 존재로 한다 — 디렉터리 존재는 신호가 아니다.
- 스코프 분리(REQ-DOC-004): 폴백은 workflowsDir만 바꾸고 skillsDir는 프로젝트에 유지한다. L6 참조 해석이 프로젝트 스킬을 보려면 프로젝트+사용자 양쪽 해석 사슬을 명시한다 — L6:FAIL·L1:PASS 오류의 양축을 동시에 닫는다.
