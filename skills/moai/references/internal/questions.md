# Internal: questions

When to read: before you ask the user anything in the UPDATE, PROJECT or SETUP route, or go down the interview question bank (`internal/interview`).

How a question reaches the user (user decision 2026-11-16, cards C-51 and C-52). It holds for every question of those routes, including a pick that SKILL.md sorts as case (2).

1. Run, do not hand over. Read-only previews run without asking. After the user has seen the preview and picked, run the command yourself. Never tell the user to run a command in a terminal when this session can run it; the user only chooses.
2. Every question is a selection. List the options, put the recommended one first and mark it, and give the reason for it in one line. Never ask an open or free-text question when the options can be listed: take them from what was read (`project-detect`, the manifests, the preview) or from the row's options in the question bank. A yes-or-no ask is a selection of two options with a recommendation. When only the user's own words can answer (a purpose with nothing to read), offer drafts written from what was read; the host's own "Other" takes the user's words.
3. A recommendation is not an answer. A case-(2) question — a choice that cannot be undone, that touches a HOLD category, that changes a `guarded` setting (the real HOME, keys, permissions, deletions), that sends something outside, or that states what only the user did ("I closed the other sessions") — waits for the user's pick with no default applied. Nothing is preselected for it: the recommended option is still listed first and marked in its label text, but no option carries a preset answer. A cancelled, empty, timed-out or unanswered result is not a pick: nothing runs, the step stays open and is reported as open; never go on by best judgment. Recommend only what the preview gives a reason for, else the option that changes or removes least. After a real pick this session runs the command. Nothing is deleted unless the user picked exactly that.
4. What only the user can do, such as closing other running sessions, is a selection too: "I did it, continue (recommended)" first, then "Stop here".
5. Use the host's question tool whenever the host lists it, as the table says. Plain text is the fallback only in the cases of its last column; say that it is the fallback.
6. At most three questions per call (the Codex CLI limit, kept on every host), related questions together, one axis per question. Split a longer set into calls of at most three, in its printed order. The `moai language-setup <project> --questions` set already carries what a selection needs (its `options`, and each item's `suggested` and `default`): relay each item with its suggested value first and marked recommended, never as a bullet list, and pass the picks back with `--answers`.
7. A secret value never goes through a question tool, a command argument or this session's output: the user types it into the product's own hidden prompt in their own terminal. It is the one input this session does not carry for them.

| Host | Tool | How to call it | When the host does not list it |
| --- | --- | --- | --- |
| Claude Code | `AskUserQuestion` | The recommended option first, its label ending in "(Recommended)"; the tool adds "Other" itself. | A subagent has no such tool: return the open questions, their options and the recommendation to the parent session, which asks. |
| Codex CLI | `request_user_input` | At most 3 questions per call, 2 or 3 options each, the recommended one first with "(Recommended)"; never add an "Other" of your own, and when more options exist list the likeliest and leave the rest to the tool's own free-text choice. It is listed in Plan mode, or in Default mode when `features.default_mode_request_user_input` is on (under development, off by default; the `moai codex` launcher is to turn it on — card C-52, not in this version): go by the tool list. In Plan mode only previews and picks happen, because Plan mode forbids actions that change anything: the applies run after the user leaves Plan mode; say so once. The Default-mode instructions say to continue with best judgment when the tool returns no answers; for a case-(2) question never do that: no answer is not a pick (rule 3). Never `request_user_input_async` for a question a step waits on: nobody is made to answer it. | Plain `codex`, `codex exec` or a subagent: say once that `/plan` enables the dialog, then ask one question per message with numbered choices, the recommended one first, and wait for the answer. |
| OMP | `ask` | Ask with one HTML form: radio buttons for one of, checkboxes for several of, `<select>` for a long list, the recommendation preselected with `checked`; never add an "Other" of your own. The form's values are submitted when the user does not answer in time (the `ask.timeout` setting), so for a case-(2) question (rule 3) nothing is preselected: no `checked`, no `selected` and no `value`, the recommendation is named in the label text only, and a submission without a choice is not a pick. | In print mode or a subagent do not call it: put the open questions, their options and the recommendation in the final answer. |
| Any other host | none named here | Use the host's own question tool the same way when it lists one. | Ask one question per message with numbered choices, the recommended one first, and wait for the answer. |
