# Internal: questions

When to read: before you ask the user anything in the UPDATE or PROJECT route, or go down the interview question bank (`internal/interview`).

How a question reaches the user. It holds for every question of those routes, including a pick that SKILL.md sorts as case (2).

1. Run, do not hand over. Read-only previews run without asking. After the user has seen the preview and picked, run the command yourself. Never tell the user to run a command in a terminal when this session can run it; the user only chooses.
2. Every question is a selection. List the options, put the recommended one first and mark it, and give the reason for it in one line. Never ask an open or free-text question when the options can be listed: take them from what was read (`project-detect`, the manifests, the preview) or from the row's options in the question bank. A yes-or-no ask is a selection of two options with a recommendation. The one exception is the purpose of a project: only the user's own words can answer it, so ask it as plain text in the conversation (the one question asked as plain text even on a host that lists a question tool), with no draft and no option written from the README, the manifests or the code, and take the user's typed answer as it is.
3. A recommendation is not an answer. A case-(2) question — a choice that cannot be undone, that touches a HOLD category, that changes a `guarded` setting (the real HOME, keys, permissions, deletions), that sends something outside, or that states what only the user did ("I closed the other sessions") — waits for the user's pick with no default applied. A question that holds any case-(2) option is a case-(2) question as a whole, even when its other options are ordinary steps. Nothing is preselected for it: the recommended option is still listed first and marked in its label text, but no option carries a preset answer. A cancelled, empty, timed-out or unanswered result is not a pick: nothing runs, the step stays open and is reported as open; never go on by best judgment. Recommend only what the preview gives a reason for, else the option that changes or removes least. After a real pick this session runs the command. Nothing is deleted unless the user picked exactly that.
4. What only the user can do, such as closing other running sessions, is a selection too: "I did it, continue (recommended)" first, then "Stop here".
5. Use the host's question tool whenever the host lists it, as the table says. Plain text is the fallback only in the cases of its last column; say that it is the fallback.
6. At most three questions per call, on every host, related questions together, one axis per question. Split a longer set into calls of at most three, in its printed order. The `moai language-setup <project> --questions` set already carries what a selection needs (its `options`, and each item's `suggested` and `default`): relay each item with its suggested value first and marked recommended, never as a bullet list, and pass the picks back with `--answers`. The four language items and the one confirmation of `internal/interview` are five selections: ask them in two calls of three questions or fewer, the languages first.
7. A secret value never goes through a question tool, a command argument or this session's output: the user types it into the product's own hidden prompt in their own terminal. It is the one input this session does not carry for them.

| Host | Tool | How to call it | When the host does not list it |
| --- | --- | --- | --- |
| Claude Code | `AskUserQuestion` | The recommended option first, its label ending in "(Recommended)"; the tool adds "Other" itself. | A subagent has no such tool: return the open questions, their options and the recommendation to the parent session, which asks. |
| Any other host | none named here | Use the host's own question tool the same way when it lists one. | Ask one question per message with numbered choices, the recommended one first, and wait for the answer. |
