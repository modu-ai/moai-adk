## Sessions and roles

- Leader session (label `leader`): owns `src/`, `tests/`, `docs/`, `.github/`, `AGENTS.md`, `AGENTS.local.md`, `.gitignore`, `.moai-cli/`; holds the user question channel; supervises the lanes and runs the integration gate; relays lane reports; keeps the decisions log. Leader commits also travel through a PR under the integration gate.
- Lane sessions (`agent-N`): one Issue at a time in their own worktree. `agent-2` is the read-only independent auditor (never writes to the repo or GitHub). `agent-1` owns `skills/moai/` only when assigned. New sessions are opened only by the operator; no session spawns another.
- Start sessions with `moai-cli cc|glm|codex` — a plain host session with no role (main model `opus` at effort `medium`, advisor `fable` on Claude hosts; #2053). The launcher flags `-l|-a` (`moai-cli -l|-a`, `moai-cli cc|glm|codex -l|-a`) are deprecated since #2164 (user decision 2026-11-09 D-1, docs/decisions-2026-11-08.md): #2164 adds a stderr warning and a note while still composing the same command; removal is a later card. `--name` stays. The legacy `moai-cli session --role …` form is compatibility only.
- The MoAI role is a skill argument typed inside the open session (#2160): `/moai --mode leader [--autonomy full|semi]` or `/moai --mode agent` (Codex: `$moai --mode agent`), routed by `skills/moai/SKILL.md` to `skills/moai/workflows/mode-leader.md` and `mode-agent.md`. The spelling `--leader-mode`/`--agent-mode` in the SPEC title is historical. Only Claude Code sessions take leader mode in rc.2 (D-3); Codex sessions run agent mode and are reached through Issue comments and `.md` files (no cross-session channel).
- Build folders: one build folder per worktree, inside it — `<worktree>/target/` (do not set `CARGO_TARGET_DIR`). An audit clone builds in its own `target/` too. One dependency cache is shared as `CARGO_HOME`: `/tmp/moai-product-cargo` once it holds the prepared cache (`registry/cache` present — a bare folder that a cargo run left behind does not count) and `/tmp/moai-rc-product-cargo` until then (the commands below pick it). `--offline` builds need the prepared cache, and an empty new folder fails at dependency resolution (PR #2585 audit B1); moving the existing cache to the new name once (`mv /tmp/moai-rc-product-cargo /tmp/moai-product-cargo`, when no build runs) is the leader's act, and nothing is downloaded again. A shared target dir (or `build.build-dir`) ran another tree's binary (observed 2026-11-08 and 2026-11-10, #2380 §3.3); the per-session target folders (`/tmp/moai-rc-target-<label>`, named `/tmp/moai-target-<label>` after #2563) outlived their worktrees (57 folders, 65.9 GiB), so that rule is retired. Existing `/tmp/moai-rc-target-*` and `/tmp/moai-target-*` folders are removed only from a listed, confirmed plan.
- Keep notes, PR bodies and audit logs under an ignored `target/<name>/` only while the card is open; copy anything that must survive into the Issue/PR record. Cleanup removes cargo output only — profile folders (`debug/`, `release/`, with `.cargo-lock`), target-triple folders (with their own `CACHEDIR.TAG`), `CACHEDIR.TAG`, `.rustc_info.json`, `tmp/` — never the whole `target/`. `moai-cli worktree-gc-plan` lists exactly those paths as `trim_paths` and everything else as `preserved_in_target`.

## Agent loop (self-claim)

The self-claim round is defined once in `docs/design-review/autonomy-modes-spec.md` §3 (seven steps, each with its failure branch) and §4 (why the claim comment id arbitrates); `moai-cli queue-next` runs one round (#2161). This section holds only what is specific to this repository.

- Branch `issue/<number>-<key>` from the latest `origin/v2026.11.0`; worktree at `<primary>/.moai-cli/worktrees/<number>-<key>` for every host (the Go `moai` PreToolUse hook rejects Edit/Write outside the primary checkout; `.claude/worktrees/` would write into preserved state and pollute the 00-A inventory; `/.moai-cli/worktrees/` is gitignored).
- Worktree entry and exit (user decision 2026-11-08): a lane starts a card with `EnterWorktree(<primary>/.moai-cli/worktrees/<n>-<key>)`, and after the handoff leaves with `ExitWorktree(keep)` — a lane never deletes a worktree. After the work is merged, the leader trims its cargo output at once and removes the worktree after reporting the list to the user, using `moai-cli worktree-gc-plan . --integration-ref origin/v2026.11.0` (read-only; `remove` only when merged, no tracked change, no untracked file, no ignored file outside cargo output, no process inside and no change in 120 minutes) and running the plan again right before acting; a changed `plan_digest` means re-check (user decision 2026-11-10, Q4 B). `git worktree remove` without `--force` still deletes ignored files of a clean worktree (measured), so a worktree holding lane notes under `target/<name>/` is never a `remove` candidate. The plan does not read claim leases or files held open by a process working elsewhere (#2380 audit 6811382861 B2); the leader checks both, and `worktree.gc.apply` (#2498) re-checks them right before it deletes. Never move into or out of a worktree with a shell `cd` (nor `cd <worktree> &&` command prefixes). A worktree first entered by shell `cd` before this rule is finished as is; `ExitWorktree` is a no-op there, and the next card starts with `EnterWorktree`.
- The same hook blocks `gh` comments and Writes from lane worktrees, so lanes send their claim comment and owned-report text to the leader, who posts it marked "레인 agent-N 보고 중계"; audit verdicts are relayed the same way. The hook itself is Go MoAI state and is not edited.
- Hand-off (user decisions 2026-11-08 ADK_LANE_LOOP / ADK_LOCAL_GUIDANCE_20261108_01 and "a lane waiting with nothing to do is the bottleneck"): implement and run the full check set → open the PR (or push the repair) → send the leader a durable report (exact head and base SHAs, each check command with its exit code, every AC as passed/failed/not_run, remaining responsibilities and HOLDs) → stop writing and confirm nothing is lost (`git status --short` empty and `git ls-remote origin <branch>` equals local HEAD) → `ExitWorktree(keep)` → start the next round at once. A lane never waits for the audit or the merge, and its handoff is not PR completion.
- Audit clone (independent audit of a PR head, #2380 §D4, user decision Q6): `moai-cli audit-clone-plan . --pr <n> --head <40hex> --head-branch <branch> --base-branch v2026.11.0` prints the commands — a single-branch, no-checkout clone of the head branch into `/tmp/moai-audit-<pr>-<head8>`, a fetch of the base branch only, a detached checkout of the exact head, `rev-parse HEAD` (must equal the head) and `merge-base` (the verdict's `base`). Never a linked worktree of the author's clone and never `--reference`/`--shared`. After the verdict is posted and read back, copy the logs to `~/.moai-cli/projects/<id>/audits/<pr>-<head8>/` (the plan's `evidence_dir`) and remove your own clone.
- A card whose only open blocker is a PR already in the leader queue may be started from that PR's head; the lane says so in its own PR and re-merges onto `v2026.11.0` after the blocker merges.
- Blocks and limits: report a real block (permission or hook denial, missing decision, failing gate) with the exact command and stop. Never route around an unapproved permission, spend, HOLD or security gate; stop after three failures of the same step. No forced deletion or process kill, and no branch switch, reset or stash in the shared checkout. This cycle does not lift any HOLD.
- Loading: hosts do not load this file by themselves (Claude Code loads `AGENTS.md` only, and only without a `CLAUDE.md` variant; Codex reads `AGENTS.md` chains). A lane reads this file at the start of each card; a leader message that hands over a card names it.
- Check set, run from the repository root before every PR and re-run after the final edit:

```sh
CARGO_HOME=$(test -d /tmp/moai-product-cargo/registry/cache && echo /tmp/moai-product-cargo || echo /tmp/moai-rc-product-cargo) cargo test --offline --locked
CARGO_HOME=$(test -d /tmp/moai-product-cargo/registry/cache && echo /tmp/moai-product-cargo || echo /tmp/moai-rc-product-cargo) cargo clippy --offline --locked --all-targets -- -D warnings
cargo fmt --check
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p '*_test.py'
git diff --check
git diff --cached --check
```

Test in temporary projects or fixtures, never against installed user state. Do not claim Windows/Linux results from Mac fixtures.

## Leader supervision

Leader mode supervises and does not dispatch. The division of work, the supervision loop, the autonomy levels `full`/`semi` with the keep-set, and the paste-ready `/goal` line are defined once in `docs/design-review/autonomy-modes-spec.md` §2, §5, §6 and §7; `moai-cli leader-tick` runs one tick (#2162) on `leader.pr_check_interval_secs` (default 300 — a user-set value, not a measured one; D-2). The items below are the repository-specific part.

- Record: `.moai-cli/manifests/assignments.json`, schema in `docs/design-review/assignments-schema.md` (#2139, user decisions 2026-11-09 00:3x and D-4). `unassigned` is a snapshot recomputed from the remote (open Issues of the active milestones minus those with a claim comment); `assigned` gets an entry only when a claim comment id exists; a claim that lost the lowest-id race stays as `stage: lost`. Only the leader commits the file; lanes read it.
- **The local file is not a lock; ownership is the claim comment.** The file is a same-host cache and write-ordering aid. A name in it grants no right to write that Issue, and when it disagrees with the remote, the remote wins.
- When a tick runs (user decision 2026-11-08 "the leader always keeps checking lane progress"): on the interval, and also after every merge, every lane report or handoff, every restart, whenever the leader would otherwise wait, and when a lane reports idle with an empty list.
- What a tick reads — evidence, not status labels: open PRs with head, base, merge state and the `moai/audit` status on the current head; the claim comments against `assignments.json`; `ListAgents` (who is live, busy or idle, duplicate names); each lane worktree's `git status --short`; the lane's last reported command and exit code. Stage changes come from the remote (branch, PR, status, merge), never from a lane message or an idle notice alone.
- What a tick does:
  1. Claim mismatch: correct `assignments.json` from the remote and record what differed as a comment on that Issue; the file keeps no history.
  2. Repair: write it as an Issue comment with `assignee-hint: agent-N` addressed to a free lane that is **not the author** (user decision 2026-11-09 00:0x; it supersedes the 2026-11-08 "repair to the last writer" rule). The hint grants nothing — ownership still comes from that lane's claim comment, and one writer per branch holds.
  3. Stalled lane: a lane idle without a reason, or busy past its reported step with no report, is asked for its actual last command and exit code; a block is recorded and raised to the user.
  4. Refill: keep a next card ready for every lane, in this order — (1) a ready card whose blockers are all closed; (2) a card whose only open blocker is a PR already in the leader queue; (3) a recorded follow-up turned into an Issue — audit non-blocking notes, defect candidates (RED test first, closed as not-a-defect when it does not reproduce), the ledger's `followup_candidates`; (4) when none exists, tell the waiting lane why (which open PR or HOLD it waits on) and which card is reserved for it.
  5. Each tick and its outcome go into the dispatch journal.
- Cards from a confirmed report (synthesis report §10.2 F-A–F-D): after the user confirms a report, the leader turns its rows into new Issues or edits the bodies of existing ones — new Issue publication waits for that confirmation at either autonomy level. Each body is mirrored to `.moai-cli/reports/issue-bodies/<n>-<key>.md` with a "사용자 결정" section; a card that edits a design Page takes "sha256 of the corrected copy + leader read-back" as its acceptance. Completion of such a card is read from the merge or the verdict file like any other. Lanes get only `.md` paths in tracked locations (Codex lanes in their first prompt), so a report must move to a tracked path such as `docs/design-review/` before its cards are issued.
- The leader never invents work outside the Issues and that recorded backlog, never splits one card between two writers, never creates a new or duplicate writer, and never lifts a HOLD to make work; a card that needs a HOLD answered waits for the user while the lane takes another. A duplicate session found after a restart freezes until the operator assigns it.
- Lease: default 4 hours when `lease_until` is omitted (D-5, #2166); expiry is displayed only (takeover rule: `AGENTS.md` § Workflow step 1).

## Gate

- Integration gate: ruleset `RC1 integration gate (v2026.11.0)` (id 26791615) requires a PR, the status `moai/audit`, an up-to-date branch (strict) and forbids force-push and deletion, with no bypass. Author, auditor and integrator are three different sessions; the auditor is `agent-2`.
- Procedure: read the auditor's verdict first line, verify PR head == audited SHA and merge-base == base tip (else `gh pr update-branch` and re-audit), post `moai/audit=success` with the verdict comment as target_url, then `gh pr merge --auto --merge`.
- After every `update-branch`, compare the changed lines with the audited delta before asking for a delta audit: when both sides changed the same line the same way (for example a fixed array length), git merges silently and the build can break (observed on PR #2044, 2026-11-08) — registries such as `OPERATIONS` are length-free slices for that reason.
- Both autonomy levels keep the ruleset, the independent audit, no secrets in logs, no hook or permission bypass and Go-state preservation unchanged.
- Known gap: all sessions share one GitHub account, so the status source cannot be pinned (audit-only GitHub App is a later HOLD).
