# `lane-send`

operation `lane.send`(SPEC-20261119-lane-send-guard, 카드 C-120 조각 B). 코드: `src/ops/lane_send.rs`(명령)와 `moai_cli::lane_status::lane_send`(`src/lane_send.rs`, 판정과 `orca` 호출). 화면 읽기는 `lane-screen` 과 같은 분류기(`moai_cli::lane_status::lane_screen`)를 써요.

`lane-send --terminal HANDLE --text TEXT [--enter] [--now YYYY-MM-DDTHH:MM:SSZ]` 는 Orca 터미널 `HANDLE` 에 글 하나를 보내되, **보내기 전에 그 터미널의 그려진 화면을 읽고** 레인이 `working` 이거나 `idle` 일 때만 보내요. 2026-11-19 에 Yes/No 확인 창이 떠 있는 레인에 글과 Enter 가 들어가 `git reset --hard` 의 `Yes` 가 눌린 일을 막으려는 도구예요. `orca terminal send` 는 대상 화면을 보지 않아요.

- **읽기**: `orca terminal read --terminal HANDLE --screen --json` 을 부르고, 답이 Orca 의 JSON 이 아니면(글자만 오면) 화면으로 믿지 않고 `unreachable` 로 거절해요. `source` 가 `screen` 이 아닌 읽기는 `unknown` 이에요.
- **거절**: `working`·`idle` 이 아닌 모든 상태(`permission_prompt`·`input_pending`·`usage_limit`·`unknown`·`unreachable`)는 아무것도 보내지 않고 종료 코드 1 과 오류 글을 줘요. 오류 글에 상태, 이유, 읽어 낸 화면 줄 하나가 있어요. 번호가 붙은 `Yes`·`No` 줄 한 쌍은 번호 앞에 무엇이 있든(목록에 없는 커서 `◆` 도) 확인 창이라 거절해요(B1). 아래쪽 8줄 안에 확인 질문(`Do you want …` 류, 또는 `Overwrite? (y/N/a)` 같은 괄호 질문 자체)이 있고 그 질문 줄이나 아래 줄에 **선택 모양**이 있으면 `unknown` 이라 거절해요(R-N1, R-B1, `lane-screen` 과 같은 규칙: `Do you want to proceed? (yes/no)` 처럼 선택이 질문과 같은 줄에 있어도 거절). 질문 줄은 첫 `?` 뒤의 꼬리에 모양 검사를 해요(리뷰 노트 10724): `Do you want to proceed? Yes/No`·`Do you want to delete the build folder? [Yes] [No]`·`Do you want to continue? yes or no` 처럼 꼬리가 선택 모양이면 일하는 화면에서도 대기 화면에서도 거절하고, 질문 자신의 낱말은 모양으로 읽지 않아요(`Would you like me to commit or push?` 는 평범한 질문이라 보내요). `?` 가 없는 질문 줄은 끝의 세 낱말에서부터 각각 읽어요. 질문 줄에서는 선택 짝도 줄 어디에서든 읽어요(리더 결정 10737, 델타 리뷰 10736): 낱말과 낱말 사이의 `/`·`|`(공백이 있든 없든)가 있으면 선택 짝이라 거절해요 — `Yes/No: do you want to proceed?`, `… now yes/no please confirm it`, `… ? Yes, and don't ask again / No, tell Claude what to do differently`(실제 권한 질문을 한 줄로 편 꼴). 짝의 조각이 모두 글자뿐이어야 하므로 점·콜론·숫자·밑줄이 든 토큰(`src/main.rs`, `https://host/x`, `docs/v2/api`)과 빈 조각이 있는 토큰은 짝이 아니에요. 이 규칙은 낱말 목록이 아니라 모양이라 `and/or` 와 폴더 이름만으로 된 경로(`src/lib`, `crates/core/src`)도 질문 줄 속에서는 짝으로 읽어 거절해요(대가: 그런 경로를 넣어 묻고 멈춘 화면에는 `lane-send` 가 거절하고, 리더가 화면을 읽고 보내요. 그 줄에서만, 안전한 쪽). 모양으로는 `… now yes or no please confirm it` 과 `Would you like me to commit or push?` 를 가를 수 없어서(S-N2), 낱말 목록은 되살리지 않고 예외 하나만 뒀어요(사용자 결정 2026-11-27, 레저 노트 10779, SPEC 개정 3): 질문 줄 안에서 긍정 낱말과 부정 낱말(`yes`/`no`, `y`/`n`, 대소문자·순서 무관, 둘레 문장부호 허용: `(yes, or no)`)이 `or` 로 바로 이어진 줄은 거절해요. 다른 `or` 짝(`commit or push`, `yes or maybe`)이나 `yes to one or no to two` 처럼 `or` 가 더 긴 구절을 잇는 줄은 거절하지 않아요. 낱말 목록(`yes`·`no`·`allow`…)은 없고 모양이 기준이에요(SPEC-20261120-lane-screen-followups REQ-6): 짧은 줄(40자 안)이 `[1] Yes`·`[ Proceed ] [ Cancel ]`·`(a) Keep` 처럼 괄호로, 또는 `1. Proceed`·`1: Yes`·`a. Yes` 처럼 번호나 글자로 시작하거나, `Approve / Reject`·`Keep | Replace`·`choose: yes or no` 처럼 짧은 낱말들이 `/`·`|`·`or` 로 나뉘거나, 괄호 안에 세 글자 이하 토큰이 둘 이상 `/`·`|` 로 나뉜 줄(`(y/N/a)`)이에요. 아래에 번호 줄이 둘 이상이거나 낱말 하나짜리 줄이 연달아 둘이어도(`Allow` 다음 줄 `Deny`) 거절해요. 질문이 없어도 `[1] Yes`·`1: Yes`·`a. Yes` 같은 새 모양의 목록 줄이 아래쪽 6줄 안에 둘 이상이면 거절해요(`1.`·`1)` 줄은 번호 규칙이 따로 읽어요). 질문으로 대화를 끝내고 입력 줄에서 기다리는 레인은 질문 줄과 그 아래에 선택 모양이 없고 번호 줄이 둘 미만이면 거절하지 않고 보내요(S-N2). **대가와 이득**(REQ-7, 사용자 승인 2026-11-27): 이득은 `Approve / Reject`·`Accept / Decline`·`1. Proceed` 같은 확인 창과 `[1] Yes`·`(y/N/a)` 가 있는 화면에 글이 들어가지 않는다는 것이고, 낱말 목록을 늘려 가며 뒤쫓지 않아도 된다는 것이에요. 대가는 두 가지예요: 모양이 넓어서 선택처럼 생긴 줄(`1. 다음 단계`, `tests passed or failed`)이 질문 아래에 있으면 일하는 레인도 더 자주 거절된다는 것, 그리고 질문 아래의 평범한 한 줄(`no changes yet`, `yes, go ahead`, 낱말 하나 `yes`)은 이제 선택으로 읽지 않아 거절하지 않고 보낸다는 것이에요(그 줄이 정말 선택이라면 화면의 모양이 그 줄 하나뿐인 경우가 이 기준이 놓치는 곳이에요). `usage_limit` 은 해제 시각도 UTC 로 적고, 시간대가 없거나 모르는 시간대면 "reset time is unknown" 이라고 해요(`lane-screen` 과 같은 규칙).
- **두 번 읽기**: 보내기 직전에 한 번 더 읽어서 상태가 첫 읽기와 다르면 보내지 않아요(`working` 에서 `idle` 로만 바뀌어도 거절해요). 두 읽기 사이의 틈은 0 이 되지 않아요.
- **글 검사**(`orca` 를 부르기 전에): 비어 있지 않고, `-` 로 시작하지 않고(`orca` 의 옵션으로 읽힐 수 있어요), 2000자 이하이고, `lane-duty` 의 입력 안전 규칙(제어 문자·줄 구분자·양방향 문자 거절)을 통과해야 해요. 거절한 글은 오류 글에 되풀이하지 않아요. 터미널 핸들은 영문자·숫자·`.`·`_`·`-` 128자 이하이고 영문자나 숫자로 시작해야 해요.
- **Enter**: `--enter` 를 줄 때만 보내요. 기본은 글만 넣어요.
- **보내기 실패**: `orca terminal send` 가 실패하면 종료 코드 1 과 "lane send failed" 오류를 줘요. 보냈다고 말하지 않고 다시 보내지도 않아요. 프로그램이 종료 코드 0 으로 끝나도 답을 읽어서, 답이 JSON 객체이고 `ok` 가 `true` 일 때만 보냈다고 해요(읽기 쪽과 같게). `ok: false` 면 "answered ok:false" 와 Orca 의 오류 글 한 줄(제어 문자 없이 160자까지)로, 답이 글자뿐이거나 비어 있거나 `ok` 가 없거나 불리언이 아니면 "not an Orca answer" 와 "글이 레인에 닿았을 수 있어요" 로 실패해요(B2).
- **`orca` 호출**: 프로그램은 `MOAI_ORCA_BIN`(없으면 PATH 의 `orca`)이고, 호출 하나는 15초(`MOAI_ORCA_TIMEOUT_SECS` 로 1에서 300초) 안에 끝나야 해요. 없거나 늦으면 `unreachable` 로 거절해요. 프로그램이 끝난 뒤 그 출력을 읽는 데도 같은 제한이 걸려요: 자식 프로세스가 출력을 계속 쥐고 있으면 제한(적어도 0.25초의 말미)이 지난 뒤 읽기를 버리고 "did not finish its output" 으로 거절해요(`lane-screen --scan` 도 같은 호출을 써요).

성공하면 결과에 `sent`(참), `terminal`, `state`(보낸 때의 상태), `evidence`(읽은 화면 줄), `enter`, `orca`(`orca terminal send` 의 JSON 답)가 있어요. 이 도구는 확인 창에 대신 답하지 않고, 기다렸다 다시 보내지도 않아요. `orca terminal send --help` 는 다른 에이전트에게는 `orca orchestration send` 를 쓰라고 해요: 이 도구는 그 길을 바꾸지 않고 `terminal send` 앞에서 화면만 지켜요.
