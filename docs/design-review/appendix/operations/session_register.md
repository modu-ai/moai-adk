# `session-register`

operation `session.register` · 코드 `src/ops/session_register.rs`, `src/lane_registry.rs` · Issue #2592 S-C (리더 결정 6856973444 = (가) 이름 등록부, 설계 6850553121)

`session-register [PROJECT] --name NAME [--instance ID | --continue] [--lease-secs 14400] [--mode leader|agent] [--release [--by leader]] [--show] [--now T]` 는 (기본 lease 는 4시간이고 #3015 C3 에서 3600초에서 늘렸다. `PROJECT` 는 `--show` 일 때만 빼도 되고, 빼면 지금 폴더가 속한 clone 을 읽는다. 등록·갱신·`--release` 는 `PROJECT` 가 꼭 있어야 하며 없으면 `PROJECT is required (only --show may leave it out)` 오류다) 레인 이름을 clone 공통 폴더의 등록부 `<clone common dir>/.moai-cli/sessions/<NAME>.json`(`-a` 번호 매기기와 같은 폴더, 모든 worktree 가 같이 본다)에 적는다. 같은 이름이 lease 안에 다른 instance 로 이미 있으면 `conflict`(`conflict in session registry: name … is in use by another instance until <UTC>`)로 거부하고 아무것도 쓰지 않는다. 그 instance 의 id 는 보여 주지 않는다. 첫 호출(`--instance` 없음)은 새 `instance`(16진수 32자)를 만들어 돌려준다. 같은 세션은 wake 마다 그 값을 `--instance` 로 넘겨 lease 를 늘린다(`renewed`). lease 가 끝난 항목은 누구나 새로 등록한다(`previous: expired`). `--release --instance ID` 는 그 instance 가 가진 이름을 지운다(`released`; 항목이 없거나 lease 가 끝났으면 `already_free`, 다른 instance 면 `conflict`). 세션을 비우기 전에 쓴다. `--show` (#2902 O3a)는 아무것도 쓰지 않고(폴더·lock 도 만들지 않는다) 현재 holder 를 `{"status":"held","name","instance","lease_until"}` 로, 항목이 없거나 lease 가 끝났으면 `{"status":"free","name"}` 으로 보여 준다. 리더는 그 `instance` 로 `--release --by leader --instance ID` 를 부른다. 같은 lock 아래의 compare-and-delete 이므로, 그 사이 다시 등록된(다른) instance 는 `conflict` 로 남고, 끝난 lease·없는 항목은 `already_free` 다. 지웠을 때만 결과에 `"released_by": "leader"` 가 붙는다. `--by` 는 `leader` 만 받고 `--release` 와만 쓴다. `--by` 없는 `--release` 의 출력은 그대로다. 이름은 `A-Z a-z 0-9 . _ -` 1~64자이고 첫 글자는 영문자나 숫자다. lease 는 60~86400초다. 쓰기는 `registry.lock` 의 배타 `File::lock` 아래에서 임시 파일 → rename 으로 한다. 링크·일반 파일이 아닌 것·4 KiB 넘는 것·형식이 틀린 항목은 거부하고 덮어쓰지 않는다. 결과: `status`(`registered`·`renewed`·`released`·`already_free`), `previous`(`none`·`expired`·`same_instance`), `name`, `instance`, `lease_until`(UTC), `entry`. 막는 범위는 같은 기기·같은 clone 이다. 다른 기기의 같은 이름은 막지 못한다(설계 (나)의 몫).

`--continue` (SPEC-20261123-lane-continues-card)는 `/clear` 나 재시작 뒤 같은 레인이 자기 이름을 이어받는 길이다. 항목의 `session` 이 다른 호스트 세션 id 이고 `worktree` 가 지금 실행 폴더의 git worktree(정규 경로)와 같을 때, 새 세션이 항목을 통째로 바꿔 쓰고(새 `instance`, `status: continued`, `previous: other_session`) 바뀐 세션 id 를 `previous_sessions` 맨 앞에 남긴다(최대 8개, 새것이 먼저). 증명이 하나라도 없으면 `session-register --continue refused: …` 로 빠진 증명을 말하고 항목은 바이트 그대로다(항목에 세션 id 가 없음, 항목에 worktree 가 없음, 항목이 다른 worktree, 이 세션에 호스트 id 가 없음, 실행 폴더가 git worktree 밖, 항목이 이미 이 세션). 항목이 없으면 보통 등록이다(`registered`). `--instance`·`--release`·`--show` 와 같이 쓰지 않는다(사용법 오류, 종료 2). `--continue` 없는 호출은 예전처럼 `conflict` 다. 모든 등록·갱신은 항목에 `worktree`(실행 폴더가 속한 git worktree 의 정규 경로; git 밖이면 키를 뺀다)를 적고, 같은 instance 갱신은 `session`·`worktree`·`previous_sessions` 를 그대로 둔다. 이 값을 읽는 쪽이 `card adopt` 다(`lane_registry::session_entries`: 읽을 수 없는 항목은 오류로 말하고 건너뛰지 않는다).

`--mode leader|agent` (#2928, 결정 D1 = (A))는 세션의 모드를 항목의 `mode` 키에 적는다. 줄 때만 적고(항목은 매번 통째로 다시 쓰므로 갱신 때도 다시 넘긴다), 같은 instance 갱신 때 새 값으로 덮는다. 결과에도 `"mode"` 가 붙는다. `leader`·`agent` 말고는 사용법 오류(종료 2)이고, `--show`·`--release` 와 함께 쓰지 않는다. `--show` 는 정확히 `leader`·`agent` 인 `mode` 만 보여 주고, 다른 글자(손으로 적은 값·제어 문자)는 보여 주지 않는다. `--mode` 없는 등록·`--show` 의 출력과 항목은 바이트 그대로다(`read_entry` 는 모르는 키를 무시해 schema 1 그대로). 상태줄은 `lane_registry::mode_of(common, name, now)` 로 읽는다: 잠금·폴더 생성 없음, 링크·4 KiB 초과·잘못된 이름·형식이 틀린 항목은 없음으로, `entry.name == name` 이고 `lease_until > now` 이고 `mode` 가 정확히 `leader`/`agent` 일 때만 값을 준다. 상태줄 셋째 줄의 이름표는 이 값이 `leader` 일 때만 `leader`, 그 밖은 모두 `agent` 다.

`--mode leader` 는 등록된 조정 창이다 (SPEC-20261123-leader-registration-lease). 세 가지를 더한다. (1) 이 세션에 호스트 세션 id(`CLAUDE_CODE_SESSION_ID`·`CODEX_THREAD_ID`)가 없으면 폴더도 잠금 파일도 만들기 전에 거부한다(`leader registration refused: … no host session id`). id 가 있으면 항목의 `session` 에 적는다. (2) `mode` 가 `leader` 이고 lease 가 `now` 보다 늦게 끝나는 항목이 다른 이름으로 이미 있으면 `conflict in session registry: the leader entry `<이름>` is live until <UTC>` 로 거부하고 아무것도 쓰지 않는다. 그 항목의 instance 는 보여 주지 않는다. 같은 이름을 다른 instance 가 쥔 경우는 위의 이름 conflict 가 그대로 막는다. 첫 항목의 lease 가 끝나면 다른 창이 등록한다. `agent` 모드 등록은 leader 항목에 막히지 않는다. 항목을 읽지 못하면 둘째 창이 있는지 판단할 수 없으므로 그 오류 그대로 거부한다. (3) 같은 instance 갱신은 항목의 `session` 과 같은 세션에서만 받는다(다르면 `leader renewal refused: … another host session`, 항목은 바이트 그대로). 세션 id 없이 쓰인 옛 항목은 갱신하는 세션의 id 로 채운다. `--continue` 는 leader 에도 그대로이고 `/clear` 뒤 새 세션이 이어받는 길이다.

`--show` 는 항목에 모양이 맞는 `session` 이 있으면 `"session"` 도 보여 준다(레인이 살아 있는 조정 창의 세션 id 를 읽는 길). `--liveness-of <세션 id>` 는 그 id 를 적은 항목이 `mode: leader` 이고 lease 가 남아 있고 `.live` 잠금 파일이 없으면 `alive` 로 답하고 evidence 에 `name`·`lease_until`·`basis: registry_lease` 를 담는다(런처 없이 열린 창은 lease 가 유일한 흔적이다). `.live` 파일이 있으면 런처의 말이 우선이라 예전 답 그대로이고, leader 가 아닌 항목은 lease 로 살아 있다고 보지 않는다. 읽기 전용이라 아무것도 쓰지 않는다. 갱신이 빠졌는지는 `leader-round` 의 `registration` 부분이 보여 준다(`docs/design-review/appendix/operations/leader_round.md`).
