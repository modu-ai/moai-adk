# `project-detect`

operation `project.detect` · 코드 `src/ops/project_detect.rs` · #2496

`project-detect PROJECT` 는 `/moai project` 경로를 위해 프로젝트 사실(새 프로젝트인지, manifest, 언어, 언어 서버, 설정된 MCP 서버 이름, 데이터베이스)을 찾는다. 읽기만, `detected` 가 채워진 프로필을 `project-plan` 에 넘긴다. `src/main.rs` 에서 그대로 옮김(#2834 R4a).

규모(SPEC-20261122-project-scale, 코드 `src/project_scale_detect.rs`): 결과에 `detected` 옆으로 `scale` 이 붙는다(프로필에는 들어가지 않는다). `kind` 는 `small`·`large_tree`·`monorepo` 중 하나이고 사용자의 선택이 이긴다. 작업 공간 표지(`pnpm-workspace.yaml`·`lerna.json`·`nx.json`·`turbo.json`·`rush.json`·`go.work`, 루트 `package.json` 의 `workspaces` 키, 루트 `Cargo.toml` 의 `[workspace]` 표)가 하나라도 있거나 manifest 가 있는 하위 폴더가 3개 이상이면 `monorepo`, 그 밖에 추적 파일이 5,000개 이상이면 `large_tree`, 아니면 `small`. 두 기준은 moai 의 기본값이다(공식 문서도 블로그도 숫자를 주지 않는다). `tracked_files` 는 git 인덱스 머리의 항목 수를 읽는다(프로그램을 시작하지 않는다. 링크된 워크트리는 `.git` 포인터가 가리키고 그 폴더가 이 폴더를 되가리키는 관리 폴더의 인덱스만 읽고, 링크인 `.git` 은 따라가지 않는다). 인덱스를 읽을 수 없으면 제한된 걷기(폴더 깊이 3, 항목 5,000)의 파일 수를 세고 `lower_bound` 가 `true` 이다. `markers`·`packages`(최대 64개)·`manifest_folders` 도 함께 나온다. 읽기만 하고 아무것도 쓰지 않는다.

버저닝(card C-69): 결과에 `detected` 옆으로 `versioning` 이 붙는다(프로필에는 들어가지 않는다). `scheme` 은 `semver`·`calver`·`headver`·`mixed`·`none` 중 하나, `latest` 는 버전으로 읽힌 가장 높은 값(날짜순이 아니라 버전순: 숫자 마디를 차례로 비교한 뒤 pre-release 를 SemVer 2.0.0 §11.4 순서로 비교, 그래서 `rc.10` 이 `rc.2` 보다 높다. 없으면 `null`), `evidence` 는 버전순으로 가장 높은 태그 이름 최대 5개(`mixed` 이면 거기에 없는, 센 방식마다의 가장 높은 태그를 덧붙임)와 루트 `Cargo.toml`·`package.json`·`pyproject.toml` 의 버전을 `source`·`value`·`shape` 로 적은 목록, `tags` 는 태그를 읽은 결과(`read`·`no_repository`·`unavailable`)이고 `unavailable` 이면 `tags_reason` 이 이유를 적는다. 태그 중 하나라도 모양이 읽히면 태그가 정하고, 아니면 매니페스트가 정한다. 두 가지로 읽히는 모양(`26.4.1`, `16.4`)은 `shape: ambiguous` 와 `note` 로 적고 세지 않는다. HeadVer 모양은 모두 SemVer 로도 유효하므로 `note` 에 그렇게 적고, 첫 숫자(major)가 같은 SemVer 태그가 있을 때만 SemVer 로 센다(`v1.999.0`·`v1.1000.0`·`v1.1001.0` 은 `semver`). 남은 HeadVer 태그의 head 가 모두 모든 SemVer major 보다 크면(그래서 모든 HeadVer 태그가 모든 SemVer 태그보다 높게 정렬되면) SemVer 에서 HeadVer 로 옮겨 간 것으로 보고 `headver` 로 낸다(`v3.0.0`·`v3.2.0`·`4.2647.1`·`4.2647.3` 은 `headver`, `latest` 는 `4.2647.3`). 그 밖의 섞임(`v5.0.0` 옆의 `3.2647.1`)은 `mixed` 이다.

태그 이름은 파일에서만 읽는다. 프로그램을 시작하지 않고, git 객체와 git 설정을 읽지 않으며, 아무것도 쓰지 않고 네트워크를 쓰지 않는다. `<project>/.git` 이 실제 폴더이면 `refs/tags` 아래 일반 파일의 이름(내용은 읽지 않음. 링크는 태그가 아니며 따라가지 않음. 디렉터리 항목 최대 2,000개, 폴더는 4마디 이름까지만 들어가고 더 깊은 이름은 건너뜀)과 `packed-refs` 의 `<id> refs/tags/<이름>` 줄(일반 파일, 최대 4 MiB, `^` 줄은 건너뜀)을 읽는다. `.git` 이 파일이면 연결된 작업 트리일 때만 따라간다: `gitdir: <경로>`(상대 경로면 프로젝트 폴더 기준)가 가리키는 관리 폴더에 `commondir` 와 `gitdir` 파일(상대 경로면 관리 폴더 기준)이 있고, `gitdir` 가 `<project>/.git` 을 되가리키며, 관리 폴더가 `commondir` 가 가리키는 공통 폴더의 `worktrees/<이름>` 일 때, 그 공통 폴더에서 같은 규칙으로 읽는다(`git worktree add --relative-paths` 가 쓰는 상대 포인터도 읽힌다). 공통 폴더는 프로젝트 밖에 있다. 관리 폴더와 공통 폴더 자체는 실제 폴더인지(링크가 아닌지) 확인하지만, 거기까지 가는 경로의 링크는 따라간다. 그 밖의 경우(`.git` 이 링크, 서브모듈 포인터, 이 폴더를 되가리키지 않는 저장소를 향한 포인터, 공통 폴더의 `worktrees` 밖에 만든 관리 폴더, `refs`·`refs/tags`·`packed-refs` 가 링크나 특수 파일, 한도 초과)는 `tags: unavailable` 과 이유를 내고 태그를 읽지 않는다. `.git` 이 없으면 `no_repository` 이고 상위 폴더 저장소는 읽지 않는다. 짧고 평범한 이름(ASCII 영숫자와 `. - _ + / @`, 64바이트 이하)만 후보가 되고 출력에 나온다. 모양 판정 규칙은 `src/versioning.rs` 와 `skills/moai/references/internal/versioning.md`.
