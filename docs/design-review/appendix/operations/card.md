# `card`

operation `card` · 코드 `src/ops/card.rs`, `src/card/command.rs`, `src/card/dispatch.rs`, `src/card/work.rs`, `src/ledger/workflow.rs` · Issue #3070 C1 (PLAN 댓글 6905829690, 명령 모양 6898149938), 카드 C-53 S1(작업·마감 경로)

`card <동작>` 은 프로젝트 로컬 원장(#3068)의 카드를 읽고 쓴다. 낱말 하나에 동작이 중첩돼 있고 봉투의 `operation` 은 항상 `card`, 동작은 결과의 `action` 으로 나간다. 모든 동작의 도움말 첫 문장은 `Reads the ledger only.` 또는 `Writes the ledger.` 로 시작한다(시험이 묶는다). **원장 파일과 폴더는 `ledger-register-apply` 만 만든다**; `card` 의 어떤 동작도 만들지 않는다.

- `rev` 는 기준을 하나 넣을 때마다 스키마 트리거(`card_touch_ac_insert`)가 올려서, 기준이 n 개인 새 카드는 `1 + n` 이다.
- 시각은 모두 트랜잭션의 DB 시계 값(`unixepoch()`)이다. `--by` 기본값 `user`(1–80자 한 줄).
- 오류: 원장이 없으면 `not_found`(안내 문장에 `ledger-register-plan` → `ledger-register-apply`), 쓸 수 없는 원장·WAL·낯선 파일은 `blocked`, 거절된 입력은 `card <동작> refused: …` (`invalid_input`), 쓰기 잠금을 오래 못 잡으면 `io`(`retryable`, 원장 메시지는 `ledger busy`). 제목·기준은 앞뒤 공백을 잘라서 저장한다. 새 `kind` 를 만들지 않는다.

- **보유자는 입력이 아니라 이 세션의 id** 다: `take`·`release`·`handoff` 는 호스트가 세션에 설정한 `CLAUDE_CODE_SESSION_ID`(없으면 `CODEX_THREAD_ID`)를 `session_current::resolve` 로 읽어 쓴다. 없거나 모양이 틀리면 `card <동작> refused: this session has no id …`(`invalid_input`)이고 아무것도 안 바뀐다. `--holder` 옵션은 없다(#3115 판정 N1: 보유자 이름만 알면 남의 카드를 풀 수 없게). 환경변수를 위조하는 호출자까지 막지는 않는다.
- `take` 는 `--scope` 가 없을 때 카드의 쓰기 범위를 쓰기 트랜잭션 **밖에서** 읽는다. 카드 범위를 바꾸는 명령(K3 `edit`)이 아직 없어 지금은 경쟁이 없다. `edit` 를 더하는 조각은 이 읽기를 트랜잭션 안으로 옮기거나 범위가 바뀌면 예약을 거절해야 한다(#3121 판정 N).
- `ready` 는 살아 있는 예약(`held`·`expired_candidate`·`held_for_review`)이 있는 카드를 거절한다(`hold` 를 만드는 명령이 생기기 전에 두 번째 보유자 자리를 막는 장치, #3121 판정 D4). 상태 확인이 먼저라서 `active` 카드는 예약이 아니라 상태("is `active`" 문구)로 거절된다(#3122 판정 메모).
- 잘못된 종류·우선순위·상태·카드 이름을 오류 문장이 되풀이할 때는 40자까지만, 제어 문자(C0·DEL·C1)·줄/문단 구분(U+2028·2029)·방향 표식과 덮어쓰기·격리(U+200E·200F·061C·202A–202E·2066–2069)·폭 없는 글자(U+200B·2060·FEFF)는 `?` 로 바꾼다. 글자를 잇는 U+200C·200D 는 그대로 둔다(`input::echo`, 판정 D3 와 #3122 판정 메모). 본문은 데이터라 JSON 에 바이트 그대로 나간다(JSON 은 U+0020 아래만 이스케이프).
- 예약 규칙(세대·lease·쓰기 범위·울타리)은 #3068 P3(`src/ledger/reservation.rs`, `ledger_reservation.md`)의 것이다. `ready`·`take`·`release`·`handoff` 는 `C-n` 으로만 부르고(`#번호` 는 거절), P3 의 거절 문장이 그대로 나가 계약 분류가 `not_found`(`card not found`)·`conflict`(`conflict in`)·`invalid_input`(`invalid reservation input`)을 정한다.
- `export` 의 도움말 첫 문장은 `Reads the ledger only. Writes files only inside --out.` 이다(원장을 읽기만 하고 파일은 `--out` 안에만 쓴다는 뜻). 카드 하나만 내보내기(`export C-n`)는 아직 없다: 링크가 가리키는 다른 카드·사건을 어떻게 자를지가 형식 결정이라 K0 형식이 정한 뒤에 한다. 손상된 원장을 `.bak` 에서 되살리는 일은 `card` 가 아니라 `ledger-recover-*`(#3068 P6)의 몫이다.
- `export` 의 내용은 원장이 가진 것 그대로다: 카드 글(제목·본문·기준·메모·링크)과 **모든 이벤트의 payload**. 이벤트 payload 에는 예약의 `holder`(세션 id)와 `lease_until` 이 들어 있어서(`src/ledger/reservation.rs`), 원장 밖으로 나가는 순간 같은 컴퓨터의 다른 사용자나 공유 대상에게 보인다. 그래서 만든 폴더는 0700·파일은 0600 이고(유닉스; Windows 는 폴더의 기본 접근 권한을 따른다), 도움말도 "공유하기 전에 확인하라"고 적는다. 카드 글에는 앞으로 GitHub 에서 가져온 제3자 글(카드 가져오기)이 들어갈 수 있다. 읽기 전용은 시험으로 고정돼 있다: 남은 롤백 저널이 있는 원장은 쓰기 연결이라면 되돌려 쓰고 말 일인데, `export` 는 `needs_recovery` 로 거절하고 원장·저널·폴더를 그대로 둔다(`tests/card_export_cli.rs`).
- **작업·마감 경로(C-53 S1)**: `next` → `take` → `note`(PLAN·보고·결정) → `criterion` → `pr` → `review` → (검토 FAIL 이면 `reopen` → 고침 → `review`) → (병합 뒤) `pr` → `done`. GitHub Issue 없이 카드 하나를 찾고, 하고, 닫는다. 스키마는 바꾸지 않았다(결정 U3): 닫는 길은 `review → done` 하나이고 `active → done` 은 `card_transition` 에 없어서 `done` 은 `review` 카드만 받는다. `done` 의 세 조건은 트리거 `card_done_guard` 와 같은 순서·같은 문장으로 먼저 검사하고, 트리거는 마지막 방어선으로 남는다.
- **쓰는 동작의 울타리**: `criterion`·`pr`·`review`·`reopen`·`done`·`renew` 는 `release` 처럼 이 세션의 id 와 `--generation` 이 지금 예약과 같아야 한다. 옛 세대·다른 세션은 P3 의 문장 그대로 `conflict` 이고 `fence_reject` 사건 한 줄이 남는다(`op` 는 동작 이름). `criterion`·`review`·`reopen`·`renew` 는 살아 있는 lease 가 필요하고, `pr`·`done` 은 `release` 와 같이 lease 가 끝났어도 된다: PR 병합은 lease 보다 늦을 수 있고, 죽은 보유자의 카드를 되찾는 동작(S6)이 아직 없다. `note` 에는 울타리가 없다: 결정 요청(`LANE-BLOCKED` 줄)에 답하는 사람은 보유자가 아니다(결정 L3). 작성자는 `--by`, 없으면 세션 id, 그것도 없으면 `user`. 다만 **결정 메모(`decision`)는 `--by` 없이는 거절**하고(세션 없는 호출자가 `user` 로 서명되지 않게), 어떤 메모든 `card.note` 사건에 **쓴 세션 id**(없으면 `null`)가 `--by` 와 상관없이 남아 `card show` 가 작성자 옆에 보여 준다. 레인은 결정 메모를 따르기 전에 `author` 와 `session` 을 함께 본다. 환경변수를 위조하는 호출자까지 막지는 않는다(보유자 규칙과 같은 한계).
- **`pr` 의 호스트 읽기는 `src/card/work.rs` 에만 있다**: `src/ledger/` 는 프로세스·소켓·URL 을 갖지 않는다(`tests/home_isolation_scan.rs`). `work::pr` 은 `HostConnector` 를 받아 `pr_state` 한 번만 부르고, 보유자 확인(`workflow::holder_check`)을 호스트보다 먼저 해서 거절될 호출자는 요청을 만들지 않는다. 병합됐다는데 병합 커밋이 없으면 기록하지 않는다. 시험은 `FakeConnector` 와 가짜 `gh`(`MOAI_FORGE_GH_BIN`)를 쓰고 네트워크에 나가지 않는다. `MOAI_FORGE_GH_BIN` 은 제품 바이너리도 읽는 기존 시험용 이음매다(`forge::transport::GhTransport::from_env`: 존재하는 일반 파일의 절대 경로만 받음; `card-import-*`·`card-summary-*` 와 같다). 이 변수를 설정할 수 있는 사람은 `card pr` 이 읽는 PR 상태를 꾸밀 수 있으므로 제품 경로에서는 설정하지 않는다; 이 조각은 그 설계를 바꾸지 않았다.
- **`check` 의 범위 판정은 `workflow::covers`** 다: 패턴 자신, 평범한 패턴의 아래 전부, 한 구간 안의 `*`, 여러 구간의 `**`. `scope::overlap` 과 같은 정규화(소문자, `.`·`..` 해석)를 쓰지만 대칭이 아니다: 패턴보다 **위** 폴더(`src/card/` 에 대한 `src`)나 저장소 밖으로 나가는 경로는 덮지 않는다. 판정은 **경로 글자만** 본다: 디스크의 심볼릭 링크를 따라가지 않으므로 범위 안 경로가 범위 밖을 가리키는 링크여도 통과한다(실제 쓰기 가드가 링크를 봐야 한다, S3). `take --scope` 는 `add --scope` 만큼 검사하지 않는다(P3 의 길이·제어 문자 검사뿐인 기존 코드, 이 조각에서 바꾸지 않음). `check` 는 읽기 전용이라 거절을 기록하지 않는다; 커밋·푸시 가드에 묶는 일(기록하는 `fence`)은 S3 이다.
- `next` 가 건너뛰는 이유는 `take` 가 거절하는 이유와 같다: 다른 세션의 예약(`AlreadyHeld`), 다른 카드 예약과 겹치는 범위(`ScopeOverlap`, 자기 카드와의 겹침 포함), 빈 범위(`EmptyScope`). `draft`·`hold`·`done` 카드는 목록에 없다(다른 세션이 잡고 있는 카드는 상태와 무관하게 `held` 로 나온다). 아무도 잡고 있지 않은 `review` 카드는 `review_no_holder` 로 나온다: `release` 가 `review` 카드를 거절하므로 명령으로는 생기지 않고(옛 빌드·손으로 고친 원장), 되찾기(S6)가 생길 때까지 사람이 봐야 한다. 이 거절은 명령 층(`dispatch::release`)에 있고 라이브러리 `reservation::release` 는 그대로다(`tests/ledger_reservation.rs` 가 묶은 P3 동작).
- 아직 없는 동작: `edit`·`hold`·죽은 보유자 되찾기(S6)·링크 물리기(`retired`)·`restore --from-export`·`backup`.
