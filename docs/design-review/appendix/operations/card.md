# `card`

operation `card` · 코드 `src/ops/card.rs`, `src/card/command.rs`, `src/card/dispatch.rs`, `src/card/work.rs`, `src/card/spec_link.rs`, `src/card/finish.rs`, `src/card/landed.rs`, `src/ledger/workflow.rs` · Issue #3070 C1 (PLAN 댓글 6905829690, 명령 모양 6898149938), 카드 C-53 S1(작업·마감 경로), SPEC-20261117-card-spec-link(SDD-4, 카드 ↔ SPEC 연결)

`card <동작>` 은 프로젝트 로컬 원장(#3068)의 카드를 읽고 쓴다. 낱말 하나에 동작이 중첩돼 있고 봉투의 `operation` 은 항상 `card`, 동작은 결과의 `action` 으로 나간다. 모든 동작의 도움말 첫 문장은 `Reads the ledger only.` 또는 `Writes the ledger.` 로 시작한다(시험이 묶는다). **원장 파일과 폴더는 `ledger-register-apply` 만 만든다**; `card` 의 어떤 동작도 만들지 않는다.

- `export` 의 내용은 원장이 가진 것 그대로다: 카드 글(제목·본문·기준·메모·링크)과 **모든 이벤트의 payload**. 이벤트 payload 에는 예약의 `holder`(세션 id)와 `lease_until` 이 들어 있어서(`src/ledger/reservation.rs`), 원장 밖으로 나가는 순간 같은 컴퓨터의 다른 사용자나 공유 대상에게 보인다. 그래서 만든 폴더는 0700·파일은 0600 이고(유닉스; Windows 는 폴더의 기본 접근 권한을 따른다), 도움말도 "공유하기 전에 확인하라"고 적는다. 카드 글에는 앞으로 GitHub 에서 가져온 제3자 글(카드 가져오기)이 들어갈 수 있다. 읽기 전용은 시험으로 고정돼 있다: 남은 롤백 저널이 있는 원장은 쓰기 연결이라면 되돌려 쓰고 말 일인데, `export` 는 `needs_recovery` 로 거절하고 원장·저널·폴더를 그대로 둔다(`tests/card_export_cli.rs`).
- **작업·마감 경로(C-53 S1)**: `next` → `take` → `note`(PLAN·보고·결정) → `criterion` → `pr` → `review` → (검토 FAIL 이면 `reopen` → 고침 → `review`) → (병합 뒤) `pr` → `done`. GitHub Issue 없이 카드 하나를 찾고, 하고, 닫는다. 스키마는 바꾸지 않았다(결정 U3): 닫는 길은 `review → done` 하나이고 `active → done` 은 `card_transition` 에 없어서 `done` 은 `review` 카드만 받는다. `done` 의 세 조건은 트리거 `card_done_guard` 와 같은 순서·같은 문장으로 먼저 검사하고, 트리거는 마지막 방어선으로 남는다.
- **쓰는 동작의 울타리**: `criterion`·`pr`·`review`·`reopen`·`done`·`renew` 는 `release` 처럼 이 세션의 id 와 `--generation` 이 지금 예약과 같아야 한다. 옛 세대·다른 세션은 P3 의 문장 그대로 `conflict` 이고 `fence_reject` 사건 한 줄이 남는다(`op` 는 동작 이름). `criterion`·`review`·`reopen`·`renew` 는 살아 있는 lease 가 필요하고, `pr`·`done` 은 `release` 와 같이 lease 가 끝났어도 된다: PR 병합은 lease 보다 늦을 수 있고, 죽은 보유자의 카드는 `card reclaim` 이 되찾는다. `note` 에는 울타리가 없다: 결정 요청(`LANE-BLOCKED` 줄)에 답하는 사람은 보유자가 아니다(결정 L3). 작성자는 `--by`, 없으면 세션 id, 그것도 없으면 `user`. 다만 **결정 메모(`decision`)는 `--by` 없이는 거절**하고(세션 없는 호출자가 `user` 로 서명되지 않게), 어떤 메모든 `card.note` 사건에 **쓴 세션 id**(없으면 `null`)가 `--by` 와 상관없이 남아 `card show` 가 작성자 옆에 보여 준다. 레인은 결정 메모를 따르기 전에 `author` 와 `session` 을 함께 본다. 환경변수를 위조하는 호출자까지 막지는 않는다(보유자 규칙과 같은 한계).
- **`pr` 의 호스트 읽기는 `src/card/work.rs` 에만 있다**: `src/ledger/` 는 프로세스·소켓·URL 을 갖지 않는다(`tests/home_isolation_scan.rs`). `work::pr` 은 `HostConnector` 를 받아 `pr_state` 한 번만 부르고, 보유자 확인(`workflow::holder_check`)을 호스트보다 먼저 해서 거절될 호출자는 요청을 만들지 않는다. 병합됐다는데 병합 커밋이 없으면 기록하지 않는다. 시험은 `FakeConnector` 와 가짜 `gh`(`MOAI_FORGE_GH_BIN`)를 쓰고 네트워크에 나가지 않는다. `MOAI_FORGE_GH_BIN` 은 제품 바이너리도 읽는 기존 시험용 이음매다(`forge::transport::GhTransport::from_env`: 존재하는 일반 파일의 절대 경로만 받음; `card-import-*`·`card-summary-*` 와 같다). 이 변수를 설정할 수 있는 사람은 `card pr` 이 읽는 PR 상태를 꾸밀 수 있으므로 제품 경로에서는 설정하지 않는다; 이 조각은 그 설계를 바꾸지 않았다.
- **`check` 의 범위 판정은 `workflow::covers`** 다: 패턴 자신, 평범한 패턴의 아래 전부, 한 구간 안의 `*`, 여러 구간의 `**`. `scope::overlap` 과 같은 정규화(소문자, `.`·`..` 해석)를 쓰지만 대칭이 아니다: 패턴보다 **위** 폴더(`src/card/` 에 대한 `src`)나 저장소 밖으로 나가는 경로는 덮지 않는다. 판정은 **경로 글자만** 본다: 디스크의 심볼릭 링크를 따라가지 않으므로 범위 안 경로가 범위 밖을 가리키는 링크여도 통과한다(실제 쓰기 가드가 링크를 봐야 한다, S3). `take --scope` 는 `add --scope` 와 같은 검사(`card::input::validate_scope`)를 거친 뒤 P3 의 길이·제어 문자 검사를 받는다(카드 C-68 N-e). `check` 는 읽기 전용이라 거절을 기록하지 않는다; 커밋·푸시 가드에 묶는 일(기록하는 `fence`)은 S3 이다.
- `next` 가 건너뛰는 이유는 `take` 가 거절하는 이유와 같다: 다른 세션의 예약(`AlreadyHeld`), 다른 카드 예약과 겹치는 범위(`ScopeOverlap`, 자기 카드와의 겹침 포함), 빈 범위(`EmptyScope`). `draft`·`hold`·`done` 카드는 목록에 없다(다른 세션이 잡고 있는 카드는 상태와 무관하게 `held` 로 나온다). 아무도 잡고 있지 않은 `review` 카드는 `review_no_holder` 로 나온다: `release` 가 `review` 카드를 거절하므로 명령으로는 생기지 않고(옛 빌드·손으로 고친 원장), `card reclaim` 은 `held` 예약이 있는 카드만 되찾으므로 이 카드는 여전히 사람이 봐야 한다. 이 거절은 라이브러리 `reservation::release` 의 트랜잭션 안에 있어(카드 C-68 N-a) 라이브러리 호출자도 같은 거절(`FenceError::CardInReview`, 사건 없음)을 받는다. `tests/ledger_reservation.rs` 의 "옮겨 간 카드는 상태를 지킨다" 고정은 `review` 대신 `hold` 로 그 뜻을 지킨다.
- **카드 ↔ SPEC 연결(SDD-4)**: 카드는 이 컴퓨터의 개인 할 일이고 SPEC 은 git 이 추적하는 공유 파일이라, 연결은 카드 쪽(원장)에만 있다. SPEC 에는 `cards:` 키가 없고 카드 번호를 쓰지 않는다. 스키마는 바꾸지 않았다: 연결은 `event` 표의 `card.spec` 사건이라 버전 1 원장이 그대로 받고, `card export` 의 `events.jsonl` 에도 남는다(카드 파일 `C-n.md` 에는 안 보임). `moai spec show <ID>` 의 `local_cards` 가 반대 방향(이 SPEC 을 가리키는 이 컴퓨터의 카드)을 보여 준다.
- **`reclaim`(SPEC-20261119-card-reclaim)**: 보유자가 떠나 lease 가 끝난 카드(`review` 에서 멈춘 카드 포함)를 다른 세션이 이어받는 유일한 길이다. 원장 파일을 직접 고치거나 강제로 인수하지 않는다. lease 가 "끝났다" 는 판정은 울타리·`release`·`reclaim` 이 `lease_ended`(`lease_until <= now`) 한 함수로 내린다. 원장은 세션을 알 뿐 역할(리더·사용자)을 모르므로 `--by` 는 감사용 이름이고 위조될 수 있다(새 보유자의 세션 id 가 사건에 따로 남는다). 옛 보유자가 정말 끝났는지(프로세스·미커밋·미push·외부 작업)는 **확인하지 않는다**: 부른 쪽이 `--reason` 에 적는다. 후속 조각: 그 대조, "회수는 세 번까지" 한도, 살아 있는 lease 를 사용자가 되찾기(결정 L7), `expired_candidate`(만드는 코드가 아직 없음).
- 아직 없는 동작: `edit`·`hold`·링크 물리기(`retired`)·`restore --from-export`·`backup`·`add --spec`.
