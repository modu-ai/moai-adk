# `lane-next`

operation `lane.next` · 코드 `src/ops/lane_next.rs`, `src/lane_next.rs` · Issue #2831, #2873

`lane-next --lane NAME --repo OWNER/REPO [--tip BRANCH] [--wait SECS] [--shared-lanes N] [--dir .] [--snapshot FILE]` 는 이 레인이 **지금 할 일 하나**와 그 근거를 낸다. 매번 GitHub 에서 다시 읽어 계산하므로, 정지·압축 뒤 첫 실행도 놓친 일을 낸다. 순서(#1975 6855190942): P0 tip 빨강(#2831 D8(a): 모음 check `ci`/`rc-ci` 는 따로 보지 않고 취소된 job 도 빼고, 남은 job 이 그 커밋에서 실패만 했을 때 빨강 — 새 push 가 macOS 를 취소해 모음 `ci` 가 failure 인 경우는 빨강이 아님. 마지막으로 끝난 tip 커밋까지 first-parent 로 최대 10개를 거슬러 읽음. 본문에 `moai-tip-repair:` 줄이 있는 열린 PR 이 있으면 그 PR 저자만 자기 PR 로 고치고, 다른 레인은 `waiting` 에 `tip_repair_open` 으로 적힌 채 다음 순위로 감 — #2873 N2) → P1 내 PR(지금 head 의 감사 FAIL, 충돌, CI 실패) → P1 내가 감사 예약한 PR(판정 없음, 내 판정 뒤 head 가 바뀜, 재감사 요청 댓글 — 지금 head 40자와 함께) → P1 감사자 없는 남의 PR(초안 아님) → 내 `LANE-BLOCKED … kind=decision` 뒤에 `LEADER-DECISION` 이 달린 스레드(그 뒤에 `DECISION-APPLIED <결정 댓글 id>` 줄이 있으면 이미 반영한 것이라 빼요 — #2873 N11) → P2 내가 claim 한 카드(내 열린 PR 이 없고, 결정 대기가 아니고, claim 뒤 `pr-wait:` 줄이 있는데 내 PR 이 없으면 `open_draft_pr` — 상한 때문에 못 연 가지를 초안으로 열라는 할 일, 리더 결정 #1975 6870150891. 그 claim 을 본문 `Moai-Claim:` 에 담은 PR 이 병합됐으면 — `pr-wait` 보다 뒤에 병합됐거나 시각을 모르면 — 초안 대신 `card_pr_merged`: 카드가 끝났으면 닫기 대조표와 claim 해제, 아니면 이어서 — #2873 N8) → P2–P4 아무도 claim 하지 않은 열린 Issue(`hold` 라벨 제외). 내 PR·내 claim 은 `Moai-Claim: <issue>#<comment>` 와 그 댓글의 `moai-claim: session=<lane>` 로, 감사 예약은 `moai-audit-claim: lane=<lane> head=<40hex>` 로, 판정은 첫 줄 `AUDIT #… head <40hex> … verdict: PASS|FAIL` 로 읽는다. `LANE-BLOCKED` 줄은 레인 이름을 담거나 레인이 claim 한 스레드에 있어야 그 레인 것이다.

읽기만 한다(쓰기 0). 한 번 읽기에 GitHub 요청은 최대 30(높은 순위부터 읽고, 모자라면 `partial` 에 무엇을 못 읽었는지 적는다). 열린 PR 과 그 댓글(PR 마다 최근 100개), 레인의 검색 두 개, 오래된 열린 Issue 목록은 GraphQL 요청 하나로, PR 의 claim Issue·레인 스레드·열린 Issue 의 댓글과 병합된 참조 PR 은 Issue 25개마다 GraphQL 요청 하나로 읽는다(#2873 N1). 그래서 PR 이 40개여도 요청 수는 몇 개로 일정하다. REST 로는 tip 판정, 내 PR 의 check run, 최근 100개 밖의 claim 댓글만 읽는다. `--wait` 는 할 일이 생길 때까지 ⌈3600 × 30 × N / 2500⌉초마다 다시 읽는다(3600초 이하). N 은 한 토큰을 같이 쓰는 레인 수로 `--shared-lanes`(기본 10 → 432초, 1–50)이며, 그만큼 레인이 같이 돌아도 GitHub 시간당 5,000건의 절반(2,500) 안이 된다(#2873 N9). 결과에 `poll_secs` 로 적는다. `--tip` 이 없으면 열린 PR 들이 가장 많이 겨누는 base 를 tip 으로 쓴다. `--snapshot` 은 저장한 스냅숏(JSON)으로 판정만 한다. 결과: `lane`, `next`(`priority`·`kind`·`target`·`action`·`evidence` 또는 `null`), `waiting`(답이 아직 없는 결정 요청, 열린 tip 수리 PR), `partial`, `api_calls`, `writes: false`, `rounds`. 사람용 한 줄은 stderr 가 터미널일 때만, GitHub 에서 읽은 글은 넣지 않는다.
