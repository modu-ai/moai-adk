# `project-plan`

operation `project.plan` · 코드 `src/ops/project_plan.rs`

`project-plan PROJECT` 는 stdin 의 프로필(schema v2)로 프로젝트 프로필 미리보기를 낸다. 모르는 키나 v2 아닌 schema 는 값을 남기지 않고 거절한다(REQ-03A-08). `src/main.rs` 에서 그대로 옮김(#2834 R4a).

버저닝(card C-69): 프로필의 선택 키 `versioning` 은 `scheme`(`semver`·`headver`·`calver`·`custom`)과, 고른 경우의 `format`(CalVer 형식: 점으로 이은 토큰 2~4개, 단위마다 하나씩 연도 → 월 또는 주 → 일 → `MINOR` → `MICRO` → `MODIFIER` 순서이고 연도가 맨 앞. 일은 월 뒤에만 오므로 주와 함께 쓸 수 없고, `MODIFIER` 는 연도 바로 뒤에 올 수 없으며, `MAJOR` 는 거절한다(calver.org 에서 MAJOR 는 첫 숫자인데 여기서는 연도가 첫 숫자). `custom` 이면 사용자의 말 한 줄, 128글자 이하이고 제어 문자·`<`·`>`·백틱·`[`·`]`·`*`·`_`·`/`·`\`·줄 머리의 `#`·줄과 문단 구분 문자(U+2028, U+2029)·Unicode 가 기본 무시(Default_Ignorable_Code_Point, Unicode 18.0.0)로 정한 보이지 않는 문자(U+00AD, U+034F, U+061C, U+115F–U+1160, U+17B4–U+17B5, U+180B–U+180F, U+200B–U+200F, U+202A–U+202E, U+2060–U+206F, U+3164, U+FE00–U+FE0F, U+FEFF, U+FFA0, U+FFF0–U+FFF8, U+1BCA0–U+1BCA3, U+1D173–U+1D17A, U+E0000–U+E0FFF)·둘레 글자를 숨기거나 그리는 방식을 바꾸는 형식 문자(General_Category Cf, Unicode 18.0.0: U+00AD, U+0600–U+0605, U+061C, U+06DD, U+070F, U+0890–U+0891, U+08E2, U+180E, U+200B–U+200F, U+202A–U+202E, U+2060–U+2064, U+2066–U+206F, U+FEFF, U+FFF9–U+FFFB, U+110BD, U+110CD, U+13430–U+1343F, U+1BCA0–U+1BCA3, U+1D173–U+1D17A, U+E0001, U+E0020–U+E007F)가 없어야 함)·`head`(HeadVer 의 head, 0 이상 9999 이하의 정수)를 담는다. 모르는 방식, SemVer·HeadVer 의 `format`, HeadVer 가 아닌 방식의 `head`, 모르는 필드, 객체가 아닌 값(배열·문자열)은 값을 남기지 않고 거절한다. 키가 없으면 선택이 기록되지 않은 것이고, 키가 생기기 전에 쓴 프로필은 그대로 읽힌다.

결정 값의 명령(SPEC-20261126-profile-command-values): 결정(`decisions`)의 `value` 는 `go test ./...`·`./gradlew build` 처럼 `/` 가 든 명령을 받는다. 모든 `/` 는 이름 글자(ASCII 영문자·숫자와 `.` `_` `-` `*` `/`) 바로 뒤에 있어야 한다. 또 다음 값은 거절한다: 비었거나 공백뿐인 값, 256바이트를 넘는 값, 제어 문자나 백슬래시가 든 값, 프로필의 비밀 모양 검사나 밖으로 내보내는 글의 가림 검사(값 전체와, `/` 와 `=` 에서 나눈 각 조각에 돌린다)에 걸리는 값, `~/` 가 든 값, 홈 변수 `HOME`·`USERPROFILE`·`HOMEDRIVE`·`HOMEPATH` 의 `$이름` 이나 `${이름`(대소문자 무관) 뒤에 변수 이름 글자(ASCII 영문자·숫자·`_`)가 이어지지 않고 ASCII 공백으로 나눈 같은 낱말의 나머지에 `/` 가 있는 값(`$HOME/x`, `$HOME.d/x`, `${HOME}$X/x`, `$HOMEDRIVE$HOMEPATH/x`. `$HOMEBREW_PREFIX` 는 다른 변수다), 한 낱말에서 `@` 앞(낱말 처음이나 마지막 `/` 부터)에 양쪽으로 글자가 하나 이상 있는 `:` 가 있고 그 `@` 뒤의 같은 낱말에 `/` 가 있는 값(`user:pw@host/db`), 맨 앞이나 이름 글자가 아닌 글자 뒤의 `~` 가 사용자 이름 글자(ASCII 영문자·숫자와 `_` `.` `+` `-`)만 거쳐 `/` 에 이르는 값(`~name/x`), 맨 앞이나 이름 글자가 아닌 글자 뒤의 `-` 로 시작하는 플래그(`-` 에 이어지는 ASCII 영문자·숫자·`-`) 바로 뒤에 `/` 나 그런 `~` 경로가 붙은 값(`-I/usr/include`). 이 검사는 결정의 `value` 에만 쓴다. 다른 프로필 글의 검사는 그대로이고, `purpose`·`tools`·`development_methods`·`interview_revision`·`versioning.format`·결정의 `topic`·`scope` 는 계속 `/` 를 거절한다.

필드를 대는 거절: 프로필 값 검사의 거절 문장은 `invalid or nonportable profile field <id>; no values were logged` 이고 종류는 `invalid_input` 이다. `<id>` 는 걸린 키(`purpose`, `shared_files`, `versioning.format` 등)다. 결정 레코드는 `decisions[<결정 id>].<부분>` 으로 대며, 부분은 `id`·`topic`·`value`·`source`·`scope` 순서로 처음 걸린 것이다. 결정 id 가 ASCII 영문자·숫자·`-`·`_` 로 된 1~80자가 아니거나 위의 두 비밀 검사 중 하나에 걸리면 id 자리에 0부터 센 위치를 쓴다(`decisions[#0].id`). 결정이 32개를 넘으면 `<id>` 는 `decisions` 다. 거절된 값은 문장에 싣지 않는다. `leader`·`language`·`detected`·`scopes`·`work_flow`·`lane_run`·`versioning`(`format` 의 글 검사는 제외)·`test_paths`·`ci`·`checks` 의 하위 검사는 이전의 자체 문장을 그대로 쓴다.

읽지 못하는 입력: 입력이 JSON 이지만 프로필로 읽히지 않으면 `project-plan` 은 알려진 키 가운데 빠졌거나 타입이 틀린 첫 키(프로필 키 표의 순서)를 같은 문장의 `<id>` 로 댄다. 입력에 모르는 키가 있거나(알려진 키가 함께 틀려도 같다), 객체가 아니거나, 원인인 알려진 키를 찾지 못하면 필드 없는 이전 문장 `invalid or nonportable profile; no values were logged` 로 거절한다. 모르는 키의 이름은 싣지 않는다.

알려진 한계: 정당해도 계속 거절되는 값이 있다. `2>/dev/null`, `scheme://` 주소, Bazel 의 `//...`, 산문의 `a / b`, `/p:` 꼴 플래그, `$PWD:/app`, `"$PWD"/x`, `app/[slug]/page`, `(auth)/login`, `{a,b}/x`, `-Iinclude/x`, 한글 낱말 바로 뒤의 `/`, 모든 백슬래시, `PATH=$HOME:./bin` 처럼 홈 변수와 `/` 가 한 낱말에 있는 값, `npm:cowsay@1.5.0/cli` 처럼 `@` 앞에 `:` 가 있고 뒤에 `/` 가 있는 낱말이 그렇다. 반대로 전에는 `/` 때문에 거절됐지만 이제 받는 값도 있다. `../../Users/name`, `x/Users/name`, `./../../../Users/name`, scheme 없는 `host.invalid/path` 와 webhook 경로, `curl -u 이름:암호 호스트/경로`, AWS 문서 예시처럼 `/` 가 둘 든 비밀 키 모양, `x:` 처럼 `/`·`=` 가 아닌 구분자 뒤에 붙은 키 모양, 그 밖에 두 비밀 검사에 걸리지 않는 `/` 든 비밀이 그렇다. 자격 증명이 든 값은 `/` 금지가 우연히 막아 주던 것이라, 이 검사를 통과했다고 비밀이 없는 것은 아니다.

이전 버전: 이 변경 전의 `moai` 는 결정 값에 `/` 가 든 프로필을 읽을 때마다 거절한다. 그런 값은 설치된 `moai` 를 올린 뒤에 저장한다.
