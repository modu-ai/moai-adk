# `home-install-revert`

operation `home_install.revert` · 코드 `src/ops/home_install_revert.rs`, `src/home_install_apply.rs` · Issue #2871 (U3c)

`home-install-revert --home DIR [--stamp UTC] --permission-reference REF` 는 `--stamp` 의 설치(없으면 가장 새 `install-manifest-*.json`)를 되돌린다. `--home` 은 필수이다. 순서: 허가 참조 → `~/.moai` 가 링크이거나 폴더가 아니면 어떤 항목도 옮기기 전에 거절 → 설치 잠금(apply 와 같은 `home-install/apply.lock`, 쥐고 있으면 `conflict in home install`) → 이 설치가 쓴 표식(파일 이름은 매니페스트에 저장된 표식 바이트의 `generation` 에서 정함: `moai` 는 `moai.json`, `moai-cli` 는 `moai-cli.json`)이 `~/.moai` 에 그대로(매니페스트의 sha-256 과 같음)이면 지우지 않고 `~/.moai-cli/home-install/reverted-marker-<UTC>.json` 으로 rename(고쳐졌으면 `conflict in home install`, 아무것도 바꾸지 않음) → `path` 의 링크는 아직 새 대상을 가리킬 때만 옛 대상으로 되돌림(다른 곳을 가리키면 그대로 둠) → 이동 저널을 거꾸로 되짚어, 옮긴 항목마다 정체(장치:inode 등)가 그대로이고 옛 자리가 비어 있을 때만 되돌림(그 사이 바뀐 항목은 그 자리에 두고 상태 `revert_partial`) → `~/.moai` 는 apply 가 만들었고(매니페스트의 `moai_created`) 비어 있을 때만 `rmdir`. 이미 되돌린 설치를 다시 되돌리면 아무것도 바꾸지 않고 `reverted` 를 돌려준다. 저널을 쓰기 전에 멈춘 설치는 빈 저널로 끝맺어, 같은 인자의 apply 가 그것을 다시 이어가지 않는다. 그 밖에는 아무것도 지우지 않는다.
