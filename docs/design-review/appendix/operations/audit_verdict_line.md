# `audit-verdict-line`

operation `audit.verdict_line` · 코드 `src/ops/audit_verdict_line.rs`, `src/gate_collect.rs` · Issue #2833 D4

`audit-verdict-line --pr N --head 40HEX --verdict PASS|FAIL --title TEXT [--base 40HEX] [--repo OWNER/REPO] [--dir .] [--tip …]` 는 감사 판정 댓글의 첫 줄을 만든다. 줄은 늘 감사자가 본 head(`--head`)를 적고 `AUDIT #N (TEXT) head <head> base <base> — verdict: <V>` 를 결과 `line` 에 낸다. 출력 직전에 GitHub 에서 PR 의 지금 head 를 읽는다(GET 만). 지금 head 가 `--head` 와 같으면 그대로 낸다. 다르면 로컬 저장소에서 `gate_collect::mechanical_delta(--head, 지금 head, --tip)` 를 재서 base 가지만 합친 변화일 때만 낸다 — 게이트가 `--head` 의 PASS 를 지금 head 로 넘기므로(AUTO-DELTA) 결과에 `current_head` 와 `auto_delta`(PASS 일 때만 참)를 덧붙인다. 그 밖의 변화(저자 커밋, PR 밖 파일, 바뀐 PR 줄)거나 새 head 가 로컬에 없으면 줄을 내지 않고 두 head 와 감사할 delta(`<head>..<지금 head>`)를 적은 오류를 낸다(감사 6869947940 B1: 아무도 감사하지 않은 head 를 적은 판정을 막는다). base 는 `--base` 를 주면 그 값, 아니면 `--head` 와 `--tip` 의 merge base 다(head 를 먼저 fetch). 줄은 게이트 G1 이 읽는 `gate::parse_verdict` 로 같은 head·base·판정이 다시 읽힐 때만 낸다(16진수 40자가 아니거나 제목이 여러 줄이면 거부). 아무것도 쓰지 않는다.
