# `audit-gate`

operation `audit.gate` · 코드 `src/ops/audit_gate.rs`, `src/audit_gate.rs` · SPEC-20261117-audit-gate(CI 재설계 D2)

`audit-gate [--pr N [--head 40HEX] [--repo OWNER/REPO]] [--require-pass]` 는 CI `audit-gate` job 이 쓰는 감사 판정이다. PR 의 판정 댓글(첫 줄 `AUDIT #N (…) head <40hex> base <40hex> — verdict: PASS|FAIL`)을 병합 관문과 같은 함수(`gate::verdict_line`, `gate::parse_verdict`, `gate::auditor`, `gate::parse_body_tier`, `gate::tier_of`)로 읽고 `state` 를 `pass`·`fail`·`missing` 중 하나로 낸다. 저장소 구성원의 댓글만 센다. 규칙: 올린 FAIL(읽히지 않는 `AUDIT #` 첫 줄 포함)은 같은 감사자가 뒤에 PASS 를 올릴 때까지 모든 tier 를 막는다(`fail`); tier 0 은 열린 FAIL 이 없으면 `pass`; tier 1·2 는 바로 이 head 에 40자 base 를 가진 PASS 가 있고 그 감사자 lane 이 PR 커밋의 `Moai-Session:` trailer 값(저자) 어디에도 없어야 `pass`, 아니면 `missing`. 커밋에 `Moai-Session:` 이 하나도 없으면 저자를 모르는 것이라 `missing` 이다. 판정 댓글이 첫 줄 아래에 `Moai-Session: <감사자 session id>` 줄을 가지면(SDD-6, `internal/commit-trailers`) 그 session 과 감사자 lane 이름 중 하나라도 저자면 저자의 PASS 이고, 두 판정은 session 이 같을 때(없으면 lane 이 같을 때) 같은 감사자다. tier 는 PR 본문의 `audit-tier: n` 을 경로 규칙이 올린 값이고, 파일을 못 읽으면 2 다. PASS 가 CI 실행을 인용하는지는 아직 보지 않는다(`cites_run_checked: false`, 다음 조각). `--pr` 이면 GitHub 에서 읽고(GET 만), 없으면 stdin 의 입력 JSON(`schema_version`, `pr`, `head`, `body`, `files`, `commit_messages`, `comments`)으로 정한다. `--require-pass` 는 `pass` 가 아니면 오류로 끝낸다(job 의 종료 코드). 아무것도 쓰지 않는다.

릴리스 감사 요약(SPEC-20261125-release-audit-summary). 구성원의 댓글 첫 줄이 `RELEASE-AUDIT-SUMMARY ` 로 시작하면 `moai release-audit-summary` 가 올린 요약으로 읽는다. 읽는 문법은 만드는 쪽과 같은 `src/release_audit_summary.rs` 의 `parse` 한 곳이다. 입력에는 필드 `release_base`(PR base 와 head 의 merge base, 40자 hex, 기본 없음)가 더해졌다. `--pr` 로 읽을 때는 구성원의 요약 댓글이 있을 때만 GitHub compare 로 merge base 를 한 번 읽고(스캔 레지스트리를 읽는 PR 이면 그 읽기와 한 번을 나눈다), 요약이 없으면 읽지 않는다. 규칙은 `AUDIT #` 규칙 위에 이렇게 얹힌다. (1) 비구성원의 요약은 다른 댓글처럼 버려진다. (2) 요약이 읽히지 않으면(머리글이 있는데 줄 수, 이어짐, 세션 표, 한도 중 하나가 어긋남) 열린 FAIL 이다: `fail`/`summary-malformed`. 이 head 를 이름으로 댄 요약에 `FAIL` 줄이 있어도 `fail`/`summary-fail` 이고, 이 둘은 옛 경로가 통과해도 tier 0 에서도 막는다. 열린 `AUDIT #` FAIL 은 규칙 2 로 먼저 판정되어 유효한 요약도 막는다(`open-fail`). (3) 다른 head 를 댄 요약은 읽지 않는다. (4) tier 1·2 에서 이 head 를 댄 요약은 모두 통과해야 하고 옛 경로는 보지 않는다: 요약의 base 가 `release_base` 와 다르거나 `release_base` 를 못 읽었으면 `missing`/`summary-base`, `NONE` 줄이나 세지 못하는 `PASS` 줄이 하나라도 있으면 `missing`/`summary-landings`(이름 10개까지와 전체 개수), 모두 통과하면 `pass`/`release-summary`. `PASS` 줄은 줄의 모든 `v=` 가 `Verdict::counts` 를 통과할 때만 센다: 제외 목록이 비지 않고 감사자가 그 안에 없어야 하며 같은 세션인지는 `trailers::same_identity` 로 가른다. 요약이 없으면 옛 경로의 결과를 그대로 돌려준다. 요약은 PR 커밋 목록(250개 한도)이나 파일 목록 없이도 판정하므로 릴리스 PR 에서도 저자를 몰라 닫히지 않는다. 게이트가 스스로 확인하는 것은 멤버 댓글, 정확히 PR head, 같은 merge base, 줄 수와 이어짐, 줄의 제외 목록이고, 목록이 실제 이력과 완전하다는 것과 감사자·작성자·판정의 사실은 멤버의 댓글을 믿는다(멤버가 가짜 `AUDIT #` PASS 를 쓰는 것과 같은 신뢰 수준).
