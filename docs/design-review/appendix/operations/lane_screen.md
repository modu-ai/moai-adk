# `lane-screen`

operation `lane.screen`(SPEC-20261119-lane-screen-guard, 카드 C-120). 코드: `src/ops/lane_screen.rs`(명령)와 `moai_cli::lane_status::lane_screen`(`src/lane_screen.rs`, 분류와 시간 변환).

`lane-screen [--home DIR] [--now YYYY-MM-DDTHH:MM:SSZ]` 는 표준 입력으로 레인 화면 하나를 읽어요: Orca `terminal read --screen --json` 의 답이거나 화면을 그대로 옮긴 글이에요(64 KiB 까지). 그리고 그 화면의 상태 `working`·`idle`·`permission_prompt`·`input_pending`·`usage_limit`·`unreachable`·`unknown` 중 하나를, 그렇게 읽은 화면 줄 하나(`evidence`)와 함께 보여요.

- **확인 창(`permission_prompt`)**: 번호 붙은 `Yes` 줄과 `No` 줄이 함께 있을 때예요. `Do you want` 질문 줄은 없어도 되고(있으면 그 줄이 `evidence`), 커서가 `❯` 가 아니라 `>` 여도, 창이 세로 테두리(`│`) 안에 있어도, 커서 표시가 없어도 같아요: Enter 가 `Yes` 를 고를 수 있는 화면은 보내기를 허락하는 상태(`working`·`idle`)로 읽지 않아요(2026-11-19 감사 B1). `Yes`·`No` 는 낱말 전체예요(`Yesterday`·`Not now` 는 아니에요). 같은 화면에 작업 중·대기 표지가 있어도 이쪽이 이겨요.
- **그 밖의 선택 창(`input_pending`)**: 번호 줄(`1. …`)이 둘 이상이고 그중 하나에 커서 표시(`❯`·`>`·`›`·`▶`·`▸`·`→`·`➜`·`➤`)가 있거나, `Enter to confirm`·`Enter to select`·`Esc to cancel`·`Esc to exit` 줄이 있을 때예요. 줄 앞의 세로 테두리(`│`·`┃`·`║`·`|`·`╎`·`┆`)는 건너뛰고 읽어요. 커서 표시가 없는 번호 목록은 선택 창이 아니라 글 속 목록이라 보지 않아요(`Yes`·`No` 번호 줄 한 쌍은 위의 확인 창이에요).
- **사용 한도(`usage_limit`)**: `limit` 과 `reset` 이 한 줄에 있거나 `limit reached` 줄이 있을 때예요. 선택 창·대기 표지보다 앞서요. `reset` 에는 해제 시각을 UTC 로 적어요: `--home` 의 `usage-limits.json` 이 `usage_limit::evaluate` 로 `reached`(창 하나가 100% 이상)면 그 `resets_at`(`reset.source: home`), 아니면 화면 글자(`reset.source: screen`)예요. 화면 글자는 `YYYY-MM-DD HH:MM[:SS]`, `Mon D[, YYYY] at H[:MM]am|pm`, `H[:MM]am|pm` 꼴을 읽고, 시간대는 `UTC`·`GMT`·`Z`·`UTC±H[:MM]`·`±HH:MM`·`Asia/Seoul`·`Asia/Tokyo`·`Asia/Shanghai`·`Asia/Hong_Kong`·`Asia/Singapore` 만 알아요. **시간대가 없거나 모르는 시간대는 UTC 도 현지 시각도 아니에요**: `reset.utc` 가 null 이고 `reset.unknown` 이 참이며 `reset.raw` 에 화면 글을 그대로, `reset.why` 에 이유를 적어요(2026-11-19: glm 레인의 `Your limit will reset at 2026-11-19 17:30:55` 는 시간대가 없었고 실제로는 UTC+8 이었어요). 해·날짜가 없는 시각은 `--now`(기본은 시계) 이후의 가장 가까운 때예요. 화면에 적힌 해가 1970 보다 작거나 9999 보다 크면 해제 시각이 아니라 `unknown`(`the date is impossible`)이에요(2026-11-19 감사 N1: 터무니없이 큰 해가 날짜 계산을 넘치게 해 debug 빌드가 panic 했어요).
- **작업 중(`working`)**: `esc to interrupt` 줄이 있을 때예요. **대기 중(`idle`)**: `❯` 입력 줄과 `shift+tab to cycle`·`? for shortcuts` 줄이 함께 있을 때예요. 둘 다 비어 있지 않은 줄이 6줄 이상일 때만 판정해요(`MIN_ROWS`): 폭이 좁아 tail 이 세 줄뿐이면 `esc to interrupt` 만 보이는 일이 있었어요.
- **`unreachable`**: Orca 의 답이 `ok: false` 이거나 터미널 `status` 가 `exited` 일 때예요. **`unknown`**: 위 어디에도 맞지 않거나, 읽은 것이 그려진 화면이 아니거나(`source` 가 `screen` 이 아님), 화면이 비어 있거나 줄이 모자랄 때예요. 셸 화면은 `unknown` 이지 `idle` 이 아니에요. **확인 질문이 화면 아래쪽에 있는데 선택 줄을 못 읽은 화면도 `unknown` 이에요**(2026-11-19 재감사 R-N1): 비어 있지 않은 마지막 8줄 안에 `do you want`·`would you like`·`are you sure`·`proceed?`·`[y/n]`·`(y/n)` 이 있으면, 번호 줄 앞머리가 목록에 없는 모양(`»`·`[1]` 등)이라 `Yes`·`No` 를 못 읽었어도 `working`·`idle` 표지보다 이쪽이 이겨요(`evidence` 는 그 질문 줄). 모르는 화면에 글을 보내지 않는 쪽이 안전해서예요. 대가는, 대기 중인 레인이 질문 글을 대화 끝에 남겨 둔 경우에도 아래쪽 8줄 안이면 `unknown` 이 된다는 것이에요(안전한 쪽으로 틀려요).

출력은 `state`, `evidence`(한 줄, 제어 문자 없이 160자까지), `reason`(고정 문구), `rows`(비어 있지 않은 줄 수), `reset`(사용 한도일 때만), `pane`이에요. `pane` 은 `lane-status` 의 `PaneObservation`(`state`·`source`·`observed_at`·`until`)과 같은 모양이고, `lane-status` 가 아는 다섯 상태(`working`·`permission_prompt`·`input_pending`·`unreachable`·`usage_limit`)일 때만 채우며 `idle`·`unknown` 은 null 이에요. 화면 전체는 출력하지 않아요. 파일을 쓰지 않고 어느 터미널에도 입력을 보내지 않아요. 보내기는 `SPEC-20261119-lane-send-guard`(`lane-send`), 목록은 아래 `--scan`(`SPEC-20261119-lane-screen-scan`)이 맡아요.

## `--scan`

`lane-screen --scan [--now T]` 는 표준 입력을 읽지 않고 열려 있는 터미널을 모두 훑어요(2026-11-19 에 레인 여덟이 사용 한도로 멈췄는데 사용자가 말해서야 알았어요). `orca terminal list --json` 으로 목록을 얻고(`result.terminals[]`), 터미널마다 `orca terminal read --terminal HANDLE --screen --json` 을 **한 번에 하나씩 순서대로** 불러 위의 분류기로 읽어요. 최대 200개를 읽고, 그보다 많거나 Orca 가 `truncated`·`totalCount` 로 목록이 잘렸다고 하면 `truncated` 가 참이고 표 끝에 "m of n terminals shown: the list was cut short" 줄이 붙어요(전부 봤다고 말하지 않아요).

- **줄(`terminals[]`)**: `handle`·`title`·`branch`(목록이 준 글이라 제어·줄 구분·양방향 문자를 지우고 80자에서 잘라요)·`state`·`reason`·`evidence`·`reset`. 읽기 실패(`exited with code N`, 시간 제한), 핸들 없음, 옵션으로 읽힐 수 있는 핸들(`-` 로 시작, 공백 등: `orca` 에 넘기지 않아요), Orca 의 JSON 이 아닌 글자만 온 답은 그 줄만 `unreachable` 이고 나머지는 계속해요.
- **`reset`**: 사용 한도인 줄에만 있고, 화면 글자에서만 읽어요(`--home` 과 같이 쓰지 못해요: 터미널에서 레인의 HOME 을 알 수 없어요). 시간대가 없거나 모르는 시간대는 UTC 를 지어내지 않고 `unknown`(표에는 `unknown`)이에요.
- **출력**: `terminals`, `count`(읽은 수), `total`(Orca 가 말한 전체 수), `truncated`, `by_state`(상태별 개수), `table`(사람이 읽는 줄의 목록: 머리줄, 터미널마다 한 줄, 잘렸으면 끝 줄)이에요. 화면 전체는 남기지 않고 근거 줄 하나만 둬요.
- **실패**: `orca` 가 없거나, 종료 코드가 0 이 아니거나, 시간 제한을 넘기거나, JSON 이 아니거나 `ok: false` 거나 `terminals` 가 없으면 종료 코드 1 과 "the terminal list could not be read: …" 예요. 파일을 쓰지 않고 어느 터미널에도 입력을 보내지 않아요(`orca terminal send` 를 부르는 코드가 없어요).
- **Orca**: 사용자가 이 명령을 부를 때만 `MOAI_ORCA_BIN`(기본 `orca`) 프로그램을 띄워요(`MOAI_ORCA_TIMEOUT_SECS`, 기본 15초, 호출마다). 터미널이 멈추면 그만큼 기다려요. 셸 터미널은 추측하지 않아 `unknown` 이에요.
- **한도 줄과 Yes/No 메뉴가 한 화면에 같이 있을 때(조각 A 재감사 R-N3)**: 분류기는 확인 창을 먼저 읽어 `permission_prompt` 로 두고(보내기 보호가 우선이에요), 한 줄 읽기(`lane-screen`)의 `reset` 은 비어요. `--scan` 은 그 줄에도 화면의 한도 글에서 `reset` 을 채우고 `reason` 끝에 "a usage-limit message is also on the screen" 을 붙여서, 한도로 멈춘 레인이 해제 시각 목록에서 빠지지 않게 해요. 한도 글이 없는 확인 창은 `reset` 이 null 이에요. 단, 화면 어디든 `limit` 과 `reset` 이 한 줄에 있는 글이면 한도 글로 읽어요(확인 창 안의 명령 글이 그런 낱말을 담으면 잘못 채울 수 있어요).
