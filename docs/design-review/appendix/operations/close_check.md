# `close-check`

operation `close.check` · 코드 `src/ops/close_check.rs`, `src/close_check.rs` · Issue #2903 (#2899 O4)

`close-check ISSUE --repo OWNER/REPO [--snapshot FILE]` 는 레인이 자기 카드 Issue 를 **지금 닫아도 되는지** 답한다. 첫 줄이 `CLOSE-TABLE #<ISSUE>`(번호 뒤에 숫자가 이어지지 않음, 인용 `>` 아님)인 가장 새 댓글을 닫기 대조표로 읽는다. 그 안의 표 가운데 머리줄의 둘째 칸부터 `판정`·`상태`·`결과`·`verdict`·`status` 로 시작하는 칸(대소문자 무시, 처음 것)이 있는 표만 기준표이고, 그런 칸이 없는 표(예: `남은 것 | 근거 | 몫`)는 남은 일 목록이라 세지 않는다. 기준표의 머리줄·구분줄을 뺀 각 행은 판정 칸이 "충족" 뜻 낱말 — `충족`·`해당 없음`·`끝`·`병합`·`지킴`·`완료`·`closed`·`met`·`pass`·`done`·`n/a` — 로 시작하고 그 뒤에 글자·숫자가 이어지지 않을 때 충족이다(`미충족`·`부분 충족`·`끝남`·`metadata` 는 아님; 칸이 모자란 행은 충족 아님). 두 낱말 목록은 2026-11-14 에 최근 닫힌 Issue 25개의 닫기표에서 셌다(충족 76·끝 20·`CLOSED …` 6·병합 3·지킴 2행). 판정: `close`(표 있음, 기준 행 1개 이상, 모두 충족, 본문 줄 맨 앞 `Moai-Claim: <ISSUE>#…` 로 이 Issue 를 잡은 열린 PR 없음), `keep_open`(이유 목록 — 충족 아닌 행은 `unmet` 에 그대로, 후속 카드 번호를 표에 적고 열어 둠), `no_table`, `already_closed`, `uncertain`(표가 없는데 오래된 댓글을 못 읽음). Issue 상태·최근 댓글 100개·이 Issue 를 참조한 PR(상태·본문)은 GraphQL 요청 하나로 읽는다. 쓰기 0 — 닫기는 레인이 `next` 의 명령으로 한다. 결과: `issue`, `state`, `verdict`, `close_table_comment`, `rows`, `unmet`, `open_prs`, `merged_prs`, `reasons`, `next`, `partial`, `writes: false`.
