# `close-check`

operation `close.check` · 코드 `src/ops/close_check.rs`, `src/close_check.rs` · Issue #2903 (#2899 O4)

`close-check ISSUE --repo OWNER/REPO [--snapshot FILE]` 는 레인이 자기 카드 Issue 를 **지금 닫아도 되는지** 답한다. 첫 줄이 `CLOSE-TABLE #<ISSUE>`(번호 뒤에 숫자가 이어지지 않음, 인용 `>` 아님)인 가장 새 댓글을 닫기 대조표로 읽는다. 그 안의 표 가운데 머리줄의 둘째 칸부터 `판정`·`상태`·`결과`·`verdict`·`status` 로 시작하는 칸(대소문자 무시, 처음 것)이 있는 표만 기준표이고, 그런 칸이 없는 표(예: `남은 것 | 근거 | 몫`)는 남은 일 목록이라 세지 않는다. 기준표의 머리줄·구분줄을 뺀 각 행은 판정 칸이 "충족" 뜻 낱말 — `충족`·`해당 없음`·`끝`·`병합`·`지킴`·`완료`·`closed`·`completed`·`met`·`pass`·`done`·`n/a` — 로 시작하고(대소문자 무시, 낱말 뒤에 글자·숫자가 이어지지 않음: `미충족`·`부분 충족`·`끝남`·`metadata` 는 아님) 그 뒤에 **근거만** 있을 때 충족이다(리더 결정 6875953130, 감사 6875910836 N1 — 허용 목록). 근거로 치는 것: 백틱 코드(통째로 빼고 봄; 닫히지 않은 백틱은 근거 아님), 숫자가 든 낱말(커밋·`#번호`·숫자·날짜·`B2` 같은 식별자), 다른 충족 낱말, 공백, `?` 를 뺀 ASCII 문장부호, `—`·`–`·`·`·`…`·`✓`·`✅`. 그 밖의 낱말(`충족 아님`·`병합 대기중`·`충족 — 확인 필요`·`met, blocked`·`PASS (agent-9)`)이나 기호(`✗`), `?` 가 하나라도 있으면 충족이 아니다. 거부 목록이 아니라 허용 목록이라, 틀릴 때는 열어 두는 쪽으로만 틀린다 — 설명은 판정 칸이 아니라 근거 칸에 쓴다. 칸이 모자란 행은 충족 아님. 울타리 코드 블록(```` ``` ````·`~~~`) 안의 줄은 표가 아니다. 충족 낱말과 판정 머리말은 2026-11-14 에 최근 닫힌 Issue 25개의 닫기표에서 셌다(충족 76·끝 20·`CLOSED …` 6·병합 3·지킴 2행). 판정: `close`(표 있음, 기준 행 1개 이상, 모두 충족, 본문의 `Moai-Claim: <ISSUE>#…`(맨 줄이 이기고, 맨 줄이 없으면 본문 안 첫 `숫자#숫자` 토큰 — `lane-next` #2923 과 같은 읽기, 더 많이 셀수록 열어 두는 쪽) 로 이 Issue 를 잡은 열린 PR 없음 — PR 은 이 Issue 를 교차 참조한 것과, `Refs #<ISSUE>` 없이 claim 줄만 있는 것까지 찾도록 `repo:OWNER/REPO is:pr is:open "Moai-Claim: <ISSUE>#"` 검색 결과(최대 30개)를 같이 읽고, 그 본문을 같은 규칙으로 다시 읽는다), `keep_open`(이유 목록 — 충족 아닌 행은 `unmet` 에 그대로, 후속 카드 번호를 표에 적고 열어 둠), `no_table`, `already_closed`, `uncertain`(표가 없는데 오래된 댓글을 못 읽음).
