# [RC1][공통 skill과 host] 02-C Codex Desktop 발견 호출과 adapter 검증

## 목표와 사용자 가치
Codex Desktop(및 CLI/IDE)에서 공통 package projection(`~/.agents/skills/moai/SKILL.md`, 선택 시 `.agents/skills/moai/`)이 공식 경로에서 발견되고 `$moai`(Desktop composer)·`/skills`·`$`(CLI/IDE)로 명시 호출됨을 host 증거로 확인한다. `agents/openai.yaml`(interface·policy.allow_implicit_invocation·dependencies)을 Codex adapter metadata로 분리하고, AGENTS.md 발견 체인(override→AGENTS→fallback, 32 KiB 예산, root→cwd 연결), project trust(`.codex/` 레이어는 trusted에서만 로드), `tui.status_line`, hooks(`hooks.json`/inline 병합, hash trust, command/mcp_tool만 지원, cloud는 Global MCP hook만)의 지원/제한 증거를 `host-capabilities`에 기록한다. Codex Desktop 발견·SETUP·UPDATE는 양 host RC1 확정 조건이므로 실패 시 RC를 blocked로 두고 Claude-only로 축소하지 않는다(HA-10).

## 비목표와 범위
비목표: 사용자 홈 설치본 실제 설치·UPDATE(EP-05), Codex cloud 환경 hook 인증(관측·unknown 기록만), 전체 Codex hook 12 event adapter 이식(Go 세대 자산은 참고만), `.codex/config.toml` 전체 교체, personality(deprecated) 기반 style 선택기, `.codex/skills`를 기본 경로로 가정. 범위: Codex adapter 계약(discovery/invocation/openai.yaml/AGENTS 진단/trust/status_line/hooks 최소 baseline)과 fixture, Desktop vs CLI/IDE 표면 차이 기록, 지원표 입력.

## SPEC 요구(GEARS)
- REQ-02C-01 (Ubiquitous) Codex projection `SKILL.md`는 02-A canonical body와 바이트 동일하고 frontmatter는 `name: moai`·`description`만 가져야 하며, Codex 선택 UI metadata는 별도 `agents/openai.yaml`에만 두어야 한다.
- REQ-02C-02 (WHEN) `agents/openai.yaml`을 생성할 때, `interface.display_name`·`short_description`·`default_prompt`(명시 호출 프롬프트)만 기본으로 채우고 `policy.allow_implicit_invocation`은 사용자가 선택한 값으로만 기록해야 한다(기본값 true를 조용히 바꾸지 않음).
- REQ-02C-03 (WHEN) 사용자가 Desktop composer에서 `$moai`(또는 CLI/IDE `/skills`·`$moai`)로 호출했을 때, 검증은 Codex exact version·표면(Desktop/CLI/IDE)·실제 읽힌 SKILL.md 경로·reference 읽기 흔적을 receipt로 남겨야 하며 selector 노출만으로 `host_loaded:true`를 기록하지 않아야 한다.
- REQ-02C-04 (IF) 동명 `moai` skill이 둘 이상 발견되면(예: `~/.agents/skills`와 `.agents/skills`), adapter는 병합되지 않고 둘 다 selector에 나타날 수 있음을 경고하고 실제 읽힌 path/version을 보고해야 한다.
- REQ-02C-05 (Ubiquitous) doctor는 전역 `~/.codex/AGENTS.override.md`/`AGENTS.md`, 프로젝트 root→cwd의 override/AGENTS/fallback, 합산 바이트와 `project_doc_max_bytes`를 확인해 어떤 파일이 실제 포함됐는지와 32 KiB 초과 여부를 기록해야 하며 `AGENTS.override.md`를 개인 보충용으로 생성하지 않아야 한다.
- REQ-02C-06 (IF) 프로젝트가 untrusted이면, adapter는 `.codex/config.toml`·`.codex/hooks.json`이 로드되지 않음을 `blocked_by_trust`로 기록하고 trust 상태를 자동으로 바꾸지 않아야 한다.
- REQ-02C-07 (WHERE) statusline을 선택한 경우, `[tui] status_line` 관리 key만 의미 단위로 병합하고 검증되지 않은 항목 ID는 쓰지 않으며(`unverified_item`로 표시), 기존 사용자 `status_line`이 있으면 conflict로 보고해야 한다. Claude shell renderer를 Codex에 이식하지 않아야 한다.
- REQ-02C-08 (WHERE) hook을 선택한 경우, `hooks.json`과 inline `[hooks]` 중 한 곳에만 정의해 이중 실행을 피하고, 정의 hash·trust 필요·`prompt`/`agent` handler 미지원·cloud 미지원을 결과에 명시해야 한다. 결정 없음·exit 0을 allow로 해석하지 않아야 한다.
- REQ-02C-09 (Ubiquitous) 결과 schema는 02-B와 동일하게 `files_created`·`host_loaded`·`execution_verified`를 분리하고 Desktop/CLI/IDE 표면별로 기록해야 한다.
