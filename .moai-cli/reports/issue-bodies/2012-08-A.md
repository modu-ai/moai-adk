# [RC1][RC 인증과 문서] 08-A 최신 base 통합과 SYNC 연결

## 목표와 사용자 가치
독립 AUDIT을 통과한 후보(candidate tree/patch)를 최신 `v2026.11.0` tip에 통합하고, 통합된 정확한 tree에 대해 로컬 build/test를 다시 실행하며, 독립 review와 exact-SHA CI 결과를 PR에 연결하고, SPEC 차이를 구현 누락/amendment/문서 누락으로 분류해 기록하며, push·PR 개설·댓글·merge·release라는 외부 효과를 권한별로 분리하는 SYNC 절차와 그 receipt를 만든다. 사용자 가치: '과거 브랜치의 PASS를 새 merge 결과에 복사'하는 false PASS와, 한 번의 승인으로 여러 외부 효과가 묶여 나가는 사고를 막는다. 이 Issue의 결과물은 이후 모든 실행 Issue의 PR 경로가 되므로 08-C(E2E)의 선행이다.

## 비목표와 범위
범위: `skills/moai/workflows/sync.md`의 절차를 검증 가능한 단계로 구체화, 통합 receipt JSON 계약(`integration receipt`는 현재 'planned; not implemented'), `v2026.11.0` 대상 PR 규약(`--base` 명시·`Refs #n`·exact SHA·로컬 시험 증거), Rust CI workflow 초안(`cargo test/clippy/fmt`를 PR의 head SHA와 merge SHA에 묶어 기록), 독립 review 입력 패키지(승인 SPEC·exact diff·receipt). 비범위: 실제 merge 실행과 release(통합 owner·사용자 권한), `v2026.11.0` 브랜치 보호/ruleset 변경(admin 외부 효과, HOLD), merge queue 도입, `main`의 Go 세대 required checks 변경, GitLab MR adapter, 자체 서버·DB. 설계 06-page의 'SYNC는 push·merge·release·계정 변경을 묶어 자동 승인하는 명령이 아니다'를 그대로 따른다.

## SPEC 요구(GEARS)
- REQ-08A-01 [Ubiquitous] 시스템은 통합 후보마다 `base_sha`, `candidate_sha`, `merge_base`, `spec_digest`, `audit_verdict_ref`, `local_test_receipt_ref`를 가진 integration receipt(JSON, schema_version 1)를 기록해야 한다.
- REQ-08A-02 [WHEN] 후보가 최신 `v2026.11.0` tip을 포함하지 않을 때(`git merge-base --is-ancestor <origin/v2026.11.0> <candidate>` exit 1) 시스템은 상태를 `needs_rebase`로 두고 이전 tree의 PASS를 새 tree에 복사하지 않아야 한다.
- REQ-08A-03 [WHEN] 재통합이 발생했을 때 시스템은 통합된 정확한 tree에서 로컬 build/test(`cargo test --offline --locked`, `cargo clippy ... -D warnings`, `cargo fmt --check`, Python unittest)를 다시 실행하고 그 exit code를 receipt에 넣어야 한다.
- REQ-08A-04 [Ubiquitous] PR은 `--base v2026.11.0`을 명시해 열어야 하고 본문은 `Refs #<issue>`만 사용하며 `Closes/Fixes/Resolves` 키워드를 포함하지 않아야 한다(비기본 브랜치에서 무시되므로 Issue 종료는 SYNC 보고로 수행).
- REQ-08A-05 [WHERE] GitHub Actions가 연결된 저장소에서 시스템은 CI 결과를 PR의 `head.sha`(후보)와 merge ref SHA 둘 다에 대해 조회해 receipt에 기록해야 하며, merge conflict로 workflow가 실행되지 않은 경우를 `not_run`으로 보존해야 한다.
- REQ-08A-06 [IF-THEN] 독립 review verdict가 없거나 작성 context와 분리되지 않았으면 시스템은 통합 상태를 `blocked`로 두고 PR 개설 이후 단계로 진행하지 않아야 한다.
- REQ-08A-07 [Ubiquitous] push·PR 생성·Issue 댓글·merge·release는 각각 별도의 권한 확인과 operation ID를 가져야 하며, 한 효과의 승인이 다른 효과를 허가하지 않아야 한다.
- REQ-08A-08 [WHEN] 구현과 SPEC의 차이가 요구 자체의 변경일 때 시스템은 amendment 기록(원 SPEC digest·변경 요지·재승인 필요)을 생성하고 acceptance를 조용히 낮추지 않아야 한다.
- REQ-08A-09 [WHEN] 외부 쓰기(PR 생성·댓글)가 timeout으로 끝났을 때 시스템은 같은 요청을 즉시 반복하지 않고 operation marker로 기존 PR·댓글을 재조회한 뒤에만 재시도해야 한다.
- REQ-08A-10 [Ubiquitous] (amendment A1, 아래 기록) `v2026.11.0`에는 ruleset `RC1 integration gate (v2026.11.0)`(id 26791615)이 PR 필수·`moai/audit` status·strict up-to-date를 강제한다. 시스템은 그 위에서도 로컬 build/test receipt를 PR 필수 증거로 요구해야 하며, CI 부재·미완료를 PASS로 해석하지 않아야 한다. (원문: "required status check가 설정되지 않은 동안" — ruleset 활성으로 전제가 사실과 달라 정정)
