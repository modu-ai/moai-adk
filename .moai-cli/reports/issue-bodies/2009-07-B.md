# [RC1][Forge 보고와 판단 context] 07-B 로컬 TODO 선택 승격 구현

## 목표와 사용자 가치
forge를 나중에 연결한 프로젝트에서 로컬 TODO(`tasks.md` 또는 typed task 목록)를 Issue로 옮길 때, 전송 전 redacted preview → 사용자 선택 → 기존 Issue·operation marker 재조회 → 허용된 생성/연결 → remote ID 확인 → 최소 mapping 저장의 순서를 Rust로 구현한다(P07·D80 확정). `moai-cli todo-promote-preview PROJECT`(쓰기 없음)와 `moai-cli todo-promote-apply PROJECT --preview-digest D --permission-reference R`(선택 항목만 생성)의 두 단계로 나누고, timeout·응답 유실은 `uncertain`으로 남겨 재조회 전에는 같은 Issue를 다시 만들지 않는다. 사용자 가치: 비공개 메모·비밀이 외부로 나가지 않고, 중복 Issue가 생기지 않으며, 승격 후 업무 원장이 Issue 하나로 정리된다.

## 비목표와 범위
범위: preview/apply 2단계 명령, redaction 게이트, 중복 후보 조회, operation marker, mapping 저장(`<project>/.moai-cli/forge/promotions.json`), uncertain 재조회. 비범위: 제목 유사도 자동 병합, 승격 후 Issue 본문 자동 갱신, GitLab 생성, `tasks.md` 자체의 편집 UI(세션 TODO는 host 영역), 비밀 탐지의 완전성 주장. 기존 `experiments/todo_promotion.py`는 역사적 실험으로 보존하고 제품 경로로 승격하지 않는다.

## SPEC 요구(GEARS)
- REQ-PROMO-001 Ubiquitous `todo-promote-preview`는 어떤 네트워크 쓰기도 수행하지 않아야 하며 출력에는 선택 후보별 `local_id`, `state(preview_only|blocked_review|already_published|duplicate_candidate)`, `target{owner,repo,visibility}`, `redacted_title`, `redacted_body_digest`, `preview_digest`만 포함해야 한다.
- REQ-PROMO-002 WHEN 사용자가 선택하지 않은 항목이 있으면 그 항목의 제목·본문은 preview 출력과 apply 요청 어디에도 포함되어서는 안 된다(TASK-PROMOTION-PRIVATE).
- REQ-PROMO-003 WHEN 항목에 `disclosure_review: approved`가 없거나 redaction 필터가 비밀 모양 문자열을 발견하면 상태를 `blocked_review`로 두고 전송하지 않아야 한다.
- REQ-PROMO-004 WHEN apply가 호출되면 `preview_digest`가 현재 트리·tasks.md digest·선택 목록에서 다시 계산한 값과 일치해야 하며 다르면 쓰기 없이 `stale`을 반환해야 한다.
- REQ-PROMO-005 WHEN Issue를 생성하기 전에 operation marker `<!-- moai:op promote:<project_id>:<local_id>:<attempt> -->`로 기존 Issue를 재조회해야 하며, marker가 발견되면 생성하지 않고 그 Issue에 연결해야 한다.
- REQ-PROMO-006 WHEN 생성 요청이 timeout·연결 유실·5xx로 결과를 알 수 없으면 mapping을 `uncertain`으로 기록하고 재조회 전까지는 동일 marker로 재생성하지 않아야 한다(TASK-PROMOTION-UNCERTAIN).
- REQ-PROMO-007 WHEN 생성 응답을 받으면 응답의 `id/node_id/number/html_url`과 본문 marker를 다시 GET으로 확인한 뒤에만 `published`로 기록해야 한다.
- REQ-PROMO-008 Ubiquitous mapping 파일 `<project>/.moai-cli/forge/promotions.json`은 임시 파일+rename으로 갱신하고, 쓰기 전 마지막 읽기 digest가 다르면 `conflict`로 멈춰야 한다(TASK-FILE-CONFLICT).
- REQ-PROMO-009 WHERE 제목 유사 Issue 후보가 있으면 `duplicate_candidate`로 표시만 하고 자동 병합·자동 연결을 해서는 안 된다.
- REQ-PROMO-010 WHILE forge 연결이 끊긴 상태(offline)라도 이미 published 항목의 원장은 Issue로 유지해야 하며 로컬이 두 번째 원장이 되어서는 안 된다(TASK-OFFLINE-AUTHORITY).
- REQ-PROMO-011 Ubiquitous 지속 요청이 없는 미연결 프로젝트에서는 `tasks.md`·DB·서버를 생성해서는 안 된다(TASK-SESSION-NO-FILE).
