## SPEC 요구(GEARS)
- REQ-00B-01 WHEN 설정 inventory를 수집하면, 도구는 GET 요청만 사용해 labels(전체 페이지)·org issue types·milestones(state=all)·Issue(state=all, PR 제외)·PR(state=all)·#1976 계층의 sub-issue·dependency를 하나의 typed JSON(`schema_version: 1`, `fetched_at`, 사용한 `X-GitHub-Api-Version` 또는 gh 버전)으로 기록해야 한다.
- REQ-00B-02 WHEN labels를 기록하면, 도구는 각 label을 축(type/priority/status/area/host/functional/legacy-synonym/unknown)으로 분류하고 동의어 묶음(`type:fix`↔`bug`, `priority:P0`↔`critical` 등)을 명시해야 하며 분류 불가 label은 `unknown`으로 남기고 임의로 정리하지 않아야 한다.
- REQ-00B-03 WHEN 중복 지도를 만들면, 도구는 열린 43개 Issue 각각을 RC1 논리 키(EP-xx/NN-X) 또는 `비RC1`에 매핑하고, 닫힌 420개 중 제목·SPEC ID·논리 키가 RC1 항목과 겹치는 후보를 열거해야 하며 중복 확정은 사람이 판단하도록 `candidate`로만 표시해야 한다.
- REQ-00B-04 WHEN Issue 목록을 수집하면, 도구는 응답에 `pull_request` 키가 있는 항목을 PR로 분리하고 Issue 수에 포함하지 않아야 한다.
- REQ-00B-05 WHILE 수집이 진행되는 동안, 도구는 POST/PATCH/PUT/DELETE를 호출해서는 안 되며 호출 로그에 GET 외 메서드가 0건임을 증명해야 한다.
- REQ-00B-06 WHEN 양식 inventory를 만들면, 도구는 tracked 양식 3종·untracked 이전 세대 양식 3종·PR 템플릿·label-sync workflow의 경로·sha256·채택 상태(채택/미채택-보존/미검토)를 기록해야 하고 `tests/github_assets_test.py`가 검사하는 항목과 모순이 없어야 한다.
- REQ-00B-07 IF 동일 원격 상태에서 두 번 수집하면, THEN `fetched_at`·ETag 필드를 제외한 산출물은 byte-identical이어야 한다.
- REQ-00B-08 WHERE Projects v2 토큰 scope가 없으면, 도구는 `projects: unavailable(read:project scope missing)`로 기록하고 실패로 처리하지 않아야 한다.
- REQ-00B-09 WHEN 산출물을 저장하면, 도구는 토큰·사용자 이메일·비공개 URL을 포함하지 않아야 하며 Issue 본문 전문 대신 number/id/node_id/title/state/state_reason/labels/milestone/type만 담아야 한다.
