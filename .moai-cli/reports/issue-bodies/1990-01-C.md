# [RC1][Rust 실행과 저장] 01-C CLI와 선택 MCP의 동일 계약 연결

> **HOLD 전제 주의** — REQ-01C-01의 stdout envelope 의무화는 00-D HOLD-00D-1(선택지 C: envelope 없이 현행 유지)과 겹침. 00-D 결정 뒤 확정.

## 목표와 사용자 가치
skills/moai(공통 skill)가 호출하는 내부 실행 계약을 하나의 typed 도메인 함수 집합으로 고정하고, (1) CLI(고정 program+argv+typed stdin → stdout JSON, stderr 진단, 안정 error code/retryable)가 기본이며 서버 없이 동작하고, (2) 선택 MCP adapter(stdio, JSON-RPC 2.0, MCP 2025-11-25)가 같은 함수를 같은 입력 schema·같은 결과·같은 '승인 경계'(plan digest + permission reference 없이는 mutation 불가)로 노출하는 parity를 fixture로 증명한다. 현재 `main.rs`는 6개 subcommand에 exit 0/1·문자열 오류만 있고 protocol_version·request_id·error code·retryable이 없어 02-B/02-C(host adapter)·05-C(VERIFY receipt)가 안정적으로 기댈 계약이 아직 없다.

## 비목표와 범위
비목표: MCP 서버 상시 호스팅·remote(Streamable HTTP) 서버, Go MCP 38개 tool의 일괄 포팅(21페이지 계승표는 02-A/후속이 다룸), host 설정(`.mcp.json`, `config.toml`)에 MCP 서버를 자동 등록, TOON 등 파생 포맷, 사용자용 terminal 명령 추가. 범위: 도메인 함수 경계(`project.plan/apply`, `agents.plan/apply`, `package.inspect/resolve`, `identity`, 추후 `apply.recover`)와 공통 envelope(protocol_version, request_id, error{code,retryable}), CLI 출력 고정, parity fixture, MCP adapter는 HOLD-C1 결정 범위에서만(최소 `tools/list`+`tools/call` stdio 골격 또는 계약 문서만).

## SPEC 요구(GEARS)
> MCP revision 기준 HOLD(P06): 아래 요구 중 `initialize` 협상·stateful 가정은 2025-11-25 이전 revision 기준이다. 현행 2026-07-28은 stateless(`initialize` 제거, `server/discover` 필수)이므로 기준 revision과 2025-11-25 호환 유지 여부를 사용자 결정 전까지 확정하지 않는다.
- REQ-01C-01 (Ubiquitous) 모든 내부 명령의 stdout은 단일 JSON object(또는 명시 JSONL)여야 하며 `protocol_version`(현재 1)과 호출자가 준 `request_id`를 그대로 포함해야 한다; stderr에는 진단만 쓴다.
- REQ-01C-02 (Ubiquitous) 오류 응답은 `error{code: <안정 식별자>, message, retryable: bool, next_actions?[]}` 형식이어야 하고 코드 집합(예: invalid_input, stale_plan, permission_reference_required, target_changed, exclusive_create_refused, no_git, partial_apply)은 00-D schema에 고정되어 문서화되어야 한다.
- REQ-01C-03 (Ubiquitous) mutation 함수(project.apply, agents.apply, apply.recover)는 CLI와 MCP 어느 transport에서도 확인된 plan digest와 비어 있지 않은 permission reference 없이는 실행되지 않아야 하며, MCP tool annotation이나 자연어 승인 문구를 승인으로 해석하지 않아야 한다.
- REQ-01C-04 (WHEN) 같은 typed 입력이 CLI(stdin)와 MCP(`tools/call` arguments)로 들어올 때, 시스템은 `request_id`·timestamp를 제외하고 byte 동일한 결과 JSON을 돌려줘야 한다(parity).
- REQ-01C-05 (WHERE) MCP adapter가 활성화된 경우, 시스템은 stdio transport에서 stdout에 MCP 메시지 외 어떤 바이트도 쓰지 않아야 하고 메시지에 내부 개행을 포함하지 않아야 하며, 도구 결과를 `structuredContent`(JSON object)와 동일 내용의 text 블록으로 함께 반환해야 한다.
- REQ-01C-06 (WHERE) MCP adapter에서 도메인 오류는 `isError: true` 결과로, 알 수 없는 tool·schema 위반은 JSON-RPC 오류(-32602 등)로 구분해 보고해야 한다.
- REQ-01C-07 (Ubiquitous) MCP adapter는 `initialize`에서 지원하는 protocolVersion(2025-11-25)을 협상하고, 클라이언트가 지원하지 않는 버전을 요구하면 다른 지원 버전을 돌려주거나 오류를 내야 하며, 노출 tool 목록은 명시 allowlist로만 결정되어야 한다. (P06 HOLD: `initialize` 협상은 2025-11-25 이전 revision 기준)
- REQ-01C-08 (Ubiquitous) MCP adapter 부재·비활성 상태에서도 모든 기능은 CLI만으로 동일하게 수행 가능해야 한다(no-server 기본).
- REQ-01C-09 (Ubiquitous) stdin 입력 크기(64 KiB)와 출력 크기 상한, UTF-8 요구, 알 수 없는 입력 키 거부(deny_unknown_fields)는 두 transport에서 동일해야 한다.
- REQ-01C-10 (Ubiquitous) 시스템은 사용자 자연어나 외부 문자열을 shell 명령에 이어붙이지 않고 고정 program+argv+typed stdin으로만 호출되어야 한다.
