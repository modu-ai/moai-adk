# [RC1][공통 skill과 host] 00-F 개발 세션 론처 — `moai -l | -a`, `moai cc|glm|codex -l | -a` (허브 없이, Claude Code 내장 크로스 세션 통신만)

## 사용자 결정 (2026-11-08 18:0x, 출처 docs/decisions-2026-11-08.md)
- 허브(실시간 중계)는 다음 버전. RC1은 **론처만** 만들고, 세션 간 통신은 Claude Code 내장 크로스 세션 메시징(`--name`으로 식별, `ListAgents`/`SendMessage`)만 쓴다.
- 지원 문법(시험 기간 바이너리 이름은 `moai-cli`; 제품명 `moai`는 D79 이름 전환 뒤): `moai -l`(리더) / `moai -a [host]`(에이전트), `moai cc -l|-a`, `moai glm -l|-a`, `moai codex -l|-a`. 기본 host는 `cc`(Claude Code).
- Claude Code 세션 기본값: 모델 `opus`, effort `medium`, **`--advisor fable`**, **`--dangerously-skip-permissions`**(임시 기본; 추후 설정에서 선택). `--name`은 `leader` 또는 `agent-<n>`(자동 부여 가능).
- 기존 `moai-cli session` 서브커맨드(2026-11-08 구현, Claude만)를 이 문법으로 확장한다. 설정 파일 연동(기본값 선택)은 후속 Issue.

## 목표와 사용자 가치
한 명령으로 리더/에이전트 세션을 host별로 띄우고, Claude 세션들은 이름으로 서로 메시지를 주고받을 수 있다. 운영자는 호스트별 플래그를 외우지 않는다.

## 비목표와 범위
- 비목표: 허브/브로커, Codex↔Claude 간 메시지 중계(Codex는 `codex queue`가 있으나 RC1 미사용), ZCode(별도 02-D), 설정 파일 UI, 세션 자동 재시작.
- 범위: `src/session.rs` 확장(host 열거: claude|glm|codex), `src/main.rs`(top-level `-l`/`-a` + `cc|glm|codex` 서브커맨드 → 공통 요청으로 라우팅), `tests/product_cli.rs`(dry-run fixture), `docs/rust-product-path.md`, AGENTS.local.md 사용 예 1줄(리더 PR).

## SPEC 요구(GEARS)
- REQ-00F-01 WHEN `moai-cli -l` 또는 `moai-cli -a [host]`가 호출되면, 시스템은 반드시 host 기본값 `cc`로 `session` 요청을 구성해야 한다(`-l`은 role leader·name `leader`, `-a`는 role agent·name `agent-<n>`; `<n>`은 `--name`이 없으면 같은 머신의 기존 named 세션과 겹치지 않는 다음 번호 — 조회 불가 시 1).
- REQ-00F-02 WHEN host가 `cc`이면, 시스템은 반드시 `claude --name <name> --model opus --effort medium --advisor fable --dangerously-skip-permissions`를 구성해야 하며, `--no-advisor`·`--permissions`(skip 해제)·`--model`·`--effort` 옵션으로 각각 끌 수 있어야 한다.
- REQ-00F-03 WHEN host가 `glm`이면, 시스템은 반드시 `cc`와 같은 `claude` argv에 env `ANTHROPIC_BASE_URL=https://api.z.ai/api/anthropic`, `API_TIMEOUT_MS=3000000`을 더하고, `ANTHROPIC_AUTH_TOKEN`은 **값을 다루지 않고** 호출 환경에 이미 있는지(존재 여부)만 확인해 없으면 `blocked`로 종료해야 한다(토큰은 출력·로그·receipt에 절대 쓰지 않는다). `--advisor`는 z.ai 경로에서 미지원 가능성이 있어 glm에서는 기본 **생략**하고 note로 알린다(Anthropic API 전용 — advisor 문서).
- REQ-00F-04 WHEN host가 `codex`이면, 시스템은 반드시 `codex -s workspace-write -a on-request [-m <model>] [PROMPT]`를 구성하고, 세션 이름은 플래그가 없으므로 첫 PROMPT에 `MoAI session name: <name>` 한 줄을 넣어 운반해야 한다. Codex는 크로스 세션 채널이 없음을 note로 알린다.
- REQ-00F-05 [Ubiquitous] 모든 host에서 `--dry-run`은 typed JSON(`host`, `role`, `name`, `argv`, `env_keys`(이름만), `notes`, `executed:false`)을 출력하고 어떤 프로세스도 시작하지 않아야 한다. 테스트는 dry-run만 사용한다.
- REQ-00F-06 [Ubiquitous] 기존 `moai-cli session` 호출 호환을 유지한다(기존 시험 2개 통과).

## 구현 계획
1. `SessionRequest`에 `host ∈ {claude, glm, codex}`, `advisor: Option`, `skip_permissions: bool`, `prompt: Option`; `compose()`를 host별 분기로.
2. `main.rs`: clap top-level `-l/--leader`, `-a/--agent [HOST]`, 서브커맨드 `cc|glm|codex {-l|-a} [--name] [--model] [--effort] [--no-advisor] [--permissions] [--dry-run] [PROMPT]` → 모두 `SessionRequest`로 변환(기존 `session`은 유지).
3. GLM env: `Command::env`로 BASE_URL·TIMEOUT만 주입, 토큰은 상속(존재 검사 `std::env::var_os`).
4. 다음 agent 번호: `~/.claude/...` 조회는 미확인 → RC1은 `--name` 없으면 `agent-1` 고정 + note(후속: 세션 목록 조회).
5. 테스트(dry-run) 5개, 문서, PR.
