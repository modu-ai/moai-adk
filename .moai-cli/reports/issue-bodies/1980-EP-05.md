- 서명·검증: **A** GitHub artifact attestation만(Sigstore Public Good, SLSA Build L2, `gh attestation verify`). 키 운영 없음.
- release tag/feed namespace: **B** 같은 repo(`modu-ai/moai-adk`), 다른 접두사 `moai-cli-v<version>`(예: `moai-cli-v2026.11.0-rc.1`). Go 3.x checker의 `v`/`go-v` 필터를 통과하지 않음. 기존 release automation·tag 관례 충돌 여부는 08-D 전에 확인.
- binary 경로: **A** `~/.moai-cli/bin/moai-cli`(receipt와 같은 namespace, installer가 PATH 안내).
- 추가 요구(사용자 2026-11-08): **기존 Go 사용자가 `moai update`(Go)를 실행하면 moai-cli(Rust)를 설치하고 기존 Go `moai`를 제거하며 마이그레이션**되어야 한다. 함의: Go checker가 Rust tag를 보지 않으므로(위 B), 마지막 Go 릴리스(`v3.x` 접두사, Go 채널)가 **마이그레이션 브리지** 역할을 해야 한다 — Rust release 조회(`moai-cli-v*`) → attestation 검증 → `~/.moai-cli/bin` 설치 → 상태 마이그레이션(`~/.moai`→`~/.moai-cli`, 프로젝트 `.moai`→`.moai-cli`; 복사+백업, 원본은 검증 전 보존) → 검증 뒤 Go 제거·`moai` 이름 전환(D79). 지금 실행하지 않으며 설계·Issue 범위만 반영한다.
- 추가 결정(16:1x): Windows 교체 A self-replace · 브리지 B(Go 최소 + Rust `moai-cli migrate --from-go`) · Go 제거 B(검증 통과 시 자동, 백업 보관) · 신규 04-D Issue 발행. 출처 (출처: docs/decisions-2026-11-08.md · 리더 세션 AskUserQuestion 응답 · manifest user_decisions). 남은 HOLD: 백업 보관 기간·롤백 명령, OS/arch matrix(P12), P04·P05 나머지.

## 목표와 사용자 가치
사용자가 컴퓨터에 moai-cli를 한 번 추가하면 Claude Code·Codex 두 host가 같은 공통 skill package를 발견하고, 세션 안의 '/moai update' 요청 한 번으로 설치된 모든 host를 사전검사(preflight)·미리보기(preview)·host별 적용하며, 어느 host가 실패해도 성공한 host는 유지하고 실패 host에서는 이번 요청이 바꾼 관리 파일 중 안전이 확인된 부분만 복구한다. 이 모든 과정에서 기존 Go 세대(`moai`, `~/.moai/`, `<project>/.moai/`, Go release feed)와 binary·feed·state·owner를 완전히 분리해 서로 오유입되지 않게 한다(D72·D78·D79, 설계 02 §5·§7, 12 §4·§5·격리 시험 계약).

## SPEC 요구(GEARS)
- REQ-EP05-01: WHILE RC 시험 기간 동안, moai-cli는 Go 세대의 `~/.moai/`·`<project>/.moai/`·Go release feed를 읽기 전용 이행 입력으로만 다루며 생성·이동·삭제·쓰기를 해서는 안 된다.
- REQ-EP05-02: WHEN 사용자가 세션에서 UPDATE를 요청하면, moai-cli는 설치된 모든 host projection을 함께 사전검사·미리보기·host별 적용하고 host별 결과를 구분해 반환해야 한다(host 선택은 기본이 아니다).
- REQ-EP05-03: IF 한 host의 적용이 실패하면, moai-cli는 성공한 host의 새 상태를 유지하고 실패 host에서는 이번 요청이 바꾼 관리 파일 중 현재 hash·소유권으로 안전이 확인된 것만 복구하며 사용자 수정은 보존해야 한다.
