# [RC1][EP-06] PLAN RUN VERIFY AUDIT — GEARS 요구 계약, task DAG admission, 실제 VERIFY receipt, 독립 AUDIT

## 목표와 사용자 가치
사용자 요구를 GEARS 요구(REQ)와 관찰 가능한 AC로 고정하고(05-A), 승인 snapshot digest와 task DAG로 RUN 진입을 통제하며(05-B), 실제 명령 실행 결과를 exact tree·SPEC·policy digest에 묶은 receipt로 기록하고(05-C), 구현 context와 분리된 AUDIT가 must-pass 조건을 결정론적으로 판정해 완료를 admission(05-D)하는 네 단계를 Rust `moai-cli` 안에 하나의 호스트 중립 계약으로 구현한다. 가치는 '모델의 완료 발화·exit 0·PR 개설'이 아니라 '정확한 변경본에 묶인 증거'만 완료로 인정되게 만드는 것이다(설계 D29·V11, 메인 §15).

## 비목표와 범위
비목표: 별도 MoAI SPEC 서버·DB·상시 감사 서버 구축, 고정 전문 agent bundle 배포, 모든 요청에 다중 모델 호출 강제, 기존 Go `internal/spec`(lint·closer·audit·dag.go)의 포팅(참고만), Go `.moai/`·`~/.moai/`·원격 `main` 변경, EARS 읽기 지원 폐기 결정, `.github` 양식 변경(00-C 소유), 클라우드 runner 제출(`task submit --execution cloud`)의 실제 provider 연동(EP-07/08 범위). 범위: `moai-cli` 단일 crate 안의 spec/plan/verify/audit 모듈과 typed JSON 계약, 임시 디렉터리 fixture, `skills/moai/workflows/{plan,run,verify,audit}.md`와의 정합. 영역 공통 SPEC을 별도 문서로 둘지 inline AC로 둘지는 HOLD.
