# [RC1][최초 설정과 맞춤 생성] 03-C 프로젝트별 맞춤 파일 생성 구현

## 목표와 사용자 가치
profile(03-A)과 외부 skill 읽기 결과(03-B)를 입력으로, 프로젝트별 생성 계획(generation plan)을 만들어 preview하고 승인된 plan만 적용한다. 생성 대상은 AGENTS.md 관리 구간(기존 `agents-plan/apply` 확장), portable 프로젝트 workflow/skill(`.moai-cli/workflows/<id>/`, 선택 시 `.claude/skills/<id>/`·`.agents/skills/<id>/` projection), 사용자가 선택하고 host가 지원할 때만 만드는 native 역할(`.claude/agents/<role>.md`, `.codex/agents/<role>.toml`), `.gitignore` 관리 구간이다. 모든 파일은 baseline/current/desired 3-way로 결정하고 사용자 영역은 바이트 보존, 충돌은 보고만 한다. 같은 입력으로 다시 실행하면 모든 파일이 `unchanged`이고 diff 0이다(SETUP-03/04/05).

## 비목표와 범위
고정 agent bundle 배포 없음(SETUP-03). `.claude/settings.json`·`.codex/config.toml`의 의미 단위 병합은 HOLD-2(02-B/04-B와의 소유권) 결정 전까지 범위 밖이며, 결정 시에도 hook·statusline·permissions 활성화는 하지 않는다(빈 안전 baseline만). host 발견·명시 호출 검증은 02-B/02-C, 적용 receipt 저장 경로는 01-B 계약을 따른다. 외부 skill 본문을 그대로 복제하지 않고 license가 `reviewed`인 source만 attribution과 함께 참조한다. Go `.moai/`·`~/.moai/`·기존 `CLAUDE.md` 계열 불변.

## SPEC 요구(GEARS)
- REQ-03C-01 (WHEN) typed `GenerationRequest`(profile 참조, `workflow_id`, `native_roles[]`(각 `role_id`·`host`·`purpose`·`read_only_intent`), `skill_projections[]`, `language`)가 들어오면, moai-cli `generation-plan`은 파일별 `path`·`action`∈{create,merge,append,unchanged,conflict}·`tracked_by_default`·`expected_sha256`·`baseline_sha256`·`rendered_sha256`·`source_refs[]`를 담은 plan과 `plan_digest`를 반환하고 아무것도 쓰지 않아야 한다.
- REQ-03C-02 (Ubiquitous) 모든 파일 결정은 `decide(baseline,current,desired)` digest 3-way를 따라야 하며, baseline과 다른 current를 덮어쓰는 경로가 없어야 한다(conflict는 보고만).
- REQ-03C-03 (WHEN) `generation-apply`가 plan을 받으면 재계획 digest 일치·`conflict` 0건을 확인한 뒤 파일을 임시 쓰기→(신규: hard_link exclusive / 기존: rename)으로 적용하고 마지막에 `generation.json`을 갱신해야 하며, 중간 실패 시 `partial apply`와 적용 목록을 보고해야 한다.
- REQ-03C-04 (WHEN) 동일 `GenerationRequest`로 apply를 두 번 실행하면, 두 번째 plan의 모든 파일 action이 `unchanged`이고 대상 파일·`generation.json`의 sha256이 첫 번째와 같아야 한다(SETUP-05).
- REQ-03C-05 (WHERE) `native_roles`가 비어 있는 요청에서는 `.claude/agents/`·`.codex/agents/` 아래 어떤 파일도 계획·생성하지 않아야 한다(SETUP-03, 고정 bundle 없음).
- REQ-03C-06 (WHEN) `native_roles`에 Claude 역할이 있으면 `.claude/agents/<role_id>.md`를 `name`·`description` 필수 frontmatter와 요청된 `tools` 허용 목록으로 렌더하고, Codex 역할이 있으면 `.codex/agents/<role_id>.toml`을 `name`·`description`·`developer_instructions`로 렌더하되 `sandbox_mode`·`approval_policy`·`mcp_servers` key를 쓰지 않아야 하며, `read_only_intent:true`인 Codex 역할에는 plan `warnings`에 '지침은 sandbox를 만들지 않음'을 포함해야 한다.
- REQ-03C-07 (Ubiquitous) 렌더에 들어가는 모든 profile·요청 문자열은 관리 마커 토큰(`<!--`, `-->`, `moai:managed:`, `# moai:managed:`)과 frontmatter 구분자(`---` 줄)를 포함하면 거부되어야 한다.
- REQ-03C-08 (IF) `sources.json`의 어떤 source가 `license.status != reviewed`이면, 그 source를 `source_refs`로 참조하는 생성물은 계획되지 않아야 하고 plan `warnings`에 사유가 포함되어야 한다; `reviewed` source는 생성물 안에 attribution 줄(source URL·revision·license)로 표기되어야 한다.
- REQ-03C-09 (WHEN) 생성한 skill projection(`.claude/skills/<id>/SKILL.md`, `.agents/skills/<id>/SKILL.md`)을 만들 때 `name`은 디렉터리명과 같고 Agent Skills 명세 문자 규칙을 만족해야 하며, 동명 디렉터리가 이미 있고 manifest baseline이 없으면 `conflict`로 보고해야 한다.
- REQ-03C-10 (WHILE) 기존 `CLAUDE.md`·`.claude/CLAUDE.md`·`CLAUDE.local.md`·`AGENTS.override.md`가 있는 동안, plan은 이를 `host_notes`로 보고하고 삭제·수정·새 CLAUDE.md 생성을 계획하지 않아야 하며, 예상 AGENTS.md 크기가 32 KiB를 넘으면 경고해야 한다.
- REQ-03C-11 (Ubiquitous) apply 결과는 `files_created[]`, `files_merged[]`, `host_loaded:false`, `execution_verified:false`를 분리해 보고해야 한다.
