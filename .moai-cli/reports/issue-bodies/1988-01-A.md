# [RC1][Rust 실행과 저장] 01-A Rust 파일 resolver와 작업 identity 구현

> **HOLD 전제 주의** — 3단계 임시 sha256(common-dir) 기본값은 P08/P09 HOLD 해소 전 구현 착수와 같음 → 결정 전 보류.

## 목표와 사용자 가치
moai-cli가 어떤 디렉터리에서 불려도 (1) Git common-dir(clone 경계)와 개별 git-dir/worktree(workspace 경계)를 구분해 식별하고, (2) 프로젝트 상태 `<project>/.moai-cli/`와 홈 상태 `~/.moai-cli/`의 위치를 하나의 resolver로 결정하며, (3) Go 세대 경로(`.moai/`, `~/.moai/`, `MOAI_HOME`)를 절대 쓰기 대상으로 잡지 않는 typed `identity`/`resolve_scope` 결과를 돌려주게 한다. 현재 코드(`root_of`)는 canonicalize만 하고 git을 전혀 보지 않으므로, 같은 repo의 두 worktree가 서로 다른 project로 보이거나 bare/separate-git-dir에서 오판할 수 있다. 이 Issue가 01-B의 receipt 키, 04-A의 세대 분리 fixture, 06-A의 claim record의 `worktree identity` 필드의 기반이 된다.

## 비목표와 범위
비목표: `~/.moai-cli/` 아래에 실제 파일을 쓰는 설치 명령(04-A), worktree 생성·삭제·GC(EP-07/ST-05~06), Go `worktreeroot`의 `moai-project-key` 기록 형식 포팅, 폴더명 `.moai` 전환, 원격 URL·basename 기반 identity. 범위: `src/` 안의 새 모듈(가칭 `identity.rs`/`resolver.rs`)과 `moai-cli identity <PATH> --json` 같은 읽기 전용 명령 1개, `tests/product_cli.rs` 또는 새 통합 테스트의 git fixture, `docs/rust-product-path.md` 갱신.

## SPEC 요구(GEARS)
- REQ-01A-01 (Ubiquitous) 시스템은 입력 경로에서 `git rev-parse --path-format=absolute --git-common-dir`와 `--absolute-git-dir`를 실행한 결과를 각각 `clone_anchor`와 `workspace_git_dir`로 typed 보고해야 하며, 두 값이 같으면 `workspace_kind: primary`, 다르면 `linked`로 분류해야 한다.
- REQ-01A-02 (WHEN) 입력 경로가 Git 작업 트리 밖이거나 `git`가 PATH에 없을 때, 시스템은 `identity_status: no_git | git_unavailable`과 이유를 돌려주고 추정 identity를 만들지 않아야 한다.
- REQ-01A-03 (WHERE) bare repository(`--is-bare-repository`가 true)에서는 시스템은 `workspace_kind: bare`를 보고하고 프로젝트 상태 디렉터리 생성 대상을 제시하지 않아야 한다.
- REQ-01A-04 (Ubiquitous) 시스템은 `.git`이 디렉터리인지 gitfile인지에 의존하지 않고 git의 출력만으로 경계를 판정해야 한다.
- REQ-01A-05 (Ubiquitous) 시스템은 project state root를 `<show-toplevel>/.moai-cli`로, home state root를 `$HOME/.moai-cli`(또는 HOLD-결정된 override 변수)로 결정해야 하며, `.moai`·`~/.moai`·`MOAI_HOME`을 결코 쓰기 대상으로 반환하지 않아야 한다.
- REQ-01A-06 (WHEN) 입력 경로 또는 state root 후보에 symlink·reparse point가 있을 때, 시스템은 기존 `target()` 규칙과 동일하게 거부하고 이유를 보고해야 한다.
- REQ-01A-07 (Ubiquitous) identity 출력은 project_id(프로젝트 profile), clone_id(common-dir 기반), workspace_id(git-dir 기반)를 분리한 필드로 가져야 하며 basename·branch·remote URL만으로 어떤 ID도 만들지 않아야 한다.
- REQ-01A-08 (WHEN) 같은 common-dir를 가진 두 worktree에서 호출될 때, 시스템은 동일한 clone_id와 서로 다른 workspace_id를 돌려줘야 한다.
- REQ-01A-09 (Ubiquitous) identity 명령은 읽기 전용이어야 하며 어떤 파일도 생성·수정하지 않아야 한다(향후 key 기록은 HOLD 결정 후 별도 쓰기 경로).
- REQ-01A-10 (Ubiquitous) 출력은 stdout 단일 JSON object, 진단은 stderr, exit 0/1이어야 하고 입력 경로 값을 오류 메시지에 그대로 echo하지 않아야 한다(기존 no-echo 규칙 유지).

## 구현 계획
1. 1. 00-D(#1987)는 초안으로 통합됨(c4a7d221d; HOLD-00D-1 envelope·HOLD-00D-3/4 오류·exit는 미결). 리더 결정(RC1 임시): identity 출력은 **현행 계약**(envelope 없음, stdout typed JSON, stderr 평문, exit 0/1)을 따르고 필드명은 00-D `variants` A/B 양쪽과 호환되는 평면 키를 쓴다; 00-D 확정 시 01-C가 조정.
2. 2. `src/identity.rs` 신설: `git` 하위 프로세스를 고정 argv로 실행(`rev-parse --path-format=absolute --git-common-dir`, `--absolute-git-dir`, `--show-toplevel`, `--is-bare-repository`; 필요 시 `worktree list --porcelain -z`), stdout 크기 상한·UTF-8 검증·exit code 분기. 사용자 입력을 shell 문자열에 이어붙이지 않는다.
3. 3. `Identity` typed struct(project_id?, clone_id, workspace_id, workspace_kind, state_roots{project, home}, status)와 ID 파생 함수. 파생 규칙은 HOLD-1 결정 전까지 `sha256(canonical common-dir path)`를 임시 구현으로 두고 `@MX:DEBT`+`@MX:UPGRADE` 표기.
4. 4. `main.rs`에 `identity <PATH>` 읽기 전용 subcommand 추가(기존 패턴: stdout JSON, stderr 진단, exit 0/1).
5. 5. 기존 `root_of`/`target`가 identity의 `show-toplevel`을 선택적으로 받도록 하되 기존 동작·테스트는 그대로 유지(회귀 금지).

8. 8. 로컬 build/test/clippy/fmt 실행 로그를 PR 본문에 첨부, 독립 review 요청, `Refs #1988`.

- key 파생(HOLD-1) 전에 임시 sha256(path) 구현은 repo 이동 시 key가 바뀌는 한계가 있음(설계 '이동·동명 repo 구분' 요구와 충돌 가능) — DEBT로 명시.
