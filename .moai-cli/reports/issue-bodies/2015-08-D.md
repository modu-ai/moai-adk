## SPEC 요구(GEARS)
- REQ-08D-01 [Ubiquitous] 지원표의 각 행은 08-C receipt(`os`·`arch`·`host`·`host_exact_version`·`mode`·`skill_digest`·`moai_cli_sha`·결과)를 출처로 가져야 하며 receipt 없는 행은 `not_run`으로만 표기해야 한다(RL-10).
- REQ-08D-02 [Ubiquitous] 릴리스 체크리스트는 exact candidate SHA, 모든 artifact의 sha256, provenance/attestation 또는 서명의 검증 명령과 결과, known-good restore 시험 결과, 3.x updater 격리 확인, 문서 예제 재현 결과, 미결 목록(P04·P12·signing 운영)을 항목으로 가져야 한다.
- REQ-08D-03 [WHEN] 릴리스 후보 version이 `2026.11.0-rc.1`일 때 문서와 체크리스트는 이를 prerelease로 표기하고 `latest`로 설정하지 않아야 하며(Go stable updater 보호), tag/feed namespace가 Go RC 채널 client에 노출되는지 확인 항목을 포함해야 한다.
- REQ-08D-04 [IF-THEN] 지원표·체크리스트의 어느 필수 행이 `failed`·`blocked`·`not_run`이면 릴리스 검토 문서는 verdict를 `release blocked`로 기록해야 하며 평균 점수로 상쇄하지 않아야 한다.
- REQ-08D-05 [Ubiquitous] 릴리스 검토 verdict는 구현 context와 분리된 독립 reviewer가 작성해야 하며 reviewer·공유 context 범위·대조한 digest를 기록해야 한다.
- REQ-08D-06 [Ubiquitous] 사용자 문서는 3.x 명령(`moai init`·`moai update`)을 차세대 필수 단계로 안내하지 않아야 하며 `/moai`·`$moai` 자연어 진입을 기본으로 두고 수동 명령은 명시적 fallback으로 분리해야 한다.
- REQ-08D-07 [Ubiquitous] 문서·체크리스트·지원표에는 secret·개인 절대 경로·비공개 운영 정보가 없어야 한다.
- REQ-08D-08 [WHERE] 서명 identity나 attestation workflow가 아직 결정되지 않은 경우 체크리스트는 해당 항목을 `HOLD/not_run`으로 두고 checksum만으로 서명 검증을 대체했다고 쓰지 않아야 한다.
- REQ-08D-09 [Ubiquitous] 같은 version에 다른 digest의 artifact를 재배포하지 않아야 하며, 교정은 `rc.2`로 해야 한다(tag immutability ruleset과 일치).
