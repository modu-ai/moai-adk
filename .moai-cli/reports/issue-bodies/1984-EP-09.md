# [RC1][EP-09] RC 인증과 문서

## 목표와 사용자 가치
RC1(`2026.11.0-rc.1`)이 실제로 출시 가능한 상태인지 증명하는 영역이다. 네 개의 실행 Issue가 각각 (08-A) 검증된 후보를 최신 `v2026.11.0`에 통합하고 PR·독립 review·exact CI를 연결하는 절차, (08-B) 개발 저장소에서 검증한 `.github` 자산을 Rust 생성 템플릿으로 '추가'하는 경로, (08-C) 양 host(Claude Code·Codex)에서 SETUP/UPDATE/중단 복구를 실제로 돌려 본 E2E 증거, (08-D) 지원표·릴리스 체크리스트·서명/checksum/provenance·미결 목록·독립 release 감사를 만든다. 가치는 '파일이 있다'가 아니라 '해당 조합에서 실제로 동작했고 복구됐다'는 증거가 Issue 원장에 남는 것이다. 설계 정본 §24 'RC 승격' 행(서명 artifact·OS/host matrix·migration·rollback·문서, 지원 조합별 실제 E2E와 restore)과 12-page §7 'RC release review'(필수 gap 존재 시 release blocked)를 그대로 완료 기준으로 쓴다.

## 비목표와 범위
범위: 통합·SYNC 절차와 receipt, `.github`→`templates/github/` 승격과 renderer fixture, host E2E·restore 시험, 지원표·릴리스 검토 문서. 비범위: 실제 GitHub Release 게시·tag push·서명 identity 발급·Homebrew/npm 등 패키지 채널 운영(별도 release 권한과 사용자 결정), Go 세대 `.moai/`·`~/.moai/`·원격 `main`·Go release 자산 변경, GitLab provider adapter 구현(설계 §9는 GitLab을 별도 adapter로 둔다), 후속 Desktop(M5). P04(첫 RC 인증 순서)·P12(OS/arch·locale matrix)·signing 운영은 사용자 미결이므로 이 영역 안에서 확정하지 않는다. 개발 저장소 `.github/`는 승격 후에도 유지한다(이동 아님).
