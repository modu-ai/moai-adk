# [RC1][EP-07] 실행 소유권과 통합

## 목표와 사용자 가치
한 Issue를 한 세션이 끝까지 책임지게 하는 실행 소유권 계약(claim·attempt·epoch)과, 그 세션이 만든 변경을 분리된 worktree와 PR로 식별해 v2026.11.0 통합 대상까지 안전하게 넘기는 경로를 Rust `moai-cli`에 만든다. 사용자 가치: 같은 Issue를 두 세션이 동시에 구현하는 중복 작업, 늦게 도착한 옛 결과가 새 결과를 덮는 사고, 결과 불명 외부 효과(PR·댓글)의 이중 생성을 구조적으로 막고, 중단·인계 시 미커밋 변경을 잃지 않는다. GitHub assignee·label·댓글은 표시(projection)일 뿐 lock이 아니라는 설계 원칙(D36, 설계 11:72)을 코드와 fixture로 고정한다.

## 비목표와 범위
비목표: 여러 컴퓨터·여러 리더 사이의 전역 분산 lock 구현(로컬 파일 lock은 단일 host 범위라는 설계 00:589·§8 원칙 유지), 무응답 자동 takeover(P08 HOLD, 설계 11:72·§8 '이번 계획에서 무응답 자동 takeover를 새로 승인하지 않는다'), 별도 서버·공용 DB·상시 daemon, 최신 base 통합·merge·release 실행(08-A 영역), GitHub label 체계 변경, Go `.moai/`·`~/.moai/`·`moai` 바이너리 변경, 원격 `main` 변경. 범위: `src/` 신규 모듈(예: claim journal·handoff 검증·worktree/PR 식별)과 `tests/` fixture, `docs/rust-product-path.md` 계약 추가, `skills/moai/workflows/run.md`·`sync.md`의 preflight 문구 보강. 상태 디렉터리는 확정된 `<project>/.moai-cli/`·`~/.moai-cli/`만 사용한다.
