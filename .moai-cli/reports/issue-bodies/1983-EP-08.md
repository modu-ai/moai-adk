# [RC1][EP-08] Forge 보고와 판단 context

## 목표와 사용자 가치
GitHub(후속 GitLab) Issues를 공식 업무 원장으로 쓰는 online-first 흐름의 '바깥쪽 절반'을 Rust `moai-cli`에 연결한다. 하위 4개 실행 Issue가 각각 (1) Issue 읽기·polling adapter와 stable 식별자, (2) 로컬 TODO의 선택 승격, (3) 간결 보고 댓글과 artifact 참조, (4) API 없이 완주하는 native 판단과 fresh context 측정을 맡는다. 사용자 가치는 서버·DB·상시 daemon 없이도 한 SPEC을 계획→실행→검증→Issue 보고까지 끝낼 수 있고, 그 과정에서 사람의 Issue 편집·비공개 메모·비밀이 보존된다는 점이다(설계 00 §10·§13, 06, 13 페이지).

## 비목표와 범위
범위: GitHub REST 기본 흐름, GitLab 이식을 위한 external reference 계약(어댑터 구현은 제외), native 판단 기본 경로, snapshot/freshness/token 측정의 최소 계측. 비범위: webhook 수신(설계상 선택 adapter), GitLab adapter 구현, Decisions/Jev 등 선택 판단 backend(P10 HOLD), code graph·MX 전체(F13은 후속), 대형 artifact 저장소 선택 확정(P09 HOLD), 수치 budget 확정(P11 HOLD), Go `.moai/`·`~/.moai/`·설치본 변경, 원격 `main` 변경. 모든 외부 쓰기는 사용자 허용 범위 안에서만 수행하며 이 영역 설계가 쓰기 권한을 만들지 않는다.
