# [RC1][설치와 UPDATE] 04-C UPDATE 부분 실패와 복구 검증

## 목표와 사용자 가치
04-B의 host별 transaction이 중간에 끊기거나 한 host만 실패했을 때, 성공한 host의 새 상태는 그대로 두고 실패 host에서는 이번 요청이 바꾼 관리 파일 중 현재 hash가 receipt의 after와 일치하는(=그 사이 사용자 수정 없음) 파일만 before로 되돌리며, 그 외(사용자 수정·불명)는 conflict로 보존하는 복구 계약(`recovery-plan` 읽기 전용 → `recovery-apply`)을 구현하고 crash-point fixture로 증명한다. 사용자 가치: 업데이트가 깨져도 파일을 잃지 않고, 일괄 롤백으로 다른 host의 정상 상태가 되돌아가는 일이 없다(D72, UPDATE-PARTIAL, RL-03, HA-02).

## 비목표와 범위
비목표: 자동 재시도 루프, 성공 host 포함 일괄 rollback(설계가 명시 비채택), moai-cli 실행 파일 자체의 복구(설치 방식 HOLD), host 실제 로딩 실측(08-C), 동시 writer 완전 배제(OS CAS 아님을 문서화). 범위: (1) 실패 주입 fixture 5종 이상 (2) 읽기 전용 `recovery-plan` (3) 안전 조건을 만족하는 파일만 되돌리는 `recovery-apply` (4) 전체 보고(`success|partial`, host별 version·applied·failed·recovered·conflicts).

## SPEC 요구(GEARS)
- REQ-04C-01: WHEN `recovery-plan`이 호출되면, moai-cli는 각 host receipt를 읽어 `committed`면 `none`, `pending`이면 파일별로 현재 sha256을 receipt의 `before_sha256`/`after_sha256`과 대조해 `matches_before(미적용)|matches_after(이번 변경, 복구 가능)|conflict(사용자 수정·불명, 보존)|missing(파일 없음)` 중 하나로 분류하고, 어떤 파일도 쓰지 않아야 한다.
- REQ-04C-02: WHEN `recovery-apply`가 승인된 plan_digest·permission_reference와 함께 호출되면, moai-cli는 `matches_after`인 파일만 receipt에 보관된 before 내용(또는 before가 '없음'이면 삭제)으로 되돌리되 rename 직전 현재 sha256을 다시 검증하고, `conflict`·`missing`·`matches_before` 파일은 건드리지 않아야 한다.
- REQ-04C-03: moai-cli는 복구 수행 전 receipt에 before 내용의 복사본(`~/.moai-cli/installations/<id>/hosts/<host>/known-good/<sha256>`)이 있어야만 되돌릴 수 있으며, 사본이 없으면 해당 파일을 `conflict(no_known_good)`으로 보고해야 한다(04-B가 pending 기록 시 before 바이트를 보관하는 것을 전제).
- REQ-04C-04: WHILE 어떤 host가 `pending`인 동안, moai-cli의 `update-apply`는 그 host에 대한 새 적용을 거부하고 `recovery-plan`을 먼저 안내해야 하며, 다른 `committed` host에는 영향을 주지 않아야 한다.
- REQ-04C-05: moai-cli는 복구 후 host receipt를 `recovered`(되돌린 파일 목록·남은 conflict 포함) 또는 conflict가 남으면 `pending`으로 유지해 기록하고, 성공 host의 receipt·파일에는 어떤 쓰기도 해서는 안 된다.
- REQ-04C-06: moai-cli의 전체 보고는 `status ∈ {success, partial}`과 host별 `version_before/version_after`, `applied`, `failed`, `recovered`, `conflicts`를 포함해야 하며, 복구를 '성공'으로 요약하면서 남은 conflict를 생략해서는 안 된다.
- REQ-04C-07: IF 복구 중 다시 실패하면(권한 거부·디스크 가득·재검증 불일치), moai-cli는 되돌리기 전 파일을 그대로 두고 어디까지 되돌렸는지 receipt에 기록하며 자동 재시도를 해서는 안 된다.
