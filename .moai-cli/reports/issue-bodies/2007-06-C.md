# [RC1][실행 소유권과 통합] 06-C 세션별 worktree와 PR 연결 구현

## 목표와 사용자 가치
claim된 Issue마다 전용 branch·worktree를 만들고, 그 worktree의 identity(common-dir·git-dir·HEAD)를 claim record에 묶어 '한 Issue 한 owner 한 writer'를 로컬에서 보장하며, 변경·시험 receipt·PR을 logical key·Issue URL·SPEC digest·base/candidate SHA로 식별해 v2026.11.0 대상 PR 본문에 고정한다. 활성 claim 간 write_scope 겹침을 미리 감지해 같은 파일·schema·lockfile 경합을 dependency 또는 통합 순서로 넘긴다. 사용자 가치: PR만 보고도 어떤 Issue·SPEC·시험·정확한 SHA인지 추적되고(GH-PR-EVIDENCE), 두 세션이 같은 파일을 동시에 고치는 충돌을 PR 단계가 아니라 claim 단계에서 막는다.

## 비목표와 범위
비목표: 최신 base rebase·merge·CI 재검증(08-A), branch protection·ruleset 변경(사용자 승인 사항, 아래 HOLD), PR merge, `Closes` 자동 닫기(비기본 브랜치 대상이라 작동하지 않고 완료는 리더 판정), worktree 자동 삭제·GC(F22/D43 영역). 범위: `src/worktree.rs`·`src/pr_link.rs`(제안), `worktree-plan/apply`·`pr-body-render`·`scope-check` 하위 명령, fixture, 문서. PR 생성 자체는 호스트가 `gh pr create`로 실행하고 `moai-cli`는 본문·검증 receipt·effect intent를 만든다.

## SPEC 요구(GEARS)
- REQ-06C-01 WHEN `worktree-plan`이 호출되면, 시스템은 claim record(06-A)의 task_ref·epoch를 읽고 branch 이름 `<prefix>/<logical_key>-<issue_number>-e<epoch>`(prefix는 PLAN 확정)과 worktree 경로(루트는 HOLD)를 계산해 JSON plan(digest 포함)으로 출력하고 어떤 git 변경도 하지 않아야 한다.
- REQ-06C-02 WHEN `worktree-apply --plan-digest`가 호출되면, 시스템은 plan을 현재 트리와 재대조한 뒤 `git worktree add --lock --reason "moai claim <task_key> e<epoch>" -b <branch> <path> <base_sha>`를 실행하고, 생성된 worktree의 `git rev-parse --git-common-dir`·`--git-dir`·`HEAD`를 record.worktree에 기록해야 한다.
- REQ-06C-03 IF 대상 branch가 이미 다른 worktree에 체크아웃돼 있거나 경로가 존재하면, THEN 시스템은 `--force`를 쓰지 않고 `conflict`로 중단하고 기존 worktree 정보를 반환해야 한다.
- REQ-06C-04 [Ubiquitous] 시스템은 주 checkout(primary worktree)에서 `git checkout|switch|branch -D|reset --hard|stash`를 실행하지 않아야 하며, 새 branch는 항상 `worktree add -b`로만 만들어야 한다.
- REQ-06C-05 WHEN 새 claim의 write_scope가 다른 활성 claim의 write_scope와 경로 glob 교집합을 가지면, 시스템은 `scope_conflict{other_task, overlap[]}`를 반환하고 record를 `blocked(reason=scope_conflict)`로 표시하되, 리더가 `--integration-order <task_ref>` 또는 dependency를 지정하면 진행을 허용해야 한다.
- REQ-06C-06 [Ubiquitous] 시스템은 `Cargo.lock`·`Cargo.toml`·`.github/**`·`.moai-cli/manifests/**`·`AGENTS.md`를 '공유 interface 경로'로 기본 등록하고, 둘 이상의 활성 claim이 이를 포함하면 REQ-06C-05와 같이 다뤄야 한다.
- REQ-06C-07 WHEN `pr-body-render`가 호출되면, 시스템은 본문에 `logical_key`, Issue URL(`https://github.com/modu-ai/moai-adk/issues/<n>`)과 `Refs #<n>`, `spec_ref{id,revision,digest}`, `base_sha`(40자), `candidate_sha`(현재 HEAD 40자), `epoch`, 실제 시험 명령·exit code 요약, 독립 review 링크 자리, `not_run` 목록을 포함하고 `Closes|Fixes|Resolves` 계열 키워드를 넣지 않아야 한다.
- REQ-06C-08 IF 호출자가 `--allow-close`를 주더라도 PR base가 기본 브랜치가 아니면, 시스템은 'closing keyword는 기본 브랜치 대상에서만 해석됨'을 경고하고 키워드를 넣지 않아야 한다.
- REQ-06C-09 WHEN PR 본문이 렌더되면, 시스템은 06-B의 `effect-intend{kind: pr_create, operation_id}`를 기록하고 본문 끝에 `<!-- moai-op: <operation_id> -->` marker를 넣어 reconcile 조회 키로 쓰게 해야 한다.
- REQ-06C-10 WHEN 같은 입력으로 `worktree-plan`·`pr-body-render`를 재실행하면, 시스템은 바이트 동일 출력을 내야 한다(candidate_sha가 같을 때).
- REQ-06C-11 [Ubiquitous] 시스템은 PR 개설·ACK를 record 상태 `pr_ready`로만 바꾸고 `integrated`·완료로 승격하지 않아야 한다.
- REQ-06C-12 WHERE 사용자 체크아웃 경로가 D38 기본값과 다르면, 시스템은 기존 경로를 그대로 지원하고 이동·생성 강요를 하지 않아야 한다.

## 관련 논문
해당 논문 없음 — worktree 격리·PR 본문 식별·branch protection은 도구 계약(git·GitHub) 문제이며 직접 적용되는 동료심사 논문을 확인하지 못했다. 소유권·fencing 근거는 06-A/06-B의 Gray&Cheriton 1989·Burrows 2006·Kleppmann 2016을 공유하며, merge `sha` 파라미터가 그 fencing의 GitHub 측 구현점이다. 논문을 지어내지 않는다.

## 베스트 프랙티스 채택/비채택
- `git worktree add --lock --reason -b <branch> <path> <base>`로 생성 직후 race 없이 잠그고, 체크아웃 충돌은 `--force` 없이 중단 · 판정: 채택 · 이유: 공식 문서가 --lock의 무-race 보장과 중복 체크아웃 거부를 명시 · 출처: https://git-scm.com/docs/git-worktree (2026-11-08)
- worktree identity는 `git rev-parse --git-common-dir`/`--git-path`로 얻고 basename·`.git` 모양으로 추정하지 않음 · 판정: 채택 · 이유: D42 결정과 문서 'do not make any assumption about whether a path belongs to $GIT_DIR or $GIT_COMMON_DIR' · 출처: https://git-scm.com/docs/git-worktree (2026-11-08)
- 비기본 브랜치 대상 PR에는 `Refs #n`만, closing keyword 금지 · 판정: 채택 · 이유: 키워드는 기본 브랜치 대상에서만 해석되며 완료 판정은 리더 · 출처: https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue (2026-11-08)
