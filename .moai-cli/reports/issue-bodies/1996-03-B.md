# [RC1][최초 설정과 맞춤 생성] 03-B 외부 skill 탐색 검토와 provenance 구현

## 목표와 사용자 가치
인터뷰 결과와 관련된 외부 skill 후보를 모아 source·고정 revision·tree digest·license·설치 scope·telemetry 결정을 `.moai-cli/manifests/sources.json`에 기록하고, 검토를 통과한 skill만 해당 host의 공식 skill 폴더(Claude `~/.claude/skills/` 또는 `.claude/skills/`, Codex `~/.agents/skills/` 또는 `.agents/skills/`)에 복사 설치한 뒤, 설치본의 모든 파일을 읽은 '전체 읽기 receipt'를 남긴다. 가치: 03-C의 맞춤 생성이 어떤 원문·license에서 왔는지 추적되고, 미확인 license·미확인 publisher는 자동 활성화되지 않는다.

## 비목표와 범위
skills.sh/Vercel CLI는 선택 source이며 `npx skills ...` 자동 실행·Node 자동 설치·전체 registry 설치는 하지 않는다. 설치한 skill의 script 실행, hook/MCP 등록, 네트워크 전송 승인은 별도 권한. publisher 신뢰(서명 검증)는 source가 SLSA/in-toto/Sigstore 증거를 제공할 때만 기록하고, 없으면 `publisher_trust: not_verified`로 둔다(보증하지 않음). 후보 검색어는 공개 기술·기능명으로 한정한다. 설치본을 바탕으로 맞춤 파일을 만드는 것은 03-C.

## SPEC 요구(GEARS)
- REQ-03B-01 (WHEN) 후보 목록(typed JSON: `source_url`, `source_type`∈{github,gitlab,git,local,download}, `requested_revision`, `skill_names[]`, `host_targets[]`, `scope`∈{user,project})이 stdin으로 들어오면, moai-cli `skill-source-plan`은 각 후보에 대해 `license.status`∈{reviewed,unknown,refused}, `revision.resolved`(40자 commit SHA 또는 null), `install_mode`, `telemetry_policy`를 포함한 계획을 반환하고 아무것도 쓰지 않아야 한다.
- REQ-03B-02 (IF) 후보의 license가 확인되지 않거나(`unknown`) 명시 license 파일·SPDX 식별자가 없으면, moai-cli는 그 후보를 `refused: license_unverified`로 표시하고 복제·설치·03-C 재사용 대상에서 제외해야 한다(복제 허용으로 추정하지 않음).
- REQ-03B-03 (WHEN) 설치가 승인된 후보를 적용할 때, moai-cli `skill-source-apply`는 고정 revision의 파일 트리를 host 공식 폴더(`<home>/.claude/skills/<name>/`, `<home>/.agents/skills/<name>/`, 또는 프로젝트 `.claude/skills/`·`.agents/skills/`)에 exclusive create로 복사하고, 동명 디렉터리가 이미 있으면 덮어쓰지 않고 `conflict: existing_skill`로 보고해야 한다.
- REQ-03B-04 (Ubiquitous) 설치본 tree digest는 `moai-package-tree-v1`(`package_digest`)로 계산해 `sources.json`에 기록해야 하며, symlink·특수 파일·상한 초과 트리는 설치를 거부해야 한다.
- REQ-03B-05 (WHEN) 설치가 끝나면 moai-cli `skill-read-receipt`는 설치 디렉터리의 전체 파일 목록과 각 파일 sha256, 총 바이트, `read_complete: true|false`를 receipt로 남겨야 하고, 하나라도 읽지 못했으면 `read_complete:false`와 미읽음 경로를 보고해야 한다.
- REQ-03B-06 (Ubiquitous) `sources.json`의 모든 항목은 `publisher_trust: not_verified`를 기본값으로 가지며, source가 in-toto Statement(`https://in-toto.io/Statement/v1`)·SLSA provenance·Sigstore 서명을 제공하고 moai-cli가 검증했을 때만 다른 값으로 바꿔야 한다(검증하지 않은 서명을 기록하지 않음).
- REQ-03B-07 (WHERE) Vercel skills CLI를 탐색 수단으로 선택한 환경에서는, moai-cli가 Node.js 22.20+ 존재를 capability로 보고하되 runtime을 설치하지 않고, 호출 시 `DISABLE_TELEMETRY`/`DO_NOT_TRACK` 설정 여부와 그로 인해 security-audit 요청도 꺼진다는 사실을 계획에 기록해야 한다.
- REQ-03B-08 (Ubiquitous) moai-cli는 비공개 repo 식별자·코드·개인정보를 외부로 전송하지 않아야 하며, 후보 검색어는 호출자가 준 공개 기술·기능명 문자열만 사용해야 한다(secret·절대 경로 형태는 거부).
- REQ-03B-09 (WHEN) `sources.json`이 이미 있을 때, moai-cli는 항목을 `source_url+resolved_revision` 키로 structured merge하고 사용자가 추가한 unknown key를 보존해야 하며, 동일 입력 재실행은 파일 바이트를 바꾸지 않아야 한다.
- REQ-03B-10 (Ubiquitous) 설치·읽기 결과 JSON은 `files_installed`, `read_complete`, `host_loaded:false`, `execution_verified:false`를 분리해 보고해야 한다(설치 성공을 host 발견·실행 성공으로 승격하지 않음).

## 구현 계획
1. 1. `src/sources.rs` 신설: `SourceCandidate`/`SourceRecord` 타입(deny_unknown_fields), license 판정(LICENSE/LICENSE.*/COPYING 파일 존재 + SKILL.md frontmatter `license` 필드 → SPDX 식별자 문자열 보존, 판정은 `reviewed|unknown|refused`; 자동 법적 판단은 하지 않고 '확인 증거 유무'만 기록), telemetry 정책 필드.
2. 2. revision 고정: 로컬 path source는 트리 digest만; git source는 HOLD-1 결과에 따라 (a) 호출자가 미리 체크아웃한 로컬 경로를 받거나 (b) `git` CLI를 고정 argv로 호출. 03-B 1차는 (a)로 구현하고 (b)는 capability 보고만.
3. 3. `skill-source-plan`(읽기 전용)·`skill-source-apply`(승인 plan digest + permission_reference, exclusive create 복사, 부분 실패 시 applied 목록 보고)·`skill-read-receipt` 서브커맨드를 `src/main.rs`에 추가.
4. 4. `sources.json` structured merge: 기존 파일 JSON 파싱→키(`source_url`,`resolved_revision`) 기준 병합→unknown key 보존→임시 파일→rename.
5. 5. fixture: 임시 HOME/프로젝트에 가짜 skill repo 디렉터리 생성, license 유무·동명 충돌·읽기 gap·재실행 diff 0·symlink 거부.
6. 6. `docs/rust-product-path.md`에 명령 계약·한계(publisher_trust not_verified, host_loaded false) 추가; `skills/moai/workflows/setup.md` 3항 입력 schema 참조 갱신.
