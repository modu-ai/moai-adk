# [RC1][공통 skill과 host] 02-D ZCode 지원표와 adapter gap 검증

## 목표와 사용자 가치
Z.ai ZCode(사용자가 지정한 제품; zcode.z.ai)에 대해 공식 문서로 확인된 discovery/import·AGENTS·skills·hooks·plugin 계약과 미확인 항목(statusline·output style·import 소스 경로·프로젝트 skill 경로)을 구분한 지원표를 작성하고, 공통 package를 ZCode에 연결할 때의 adapter gap(무엇이 되고, 무엇이 대안이며, 무엇이 미검증인지)을 기록한다. '지원' 표기는 실제 앱 E2E가 있는 조합에만 붙이고 문서 지원만 있는 항목은 `documented`, 확인 못 한 항목은 `unknown`으로 둔다(설계 10 §2 capability 상태 모델). RC1에서 ZCode 실측을 포함할지는 P04/P15 HOLD다.

## 비목표와 범위
비목표: ZCode용 파일 생성·설치 코드 구현(지원 범위 결정 전), ZCode 경로를 추정해 생성, `.claude/`·`.agents/` 설정 복사만으로 '활성화' 보고, OMP·OpenCode·dot·Duet 등 다른 host 확대, Go 세대 Codex/ZCode 문자열 존재를 지원 근거로 사용. 범위: 지원표 문서(`docs/host-support-matrix.md` ZCode 행 또는 `docs/zcode-support.md`), `host-capabilities` schema의 ZCode 항목(전부 unknown/documented), gap 목록과 후속 Issue 제안, 사용자 결정용 선택지.

## SPEC 요구(GEARS)
- REQ-02D-01 (Ubiquitous) 지원표는 ZCode 항목마다 `capability_status ∈ {unknown, documented, probed, certified, stale}`과 출처 URL·확인일·ZCode version을 가져야 하며, `documented`만으로 '지원'이라 표기하지 않아야 한다.
- REQ-02D-02 (Ubiquitous) 지원표의 ZCode 행은 최소 AGENTS 로딩(전역+workspace, import 미지원), skill 경로(`~/.zcode/skills`), skill 제약(description 1024자·본문 100KB), 명시 호출(`$`), Import 대화상자(소스 경로 미확인), hooks(user config/plugin만, project 무시), plugin manifest(`.zcode-plugin`·`.claude-plugin`), statusline(미확인), output style(미확인)을 포함해야 한다.
- REQ-02D-03 (IF) 공식 문서가 어떤 기능을 명시하지 않으면, 지원표는 그 항목을 `unknown`으로 두고 '표시 불가·대안·시험 대기' 중 하나로 분류해야 하며 경로나 동작을 추정해 기록하지 않아야 한다.
- REQ-02D-04 (Ubiquitous) gap 목록은 공통 package를 ZCode에 연결할 때 필요한 adapter 책임(discovery 경로 projection, `$` 호출 안내, description 길이 검사, hook 등록 위치 분리)을 열거하고 각 항목에 '구현 필요/대안 있음/미검증'을 붙여야 한다.
- REQ-02D-05 (WHILE) P04/P15가 HOLD인 동안, 이 Issue는 ZCode용 파일을 생성·설치하는 코드를 추가하지 않아야 하며 선택지·영향·근거만 기록해야 한다.
- REQ-02D-06 (WHERE) 실제 ZCode 앱 실측을 수행하기로 결정된 경우, receipt에 ZCode exact version·OS·실행 명령/화면·결과를 남기고 그 조합만 `probed`로 올려야 한다.
