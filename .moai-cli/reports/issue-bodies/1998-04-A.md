## 목표와 사용자 가치
moai-cli가 자기 설치본의 identity(실행 파일 경로·digest·version·channel·installer owner·protocol)를 `~/.moai-cli/installations/`에 receipt로 기록·조회하고, PATH의 `moai`(Go)를 자기 자신으로 오인하지 않으며, Go 세대의 release feed·상태 디렉터리와 교차 오염이 없음을 fixture로 증명한다. 사용자 가치: RC를 설치해도 기존 Go `moai`와 `~/.moai/` 작업 데이터가 그대로 보존되고, 두 세대가 서로의 업데이트 후보로 잡히지 않는다. 설치 방식 자체(artifact 배포 채널·서명·binary 경로·tag namespace·Windows 교체·중단 복구)는 사용자와의 첫 브레인스토밍 대상이므로 본 설계는 선택지·영향·근거만 제시하고 확정하지 않는다.

## SPEC 요구(GEARS)
- REQ-04A-01: moai-cli는 설치 receipt `~/.moai-cli/installations/<install_id>.json`에 `schema_version`, `product: "moai-cli"`, `generation: "rust-rc"`, `channel`, `version`, `binary_path`(절대 경로, 사용자 홈은 `~` 토큰으로 정규화), `binary_sha256`, `installer_owner ∈ {direct, cargo, homebrew, msi, unknown}`, `protocol_version`, `created_at`, `updated_at`를 기록해야 한다. 비밀·access token은 어떤 필드에도 기록해서는 안 된다.
- REQ-04A-02: WHEN `moai-cli install-inspect --json`(읽기 전용 내부 명령, 명칭은 P06 HOLD)이 호출되면, moai-cli는 PATH 해석 결과(`moai`·`moai-cli` 각각의 경로·sha256·`--version` 출력 유무), `~/.moai-cli/installations/*` 내용, Go 세대 경로(`~/.moai`, `<project>/.moai`)의 존재 여부만 보고하고 어떤 파일도 생성·수정하지 않아야 한다.
- REQ-04A-03: moai-cli는 자신의 실행 파일 경로(`std::env::current_exe`)와 receipt의 `binary_path`·`binary_sha256`이 일치할 때만 해당 receipt를 '자기 설치본'으로 간주해야 하며, PATH에서 먼저 발견된 `moai`를 자기 자신으로 간주해서는 안 된다.
- REQ-04A-04: WHILE 어떤 moai-cli 명령이 실행되는 동안에도, moai-cli는 `~/.moai/`, `<project>/.moai/`, `MOAI_HOME`이 가리키는 경로, `~/go/bin/moai`에 읽기 외의 접근을 해서는 안 된다(fixture: 실행 전후 트리 hash 동일).
- REQ-04A-05: moai-cli는 Go 3.x updater 선택 규칙(`/releases` 목록, tag 접두사 `v`/`go-v`, prerelease 비검사)을 특성화 테스트로 재현해, 후보 tag namespace(`v2026.11.0-rc.1`, `v2026.11.0`, 대안 접두사, 별도 repo)별로 Go 클라이언트가 새 artifact를 선택하는지 표를 산출해야 한다. 이 표는 결정 근거이며 결정 자체가 아니다.
- REQ-04A-06: IF receipt의 `binary_sha256`이 현재 실행 파일 digest와 다르면, moai-cli는 상태를 `stale_receipt`로 보고하고 자동으로 receipt를 갱신해서는 안 된다(갱신은 명시 apply 경로에서만).
