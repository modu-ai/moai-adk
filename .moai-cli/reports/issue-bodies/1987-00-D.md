## 목표와 사용자 가치
moai-cli(CLI stdin/stdout)와 선택 MCP(structuredContent)가 공유할 typed JSON 계약의 v1 후보를 fixture와 함께 만들고, 설계 문서에 흩어진 상태 어휘 6벌(설치 lifecycle 02:148, VERIFY verdict 07, attempt 11, SYNC 06, Issue claim §8, issue-report 22, migration 14)을 하나의 변환표로 묶어 '같은 단어가 같은 뜻'이 되게 한다. 오류 contract·exit code·`protocol_version`/`schema_version` 호환 규칙을 golden fixture로 검증하고, 현재 코드(exit 0/1만, stderr 평문 오류)와의 차이를 측정 가능한 gap으로 남긴다. P06은 사용자 미결이므로 이 Issue의 결과물은 '선택지별 fixture가 붙은 계약 초안'이며, 사용자가 HOLD-00D-1~5를 고르면 그 조합만 남기고 contracts.lock 후보로 pin한다. 01-A/01-C/02-A/05-A/06-A/07-A가 이 어휘를 기다린다.

## 비목표와 범위
Claude `settings.json`·Codex `config.toml`·MCP tool inputSchema 같은 host native 포맷을 바꾸거나 대체하지 않는다(설계 02:128·22 §2). TOON 등 다른 직렬화로 계약을 바꾸지 않는다(D77/P16 확정: JSON/JSONL 유지). MCP 서버 구현·CLI/MCP parity 실측은 01-C 소관이며 여기서는 parity가 성립하기 위한 schema·오류·상태 어휘만 정의한다. GEARS SPEC 문법은 05-A, claim 레코드 schema 본문은 06-A가 소유하며 여기서는 공통 envelope과 상태 enum만 다룬다. ## SPEC 요구(GEARS)
- REQ-00D-01 WHEN moai-cli 명령이 성공하면, 프로그램은 stdout에 `protocol_version`(정수)·`operation`·`status`(공통 enum)·`result`(명령별 typed 객체)를 가진 envelope 한 개를 JSON 한 줄로 출력하고 exit 0이어야 한다(envelope 채택 여부와 필드명은 HOLD-00D-1에서 확정).
- REQ-00D-02 WHEN moai-cli 명령이 실패하면, 프로그램은 stderr에 typed 오류 객체(`protocol_version`, `error.kind`(enum), `error.message`(값 echo 금지), 선택 `error.detail`)를 출력하고 kind별로 문서화된 exit code를 반환해야 하며 stdout에는 아무것도 쓰지 않아야 한다(오류 형태·exit 표는 HOLD-00D-3/4).
- REQ-00D-03 WHEN 입력 JSON에 schema에 없는 필드가 있으면, 프로그램은 `error.kind = invalid_input`으로 거부해야 한다(현행 `deny_unknown_fields` 유지). WHEN 출력을 소비하는 쪽(adapter)이 모르는 필드를 만나면, 소비자는 무시해야 한다(additive 호환).
- REQ-00D-04 IF 입력의 `protocol_version`이 지원 범위 밖이면, THEN 프로그램은 `error.kind = unsupported_protocol_version`과 지원 범위를 반환하고 어떤 쓰기도 수행하지 않아야 한다.
- REQ-00D-05 WHEN 상태를 출력하면, 프로그램은 공통 canonical enum 중 하나만 사용해야 하고, 설계의 6개 상태 어휘(02:148 lifecycle, 07 verdict, 11 attempt, 06 SYNC, §8 Issue claim, 22 issue-report, 14 migration) 각 토큰은 변환표(`status-crosswalk.json`)에서 정확히 한 canonical 값 또는 명시적 `no-map(사유)`에 대응해야 한다.
- REQ-00D-06 WHILE 어떤 명령도 `not_run`·`unknown`·`blocked`·`stale`을 `passed`/`applied`/`host_verified`로 승격해서는 안 되며, 변환표에 그런 매핑 행이 존재하면 fixture 테스트가 실패해야 한다.
- REQ-00D-07 WHERE MCP tool이 같은 operation을 노출하면, tool의 `structuredContent`는 CLI stdout envelope의 `result`와 byte-동등(JCS 정규화 후 동일 또는 serde 직렬화 동일 — HOLD-00D-5)해야 하고 `outputSchema`는 같은 JSON Schema 파일을 가리켜야 하며, 실행 오류는 `isError: true`로, 호출 형식 오류는 JSON-RPC protocol error로 보고해야 한다.
- REQ-00D-08 WHEN schema 파일을 제공하면, 각 파일은 `$schema: https://json-schema.org/draft/2020-12/schema`와 `$id`를 가져야 하고 golden fixture(성공·오류·각 상태값·version 불일치·미지 필드)가 schema와 코드 양쪽에서 같은 판정을 내야 한다.
- REQ-00D-09 WHEN digest를 계산하는 JSON 입력이 있으면, 프로그램은 문서화된 정규화 규칙(현행: serde 필드 순서 tuple 직렬화 / 대안: RFC 8785)을 fixture로 고정해 동일 의미 입력의 digest가 플랫폼·실행 간 동일해야 한다.
- REQ-00D-10 WHILE 이 Issue의 변경이 적용되는 동안, 기존 `.moai-cli/project.yaml`과 `.moai-cli/manifests/generation.json`(schema_version 1)은 수정 없이 계속 읽혀야 하고 `.claude/settings.json`·`.codex/config.toml`·MCP inputSchema 형식은 생성·변경되지 않아야 한다.
- REQ-00D-11 WHEN 오류 메시지를 만들면, 프로그램은 입력 값·경로·비밀 형태 문자열을 echo하지 않아야 한다(현행 'no values were logged' 규칙 유지).
