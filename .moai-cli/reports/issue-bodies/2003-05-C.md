# [RC1][PLAN RUN VERIFY AUDIT] 05-C RUN 방법론과 실제 VERIFY 연결

## 목표와 사용자 가치
RUN 요청(pinned contract)에서 변경 전략(`change_strategy`: tdd / bugfix / preserve / contract / eval / docs)과 도메인 모델링(`domain_modeling`)을 독립 선택하고, 저장소에 정의된 검증 명령을 trusted runner가 argv로 실행해 exact tree·SPEC·policy digest·환경·exit status·test selection을 묶은 receipt를 남기며, 실행하지 않은 검사는 not_run으로 보존한다. 가치: 'RED가 환경 오류가 아닌지', '테스트를 조용히 완화하지 않았는지', '어떤 tree를 검증했는지'가 기계가 읽을 수 있는 증거로 남는다(RUN-01~05, RUN-09).

## 비목표와 범위
비목표: remote/cloud runner 제출(provider 연동은 EP-07), 모델 호출 자체, coverage/mutation 수치 강제(전역 85% 같은 기준 비채택), 테스트 생성 자동화, 기존 Go verify/closure 코드 포팅. 범위: `RunRequest`/`Receipt` 타입, runner(프로세스 spawn·시간·exit·취소 기록), receipt freshness 표시(stale), oracle 변경 감지(테스트/fixture 경로 변경 목록), self-report와 runner-receipt 구분, 이 저장소의 실제 명령(`cargo test --offline --locked` 등)으로 end-to-end 1회.

## SPEC 요구(GEARS)
- REQ-05C-01: WHEN RUN 요청이 들어오면, run 모듈은 반드시 05-B의 pinned contract(spec digest·plan digest·expected revision·scope·approval)를 다시 읽고 불일치 시 실행 없이 `stale|blocked`를 반환한다.
- REQ-05C-02: run 모듈은 반드시 `change_strategy`∈{tdd,bugfix,preserve,contract,eval,docs}와 `domain_modeling`∈{not-required,required}를 독립 필드로 받고, 기존 `ddd|tdd` 단일 선택 입력은 두 필드로 매핑해 호환 기록을 남긴다.
- REQ-05C-03: WHILE change_strategy=tdd 또는 bugfix인 동안, WHEN RED 단계 결과를 기록하면 runner은 반드시 테스트 바이너리 빌드 실패·import 오류·네트워크 오류를 `environment-failure`로 분류하고 `red-confirmed`로 계산하지 않는다.
- REQ-05C-04: WHILE change_strategy=preserve인 동안, runner은 반드시 변경 전 baseline receipt(characterization)가 없으면 개선 단계 진입을 blocked로 표시한다.
- REQ-05C-05: WHEN 검증 명령을 실행하면, runner은 반드시 저장소에 정의된 명령만 argv 배열로 spawn(shell 미사용)하고 시작/종료 시각·exit status·timeout·cancel·stdout/stderr digest를 receipt에 기록한다.
- REQ-05C-06: runner은 반드시 receipt에 task_id·attempt_id·spec_digest·plan_digest·base_revision·tree_digest·policy_digest·toolchain(`rustc -V`/`cargo -V` 출력)·command_ref·test_selection·result∈{passed,failed,not_run,blocked,unknown}·producer.kind를 포함한다.
- REQ-05C-07: WHEN 계약에 선언된 검사 중 실행되지 않은 것이 있으면, runner은 반드시 그 검사를 `not_run`으로 receipt에 남기고 전체 결과를 passed로 요약하지 않는다.
- REQ-05C-08: WHEN 검증 이후 tree_digest·spec_digest·policy_digest 중 하나가 바뀌면, run 모듈은 반드시 영향받는 receipt를 `stale`로 표시하고 재검증 대상 집합을 산출한다.
- REQ-05C-09: WHEN diff가 tests/·fixtures·golden 경로를 변경하면, run 모듈은 반드시 `oracle_changes` 목록으로 분리 기록하고 구현 변경과 함께 묶어 PASS로 요약하지 않는다.
- REQ-05C-10: run 모듈은 반드시 에이전트가 작성한 JSON을 `producer.kind=self-report`로만 받아들이고 runner-receipt로 승격하지 않는다.
- REQ-05C-11: WHERE retry budget이 설정된 경우, WHEN 같은 입력으로 같은 실패가 반복되면 runner은 반드시 budget 소진 시 중단하고 마지막 diff·receipt·남은 AC를 보고한다(기본값은 P11 미결이므로 호출자 입력 필수).
