# [RC1][PLAN RUN VERIFY AUDIT] 05-D 독립 AUDIT와 완료 admission 구현

## 목표와 사용자 가치
구현 context와 분리된 reviewer가 승인 SPEC·exact diff·runner receipt를 직접 읽어 finding을 내고, 결정론적 admission reducer가 must-pass 조건(필수 검사 전부 passed, tree/SPEC/policy digest 일치, self-report 아님, unknown/stale/not_run 없음)을 확인해야만 `Verified`로 전이하는 AUDIT 계약을 구현한다. 가치: 같은 context의 자기 평가·judge 추천·exit 0만으로는 완료가 되지 않고, 독립성을 확보하지 못하면 필수 감사는 blocked가 된다(AUDIT acceptance, RUN-09, V11, D29).

## 비목표와 범위
비목표: 모델 reviewer 자체 구현(호스트 native subagent/세션을 사용), 모든 요청에 다중 모델 호출, 고정 review agent 배포, 서명·원격 attestation(provider 계약대로 후속), 통합/merge 수행(08-A), Issue 댓글 게시(07-C). 범위: `AuditInput`·`Finding`·`Verdict`·`AdmissionDecision` 타입, reducer(순수 함수), 독립성 기록(reviewer identity·context 공유 범위), waiver 레코드(원 결과 보존), GitHub PR head SHA와 verdict 대응 검사(읽기 API).

## SPEC 요구(GEARS)
- REQ-05D-01: WHEN AUDIT 입력(승인 SPEC digest·plan digest·policy digest·exact tree digest·patch·receipt 집합·finding)이 들어오면, audit 모듈은 반드시 schema·identity·attempt·timestamp 필드를 검증하고 누락 시 `unknown`으로 판정한다.
- REQ-05D-02: audit 모듈은 반드시 receipt의 tree_digest·spec_digest·policy_digest·toolchain이 현재 후보와 일치하지 않으면 그 receipt를 `stale`로 제외하고, 남는 필수 검사가 없으면 admission을 거부한다.
- REQ-05D-03: audit 모듈은 반드시 producer.kind=self-report인 증거를 must-pass 충족 근거로 사용하지 않는다.
- REQ-05D-04: WHEN 필수(required=true) 검사 중 하나라도 passed가 아니면(failed·not_run·blocked·stale·unknown), admission은 반드시 `rejected`를 반환하고 품질 점수 평균으로 상쇄하지 않는다.
- REQ-05D-05: WHEN reviewer의 자유 텍스트 판단이 evidence와 충돌하면, audit 모듈은 반드시 evidence·정책 우선으로 `held`를 반환하고 충돌을 finding으로 기록한다.
- REQ-05D-06: audit 모듈은 반드시 reviewer identity(host, subagent/session 식별자), context 공유 범위(fresh|fork|same-session), 읽기 전용 여부를 verdict에 기록하고, 공유 범위가 same-session이면 필수 감사를 `blocked(reason=independence-missing)`로 판정한다.
- REQ-05D-07: WHERE 프로젝트 정책이 waiver를 허용하는 경우, WHEN waiver가 적용되면 audit 모듈은 반드시 원래 판정과 `waived` 판정, 대상 REQ/gate, 사유, 승인 주체, 유효 범위·기간을 함께 보존하고 필수 보안·비밀·권한 gate에는 waiver를 적용하지 않는다.
- REQ-05D-08: WHEN reviewer가 코드를 수정하면, audit 모듈은 반드시 그 결과를 새 candidate(tree digest 변경)로 취급하고 기존 verdict를 무효화한다.
- REQ-05D-09: WHEN PR 후보가 있으면, audit 모듈은 반드시 verdict의 tree/commit이 PR `head.sha`와 대응하는지 확인하고 불일치 시 `stale`로 표시한다(원격 조회 실패는 `unknown`).
- REQ-05D-10: audit 모듈은 반드시 판정을 `passed|failed|not_run|blocked|stale|unknown`(00-D 확정 enum)으로만 표현하고 unknown을 passed로 자동 변환하지 않는다.
