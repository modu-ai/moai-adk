# [RC1][RC 인증과 문서] 08-B 검증된 .github를 Rust 템플릿으로 승격

## 목표와 사용자 가치
개발 저장소에서 검증된 `.github` 자산(3종 Issue form `moai-feature.yml`·`moai-bugfix.yml`·`moai-investigation.yml`, 라벨 manifest `.github/moai/labels.yml`, 필요 시 `config.yml`)을 Rust 생성 템플릿(`templates/github/`)으로 '추가'하고, `moai-cli`가 프로젝트 profile과 기존 파일을 baseline/current/new 3-way로 비교해 preview·선택 적용·재실행 diff 0·중간 실패 복구를 보장하는 renderer를 연결한다. 사용자 가치: GitHub를 선택한 프로젝트가 secret-free·한국어 양식을 동일 의미로 얻고, 기존 사용자 양식·unknown key·다른 provider 파일은 보존된다. 개발 저장소 `.github/`는 그대로 유지한다(이동 아님).

## 비목표와 범위
범위: 템플릿 분리(`templates/github/ISSUE_TEMPLATE/*.yml`, `templates/github/labels.yml`, `templates/github/manifest.json`), renderer 계약(`github-plan`/`github-apply` 가칭; 기존 `agents-plan/apply` 패턴 재사용), fixture 4종(`clean-project`, `existing-user-templates`, `conflicting-labels`, `interrupted-update`), 개발본↔템플릿 parity 시험, 정적 검증(YAML·필수 키·id 유일·secret-shape·label/assignee 키 부재). 비범위: GitHub 원격 라벨 생성·workflow 실행(별도 허용 단계), `label-sync.yml`·agentic-factory 자산 승격(README '미채택'), PR 템플릿 승격(현재 검증된 PR 템플릿 없음; `PULL_REQUEST_TEMPLATE/agentic-factory-11-handoff.md`는 미채택), GitLab `.gitlab/` 양식(별도 provider adapter), 폴더 존재만으로 모든 프로젝트에 GitHub 강제. GitHub 폼 렌더링 검증은 기본 브랜치에서만 가능하므로 이 Issue에서는 not_run으로 남긴다.

## SPEC 요구(GEARS)
- REQ-08B-01 [Ubiquitous] 시스템은 `templates/github/manifest.json`에 각 템플릿 파일의 `source_path`(개발본 경로), `source_sha256`, `template_version`, `license`, `variables[]`, `generation_condition`, `managed_scope`를 기록해야 한다.
- REQ-08B-02 [Ubiquitous] 개발본 `.github/ISSUE_TEMPLATE/moai-*.yml`과 `templates/github/ISSUE_TEMPLATE/moai-*.yml`은 변수 치환 후 의미가 동일해야 하며, 변수가 없는 파일은 바이트가 동일해야 한다(GH-TEMPLATE-PARITY).
- REQ-08B-03 [Ubiquitous] 템플릿 파일은 `labels`·`assignees`·`projects`·`type` top-level 키, 토큰/절대 홈 경로/비공개 Project ID 등 secret-shape 문자열을 포함하지 않아야 한다.
- REQ-08B-04 [WHERE] 프로젝트 profile이 GitHub Issues 사용을 선택한 경우에만 시스템은 `.github/` 생성을 계획해야 하며, 폴더 존재만으로 생성을 강제하지 않아야 한다.
- REQ-08B-05 [WHEN] 대상 경로에 사용자 파일이 이미 있고 baseline이 없을 때 시스템은 `conflict`를 보고하고 아무것도 쓰지 않아야 한다; 사용자 Markdown 템플릿·`config.yml`·unknown key는 보존해야 한다(GH-TEMPLATE-PRESERVE).
- REQ-08B-06 [WHEN] 같은 입력으로 두 번째 실행할 때 시스템은 변경 0(`unchanged`)을 보고해야 한다.
- REQ-08B-07 [IF-THEN] 적용이 파일 쓰기와 manifest 쓰기 사이에서 중단되면 다음 적용에서 이미 렌더링과 동일한 파일을 baseline으로 채택하고 false conflict를 내지 않아야 한다.
- REQ-08B-08 [Ubiquitous] 템플릿에 해소되지 않은 placeholder가 남아 있으면 시스템은 apply를 거부해야 한다.
- REQ-08B-09 [Ubiquitous] 승격은 추가이며 개발 저장소 `.github/`의 어떤 파일도 이동·삭제하지 않아야 한다.
- REQ-08B-10 [WHERE] GitHub 폼 렌더링은 기본 브랜치에서만 확인 가능하므로, 시스템과 문서는 로컬 정적 검증 통과를 '렌더링 확인'으로 보고하지 않아야 한다(not_run 유지).
