# [RC1][설치와 UPDATE] 04-B 모든 설치 host UPDATE 구현

## 사용자 결정 (2026-11-08)
- 기존 Go 사용자의 `moai update`(Go) → moai-cli(Rust) 설치·상태 마이그레이션·Go 제거 흐름이 요구됨(상세·HOLD는 #1998 04-A "사용자 결정" 절). 이 Issue의 UPDATE 설계는 그 마이그레이션 이후 상태(`~/.moai-cli/` 설치본)를 전제로 하며, 마이그레이션은 신규 04-D Issue(EP-05 하위, 선행 04-A·04-B)로 결정됨(2026-11-08). 자가 검증 통과 시 Go 자동 제거, 백업 보관.

## 목표와 사용자 가치
세션 안의 UPDATE 요청이 내부 계약(`update-plan` → `update-apply`, 명칭은 P06 HOLD)으로 연결되어, 설치된 모든 host projection(Claude `~/.claude/skills/moai/`, Codex `~/.agents/skills/moai/`)과 각 host의 관리 설정 key를 함께 사전검사하고, 파일별 baseline/current/new 3-way diff를 미리보기로 보여 준 뒤, host 단위 transaction으로 적용하고 host별 결과(`applied|unchanged|conflict|failed|not_run`, `reload_required`)를 typed JSON으로 반환한다. 사용자 가치: 한 번의 요청으로 두 host가 같은 package version/digest로 맞춰지고 사용자 수정은 보존되며, 한 host의 성공이 전체 성공으로 포장되지 않는다(D66·D72·HA-02·UPDATE-PARTIAL).

비목표: moai-cli 실행 파일 자체의 self-update(설치 방식 결정(2026-11-08: 채널 A·서명 A·tag 접두사 B·경로 A·Windows 교체 A, 출처 docs/decisions-2026-11-08.md) 반영 후 별도 결정), 프로젝트 맞춤 파일 재생성(agents-apply 재사용만), 새 권한·hook·MCP 등록(별도 범위), host 실제 로딩 실측(02-B/02-C·08-C), Go 설치본 전환(D79). 범위: (1) 전체 host inventory·preflight (2) 파일별 3-way plan과 preview (3) host별 staged apply(temp→fsync→rename→receipt) (4) host별 결과·reload 상태 보고 (5) 재실행 diff 0. 부분 실패의 복구 로직은 04-C.

## SPEC 요구(GEARS)
- REQ-04B-01: WHEN `update-plan`이 호출되면, moai-cli는 설치 receipt(04-A)와 각 host projection 경로(`~/.claude/skills/moai/`, `~/.agents/skills/moai/`)를 모두 읽고, 파일마다 baseline(마지막 apply receipt의 sha256)·current(현재 sha256)·new(stage된 package의 sha256)를 비교해 `create|update|unchanged|conflict|remove_blocked` 중 하나를 결정하며, 어떤 파일도 쓰지 않아야 한다.
- REQ-04B-02: WHILE preflight 중 한 host라도 `conflict`(baseline≠current이고 current≠new)이거나 projection 경로가 symlink·다른 파일시스템·권한 없음이면, moai-cli는 해당 host를 `blocked`로 표시하고 다른 host의 plan은 계속 산출해야 한다(전체 중단 아님, host 선택은 사용자 승인 뒤).
- REQ-04B-03: moai-cli는 plan에 `plan_digest`, `source_version`, `target_version`, `package_digest`(`moai-package-tree-v1`), `protocol_range`, `expected_file_hashes`(host·파일별), `scope`, `rollback_manifest`(파일별 before_sha256)를 포함해야 하며, `update-apply`는 동일 plan_digest·현재 hash 재검증·permission_reference 없이는 어떤 쓰기도 해서는 안 된다.
- REQ-04B-04: WHEN `update-apply`가 한 host를 처리할 때, moai-cli는 (a) host receipt를 `pending`(파일별 before/after sha256 포함)으로 기록하고 fsync, (b) 각 파일을 같은 디렉터리의 고유 임시 파일에 쓰고 fsync한 뒤 rename으로 교체(신규 파일은 exclusive create), (c) 디렉터리 fsync, (d) 모든 파일 재검증 후 receipt를 `committed`로 교체하는 순서를 지켜야 한다. 다른 host의 파일은 그 host 차례 전까지 건드려서는 안 된다.
- REQ-04B-05: IF host의 적용이 (b)~(d) 도중 실패하면, moai-cli는 그 host를 `failed`로 보고하고 receipt를 `pending`인 채 남기며, 이미 `committed`된 host를 되돌려서는 안 된다(복구는 04-C 계약).
- REQ-04B-06: moai-cli는 host별 결과에 `status ∈ {applied, unchanged, conflict, blocked, failed, not_run}`, `files`(파일별 action·before/after sha256), `reload_required ∈ {no, yes, unknown}`과 그 근거(Claude: 라이브 리로드 문서, 최상위 디렉터리 신규 생성 시 `/reload-skills`; Codex: 자동 감지, 미표시 시 재시작)를 포함해야 하며, `host_loaded`·`execution_verified`는 실측 전까지 `false`/`not_run`이어야 한다.
- REQ-04B-07: WHEN 같은 package digest·같은 plan으로 UPDATE를 재실행하면, moai-cli는 모든 host를 `unchanged`로 보고하고 projection 트리 바이트가 동일해야 한다.
- REQ-04B-08: moai-cli는 host projection을 symlink로 공유하거나 `~/.moai-cli/skills/moai/<version>/` 원본을 가리키는 링크로 설치해서는 안 되며, 각 host에 독립 복사본을 두어야 한다(D65).
- REQ-04B-09: WHERE 새 package가 기존 사용자 파일(동명 skill, 사용자 추가 파일, unknown key)을 포함하지 않는 경우에도, moai-cli는 그 파일을 삭제하거나 덮어써서는 안 되며 `remove_blocked`/`preserved`로 보고해야 한다.
