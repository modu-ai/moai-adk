# [RC1][Forge 보고와 판단 context] 07-A GitHub TODO와 polling adapter 구현

## 목표와 사용자 가치
GitHub 연결 프로젝트에서 Issue를 공식 TODO 원장으로 읽어 오는 Rust 경로를 만든다. `moai-cli forge-read PROJECT`(stdin typed JSON 요청 → stdout typed JSON)가 활성 Issue·댓글을 조건부 GET·`since` cursor·Link pagination으로 읽고, 결과마다 안정 식별자 `(provider, host, project{owner, repo, repository_id}, issue{id, node_id, number}, updated_at, etag)`를 돌려준다. rate-limit 헤더와 마지막 성공 조회 시각을 `<project>/.moai-cli/forge/poll-state.json`에 저장하고, 사람이 편집한 label·assignee·본문을 오래된 값으로 덮지 않는 쓰기 규칙(전용 add/remove API, read-before-write, 충돌 시 정지)을 라이브러리 함수로 고정한다. 사용자 가치: 서버 없이 Issue 변화를 안전하게 따라가고, 07-B·07-C·08-A가 같은 식별자와 상태 규칙 위에서 동작한다.

## 비목표와 범위
범위: GitHub REST 읽기, poll state, rate-limit 정책, 쓰기 안전 규칙(함수·테스트만, 실제 쓰기 명령은 07-C/07-B에서 노출), GitLab 이식을 위한 external reference schema(iid 포함). 비범위: webhook, GitLab adapter 구현, GraphQL, Projects v2, 상시 daemon, 자동 claim(06-A 영역), 사용자 토큰 생성·scope 확대. 이 Issue의 기본 실행은 쓰기를 하지 않는다(poll-state 파일 제외).

## SPEC 요구(GEARS)
- REQ-FORGE-001 (Ubiquitous) `moai-cli`는 Issue 참조를 항상 `(provider, host, project{owner, repo, repository_id}, issue{id, node_id, number})`로 기록해야 하며 `number`만으로 키를 만들어서는 안 된다.
- REQ-FORGE-002 WHEN `forge-read`가 같은 URL을 다시 조회할 때, 저장된 `etag`를 `If-None-Match`로 보내고 304이면 로컬 캐시 결과를 반환하며 primary limit 소모 없음을 결과의 `cache_hit: true`로 표시해야 한다.
- REQ-FORGE-003 WHEN 응답에 `retry-after`가 있으면 그 초 동안, 없고 `x-ratelimit-remaining`이 0이면 `x-ratelimit-reset`까지, 그 외 secondary limit(403/429)이면 최소 60초 후 지수 backoff로 재시도하되 설정된 최대 재시도 뒤에는 `blocked`로 종료해야 한다.
- REQ-FORGE-004 WHILE 한 `forge-read` 실행 중에는 GitHub 요청을 직렬로만 보내야 하며 동시 요청을 만들어서는 안 된다.
- REQ-FORGE-005 WHEN 응답에 `Link` 헤더가 있으면 `rel="next"` URL을 그대로 따라가야 하며 page 번호를 스스로 조립해서는 안 된다.
- REQ-FORGE-006 WHEN Issue 목록을 읽을 때 `pull_request` 키가 있는 항목은 Issue TODO에서 제외하거나 `kind: pull_request`로 분리 표시해야 한다.
- REQ-FORGE-007 WHERE 쓰기 helper(라벨·assignee 변경)가 호출되면 PATCH로 집합 전체를 보내지 않고 POST(add)·DELETE(remove) 전용 API만 사용해야 한다.
- REQ-FORGE-008 WHEN 쓰기 직전 재조회한 `updated_at` 또는 본문 digest가 마지막 읽기와 다르면 쓰기를 멈추고 `conflict`를 반환해야 한다(사람 편집 보존).
- REQ-FORGE-009 Ubiquitous poll state 파일은 `<project>/.moai-cli/forge/poll-state.json`에 임시 파일 + rename으로만 갱신해야 하며 Go `.moai/`에는 어떤 파일도 만들지 않아야 한다.
- REQ-FORGE-010 IF 토큰이 없거나 401/403이면 `blocked`와 사유만 반환하고 토큰 값을 stdout·stderr·파일 어디에도 기록해서는 안 된다.
- REQ-FORGE-011 Ubiquitous 결과 JSON은 `schema_version`, `observed_at`, `rate_limit{limit,remaining,reset,resource}`, `last_success_at`, `items[]`를 포함해야 하며 `since`는 GitHub에서 'after', GitLab에서 'on or after' 의미임을 adapter가 보정해 중복·누락이 없도록 겹침 창(overlap)을 두어야 한다.

## 관련 논문
해당 논문 없음 — HTTP 조건부 요청·rate limit·pagination은 IETF RFC 9110과 GitHub/GitLab 공식 문서가 1차 근거인 엔지니어링 표준 영역이다. 분산 idempotency 일반론으로 Pat Helland, 'Idempotence Is Not a Medical Condition'(ACM Queue, 2012)이 알려져 있으나 이번 세션에서 queue.acm.org·dl.acm.org 접근이 403으로 거부되어 내용을 검증하지 못했다(미확인). 검증되지 않은 논문은 인용하지 않는다.
