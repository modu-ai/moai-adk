# [RC1][설치와 UPDATE] 04-D Go 사용자 마이그레이션(bridge): `moai update`(Go) → moai-cli 설치·상태 이전·Go 제거

## 사용자 결정 (2026-11-08, 출처 docs/decisions-2026-11-08.md)
- 요구: 기존 Go MoAI 사용자가 `moai update`(Go)를 실행하면 moai-cli(Rust)를 설치하고 상태를 이전하며 기존 Go `moai`를 제거해 마이그레이션되어야 한다.
- 브리지 위치 **B**: 마지막 Go 릴리스(`v3.x`, Go 채널)는 moai-cli installer를 받아 실행하고 `moai-cli migrate --from-go`를 호출만 한다. 마이그레이션·백업·검증·Go 제거 로직은 Rust(이 Issue)에 둔다.
- Go 제거 시점 **B**: 자가 검증(설치 버전·`~/.moai-cli/bin/moai-cli` 실행·discovery·상태 복사 digest 검증) 통과 시 자동 제거. 백업은 `~/.moai-cli/backups/go-<date>/`에 보관하고 롤백 가능해야 한다.
- **제거 범위 재확인 필요(P13 충돌, agent-2 r3 지적)**: P13은 "기존 Go 소스 저장소·사용자 프로젝트·SPEC·설정·작업 데이터까지 삭제한다는 뜻이 아니다"라고 확정했다. 실제 `~/.moai`에는 자격 증명 파일·`.env.*`·`worktrees/`(활성 git worktree 등록)·`db/`·`claude-profiles/`·`backups/`가 있다. 따라서 "홈 통째 복사 → 자동 삭제"는 자격 증명 복제·worktree 등록 단절·P13 보호 데이터 삭제를 일으킨다. 사용자 결정(2026-11-08 16:4x, docs/decisions-2026-11-08.md): **A — 자동 제거 allowlist는 Go `moai` binary와 Go 전용 캐시·feed/update 상태만**. `~/.moai`의 데이터(자격 증명·worktrees·db·profiles·backups)는 보존하고 필요한 항목만 Rust가 읽어 `~/.moai-cli`로 변환하며, 자격 증명은 복사하지 않는다. P13과 정합.
- 전제 결정(04-A): 채널 GitHub Releases + `dist` installer, 서명 attestation만, tag `moai-cli-v<version>`, 경로 `~/.moai-cli/bin/moai-cli`, Windows 교체 self-replace.
- 이 Issue는 신규 발행(사용자 승인 2026-11-08). 지금 구현·실행하지 않는다.

## 목표와 사용자 가치
Go 사용자가 명령 하나로 Rust 세대로 넘어오되, 이전 작업 데이터(`~/.moai/`, 프로젝트 `.moai/`)를 잃지 않고 실패하면 Go 상태로 되돌릴 수 있다.

## 비목표와 범위
- Go 저장소(`moai-adk-go`)의 최종 릴리스 변경은 최소(installer 실행 + `moai-cli migrate --from-go` 호출)로 한정하며 이 Issue의 Rust 범위와 분리한다. Go 저장소는 현재 읽기 전용 정책이므로 그 변경은 별도 승인·Issue 대상(HOLD).
- D79(`moai` 이름 전환)는 자가 검증 뒤 이 흐름의 마지막 단계로 수행하되, 실패 시 전환하지 않는다.
- 프로젝트 `.moai/` → `.moai-cli/` 변환은 프로젝트별 첫 실행 시 preview 뒤 수행(SETUP/UPDATE 경로), 홈 마이그레이션과 분리.

## SPEC 요구(GEARS)
- REQ-04D-01 WHEN `moai-cli migrate --from-go`가 실행되면, 시스템은 반드시 Go 설치 identity(binary 경로·버전·`~/.moai` 존재)를 읽기 전용으로 탐지해 preview JSON을 먼저 출력해야 한다.
- REQ-04D-02 WHILE preview가 승인되지 않았으면, 시스템은 어떤 파일도 쓰지 않아야 한다.
- REQ-04D-03 WHEN 복사 단계가 시작되면, 시스템은 반드시 변환에 필요한 `~/.moai` 항목만(자격 증명 파일·`.env.*` 제외, 결정 A) `~/.moai-cli/backups/go-<date>/`로 복사(이동 아님)하고 파일별 sha256 manifest를 기록해야 한다. 원본 `~/.moai`는 그대로 둔다.
- REQ-04D-04 WHEN 자가 검증(moai-cli 버전 출력·skill 발견 경로 존재·복사 digest 일치)이 모두 통과하면, 시스템은 결정 A의 allowlist만 제거 — Go `moai` binary(PATH 해석 결과), `~/.moai/cache/` 아래 release feed·update 검사 캐시(실제 경로는 구현 시 Go `internal/update` 코드 읽기로 확정하고 receipt에 목록 기록)하고 제거 receipt를 남겨야 하며, `~/.moai`의 데이터는 건드리지 않아야 한다(사용자 결정 B+A, P13).
- REQ-04D-05 IF 자가 검증 중 하나라도 실패하면, 시스템은 Go 상태를 그대로 두고 `blocked` receipt와 롤백 안내를 출력해야 한다.
- REQ-04D-06 WHERE 프로젝트 `.moai/`가 있으면, 시스템은 홈 마이그레이션에서 이를 건드리지 않고 프로젝트별 preview 경로로 넘겨야 한다.
