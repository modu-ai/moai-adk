# [RC1][Forge 보고와 판단 context] 07-D native 판단과 context 기본 연결

## 목표와 사용자 가치
추가 API 키·크레딧 없이, 지금 실행 중인 코딩 에이전트(Claude Code 또는 Codex)의 native 판단만으로 workflow가 완주되도록 공통 skill의 판단 계약과 Rust 측 context 계측을 연결한다. (1) 판단 기록: skill workflow가 내린 intent·다음 행동 판단을 `decision_record{decision_source: native, input_digest, options, chosen, confidence: unknown|stated, authority: none}`로 남겨 '판단 ≠ 권한'을 구조로 고정한다. (2) context 계측: `moai-cli snapshot-describe PROJECT`(base commit + dirty overlay digest + 파일 digest 목록, 읽기 전용)와 `moai-cli context-bundle PROJECT`(지정 경로/범위를 content digest·freshness·포함 이유·omitted 목록과 함께 묶고, 소비 시 digest 재검사로 stale 표시)를 제공한다. (3) token 측정: 번들 크기를 바이트·줄 수와 함께 'estimate'로 표기하고, host가 보고하는 실측(Claude statusline `context_window`, Codex `model_context_window`/`/status`)을 측정 출처로 기록하되 둘을 섞지 않는다. 사용자 가치: 네트워크 없이도 PLAN→RUN이 진행되고, 오래된 context로 잘못 인용하는 일을 막으며, 비용·토큰 주장을 실측과 추정으로 구분한다.

## 비목표와 범위
범위: native 판단 기록 schema와 skill workflow 문구(02-A router 위), snapshot/bundle/freshness 최소 구현, token estimate 표기, 양 host의 context 사용량 읽기 방법 문서화. 비범위: Decisions/Jev 등 선택 backend 호출(P10 HOLD, adapter 경계만), embeddings·vector DB·graph DB, AST/LSP 통합(F12 심화·F13 graph/MX는 후속 Issue), 자동 compaction 제어, 성능 목표 수치 약속(P11).

## SPEC 요구(GEARS)
- REQ-NATIVE-001 Ubiquitous 공통 skill의 PLAN·RUN workflow는 판단이 필요한 지점마다 `decision_record{schema_version, decision_source: native|<backend>, host, input_digest, options[], chosen, rationale_ref, confidence: unknown|stated, authority: none, recorded_at}`를 `<project>/.moai-cli/decisions/<run>.jsonl`에 append해야 하며 `authority`는 항상 `none`이어야 한다.
- REQ-NATIVE-002 WHILE 선택 판단 backend가 설정되지 않았거나 승인되지 않은 동안 Rust 측 어떤 명령도 네트워크 소켓을 열어서는 안 되며 결과에 `network: disabled`를 표시해야 한다.
- REQ-NATIVE-003 WHEN 판단 결과가 권한·비용·외부 전송·파괴적 효과를 넘는 행동을 가리키면 skill은 그 행동을 수행하지 않고 사용자 결정을 요청해야 한다(판단 ≠ 권한).
- REQ-CTX-001 Ubiquitous `snapshot-describe`는 `base_commit`(git rev-parse HEAD), `dirty_overlay_digest`(추적 변경 파일의 path+bytes digest), `worktree_path`, `described_at`를 반환하고 어떤 파일도 쓰지 않아야 한다.
- REQ-CTX-002 Ubiquitous `context-bundle`의 각 item은 `path`, `range{start_line,end_line}`, `content_sha256`, `bytes`, `lines`, `reason`, `freshness: fresh|stale|unknown`을 가져야 하며 range만 있고 digest가 없는 item을 만들어서는 안 된다.
- REQ-CTX-003 WHEN 번들을 소비(재읽기)할 때 item의 현재 content digest가 기록과 다르면 `freshness: stale`로 표시하고 해당 범위를 다시 읽도록 요구해야 한다.
- REQ-CTX-004 WHEN 요청 경로가 secret 패턴(`.env`, `*.pem`, `id_rsa` 등 설정 목록)·ignored·저장소 밖(symlink escape)이면 `blocked_sensitive`로 제외하고 내용을 출력하지 않아야 한다.
- REQ-CTX-005 WHEN 설정된 `budget{max_bytes|max_items}`를 넘으면 `reason` 우선순위가 낮은 item부터 제외하고 `omitted[]`에 path·range·이유를 기록해야 하며 budget을 자동 확대해서는 안 된다.
- REQ-CTX-006 Ubiquitous token 수치는 `tokens_estimate{value, method: bytes_div_4|tiktoken_o200k|host_reported, model_scope}`로만 표기하고 `method`가 `host_reported`가 아닌 값을 실측으로 서술해서는 안 된다.
- REQ-CTX-007 WHERE host가 Claude Code이면 skill은 statusline `context_window.used_percentage`/`total_input_tokens`를, Codex이면 `model_context_window`와 `/status`를 '실측 출처'로 decision_record의 `context_usage_source`에 기록해야 하며 두 host 값을 비교·합산하지 않아야 한다.
- REQ-CTX-008 WHEN 두 worktree가 같은 경로에 다른 내용을 가질 때 각 번들은 자기 `worktree_path`·`dirty_overlay_digest`에만 묶여야 하며 공용 캐시가 다른 worktree 내용을 섞어서는 안 된다.
- REQ-CTX-009 Ubiquitous 코드 주석·README·Issue 본문에 들어 있는 명령 문자열은 번들 데이터로 전달될 뿐 실행 지시로 해석되어서는 안 된다(skill 문구에 명시).
