# [RC1][최초 설정과 맞춤 생성] 03-A 최초 딥 인터뷰 profile 구현

## 목표와 사용자 가치
최초 딥 인터뷰의 결과(목적·도구·개발 방식·host·결정 ID)를 `.moai-cli/project.yaml`이라는 작은 portable 설정에 보관하고, 재설정 때는 바뀐 key만 반영하며 사용자가 손댄 값과 unknown key는 보존한다. 지금 코드는 Profile v1을 '없으면 생성, 있으면 같을 때만 unchanged, 다르면 거부'로만 다루므로(`src/lib.rs` `plan()`), 이 Issue는 (1) 인터뷰 결정 기록을 profile에 연결하는 schema 확장, (2) key 단위 3-way 재설정 delta(`update` action), (3) 사용자 수정·주석·unknown key 보존 전략을 실제 Rust 경로와 fixture로 만든다. 가치: 이후 03-B/03-C·04-B가 참조할 profile revision/digest가 생긴다.

## 비목표와 범위
인터뷰 질문의 대화 UX(router·skill 본문)는 02-A 소유이며 여기서는 typed 입력 schema만 정의한다. 인터뷰 원문 transcript·대형 조사 자료·secret·개인 절대 경로는 profile에 넣지 않는다. YAML 전체 문법의 lossless 편집기 구현은 HOLD(아래)이며, 결정 전까지는 JSON-subset + 거부 전략을 유지한다. AGENTS.md 등 생성물 변경은 03-C, 외부 skill은 03-B. Go `.moai/`·`~/.moai/` 불변.

## SPEC 요구(GEARS)
- REQ-03A-01 (Ubiquitous) moai-cli는 profile schema v2에서 v1의 7개 key를 그대로 유지하고, `interview_revision`(문자열)과 `decisions`(각 항목 `id`·`topic`·`value`·`source`∈{repo,user,default}·`scope`) 목록을 추가하되 항목 수·문자열 길이에 상한을 두고 portable 필터(경로·credential 형태·제어문자 거부)를 동일하게 적용해야 한다.
- REQ-03A-02 (WHEN) `project-plan`에 typed profile이 들어오고 `.moai-cli/project.yaml`이 이미 있을 때, moai-cli는 key 단위로 `added/changed/removed/unchanged`를 계산해 plan에 `delta`로 반환하고 action을 `create|update|unchanged|conflict` 중 하나로 보고해야 한다.
- REQ-03A-03 (WHEN) 기존 profile의 어떤 key가 manifest에 기록된 baseline(`profile_sha256`에 대응하는 마지막 적용 값)과 다르고 새 입력도 그 key를 바꾸려 할 때, moai-cli는 그 key를 `conflict`로 표시하고 어떤 파일도 쓰지 않아야 한다(사용자 수정 우선).
- REQ-03A-04 (WHILE) 기존 파일이 JSON-subset이 아닌 일반 YAML(주석·앵커·블록 스타일)인 동안, moai-cli는 lossless 편집 전략(HOLD)이 결정되기 전까지 `existing YAML requires preservation review`로 변경을 거부하고 읽기만 허용해야 한다.
- REQ-03A-05 (WHEN) `project-apply`가 `update` plan을 받으면, moai-cli는 대상 파일의 현재 sha256이 plan의 `expected_sha256`과 같을 때만 임시 파일 쓰기→rename으로 교체하고, 다르면 `stale or altered plan; re-preview required`로 거부해야 한다.
- REQ-03A-06 (Ubiquitous) moai-cli는 profile 파일에 인터뷰 원문·절대 경로·credential 형태 문자열을 기록하지 않아야 하며, 거부 진단 메시지에 입력 값을 echo하지 않아야 한다.
- REQ-03A-07 (WHEN) 적용이 끝나면 moai-cli는 결과 JSON에 `state`, `profile_digest`, `interview_revision`, `host_verified:false`를 포함해야 하고, `generation.json`의 `profile_sha256`·`interview_revision` 갱신은 03-C의 generation apply가 담당한다는 점을 결과 `next_actions`에 명시해야 한다.
- REQ-03A-08 (IF) 입력 schema_version이 2가 아니거나 unknown key가 있으면(IF-THEN), moai-cli는 `invalid or nonportable profile`로 거부해야 하되, 기존 파일의 unknown key는 보존 대상으로 취급해야 한다.

- YAML lossless 편집은 성숙한 Rust crate가 확인되지 않아, HOLD 해소 전까지 '거부 보존'이 유일한 안전 동작이다(사용자가 주석 달린 project.yaml을 쓰면 재설정이 막힘).

- Windows/Linux에서의 rename 원자성·권한 보존은 Mac fixture로 검증되지 않는다(not_run).
- 호출자(host skill)가 인터뷰 답변을 사전 검토하지 않으면 보수적 secret 필터만으로는 유출을 막지 못한다.
