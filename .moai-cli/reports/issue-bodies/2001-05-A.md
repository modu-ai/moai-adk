## SPEC 요구(GEARS)
- REQ-05A-01: WHEN 호출자가 GEARS 본문을 제출하면, spec 모듈은 반드시 WHERE(정적 조건)·WHILE(상태)·WHEN(사건)·주체·의무 행동을 분리한 typed REQ 레코드를 반환하고, 분리할 수 없는 문장은 syntax=failed와 위치 정보를 반환한다.
- REQ-05A-02: WHILE legacy EARS 문서를 import하는 동안, spec 모듈은 반드시 원문·REQ ID·source range·안전/오류 분류를 보존하고 `If…then` 절을 WHEN으로 자동 치환하지 않으며 import 결과를 `syntax: EARS-import`로 신규 저작과 구분한다.
- REQ-05A-03: WHEN acceptance_refs 또는 source_refs가 존재하지 않는 ID를 가리키면, 구조 검사은 반드시 structure=failed와 dangling 참조 목록을 반환한다.
- REQ-05A-04: spec 모듈은 반드시 validation 결과를 syntax·structure·semantic·execution 네 필드로 분리 기록하고, syntax=passed가 semantic 또는 execution 값을 변경하지 않는다(초기값 semantic=unknown, execution=not_run).
- REQ-05A-05: WHEN 승인 snapshot을 생성하면, spec 모듈은 반드시 정규화된 canonical 내용(REQ·AC·scope·정책 revision·검증 명령)의 SHA-256 digest를 `sha256:<64 hex>` 형식으로 산출하고, 동일 내용의 키 순서·공백 차이에 대해 동일 digest를 반환한다.
- REQ-05A-06: WHERE 승인 snapshot이 존재하는 상태에서, WHEN 같은 spec_id의 본문이 변경되면 spec 모듈은 반드시 새 proposed revision을 만들고 기존 snapshot digest를 변경하지 않는다.
- REQ-05A-07: spec 모듈은 반드시 모든 REQ에 안정 ID·원문·문법 version·주체·관찰 가능한 결과·조건 종류·acceptance 참조·미해결 항목 필드를 두고, 근거 없는 정량 한도를 기본값으로 채우지 않는다.
- REQ-05A-08: WHEN 입력 크기가 64 KiB 제한을 넘거나 제어 문자·비밀 형태 문자열(기존 `portable()` 규칙)을 포함하면, spec 모듈은 반드시 값을 로그에 남기지 않고 거부한다.

## 구현 계획
1. 1. 00-D(#1987)의 상태 enum·오류 코드·JSON Schema fixture를 읽고 05-A 타입에 그대로 사용(없으면 blocked 보고, 임의 확정 금지).
2. 2. `src/spec.rs` 신설(또는 P05 결정에 따라 `src/spec/` 디렉터리): `Requirement`, `Acceptance`, `SpecDocument`, `Validation{syntax,structure,semantic,execution}`, `Snapshot{reference,digest}` 타입을 `#[serde(deny_unknown_fields)]`로 정의.
3. 3. GEARS 절 파서: 대소문자 무시 키워드 `Where`/`While`/`When` + `shall` 경계 분리; 모호 문장은 실패 + offset 반환. EARS importer: 패턴 6종 식별만 하고 의미 변환 없이 `imported_from: EARS` 기록.
4. 4. 구조 검사: ID 유일성, REQ↔AC 양방향 참조, dangling 검출. 의미 검사는 외부 finding 입력을 받아 `semantic: reviewed|unknown` 기록만 수행.
5. 5. canonical 직렬화와 digest: 결정론적 키 정렬 직렬화 후 `digest()` 재사용. 방식(RFC 8785 JCS 채택 vs 자체 정렬 직렬화)은 HOLD → 구현은 trait 뒤에 두고 fixture로 어느 쪽이든 교체 가능하게.
6. 6. `main.rs`에 임시 subcommand(`spec-plan PROJECT`, stdin JSON) 추가. 이름은 P06 확정 전까지 '임시'로 docs에 명시.
7. 7. `tests/spec_contract.rs` + `tests/fixtures/spec/{gears_*.json, ears_corpus.md, golden/*.json}` 작성(TDD: 실패 확인 → 구현 → 회귀).
8. 8. `docs/rust-product-path.md`에 계약·알려진 gap 추가, `skills/moai/workflows/plan.md`는 계약 필드명이 달라질 때만 최소 수정.
