## SPEC 요구(GEARS)
- REQ-05B-01: WHEN 승인 snapshot과 task 목록이 입력되면, plan 모듈은 반드시 dependency 그래프의 위상 순서를 산출하고, cycle이 있으면 admission을 거부하며 cycle에 속한 task ID 집합을 반환한다(self-loop 포함).
- REQ-05B-02: WHEN task가 존재하지 않는 dependency ID를 참조하면, plan 모듈은 반드시 structure=failed와 해당 ID를 반환하고 Ready로 전이하지 않는다.
- REQ-05B-03: WHEN 어떤 AC에 실행 가능한 verifier(검증 명령·property·manual review 중 하나)가 연결되어 있지 않으면, plan 모듈은 반드시 그 task를 `blocked(reason=verifier-missing)`로 표시하고 '검증 수단 확보'를 선행 task로 제안한다.
- REQ-05B-04: WHERE 두 task의 write_paths가 겹치면, plan 모듈은 반드시 둘 사이에 명시 dependency가 없는 한 충돌 경고와 함께 병렬 실행 불가로 표시한다.
- REQ-05B-05: WHEN RUN admission이 요청되면, plan 모듈은 반드시 snapshot digest·expected revision(commit 또는 tree ID)·approval 참조·approval 취소 여부·capability를 다시 읽고, 하나라도 불일치하면 `stale` 또는 `blocked`를 반환하며 Running으로 전이하지 않는다.
- REQ-05B-06: WHILE 승인 snapshot이 고정된 동안, WHEN 같은 Issue 본문이 변경되어 새 proposed revision이 생기면 plan 모듈은 반드시 이전 approval을 새 revision에 재사용하지 않는다.
- REQ-05B-07: plan 모듈은 반드시 동일 입력에 대해 동일 plan digest와 동일 위상 순서를 재현한다(동률 노드는 ID 사전순 등 결정론적 tie-break).
- REQ-05B-08: plan 모듈은 반드시 execution=not_run을 정상 상태로 보고하며, 어떤 경로에서도 not_run·unknown·blocked를 passed로 변환하지 않는다.
