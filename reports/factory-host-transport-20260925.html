MoAI Factory 세션 통신 구현 및 검증

Claude Code끼리는 네이티브 세션 메시지, Codex가 포함된 lead ↔ agent 조합은 MoAI Factory 브로커를 사용한다. Codex 수신은 MoAI가 소유한 App Server 스레드에 입력한다. 공개 역할 이름은 lead와 agent-1..n이다.

결론: macOS에서 Codex lead ↔ Codex agent의 테스트 카드 배차·상태 보고·양쪽 수신 확인을 실측했다. Codex Factory의 브로커 송신·수신 확인 도구를 좁게 승인하도록 설정한 뒤, lead와 agent 양쪽의 무인 수신 확인을 실측했다. GLM으로 구동한 Claude Code와 Codex의 양방향 카드 배차·상태 보고도 실측했다. Windows 실세션과 Anthropic 계정 Claude Code의 혼합 경로는 아직 미실측이다.

구현

  • -f agent가 다음 빈 agent-n을 차지하고 -f agent-n이 번호를 지정한다. 공개 -f worker 입력은 거부한다. 기존 저장 행의 worker-n과 lane-n은 번호 충돌 방지를 위해 읽는다.
  • Factory Codex 런처가 로컬 인증 WebSocket App Server와 TUI를 함께 소유한다. 런처가 브로커 엔드포인트를 스레드 ID와 프로세스 소유권으로 등록한다.
  • 브로커 수신 폴러가 메타데이터를 실제 Codex 스레드에 넣는다. 본문은 모델이 factory_msg_body로 별도 조회하고 factory_msg_receipt로 확인한다.
  • Codex 초기 모델 턴을 thread/inject_items로 대체해 준비 과정의 모델 호출을 없앴다.
  • 새로 생성하는 Codex 프로젝트 설정은 factory_msg_send와 factory_msg_receipt만 approval_mode="approve"로 지정한다. 나머지 MCP 도구는 기존 writes 승인 정책을 따른다. 기존 사용자 소유 설정은 자동으로 덮어쓰지 않는다.
  • Claude 전용 두 엔드포인트의 factory_msg_send를 거부해 네이티브 통신 정책을 지킨다. --spawn Factory Codex는 새 창 안의 MoAI 런처가 세션을 소유하도록 바꿨다.

실제 카드 배차와 상태 보고

기준: 격리 프로젝트의 Factory run tlw7dy. moai todo add '[FACTORY-LIVE] agent-1 배차 수신·상태 보고 확인. 파일 수정·커밋·푸시 없음.' --pick으로 테스트 카드 t1을 발행했다. Codex lead TUI에 agent-1 배차를 지시했고, agent TUI에는 수신 확인과 lead에게 status_report 회신만 지시했다.

  1. lead가 factory_msg_send(kind=dispatch_notice, task_ref=t1)를 호출했고 반환값은 factory_msg_send: ok였다.
  2. agent-1의 새 턴이 자동 시작됐다. agent가 factory_msg_body로 지시를 읽고 factory_msg_receipt: ok를 받은 뒤 factory_msg_send(kind=status_report, task_ref=t1, to_slot=lead)를 호출했다.
  3. lead의 새 턴이 자동 시작됐다. lead가 보고 본문을 읽고 factory_msg_receipt: ok를 받았다. 양쪽 TUI에서 MoAI MCP 승인창은 관측되지 않았다.

판정 범위: 카드 발행, 배차, 자동 수신, 수신 확인, 상태 보고의 왕복은 통과했다. 카드가 picked로 남은 것은 이 시험이 작업 수행·완료 판정·병합을 요청하지 않았기 때문이다. 실제 코드 작업, 증거 평가, PR·병합 요청까지 통과했다는 주장은 하지 않는다.

Windows 빌드는 실행 검증이 아니다. 큰 범위의 hook Factory 테스트는 기존 handoff 경합 테스트가 제한 시간에 걸렸고, 그 실행에서 일부 구식 worker 표기 기대값도 실패했다. 이 실행을 전체 통과로 취급하지 않는다.

[claude-code:unrecognized_model] 경고는 GLM 세션을 종료시키지 않았다. 이후 --model glm-5.3으로 살아 있는 관리 세션을 확인하고 양방향 혼합 실측을 완료했다. 경고가 모델 메타데이터 표시에 미치는 영향은 별도 점검 대상이다.

남은 위험과 완료 기준

우선순위남은 일통과 기준
높음기존 프로젝트의 MoAI MCP 설정사용자 소유 설정은 보존하며, Factory 자동 처리에 필요한 두 도구의 승인 모드를 안내·진단한다. 설정이 없으면 승인 대기 상태를 lead에 표시.
중간Anthropic 계정 Claude Code ↔ Codex 추가 검증계정 한도가 풀린 뒤 같은 배차·보고 흐름을 Anthropic 백엔드에서도 재실측.
높음카드 처리와 병합 요청테스트 카드 발행, agent 처리, 증거 기록, lead의 완료 판정 및 병합 요청을 실측. 수신 확인만으로 카드 완료 판정 금지.
중간Windows 네이티브와 WSL 2 실행각 호스트에서 Claude 네이티브 통신과 Codex 포함 브로커 경로를 별도로 실측.
중간사용자 안내·템플릿 전수 동기화기존 worker/구식 플랫폼 설명을 실제 배포 템플릿과 안내에서 제거하고 관련 테스트 통과.

공식 계약

Codex App Server 문서: thread/start, thread/inject_items, turn/start, turn/completed, WebSocket 인증과 실험적 전송 상태. Claude Code 세션 메시지 문서: macOS/Linux/WSL 2 소켓, Windows named pipe, claude -p 수신, 권한 대화상자와 버전 조건.

이 보고서의 “실측”은 위 기준 환경에서 관측한 결과만 뜻한다. 공식 문서의 지원 범위와 Windows 런타임 실측은 구분했다.
