Executive verdict

짧게 답하면: 가능, 가능, 그러나 rules 전면 삭제는 반대

Cross-session
Codex도 기존 세션에 메시지와 지시를 넣을 수 있다.

이 머신의 codex agents는 공유 App Server의 세션을 찾고, codex queue --thread … --message …는 기존 세션에 입력을 큐잉한다. 다만 Claude의 에이전트 주도 ListAgents/SendMessage와 같은 공식 P2P 계약으로 단정하면 안 된다.

Worktree
Codex도 managed worktree를 지원한다.

codex --worktree와 Desktop handoff가 있다. 하지만 Claude의 세션 중 EnterWorktree와 정확히 같은 Codex 도구는 확인하지 못했다. Codex는 대상 경로에서 새 세션 또는 재개 세션을 시작하는 어댑터가 필요하다.

Policy placement
`.claude/rules`를 전부 skills로 옮기는 건 좋지 않다.

항상 지켜야 할 안전·권한·Git 계약을 on-demand skill로 옮기면 skill이 호출되지 않은 턴에서 사라진다. 공식 문서도 persistent instructions와 skills를 보완 관계로 구분한다. 정답은 rules 삭제가 아니라 중립 원본 → 하네스별 carrier 생성이다.

최종 방향: 공통 정책·skill·agent 카탈로그 하나, Claude/Codex용 얇은 emitter, native-first/broker-fallback 세션 transport, MoAI 소유 persistent worktree. 현재 코드를 갈아엎지 않고 이미 있는 dual init·skill mirror·agent emitter·MCP broker를 확장한다.

권장 명령·상태 모델

session_msg_*는 발견·알림·질문·회신에만 쓰고, 실제 작업 지시는 영속 dispatch 레코드로 분리한다. dispatch에는 task_id, scope, authority_ref, 송수신 세션, readback 요구, 만료를 담는다. 수신자는 저장된 dispatch를 읽고 자신의 권한·worktree·카드 소유권을 다시 확인한다.

type SessionTransport interface {
    Capabilities(context.Context) CapabilitySet
    List(context.Context, SessionFilter) ([]Session, error)
    Notify(context.Context, SessionRef, Message) (Receipt, error)
    Readback(context.Context, Receipt) (DeliveryState, error)
}

type DispatchStore interface {
    Create(context.Context, AuthorizedDispatch) (DispatchRef, error)
    Claim(context.Context, DispatchRef, SessionRef) error
    Complete(context.Context, DispatchRef, []ArtifactRef) error
}

전달 성공 ≠ 작업 완료. 완료는 결과 artifact와 검증 evidence가 dispatch에 연결됐을 때만 성립한다.

moai cc -w가 생성·등록·정리를 소유한다. Claude/Codex는 이미 결정된 경로에서 실행만 한다. branch·card·evidence를 연결한다.

Ephemeral session
owner: host

Claude/Codex 네이티브 worktree를 쓴다. 탐색·단일 세션 작업에 한정하고 카드 lifecycle과 섞지 않는다.

worktree:
  ownership: moai        # moai | host
  mode: persistent-card # persistent-card | ephemeral-session
  forbid_nested: true

한 물리 worktree의 lifecycle owner는 반드시 하나다. Codex의 detached HEAD를 카드 branch로 오인하지 않고, MoAI와 호스트가 같은 tree를 각각 정리하지 못하게 해야 한다.

Policy decision

Rules와 Skills는 저장 위치가 아니라 적용 시점이 다르다

Claude는 CLAUDE.md를 항상 적용되는 지침, rules를 세션/경로 지침, skills를 작업별 절차로 설명한다. OpenAI도 AGENTS.md는 작고 지속적인 지침, skills는 필요할 때 로드하는 전문 절차라고 설명한다.

Target architecture

기능 협상

하네스 이름만 보고 기능을 추정하지 않는다. session start에 버전과 CLI/API 표면을 probe하고 harness_version, checked_at, capability, status, evidence_digest를 기록한다. 미지원과 미측정을 구분한다.

현재 agents-codex.yaml의 측정 버전은 0.147.0이고 설치 버전은 0.155.1이다. 기능이 실제로 동작하더라도 doctor는 재측정을 요구해야 한다.

Configuration

모델과 하네스를 분리하고, `gpt`를 `codex`로 바로잡는다

현재 moai init --llm claude|gpt|both는 동작한다. 하지만 gpt는 모델 계열 이름이고 실제 배포 대상은 Codex 하네스다.

  • 신규 표준: --harness claude|codex|both
  • 호환: --llm gpt를 deprecated alias로 유지
  • 저장 설정: 모델 policy와 하네스 target을 분리
harness:
  targets: [claude, codex]
  preferred: auto
  capability_probe: on-version-change

model:
  policy: high

session:
  transport_order:
    claude: [native, moai_broker]
    codex: [app_server, moai_broker]
  delivery_readback: required
  message_is_authority: false

worktree:
  default_owner: moai
  persistent_cards: true
  native_ephemeral: true
  forbid_nested: true

생성기 개선

현재 skill_mirror.go는 .claude/skills를 canonical로 보고 .agents/skills에 상대 symlink, 불가능하면 copy한다. 양쪽 가시성은 달성했지만 Claude 경로 편향이 남는다. 중립 catalog/skills에서 양쪽을 생성하고 source/mirror digest를 manifest에 기록하자. 기존 미러는 한 호환 주기 동안 유지한다.

수용 기준

  1. moai init --harness both가 양쪽 설정·agent·skill·hook을 생성한다.
  2. 동일 skill ID의 양쪽 digest가 같고 host overlay 차이는 manifest에 명시된다.
  3. 모든 안전 MUST가 persistent carrier/guard를 가지며 skill-only는 0개다.
  4. Claude↔Codex 알림 왕복과 receipt/readback이 기록된다.
  5. 메시지만으로 승인·완료 상태가 변하지 않는 negative test가 통과한다.
  6. 한 worktree에 lifecycle owner가 둘이면 거부된다.
  7. Codex detached HEAD와 MoAI 카드 branch가 구분된다.
  8. 설치 버전이 측정 버전보다 새로우면 doctor가 재측정 경고를 낸다.
  9. root instruction 결합 크기가 32KiB 아래이고 truncation mutant가 검출된다.
  10. 기존 --llm gpt 프로젝트가 명시적 경고와 함께 동일 산출물로 업데이트된다.

Gaps

  • 다른 실제 세션에 codex queue를 보내지는 않았다. 외부 세션 상태를 바꾸므로 help 계약만 측정했다.
  • Claude↔Codex 실제 왕복 E2E와 원격 App Server는 실행하지 않았다.
  • Codex 공식 developer command 색인에는 로컬에서 실측된 agents/queue가 아직 명시적으로 보이지 않았다. 버전 probe 기능으로 취급했다.

  • 코드·템플릿 migration은 구현하지 않았다.

Residual-risk

  • App Server와 CLI의 실험/안정 경계가 버전별로 바뀔 수 있다.
  • rule 자동 분류는 의미를 축약할 수 있어 조항 단위 coverage가 필요하다.
  • symlink/copy는 Windows와 파일시스템 권한에 따라 다르다.
  • 전달 성공은 수신 세션의 실행·완료를 보장하지 않는다.
  • root AGENTS는 사용자 범위 파일과 합쳐지므로 프로젝트 파일 크기만으로 truncation 안전을 증명할 수 없다.
