Decision summary

한 줄 설계: 중립 원본 → 결정적 emitter → 두 호스트 어댑터

Source of truth1개

internal/template/canonical만 사람이 편집한다.

Harness targets2개

Claude Code와 Codex는 각자의 네이티브 경로를 소비한다.

Safety rule0개

Skill에만 존재하는 hard safety clause의 허용 수.

첫 구현 단위는 세션 통신이 아니라 policy coverage inventory다. 83개 rule을 먼저 옮기면 중요한 의무가 조용히 사라질 수 있다. 조항 ID와 carrier/test 대응을 고정한 뒤 디렉터리를 이동한다.

완료 정의

  1. moai init --harness claude|codex|both가 선택한 산출물만 배포한다.
  2. 공통 안전 정책, Skill, Agent 의미는 각각 하나의 중립 원본을 가진다.
  3. 모든 hard clause가 persistent instruction 또는 guard/test를 가진다.
  4. Claude↔Codex 알림 왕복과 readback을 검증하며 메시지는 승인이나 완료를 만들지 않는다.
  5. persistent card worktree는 MoAI만 관리하고 host-native worktree는 ephemeral로 분리한다.
  6. 기존 --llm gpt 프로젝트를 손상하지 않고 마이그레이션한다.

비목표: 두 제품의 도구 이름 통일, 미지원 기능 가장, 83개 rule의 일괄 Skill 변환, 이번 단계의 코드 구현.

가짜 동등성 금지: Claude의 path-scoped rule과 Codex nested AGENTS는 같지 않다. Codex instruction chain은 실행 CWD를 따르므로 root 세션이 다른 하위 경로를 수정할 때 nested 지침이 자동 적용된다고 보장할 수 없다.

Codex scoped rule 변환 순서

  1. 데이터 손실·권한 침해 위험은 root AGENTS와 Hook으로 승격한다.
  2. 그 디렉터리에서 실행하는 작업이면 nested AGENTS.override.md와 codex -C <dir>를 묶는다.
  3. 작업 유형의 절차라면 dual Skill로 옮긴다.
  4. 파일 경로로 검사 가능하면 path-aware Hook으로 강제한다.
  5. 보존할 방법이 없으면 unsupported로 남기고 원본을 삭제하지 않는다.

Dual publication

Runtime adapter 01

세션 통신: native-first, broker-fallback, dispatch는 별도

Transport역할사용 조건Fallback
Claude nativeListAgents/SendMessage기능 probe 성공MoAI broker
Codex App Serveragents/queue/thread API버전별 probe 성공MoAI broker
MoAI brokersession_msg_register/list/send/poll교차 하네스·native 미지원명시적 전달 실패
type SessionTransport interface {
    Probe(context.Context) CapabilityEvidence
    List(context.Context, SessionFilter) ([]Session, error)
    Notify(context.Context, SessionRef, Message) (Receipt, error)
    Readback(context.Context, Receipt) (DeliveryState, error)
}
메시지는 알림일 뿐이다. 현재 broker의 “facts, not mutations” 계약은 유지한다. 실제 작업 지시는 authority_ref, scope, worktree, expected readback을 가진 영속 dispatch로 처리한다.
dispatch:
  id: dsp_...
  task_id: T-...
  scope: [internal/template/canonical]
  authority_ref: user-turn-or-approved-card
  source_session_id: ...
  target_session_id: ...
  worktree_ref: ...
  expected_readback: [artifact, tests]

수신 메시지는 dispatch ID만 알린다. 수신자는 claim 전에 권한·scope·worktree owner를 재검사한다. delivery receipt와 completion evidence는 독립 상태다.

신규 패키지 후보: internal/sessiontransport, internal/dispatch. CLI 후보: moai session list|send|readback, moai dispatch create|claim|complete.

Runtime adapter 02

type WorktreeProvider interface {
    Create(context.Context, WorktreeSpec) (WorktreeRef, error)
    Launch(context.Context, WorktreeRef, Harness) (SessionRef, error)
    Inspect(context.Context, WorktreeRef) (WorktreeState, error)
    Close(context.Context, WorktreeRef, IntegrationProof) error
}

Claude persistent

MoAI path에서 시작하거나 EnterWorktree로 진입.

Codex persistent

codex -C <path> 또는 동일 path에 묶인 thread resume.

반드시 거부할 상태

  • 한 path에 lifecycle owner가 둘
  • persistent tree 안에서 host-native tree를 중첩 생성
  • 통합 증거 없이 persistent tree 삭제
  • Codex detached HEAD를 카드 branch로 등록
  • worktree path와 dispatch scope 불일치

변경 후보: internal/worktree/provider.go, ownership.go, internal/cli/worktree/**, internal/cli/harness_launch.go, registry/guard 테스트.

CLI and configuration

  forbid_nested: true

Rollout

  1. both를 opt-in으로 시작하고 기존 기본값을 유지.
  2. doctor는 먼저 경고-only 관찰 모드.
  3. golden/E2E 안정 후 신규 프로젝트 표준을 --harness로 전환.
  4. --llm 호환 경로 유지.

Rollback

  • 이전 template manifest와 canonical digest 보존.
  • update 전 managed artifact manifest 백업.
  • 사용자 소유 파일은 rollback 대상에서 제외.
  • 기존 broker와 --llm 경로를 한 호환 주기 유지.
