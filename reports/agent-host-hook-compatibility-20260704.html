Background

목표는 MoAI를 한 번 설치해도 Claude, Codex, OpenCode 계열 코딩 에이전트에서 같은 런타임 개념을 재사용할 수 있는지 판단하고, 특히 훅 계층이 호환성의 병목이 되는지 테스트 가능한 구조로 만드는 것이었습니다.

Before
  • 호스트별 훅 이벤트 지원 수준을 코드에서 조회할 수 없었습니다.
  • Codex 프로젝트용 .codex/hooks.json 템플릿이 없었습니다.
  • OpenCode는 공식 plugin event 기반이라 Claude/Codex 훅과 1:1 대응 여부가 불명확했습니다.
  • 훅이 실제 호출됐는지 테스트하려면 런타임 로그에 의존해야 했습니다.
After
  • internal/agenthost가 Claude, Codex, OpenCode 이벤트 매핑을 SSOT로 제공합니다.
  • moai host matrix [host] --json으로 호환성 표를 CLI에서 바로 볼 수 있습니다.
  • Codex는 공식 hooks 이벤트 10개를 native로 연결하는 템플릿이 생겼습니다.
  • MOAI_HOOK_INVOCATION_LOG로 훅 호출 JSONL을 남기는 검증 경로가 생겼습니다.

Review Focus

1
OpenCode는 native parity가 아닙니다
OpenCode 공식 표면은 hook JSON이 아니라 plugin event입니다. 그래서 이 커밋은 가능한 항목을 adapter, 생명주기 추론이 필요한 항목을 fallback으로 명시합니다.
2
Codex async command hook은 제외했습니다
Codex 공식 문서상 async: true command hook은 파싱되지만 실행되지 않는 제약이 있어 템플릿에서 의도적으로 사용하지 않습니다.
3
Probe는 opt-in입니다
MOAI_HOOK_INVOCATION_LOG가 없으면 아무 파일도 쓰지 않습니다. 따라서 일반 훅 성능/동작에는 영향을 주지 않고, 테스트가 필요할 때만 켤 수 있습니다.
4
Symlink/중앙 설치 전략의 남은 경계
Codex 템플릿은 기존 .claude/hooks/moai/*.sh wrapper를 재사용합니다. 즉 중앙 설치 또는 symlink는 가능하지만, wrapper 경로와 host marker 계약은 계속 유지되어야 합니다.
