MoAI-ADK のデータベースワークフローは、プロジェクトのスキーマメタデータを中央で
管理します。`/moai db` コマンドでマイグレーションファイルをスキャンし、スキーマ
ドキュメントを自動生成し、ドキュメントと実際のマイグレーションの間のドリフトを
検出します。

このスキーマドキュメントは人間だけが読むドキュメントではありません。**エージェンティックハーネス** の観点では、
`.moai/project/db/` はエージェントの永続コンテキスト(ファイルベースのメモリ)です。
エージェントがセッションごとにマイグレーションファイルを読み直してスキーマを再構成する代わりに、
整理されたスキーマドキュメント 1 つを参照するため、同じ情報を得るのに必要なトークンが大幅に
減ります — トークノミクスがドキュメント構造にまで適用されている例です。

## 主な機能

- **対話型初期化** — `/moai db init` でデータベースエンジン、ORM、マイグレーションツールを選択し、メタデータテンプレートを自動生成
- **自動同期** — PostToolUse フックがマイグレーションファイルの変更を検知して自動リフレッシュ
- **ドリフト検出** — `/moai db verify` でスキーマドキュメントとマイグレーションファイル間の不一致を検査
- **16 言語サポート** — Go、Python、TypeScript、JavaScript、Rust、Java、Kotlin、C#、Ruby、PHP、Elixir、C++、Scala、R、Flutter、Swift

## 4 つのサブコマンド

```bash
/moai db init      # 対話型インタビューで DB メタデータを初期化
/moai db refresh   # マイグレーションファイルを再スキャンしスキーマドキュメントを再生成
/moai db verify    # ドリフトを確認 (読み取り専用)
/moai db list      # すべてのテーブルを Markdown 表で表示
```

## いつ使うのか

- 新規プロジェクト開始時のデータベースメタデータ設定
- マイグレーションファイルの追加・編集後のドキュメント自動更新
- チームメンバーへの現在のスキーマ状態の共有
- スキーマドキュメントと実際のマイグレーション状態の一貫性検証
