トークノミクスはトークンだけに適用される原則ではありません。プロジェクトに配布されるテンプレートファイルの一つひとつも、結局はセッションがロードすることになるコンテキストの候補です。カタログシステムは「必要なものだけ配布する」という原則で、このコストを初期化段階から削減します。

## 概要

MoAI-ADK v2.15+ のカタログシステムは、すべてのエージェント、スキル、プラグイン、ルールを **3 階層マニフェスト** で管理します。`moai init --slim` を使うと、プロジェクトに必要な最小限のテンプレートだけを選んで配布するため初期化が速くなり、プロジェクトに残るファイルも軽くなります。

## 3 階層マニフェスト

すべての配布対象は 3 つの階層のいずれかに属します。

| 階層 | 説明 | 配布基準 |
|------|------|----------|
| **Tier 1 (Core)** | コアインフラ — オーケストレーター、品質ゲート、基本スキル | 常に配布 |
| **Tier 2 (Standard)** | 標準拡張 — 言語別ルール、フレームワークスキル | プロジェクトの言語/フレームワーク検出時 |
| **Tier 3 (Optional)** | 選択的 — ドメインスキル、プラットフォーム別設定 | 明示的な要求またはプロジェクト設定時 |

## カタログファイル

カタログマニフェストは YAML 形式で定義されます。

```yaml
# カタログエントリの例
- id: moai-workflow-tdd
  tier: 1                    # 1=Core, 2=Standard, 3=Optional
  type: skill
  path: .claude/skills/moai/workflows/tdd.md
  languages: []              # 空配列 = すべての言語
  frameworks: []
  hash: abc123...             # コンテンツハッシュ (整合性検証)
```

`hash` フィールドがコンテンツハッシュを保持しているため、配布されたファイルが破損したり勝手に変更されたりしていないかをローダーが検証できます。

## SlimFS フィルター

`moai init --slim` は SlimFS フィルターを通じて配布ファイルを制限します。

```bash
# フルインストール (すべての階層)
moai init my-project

# Slim インストール (Tier 1 + 検出された Tier 2 のみ)
moai init --slim my-project
```

### フィルターロジック

フィルターは 4 段階で動作します。

1. Tier 1 は常に含める
2. プロジェクトの言語を検出 (Go、Python、TypeScript など)
3. 検出された言語に該当する Tier 2 項目のみ含める
4. Tier 3 は除外

## Typed Loader

`LoadCatalog()` 関数がマニフェストを型安全にロードします。文字列パースに依存せず構造体単位で検証するため、マニフェストのエラーは配布前に弾かれます。

- 3 階層分類の検証
- ハッシュ整合性検査 (Hash Sentinel)
- 欠落フィールドの検出
- 100% テストカバレッジ

## カタログの活用

### プロジェクト初期化

```bash
# 通常の初期化 — すべてのテンプレートを配布
moai init my-project

# Slim 初期化 — 最小限のテンプレートのみ配布
moai init --slim my-project
```

### 更新

更新も同じカタログを基準に動作するため、slim で初期化したプロジェクトは slim で更新すればよいのです。

```bash
# カタログベースの更新
moai update                  # すべての階層を更新
moai update --slim           # slim モードで更新
```
