MoAI-ADK는 새 버전을 내보낼 때마다 무엇이 바뀌었는지 알리기 위해 **릴리스 노트** (release notes)를 작성합니다. 릴리스 노트는 '이번 버전에서 어떤 기능이 새로 들어왔고, 어떤 문제가 고쳐졌으며, 업그레이드할 때 주의할 점은 무엇인지'를 한눈에 보여주는 변경 이력입니다. 새로운 기능, 수정된 문제, 호환성에 영향을 주는 변경(파괴적 변경)이 항목별로 정리되어 있어, 다음 버전으로 넘어갈지 현재 버전을 유지할지 판단하는 근거가 됩니다.

이 문서 사이트에는 릴리스 노트를 따로 옮겨 적지 않고 **GitHub Releases**로 연결합니다. 이유는 단순합니다. 릴리스 노트를 4개 언어로 옮겨 적으면 원본과 어긋나기 쉽고, GitHub Releases에는 릴리스 과정에서 영어·한국어 본문이 이미 함께 올라가기 때문입니다. 문서 사이트는 개념과 사용법을 설명하는 자리이고, 변경 이력은 코드 저장소가 원본으로 삼는 것이 더 정확합니다.

- [GitHub Releases](https://github.com/modu-ai/moai-adk/releases) — 버전별 릴리스 노트(영어·한국어)와 배포 산출물
- [CHANGELOG.md](https://github.com/modu-ai/moai-adk/blob/main/CHANGELOG.md) — 전체 변경 이력(영어)

버전 번호는 [유의적 버전](https://semver.org/lang/ko/) 규칙을 따릅니다. 버전은 `주.부.수` 세 개의 숫자로 이루어지는데, 첫 번째(주)는 서로 호환되지 않는 큰 변경이 있을 때 올라가고, 두 번째(부)는 기능이 추가되었어도 기존 코드가 그대로 작동할 때 올라가며, 세 번째(수)는 문제만 고쳤을 때 올라갑니다. 예를 들어 `1.4.2`에서 문제 하나만 고치면 `1.4.3`이 되고, 새 기능을 추가하면 `1.5.0`이 되며, 기존 코드가 깨지는 큰 변경을 넣으면 `2.0.0`이 됩니다. 항목 구성은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/) 형식을 따라 '추가됨 / 변경됨 / 제거됨 / 수정됨 / 보안' 같은 분류로 일관되게 정리합니다.

릴리스 노트를 읽을 때는 먼저 '파괴적 변경' 항목부터 확인하는 것이 좋습니다. 업그레이드 전 반드시 손봐야 할 코드나 설정 변경이 그 항목에 적혀 있기 때문입니다. 그 다음 '추가됨' 항목을 보면 새로 쓸 수 있는 기능을 빠르게 파악할 수 있습니다.
